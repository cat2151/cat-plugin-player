# cat-plugin-player

オーディオプラグインを手軽に演奏できる軽量アプリ。[UAPMD](https://github.com/atsushieno/uapmd)を利用しています。Rustで書かれています。

# これまでの課題と、このアプリが解決すること
- オーディオプラグインの音色は素晴らしいですね！
- 演奏するには、DAWを起動し、演奏のための前準備が必要なことが多いです。
- 手軽に演奏するための軽量アプリは、入手のためのアカウント登録が必要なことがあったり、操作感覚がnot for meだったりしました。
- 現代は、ほしいUXがあれば、バイブコーディングで実現できます。
- そうすることにしました。

# 機能
- 検出
  - 起動すると、installされているプラグインを自動で検出します
- 演奏
  - `Load` ボタンを押すと、プラグインload後、自動で演奏を開始します
- GUI
  - `Show UI` ボタンを押すと、プラグインのGUIを表示できます
- 音色
  - 音色の変更をしたいときは、プラグインのGUIを使います

# 機能（AIによる詳細な追記。読みづらいのであとでなおすつもり）

オシロスコープの表示方式と制約は[ADR 0001](docs/adr/0001-scope-follows-waveform-position.md)に記録しています。

- GUI
  - GUIを初めて開くと、描画を2秒待って自動でスクリーンショットを撮り、縦横比を保って一覧の表示枠と画面の拡大率に合わせたサイズのPNGに縮小します。`%LOCALAPPDATA%\cat-plugin-player\plugin-icons\` に保存し、名前＋メーカーが一致するプラグインはVST3 / CLAPでも同じ画像を共有します（前後の空白・大文字小文字は無視）。名前・メーカーが不足する場合は形式＋IDで区別します
  - 以前保存した形式別の画像も、一覧・お気に入りの識別情報から共有画像へ自動移行して使います。音色stateとお気に入りのロード先は従来どおり形式＋IDで区別します
  - Plugins / Favorites / Routing にプラグインの画像を表示します。行内ではボタンの高さに収め、縦横比を保って小さく表示します。画像にマウスを重ねると保存サイズで確認できます。GUI未表示のプラグインは同じ高さの仮アイコンを表示します
  - GUIは本体の右隣・上端合わせで画面の作業領域に収まる位置を優先します。収まらない場合は本体がある画面の作業領域の右下に配置します。表示時とGUIのサイズ変更時に配置し、本体の移動には常時追従しません。GUIは縮小せず、画面より横幅が大きい場合は左端、縦幅が大きい場合は上端を作業領域に合わせます
  - 白紙画像や撮影失敗時は1秒間隔で、GUI表示から最大20秒まで再試行します。保存済みの白紙画像も未撮影として扱い、GUIを開くと有効な画像で置き換えます。成功後は再撮影しません。
  - 再試行しても撮影に失敗した場合はエラーを表示します。GUIを開き直すと再試行します。撮影非対応のGUIでは仮アイコンのままです。撮り直したい場合や保存PNGが破損した場合は、該当プラグインの共有PNGと残っている旧形式別PNGを削除してアプリを再起動し、GUIを開いてください（移行時には旧PNGを残します）
- 演奏
  - 最後に演奏した instrument と接続中の effect・Bypass 状態・演奏パターンを `%LOCALAPPDATA%\cat-plugin-player\status.json` に保存し、次回起動時に復元します。停止状態、停止中の演奏パターン選択、確定したMML／コード本文も復元します。未確定の編集は保存しません
  - CLAPのNote On/Offはプラグインが対応する入力形式に合わせて送信します。MIDIのみを受け付けるsforzando CLAPもこの対象です。補修の適用範囲と検証記録は[CLAP Note形式の説明](patches/uapmd/clap-note-dialect/README.md)に記録しています
  - 左上の `Sequence` pane で、左右矢印またはドロップダウンから演奏の種類を選べます。矢印は種類の両端で循環し、停止は種類に含めません。演奏中の切替は鳴っているフレーズの全音を解放し、新しいフレーズの先頭から開始します。停止中は種類を選んでも演奏せず、`Play` で開始、`Stop` で停止します。本体ウィンドウでは `Space` キーでも開始・停止を切り替えられます（文字入力中を除く）。MML／コードを含む演奏パターンの選択と停止状態は次回起動時にも復元します
  - MML／コード進行の試奏は、`i` キーまたは `Sequence` の `Chord` ボタン（ホバーでショートカットと入力方法を確認できます）で入力画面を開きます。単音の例は `t120 c8r8d4e4r4`、コード進行の例は `C F G C` です。同じ入力欄で両方を受け付け、コード表記の変換を先に試します。大文字 `C` はコード、小文字 `ceg` はMMLになります
  - 入力は `Enter`／`Confirm` で確定し、`Esc`／`Cancel` で取り消します。取消しや変換エラーは直前の有効なフレーズを維持します。入力画面内の `Space` や `i` は文字入力に使い、`Space` による再生・停止は動作しません
  - 確定したフレーズは `Play`／`Stop` でループ再生します。休符・音長・テンポ変更・和音・末尾休符を保ちます。入力画面を開くと全体の通常演奏を一時停止します。開く直前に演奏中だった場合、確定後は新しいフレーズ、取消後は元の演奏パターンを先頭から再生します。停止中に開いた場合は確定・取消後も停止を維持し、`Play`で全体再生を開始します。通常の演奏パターンにも切り替えられます。確定直後に本文と選択・再生状態を保存し、取消時も戻した再生状態を保存します。次回起動時や音源のお気に入り・Historyから復元します。未確定の本文は保存せず、取消しや変換失敗では直前の確定本文を保ちます
  - 入力変更やカーソル移動で、その位置の単音／和音を一度試聴します。途中編集や貼り付けも対象です。同じ発音単位の内側での移動や再描画だけでは鳴らし直しません。前のテンポ・オクターブ・音長を反映し、休符やコマンドの位置では発音しません。編集を開いた時点で通常演奏は停止し、試聴音の終了後も全体再生は始まりません。次の発音単位、取消し、確定、音源交換でも試聴音を解放します。試聴は確定本文・通常の選択を変えません
  - 確定したMMLのループ再生の発音Velocityは、入力内の指定より `Velocity` 欄の設定を優先します。CC1も `CC1 modulation` 欄から操作できます。非常に過密なフレーズで演奏イベントの容量に達した場合は、鳴っている音を解放して発音を停止します。`Stop` → `Play` で再開始できます
  - アプリのFavorites／Historyからの呼び出しやBrowse patches／Random patch／Random effectによる音色変更では、停止・再生状態を維持します。再生中はフレーズの先頭から演奏し、変更前のフレーズ途中の待ちを引き継ぎません。MMLで指定した先頭休符は保ちます。音色ブラウザー中は背後のSpaceによる再生・停止とMML入力開始を抑止します。プラグイン独自GUIの音色変更は検出しません
  - Six Sines／TyrellN6 CLAPでは、ロード・state復元・接続変更などで音声処理を再構築した際、冒頭音を保つため、通常の音声処理を続けながら最初のフレーズ開始を待ちます。48kHz時の待ちはSix Sinesで約21ms、TyrellN6で約85msです。MMLの先頭休符はさらに加算されます。適用条件と実機検証は[ADR 0019](docs/adr/0019-random-patch-all-catalog.md)を参照してください
  - 演奏パターンの下の `Velocity` 欄で、同じ左右矢印・ドロップダウンから `100`・`127`・`40-100`・`80-127` を選べます。初期値は100です。範囲指定はフレーズ内のNote On順に値を上げ、次のループでは下げる動作を繰り返します。変更はフレーズを再開せず次の発音から反映し、次回起動時にも復元します
  - `CC1 modulation` 欄で、左右矢印・ドロップダウンから `0`・`127`・`sweep` を選べます。初期値は0です。`sweep` は2秒で0から127へ、次の2秒で127から0へ変化する動作を繰り返します。選択は次回起動時にも復元します
  - ギター開放弦は MIDI note number 40・45・50・55・59・64（ミ・ラ・レ・ソ・シ・ミ）を125ms間隔で順にNote Onします。最後のNote Onから2秒後に6音を同時にNote Offし、0.5秒後に繰り返します
  - `Load` 成功時、`Sequence` の種類選択・開始・停止時に記憶します。停止や `Remove` 後も記憶は残ります。古い履歴・お気に入りは従来の4音パターンで復元します
  - 終了時と `Remove` 時には、UAPMDのstate APIでプラグインが公開する音色・パラメータ等のバイナリstateを `%LOCALAPPDATA%\cat-plugin-player\states\` にプラグインごとに保存します。次回起動時や同じプラグインの再load時には、演奏開始前に復元します
  - instrument の `Load` は音源だけを置き換え、接続済み effect と設定は維持します。置き換えるプラグインの state を保存し、新しいプラグインの生成・復元・接続に成功してから切り替えます。失敗した場合は元の構成を維持してエラーを表示します
  - stateの保存範囲はプラグインとUAPMDの形式別実装によります。UI stateも要求しますが、現在のUAPMDのVST3実装はcomponent stateのみを取得します。外部サンプルの複製や、強制終了時の保存は含みません
  - 起動時は前回の instrument と effect を直接ロードし、state を復元してから演奏を開始します。その後にGUIを初期化して一覧を背景で走査します
  - 古い履歴やファイル移動などで直接ロードできない場合は、GUI表示後の走査結果から復元します。古い履歴は一度演奏すると更新されます
  - 主音源がCLAP Floeの場合は、ロードや音色復元などで音声処理を再構築した際、最初のフレーズの開始を100ms遅らせます。MMLの先頭休符はさらに加算されます。冒頭音が消える症状の観察用の暫定対策で、実機での解消は未確認です。適用条件と見直し方針は[ADR 0018](docs/adr/0018-floe-automatic-note-start-delay.md)を参照してください
  - 起動時間の計測方法と結果は [docs/startup-timing.md](docs/startup-timing.md) を参照してください
- エフェクトルーティング
  - instrument 1つ → 複数effect → 出力の直列接続です。instrument を読み込んでから最初の effect の `Load` を押し、以降は `Add` で末尾に追加します。接続済みの effect は `Remove` でその1つだけを外します。同じ形式＋IDの effect を重複して接続することはできません
  - `Sequence` 横の `Random effect` は、cmrtのeffect selectorと同じカタログ・選択対象から、インストール済みCLAP effectのプリセットを抽選します。effectが0個なら最初の1個を追加し、1個ならそのeffectを、複数なら接続済みeffectの1つを均等に選んで置き換えます。連打してもeffectの個数は増えず、他のeffectの順序・設定とBypassを維持します。重複接続を避けるため、置き換え対象以外に接続済みの形式＋IDは候補から外します。対象の段に使える候補がなければ理由を表示して変更しません
  - Random effectには音源が必要です。候補はplay-server共有coreが探索する既定のeffect・プリセットの場所から取得し、VST3への代替はしません。準備中は現在の演奏を続け、ロード・走査・音色操作を無効にします。停止中は停止、再生中は現在フレーズを先頭から再開し、MML・Velocity・CC1の全体選択を維持します。生成・適用・接続の失敗時は元の構成へ復帰し、別候補の自動抽選はしません。成功後は適用したstateと接続を次回起動用に保存し、Favorites／Historyは追加しません。保存失敗は適用済みとして表示します
  - `Routing` に接続順を表示します。effect の `↕` ボタンを上下にドラッグして順序を変更できます。ドラッグ中は移動するeffect名と挿入位置の線を表示します。instrument は並べ替えの対象外です。各プラグインの `Show UI` で音色や effect を編集できます。`Instrument`／`Effect` は左側の一覧と同じ種別色で表示します
  - 全effectを外すと音源から出力への直結に戻ります。`Bypass effect` はchain全体を対象とし、instance と設定を保持したまま素通しにできます。`b` キーでも切り替えられます（MML入力画面・Browse patches表示中と文字入力中は動作しません）。Bypass中はRouting内の接続effectをグレーで表示し、`Bypassed` を併記します
  - `Sequence` は instrument 用です。Sequence を止めても音声処理は続け、effect の余韻を出します
  - 次回起動時は instrument・全effectの順序・それぞれの state・Bypass 状態を復元してから演奏します。旧形式のeffect 1件の履歴も読み込めます。effect の復元に失敗した場合はエラーを表示して音源の直結に戻し、保存済みの構成は保持します
  - 追加・除去・順序変更は新しい接続の準備に成功した場合だけ保存します。失敗した場合は元の構成と再生を復帰し、エラーを表示します
  - 主入力・主出力の mono／stereo に対応します。mono → stereo は複製、stereo → mono は左右の平均です。補助入力は無音です
  - 接続や Bypass の変更時には短い音切れがあり、発音中の note と余韻は途切れることがあります。サイドチェイン、並列接続、ホスト側の Dry/Wet は未対応です
- 音色
  - `Random patch` 付近の `Browse patches` または `T` キーで、本体のある画面に独立した最大化ウィンドウの音色ブラウザーを開きます。本体の位置・サイズは変えません。MML編集中は開けません。枠付きのRole→Preset→検索で絞り込み、左側の条件領域と右側のPatches一覧はそれぞれスクロールできます。一覧に残りの幅と高さを使い、最大化解除や狭いウィンドウでも操作できます。上部1行にSearch・`Solo/Mute`・`Random`・`☰`が並びます。検索欄には残りの幅を使い、ブラウザー内の `/` キーで検索欄へ入力を移せます。音源条件の詳細は`Solo/Mute`のhoverで確認できます。このボタン全体のクリックまたはブラウザー内の `M` キーで縦並びのSolo／Mute overlayが開き、`OK` または `Enter` でまとめて確定します。Solo／Muteは音源名のすぐ右に並びます。選択中のモードを再クリックすると通常へ戻り、`Esc`／overlay外クリックは変更を破棄します。複数SoloはOR、Muteは除外として扱います。検索は大小無視の正規表現、空白AND、`-条件`による除外、`plugin:`条件を使います（例: `pad -bright`、`plugin:floe`、`plugin:surgext -bass`）。統合済み音色の別名も検索できます。無効な正規表現はエラーになり、適用・抽選・条件保存を止めます。0件なら検索欄の編集やRole／Presetの変更で条件を見直せます。カタログ読込待ち・失敗は0件とは別に表示します。Role・Preset・検索文字列は終了時に保存し、次回起動時に復元します。Presetは名前で復元し、削除済みの条件ならそのRoleの `ALL` に戻ります
  - 一覧は折り返さない1行の音色名セルを、幅に応じた複数列で左→右→次の行へ並べます。狭いウィンドウでは1列へ戻ります。resizeしても選択した音色は維持し、列数の変更だけでは再ロードしません。音色をクリックしても一覧の表示位置は動かしません。上下左右キーまたは `h`／`j`／`k`／`l` は見た目の並びどおりに移動します。左右は前後の音色（行端では隣の行の端）へ、上下は上下の行へ移動し、真下に音色がない短い最終行へはその行の最後へ移動します。vim風に `2j`・`10k` のように数字を先に入力すると、その回数だけ移動します（端で止まります。移動以外のキーで数字は取り消されます）。`PageUp`／`PageDown` は上下10回分移動し、数字との組み合わせではその倍数だけ移動します。キー移動・Random・絞り込み・列数変更では、選択行が画面外の場合だけ見える位置までスクロールします。全音色が収まる場合はスクロールしません。単一音源の結果では音源名を省き、混在時は音源名を残します。文字色は結果内の違いを1つだけ示します。音源が混在すれば音源名部分を音源ごとに色分けします。単一音源では、Presetが `ALL` のとき該当Presetごとに、それで区別できなければcategoryごとに音色名を色分けします。色はMonokai系です。どれも同じなら通常の文字色です。色は5色を順に繰り返すため、離れた別グループが同色になることがあります。pink音色の音色名はpinkを優先します。分類フォルダー等は省略し、同名音色を区別する場合は必要なパスを残します。Dexedのprogram指定は維持します。マウスを重ねると完全な表示パスと適用元のパス、有効なcategory、2件以上の統合件数を確認できます。Load／Sizeは一覧に常設せず、`no category`／`1 merged` も表示しません。通常音色はマウス選択／キー移動で選択を変えると即時に適用を要求し、条件変更で別の候補が選ばれたときも同じ動作です。開くだけでは音色を変えません。開くと、Browse patches／Random patchで適用して鳴っている音色が現在の結果にあれば、その音色を選択状態にして見える位置までスクロールします（再適用はしません）。鳴っている音色は終了時に保存し、次回起動時に復元した音色として引き継ぎます。effectの追加・削除・Random effectでは引き継ぎを保ちます。鳴っている音色が結果に無い、または分からない場合は、前回閉じたときの選択を保ちます（起動後初めて開くときは未選択です）。Favorites／History・instrumentの読込や削除で音色を変えた後は鳴っている音色が分からず、選択も解除されます。キー移動は開いたときの選択から始まり、未選択なら先頭へ移動します。準備中にも次の選択ができ、未開始の要求は最新1件に置き換わります。通常の適用成功時には下部の重複する音色名や固定余白を表示しません。選択と適用済みの音色が異なる場合だけ短い案内を表示し、未確認pinkなどでは前の音色が鳴り続け得ることを示します。pinkのSpace案内と適用失敗・保存エラーは表示します
  - sample容量が64,000,000 bytes以上のpink音色は自動適用しません（容量不明は通常扱い）。選択後に `Space` で音源・音色・容量の確認overlayを開き、その中で `Enter` を押すと準備・適用を開始します。確認中の `Esc` は変更せず取消します。一度適用した音色も再確認が必要です。読込中は進行overlayを表示し、途中cancelはできません。検索欄や保存メニュー・Solo／Mute overlayのSpace／Enterは音色適用に使いません（Solo／Mute overlayの `Enter` は `OK` と同じです）

## ウィンドウの位置・サイズ設定

`%LOCALAPPDATA%\cat-plugin-player\config.toml` に本体の起動位置・サイズとプラグインGUIの配置方式を指定できます。アプリを終了してから編集してください。セッションやお気に入りの選択状態は同じディレクトリの `status.json` に保存し、通常の保存では TOML を書き換えません。旧 TOML に混在している状態は初回起動時に移行し、元ファイルを `config.toml.before-status-migration.bak` に保存してから状態項目だけを除去します。設定のコメント・書式・未知の項目を保持し、削除項目に付いていた独立したコメントは末尾に残します。既存の `status.json` がある場合はそちらを優先します。

```toml
[window.main]
x = 100.0
y = 100.0
width = 1200.0
height = 800.0

[window.plugin]
placement = "right_then_bottom_right"
```

本体の `x`・`y` は論理座標で、両方を指定した場合に起動位置として使います。省略すると従来の初期位置になります。`width`・`height` は本体の内側の幅・高さ（論理座標）です。片方だけでも指定でき、省略した側や0以下・非有限の値は幅900・高さ600に戻ります。変更は次回起動時に反映されます。プラグインの配置方式は現在 `right_then_bottom_right` のみで、省略時も同じ動作です。GUIサイズと配置は実際のウィンドウ枠・画面の作業領域・DPIに基づいて計算します。本体やGUIを手で動かした位置の自動保存、プラグインごとの位置指定は行いません。

## ローカルでのビルドと実行

当アプリと `uapmd`、`clap-mml-render-tui`、`clap-mml-play-server` を同じ親ディレクトリに clone し、当アプリのディレクトリで実行します。TUIの `app` / `patches` / `patch-select` / `tui-core` とplay-serverの `core-lib` / `server-config` はCargo.tomlから常時ローカル参照します。play-serverには従来の `prepare_clap_patch_state` / `PatchStateError` に加えて `prepare_catalog_clap_patch_state` / `supports_catalog_clap_plugin`、TUIの `cmrt-patches` にはその再exportが必要です。音色ブラウザーは公開Role／Preset／filter APIとtui-coreのsample容量判定を使います。Random effectはplay-serverの `AudioEffectCatalog` / `EffectRenderer` とTUIのeffect selectorの選択条件を利用します。checkout不足やAPI不足はビルドエラーとなり、Git版への自動切替は行いません。

```powershell
cargo build --release
& ./target/release/cat-plugin-player.exe
```

UAPMD が兄弟の `uapmd` ディレクトリ以外にある場合は、先に `$env:UAPMD_DIR = 'X:\projects\uapmd'` を設定してください。ビルド時の UAPMD の場所は環境変数で指定します。config.toml はビルド設定として読みません。

`cargo install` は使わず、既定の `target/release` に生成されたexeを直接実行します。ビルドはローカルのコード（未コミット変更を含む）と既存の `target/shim` を利用しますが、ソース変更によって再構成・再ビルドが必要になる場合があります。shim DLL は exe に同梱し、GUI 起動時にキャッシュディレクトリへ展開して読み込みます。

3repoの依存構成と運用方針は [ADR 0012](docs/adr/0012-local-dependencies-and-release-execution.md) を参照してください。catでのビルドにTUIのlocal切替は不要です。TUI自身で横断ビルドする場合はTUIの既存 `python scripts/cross_repo_local.py on` 手順を使い、offは人間が担当します。ローカル参照は未commit変更も使い、Cargo.lockは各checkoutの内容を固定しません。検証時は各repoのHEADと差分を記録してください。

引数なしで GUI を起動します。`--help` と `--version` も使えます。

  - アプリ起動から音が鳴るまで体感0.2秒。演奏までを最速にしています
    - GUI表示準備などの処理も、音の後にしています
      - GUI表示より先に音が鳴るのは、いわばスプラッシュスクリーンのサウンド版かもしれません
    - releaseビルドしたexeを直接実行する必要があります（cargo経由はtimestampチェックが、デバッグビルドはデバッグコードが、それぞれ起動時の待ち時間になるため）

  - 商業用よりは、教育用の方向を向いています

  - 頻繁に破壊的変更をします
