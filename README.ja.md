# cat-plugin-player

オーディオプラグインを手軽に演奏できる軽量アプリ。[UAPMD](https://github.com/atsushieno/uapmd)を利用しています。Rustで書かれています。

# これまでの課題と、このアプリが解決すること
- オーディオプラグインの音色は素晴らしいですね！
- 演奏するには、DAWを起動し、演奏のための前準備が必要なことが多いです。
- 手軽に演奏するための軽量アプリは、入手のためのアカウント登録が必要なことがあったり、操作感覚がnot for meだったりしました。
- 現代は、ほしいUXがあれば、バイブコーディングで実現できます。
- そうすることにしました。

# 機能

オシロスコープの表示方式と制約は[ADR 0001](docs/adr/0001-scope-follows-waveform-position.md)に記録しています。

- 検出
  - 起動すると、installされているプラグインを自動で検出します
- 演奏
  - `Load` ボタンを押すと、プラグインload後、自動で演奏を開始します
- GUI
  - `Show UI` ボタンを押すと、プラグインのGUIを表示できます
  - GUIを初めて開くと、描画を2秒待って自動でスクリーンショットを撮り、縦横比を保って最大192×128のPNGに縮小します。`%LOCALAPPDATA%\cat-plugin-player\plugin-icons\` に保存し、名前＋メーカーが一致するプラグインはVST3 / CLAPでも同じ画像を共有します（前後の空白・大文字小文字は無視）。名前・メーカーが不足する場合は形式＋IDで区別します
  - 以前保存した形式別の画像も、一覧・お気に入りの識別情報から共有画像へ自動移行して使います。音色stateとお気に入りのロード先は従来どおり形式＋IDで区別します
  - Plugins / Favorites / Routing にプラグインの画像を表示します。画像にマウスを重ねると保存サイズで確認できます。GUI未表示のプラグインは仮アイコンを表示します
  - 白紙画像や撮影失敗時は1秒間隔で、GUI表示から最大20秒まで再試行します。保存済みの白紙画像も未撮影として扱い、GUIを開くと有効な画像で置き換えます。成功後は再撮影しません。
  - 再試行しても撮影に失敗した場合はエラーを表示します。GUIを開き直すと再試行します。撮影非対応のGUIでは仮アイコンのままです。撮り直したい場合や保存PNGが破損した場合は、該当プラグインの共有PNGと残っている旧形式別PNGを削除してアプリを再起動し、GUIを開いてください（移行時には旧PNGを残します）
- エフェクトルーティング
  - instrument 1つ → effect 1つ → 出力の直列接続です。instrument を読み込んでから effect の `Load` を押すだけで接続します
  - `Routing` に接続順を表示します。各プラグインの `Show UI` で音色や effect を編集できます
  - effect の `Remove` で音源から出力への直結に戻り、`Bypass effect` で instance と設定を保持したまま素通しにできます
  - `Sequence` は instrument 用です。Sequence を止めても音声処理は続け、effect の余韻を出します
  - 次回起動時は instrument・effect・それぞれの state・Bypass 状態を復元してから演奏します。effect の復元に失敗した場合はエラーを表示して音源の直結に戻し、保存済みの構成は保持します
  - 主入力・主出力の mono／stereo に対応します。mono → stereo は複製、stereo → mono は左右の平均です。補助入力は無音です
  - 接続や Bypass の変更時には短い音切れがあり、発音中の note と余韻は途切れることがあります。サイドチェイン、並列接続、ホスト側の Dry/Wet は未対応です
- 音色
  - 音色の変更をしたいときは、プラグインのGUIを使います
  - 各プラグインの `★ Add favorite` で、その瞬間の音色・設定・演奏パターン（停止を含む）をお気に入りとして複数保存できます。名前は自動で付け、後から変更できます
  - 別のプラグインを `Load` すると、置き換わるプラグインの音色・設定・演奏パターンを切り替え前に Favorites へ自動保存します。名前は `auto プラグイン名 連番` です。同じプラグインの再読み込みや起動時の復元では追加しません。保存に失敗した場合は切り替えを中止します
  - 手動・自動保存時に、同じプラグイン・役割・演奏パターン・state の重複を確認し、新しいお気に入りを残して古い項目と保存ファイルを削除します
  - [プラグイン固有処理の方針・一覧（ADR 0002）](docs/adr/0002-plugin-specific-favorite-state-comparison.md)で、製品ごとの例外・理由・適用範囲・制限を確認できます。TyrellN6 CLAPの確認済みstate形式では、演奏だけで変わる圧縮部分を重複判定から除外し、テキストの設定が同じ音色をまとめます。Vaporizer2 CLAPの確認済み形式では、読み込み・保存で生じるMSEGの時間・座標の微小差（指定項目の絶対差`1e-9`以下）を同一と扱います。この幅以内の編集は区別できません。保存データは元のまま保持します
  - 中央の `Favorites` / `Plugins` タブで一覧を切り替えます。Favorites は新しいものから表示し、お気に入り名・プラグイン名・形式で絞り込めます
  - Favorites は1件1行で表示します。長い名前・補足情報は省略し、マウスを重ねると全文を確認できます。波形・スペクトラムは右側の Routing の下に表示し、右側の幅は境界のドラッグで調整できます。`Audio analysis` の `On right` で、分析表示を右下／画面下部に切り替えられます（起動時は右下）
  - 各行の左に色付きの `Instrument` / `Effect` を表示します。お気に入り名を1クリックすると音色・設定と演奏パターンを復元します。停止で保存したお気に入りは停止のまま復元します。音源のお気に入りは接続中の effect を、effect のお気に入りは音源を維持します。effect を呼び出すには音源が必要です
  - 接続中の effect のお気に入りには `Connected - click again to remove` を表示し、名前の再クリックで effect を外します。呼び出し後に設定を編集した場合や Bypass 中も同じ動作です。音源と保存済みのお気に入りは残ります。別の effect のお気に入りをクリックすると、その設定に切り替えます
  - 行末の `…` から名前変更・削除ができます。呼び出した後の編集や従来の自動保存は、お気に入りを上書きしません。`Last favorite` は最後に保存・呼び出したお気に入りを示します
  - お気に入りは `%LOCALAPPDATA%\cat-plugin-player\favorites\` に保存します。保存・復帰時には短い音切れが入る場合があり、保存できる範囲は従来のstate保存と同じです

# 機能（AIによる詳細な追記。読みづらいのであとでなおすつもり）
- 波形表示
  - 画面下の `Oscilloscope` で、effect・Bypassを反映した出力のL（緑）とR（青）を重ねて表示します。monoは両方に同じ波形を表示します
  - 最後にNote OnしたMIDI note number（A4 = 440Hz）から表示幅を求め、`1`・`2`・`4`・`8 cycles` を選べます。Note Off後も最後のnoteを基準に余韻を表示します。和音やデチューンを含む出力は、その幅で完全に繰り返すとは限りません
  - `Zero cross` は左chの負→正の交差に合わせます。左chが無音なら右chを使い、交差がなければ先頭から表示します
  - `Similarity` は前回表示との相関係数が最大になる位置を、バッファ先頭から表示幅ぶん、1 sample刻みで総なめします。同点は先頭側を採用し、左右には同じ開始位置を使います。初回や比較対象が無音の場合はゼロクロスを使います
  - noteの発音、演奏パターン、表示周期数、トリガー方式、音声ストリームが変わると比較履歴をリセットします。十分なデータが集まるまでは待機表示になります
  - 探索は音声処理とは別のスレッドで行います。低いnote・多い周期数では表示の更新が遅くなることがあります。表示用データが途切れた場合は履歴をリセットします
  - 起動時の表示設定は4周期・ゼロクロスです。表示設定は保存しません
- 演奏
  - 最後に演奏した instrument と接続中の effect・Bypass 状態・演奏パターンを `%LOCALAPPDATA%\cat-plugin-player\config.toml` に保存し、次回起動時に復元します。停止状態も復元します
  - 左上の `Sequence` pane で、左右矢印またはドロップダウンから演奏の種類を選べます。矢印は種類の両端で循環し、停止は種類に含めません。演奏中の切替は鳴っているフレーズの全音を解放し、新しいフレーズの先頭から開始します。停止中は種類を選んでも演奏せず、`Play` で開始、`Stop` で停止します。選択中の種類と停止状態は次回起動時にも復元します
  - 演奏パターンの下の `Velocity` 欄で、同じ左右矢印・ドロップダウンから `100`・`127`・`Random`（ランダム）を選べます。初期値は100です。ランダムは各Note Onで1〜127を選びます。変更はフレーズを再開せず次の発音から反映し、次回起動時にも復元します
  - ギター開放弦は MIDI note number 40・45・50・55・59・64（ミ・ラ・レ・ソ・シ・ミ）を125ms間隔で順にNote Onします。最後のNote Onから2秒後に6音を同時にNote Offし、0.5秒後に繰り返します
  - `Load` 成功時、`Sequence` の種類選択・開始・停止時に記憶します。停止や `Remove` 後も記憶は残ります。古い履歴・お気に入りは従来の4音パターンで復元します
  - 終了時と `Remove` 時には、UAPMDのstate APIでプラグインが公開する音色・パラメータ等のバイナリstateを `%LOCALAPPDATA%\cat-plugin-player\states\` にプラグインごとに保存します。次回起動時や同じプラグインの再load時には、演奏開始前に復元します
  - instrument の `Load` は音源だけを置き換え、接続済み effect と設定は維持します。置き換えるプラグインの state を保存し、新しいプラグインの生成・復元・接続に成功してから切り替えます。失敗した場合は元の構成を維持してエラーを表示します
  - stateの保存範囲はプラグインとUAPMDの形式別実装によります。UI stateも要求しますが、現在のUAPMDのVST3実装はcomponent stateのみを取得します。外部サンプルの複製や、強制終了時の保存は含みません
  - 起動時は前回の instrument と effect を直接ロードし、state を復元してから演奏を開始します。その後にGUIを初期化して一覧を背景で走査します
  - 古い履歴やファイル移動などで直接ロードできない場合は、GUI表示後の走査結果から復元します。古い履歴は一度演奏すると更新されます
  - 起動時間の計測方法と結果は [docs/startup-timing.md](docs/startup-timing.md) を参照してください

# ビルド & 動作確認 の手順
- ※前提として、まず [UAPMD](https://github.com/atsushieno/uapmd) をビルドしてください。手順等もそちらを参照ください。Windowsなら `Microsoft C++ Build Tools` が入っていればかんたん！入っていないならAIにきいて入れればかんたん！全体にAI任せでかんたん！くらいのイメージです
- ※次の前提として、Rustが入っていなければAIにきいて入れればかんたん！くらいのイメージです
- 前述のとおり、 ../uapmd がビルド済みであることを確認します
- Surge XT などのオーディオプラグイン（instrument）がinstall済みであることを確認します。例えばREAPERでSurge XTが鳴ることを確認します
- `cargo run` します（アプリがデバッグビルドされます）
- 画面が開くことを確認します
- Surge XT などが画面にlistされることを確認します
- Loadボタンをクリックします
- Loadされ、音が鳴ることを確認します

# コマンドラインから最新版を確認・更新

```powershell
cat-plugin-player check
cat-plugin-player update
```

## 補足 ※AIが生成した文章なので読みづらいです。あとでなおすつもりです
- 引数なしでは従来どおり GUI を起動します。`--help` と `--version` も使えます。
- `check` は exe のビルド時のコミットと GitHub の `cat2151/cat-plugin-player` の `main` を比較します。`up-to-date` は一致、`update available` は不一致です（コミットの新旧判定や未コミット変更の比較はしません）。確認できれば終了コードは 0、通信失敗などは 1 です。
- `update` は参照プロジェクトの clap-mml-render-tui と同じ `cat-self-update-lib` を使います。Windows では別コンソールで `cargo install --force --git https://github.com/cat2151/cat-plugin-player` を実行します。開始後、このコマンドは終了します。更新の成否は別コンソールで確認してください。
- 更新先は Cargo のインストール先（通常 `$CARGO_HOME/bin`、未設定なら `$HOME/.cargo/bin`）です。`target/release` にある exe は置き換えません。完了後はインストール先の `cat-plugin-player` を手動で起動します。
- 更新には Git、Rust/Cargo、`python`、CMake、Microsoft C++ Build Tools と UAPMD のソースが必要です。UAPMD の場所は環境変数 `UAPMD_DIR` → `%LOCALAPPDATA%\cat-plugin-player\config.toml` の `[build]` の `uapmd_dir` → この exe のビルド時の場所、の順で選びます。絶対パスに変換して更新用の Cargo に環境変数 `UAPMD_DIR` として渡します。UAPMD 自体は更新しません。
- config には次のように指定できます（パスは実際の checkout に置き換えてください）。相対パスの場合は config.toml のあるディレクトリを基準にします。GUI のセッション保存でも build 設定は保持します。

```toml
[build]
uapmd_dir = 'X:\projects\uapmd'
```

## 補足 ※AIが生成した文章なので読みづらいです。あとでなおすつもりです
- `cargo install --force --git https://github.com/cat2151/cat-plugin-player` を直接実行するときは config を読みません。PowerShell なら先に `$env:UAPMD_DIR = 'X:\projects\uapmd'` を設定してください。未設定時のビルドは Cargo が取得したパッケージの隣の `uapmd` を探すため、Cargo を実行するカレントディレクトリに UAPMD を置いても解決しません。
- インストール先でも起動できるよう、ビルドした shim DLL は exe に同梱します。GUI 起動時にユーザーのキャッシュディレクトリへ展開して読み込みます。`check` / `update` は GUI・音声・プラグインを起動しません。

# コンセプト、目指すもの
- 楽器
  - 例えばMIDI鍵盤のついたシンセサイザーは、電源を入れて鍵盤を押せば音が鳴ります。
    - そのレベルで手軽に使えることを目指します。
      - 音を鳴らすまでの操作を最小化します。
- 鳴ること
  - 「作者の環境で鳴ること」はできるだけ維持することを目指します
- すぐ鳴ること
  - アプリ起動から音が鳴るまで体感0.2秒。演奏までを最速にしています
    - GUI表示準備などの処理も、音の後にしています
      - GUI表示より先に音が鳴るのは、いわばスプラッシュスクリーンのサウンド版かもしれません
    - releaseビルドしたexeを直接実行する必要があります（cargo経由はtimestampチェックが、デバッグビルドはデバッグコードが、それぞれ起動時の待ち時間になるため）
- 教育用
  - 商業用よりは、教育用の方向を向いています
- 実験、探索、自分用
  - 頻繁に破壊的変更をします

# 思ったことを雑に書くコーナー

  - 再現可能であるから
  - freeにシェアされるおかげで、みんなが恩恵を受けられるから

  - オーディオプラグイン から PCキーボード までの各layerの総合である
    - 中間layerがある
      - それはプラグインホスト、演奏用UIである

# スコープ外、目指さないもの
- 堅牢さ
  - 何をしても絶対にバグらない。アプリが落ちない
  - 完全互換。あらゆる過去の設定やデータをloadして動作する
- 機能
  - あらゆる機能を搭載。あらゆる用途で利用可
- 利便性
  - 便利さ、使いやすさを極限まで追求
- 性能
  - あらゆる環境でCPU負荷なく高速に動作。音は絶対に途切れない
- 要望
  - ユーザーのあらゆる要望に即応
