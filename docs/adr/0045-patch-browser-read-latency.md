# ADR 0045: 音色切替で必要なメタデータと現在値の取得を分け、成立した音声経路を保存後も使う

- 状態: 採用
- 決定者: user（repl-plugin-player の evolve と比較して patch browser の切替待ちを短縮すること。AI が推奨したマクロ準備の全現在値取得削減・音声経路の二重構築解消・VALUES rescan の全件取得削減の3点を承認）。API の分離と補修の合成方法、他案を今回分ける技術的判断は AI の設計
- 関連: [ADR 0015](0015-random-patch-transaction.md)、[ADR 0037](0037-direct-parameter-automation.md)、[ADR 0039](0039-parameter-macro-sweep.md)、[repl ADR 0022](../../../repl-plugin-player/docs/adr/0022-parameter-value-sweeps.md)

## 判断の根拠

音色ファイルの読み取りより、main thread で繰り返す parameter の現在値取得が待ちを占めていた。
Six Sines の2,554件の値取得は1周約0.7秒で、マクロ準備は名前・適格性・範囲と宛先しか
使わないのに全現在値も読んでいた。さらに音色適用後に成立した voice を保存のために
破棄し、再開時に同じ経路とマクロを準備していた。48kHz・1024 frames・effect なしの
同一 instance のメモリ内計測では、これらの値取得と VALUES 通知が最初の信号までの
約2.85秒の大半を占めた。この数値はブラウザ操作からスピーカー出音までの測定ではない。
この処理単位の基準値だけでは実アプリの切替を証明できないため、画面なしの egui から
通常のブラウザ準備・適用・保存を通し、成立した processor をメモリ内で鳴らす検証を選んだ。
通常起動に計測を混ぜないため、この入口と区間計測はテスト時だけ有効にする。

repl は未公開の evolve instance にすべての rescan を無視する host を付けている。
当アプリにはマクロの宛先・範囲を読む者がいるため、同じ省略は使えない。一方、shim は
メタデータ変更を監視するが VALUES の全件値通知を消費しない。明示的な現在値取得は
その時点の plugin の値を返すので、値通知のためだけの総なめを維持する理由はない。

## 決定

マクロの binding 解決は現在値を持たないメタデータ専用 API を使う。既存の現在値取得 API
を別の意味に変えず、必要な読み手には新しい音色の current を返す。CLAP の値取得を
別 thread へ逃がさず、世代・メタデータ revision の不一致による binding 無効化も維持する。

VALUES の全件取得・通知だけを新しい依存補修で除き、ALL・INFO・TEXT の一覧再構築、
request_callback、flush は残す。既存補修の生成出力へ合成し、依存 checkout や既存補修を
書き換えない。上流・合成入力が変わったら停止する方針は ADR 0037 と同じである。
新しく値通知を消費する機能を導入する場合には、読む側の更新方法を決め直す必要がある。

音色適用と音声経路の成立を成功の境界とし、その経路を保存後も使う。保存は成功時の
owned state だけを書き、保存のための停止と再構築を除く。これは Surge が適用直後に
旧音色を save することへの ADR 0015 の保全策も守る。保存失敗は適用済みの音色を
取り消さず、失敗時の rollback・taint・旧音源保持は従来の境界に残す。

## 今回分けた案と残る費用

AI は、最初の3点が既存の準備・所有・保存方式のまま測定された重複を除けるため推奨した。
予備 instance pool は所有・破棄・メモリ量を変える。sforzando のテンプレート化は音源固有の
state 組立てを要し、Floe・Dexed の直接適用は準備済み state を受け渡す境界を変える。
これらを今回は分けたのは AI の範囲設定であり、user が恒久的な不採用を決定したものではない。
別 plugin の生成や一時 instance の費用がなお支配的なら、それぞれ独立に再検討できる。

発音待ちや Surge のゼロ待ち条件は、読み込み受付と新音色の反映完了の違いを守るため残す。
音量補正・自動 skip・演奏機能としての crossfade、新設定・UI・保存形式やビルド方式の変更は、
今回の重複削減に必要な根拠がないため含めない。通常起動へ事前 pool・全件列挙・計測を追加せず、
既存の効果順・bypass・再生状態・固定値解除・最新選択の規則を保つ。

VALUES の省略だけでは初回のメタデータ構築や plugin 自身の処理は消えない。repl の
未公開 graph・pool・fade と同じ数値や一律の ms 上限を保証しない。補修の条件・撤去判断と
native 検証方法は[補修の説明書](../../patches/uapmd/parameter-value-sweeps/README.md)に置く。

同条件のブラウザ要求を通した比較では、Six Sines の同一 instance の選択から保存完了までが
約2.3〜2.4秒から約0.07〜0.16秒へ短縮した（48kHz・1024 frames・INIT Sine / INIT EP、
effect なし、debug の Rust テストと Release shim）。初回はメタデータ準備が残る。
先頭には旧 voice のリリース音・残留 buffer があり得るため、最初の非ゼロ信号と
新音色の音声を区別する。A-B-A の音声対照で新音色と判定した block までの同条件比較は、
再利用時に約3秒から約0.10〜0.18秒となった。これは1024 frame 単位のメモリ内判定である。
Floe・Vaporizer2 は既存の発音待ちや plugin 自身の処理が支配的で、固定の待ちを含めた
処理単位計測では明瞭な短縮が出ていない。これを理由に発音待ちや loader を変更しない。
メモリ内の音声比較と保存復元は、実ウィンドウの OS イベント配送や実デバイスの聴感と
同じ証拠ではない。evolve の既存測定も pool・graph・fade・入力音符が異なり、数値の
直接比較には使わない。
