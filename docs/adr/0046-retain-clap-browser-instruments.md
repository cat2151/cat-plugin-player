# ADR 0046: R／Browse patchesで使用したCLAP主音源を各1台保持する

- 状態: 採用
- 決定者: user（Surge XTの往復時の待ちを優先し、Surge限定案から共通化しやすい全CLAP主音源の保持案を選択。最小構成Surgeの通常カタログ復帰には解放・再生成が必要な例外を確認）。所有と失敗時の境界はAIの設計
- 関連: [ADR 0045](0045-patch-browser-read-latency.md)、[ADR 0015](0015-random-patch-transaction.md)、[ADR 0034](0034-surge-xt-startup-minimal-data-home.md)

## 共通保持を選んだ理由

ADR 0045では、値取得の重複と保存のための経路再構築を、既存の所有方式のまま除いた。
instance poolは所有・破棄・メモリー量を変えるため別の判断に分けたが、恒久的な不採用にはしていなかった。
この削減後も、Surgeから別音源を経由して戻ると、主音源を作り直す費用が残った。
userはこの待ちの改善を優先し、Surgeだけの例外にするより、R／Browse patchesで使うCLAP主音源を共通に保持する案を選んだ。

生成のshim区間だけを比べた試作では、Surgeの生成が約665〜682ms、保持個体への復帰が約34〜40msだった。
この試作だけでは通常ブラウザの準備・適用・保存や新音色の発音を証明できないため、
同じブラウザworkerとtransaction、成立したprocessorを使うメモリ内比較を判断の裏付けにした。
破棄式を再現するテスト条件と保持式の比較では、Surge復帰の要求から保存完了までが約721〜738msから約62〜76msとなり、
保持式は同じIDへ戻って主音源の生成要求を出さなかった。Six Sinesも初回のメタデータ構築が残る一方、復帰時は既存個体を使えた。
比較はreleaseのRustテストとRelease shim、48kHz・1024 frames、初回選択後はbypassしたfixture effectを接続した条件による。
実デバイスの出音時刻やコールド起動の測定ではない。

## 所有と成功境界

一度使った対象だけを保持し、稼働主音源と接続effectの一覧から非稼働音源を分ける。
これにより、routing・Favorite選択・保存が保持個体を現在の音源と誤認しない。
保持前には既存のrenderer停止とnote-offを通し、editorを隠す。非稼働個体にはrendererや空回しを持たせず、
hostのmain-thread callbackは維持する。effect、VST3、準備workerの一時個体はこの保持の対象にしない。

復帰時にも今回選んだowned stateを適用し、現在のeffect列への経路成立を成功の境界とする。
旧音源を保持側へ移すのはその後とし、復帰に失敗した対象だけを破棄して旧経路とtransportを復旧する。
別音源のbackupを保持個体へrollbackすると、その個体だけでなく失敗判定や保存まで壊すため、
同一の稼働個体への適用失敗とは分ける。無傷の旧音源はtaintしない。
成功時はADR 0015／0045のowned state保存を維持し、保存目的のnative再取得や経路再構築を増やさない。

scanのindexはidentityに使わない。形式・plugin ID・bundle実体と更新情報・sample rate・生成に関係するdata homeが一致する個体だけを使う。
走査で消失・変更した個体や、復帰に失敗した個体は再利用しない。明示Load・Favoriteの従来生成と競合する保持個体は解放し、
それらの入口に保持からの再利用という意味を加えない。保存形式を変えず、終了時は稼働音源だけを保存する。
保持一覧を永続化しないため、次回起動で余分な音源を生成せず、起動前の事前pool準備も生じない。
終了時はrendererとprocessorを先に止め、hostが生存している間に保持native個体を解放する。

## メモリー費用と再生成の例外

正常な往復では各identityについて稼働・保持を合わせて1台とし、容量による追い出しや定期解放は設けない。
再生成待ちを避ける代わりに、使った音源のsample・内部thread・メモリーが終了まで残り得る。
音源以外のprocessorやUIを往復ごとに増やすことは、この費用には含めない。

ADR 0034の最小構成Surgeは、DLLが生存していると通常カタログへ戻れないという観測に基づく例外を持つ。
保持から戻っても最小構成フラグを保ち、Show UIで通常構成へ戻す際には該当する保持個体も旧DLLの生存原因にしない。
最新state・effect・演奏設定を保全して解放・再生成し、既存の1回限りの回復を維持する。
通常の音色往復で再利用できることを、あらゆる入口で破棄しない約束には広げない。

入力bytesの保存成功と、新音色の反映も分けて検証する。Surgeの非同期反映とSix Sinesのfactory schema正規化があるため、
音色名・正規化後の往復state・settle後の異なる音声特徴とその再現・再起動後の復元を照合する。
先頭の非ゼロbufferだけを新音色の証拠には使わない。メモリ内の機械検証と、実画面のメニュー・聴感による確認は別の証拠として扱う。
