# cat-plugin-player

A lightweight application that allows you to easily play audio plugins. It utilizes [UAPMD](https://github.com/atsushieno/uapmd) and is written in Rust.

# Past Challenges and What This App Solves
- Audio plugin sounds are fantastic!
- To play them, you often need to launch a DAW and perform various preparatory steps.
- Lightweight apps for easy playback sometimes required account registration for acquisition, or their operation felt "not for me."
- In the modern era, if you desire a certain UX, you can achieve it through vibecoding.
- So, I decided to do just that.

# Features
- Automatic Installation
  - If you haven't installed an audio plugin, the app will automatically install [Surge XT](https://surge-synthesizer.github.io/) as mentioned above.
- Detection
  - Upon launch, it automatically detects installed plugins.
- Playback
  - Clicking a plugin will load it and automatically start playback.
  - It can play chord progressions like `F-G-Em-Am` and MML (Music Macro Language) like `cde`.
- GUI
  - Pressing the `Show UI` button displays the plugin's GUI, allowing you to edit sounds and effects.
- Patches
  - Each plugin has a wide variety of preset patches. You can easily select them using a unique patch browser (supported by some plugins only).
  - For plugins not supported by the patch browser, you can select patches directly from the plugin's GUI.
- Effects
  - Each plugin has a wide variety of preset effects. You can easily select them using a unique effect browser (supported by some plugins only).
  - For plugins not supported by the effect browser, you can select effects directly from the plugin's GUI.

## Settings: Window Position and Size

You can specify the main window's startup position/size and plugin GUI placement method in `%LOCALAPPDATA%\cat-plugin-player\config.toml`. Please edit after exiting the application. Session and favorite selection states are saved in `status.json` in the same directory, and normal saves do not overwrite the TOML. If states are mixed in an old TOML, they are migrated on first startup, the original file is saved as `config.toml.before-status-migration.bak`, and only state items are removed. Settings comments, format, and unknown items are preserved, and independent comments attached to removed items are left at the end. If an existing `status.json` is present, it takes precedence.

```toml
[window.main]
x = 100.0
y = 100.0
width = 1200.0
height = 800.0

[window.plugin]
placement = "right_then_bottom_right"
```

`x` and `y` for the main window are logical coordinates and are used as the startup position if both are specified. If omitted, it defaults to the traditional initial position. `width` and `height` are the inner width and height (logical coordinates) of the main window. You can specify only one; if omitted or if values are 0 or less, or non-finite, it reverts to width 900, height 600. Changes are reflected on the next startup. The plugin placement method is currently only `right_then_bottom_right`, and omitting it results in the same behavior. GUI size and placement are calculated based on actual window frames, screen work area, and DPI. Automatic saving of positions moved manually for the main window or GUI, or per-plugin position specification, is not performed.

## For Developers

### Obtaining Offline WAV

`--render-wav` generates a new host and instrument for each call, loads the specified binary state, and obtains the initial sound (200ms) of note 48, velocity 100, CC1=0, then exits. It does not use GUI, audio device, external effects, or normal session restoration.

```powershell
& ./target/release/cat-plugin-player.exe --render-wav X:/measure/out.wav --plugin-format CLAP --plugin-id org.surge-synth-team.surge-xt --plugin-path 'C:/Program Files/Common Files/CLAP/Surge Synth Team/Surge XT.clap' --state-file X:/measure/state.bin --wait-ms 10
```

Format is `CLAP` or `VST3`; ID and path are specified to match the plugin that saved the state. Create the parent folder for the output first, and use a new name for the WAV that does not have an existing `.json` file with the same name. It does not modify input state, Favorites, History, or normal config/status/state.

Saves 9600 frames of 48kHz, 256 frames, stereo 32-bit float WAV from note on. `--wait-ms` is a non-negative integer audio sample time. During this time, it processes empty events and renders without syncing to real time, even after sounding. It does not add automatic waits from normal startup. The JSON records SHA-256 of state/PCM, plugin identification, wait, onset position・processed frames, silence judgment, and time taken for generation・state application・audio processing・saving. Time spent waiting for generation callback is a separate item. Recording all-zero samples results in `status=silent`, leaving WAV/JSON and exiting non-zero; load/processing errors also exit non-zero. PCM may not match across plugins even with the same input.

### Surge XT CLAP Initial Sound Delay Judgment Table

All catalog patches are measured once each under various conditions (new process, new instance) with high-speed offline measurement. It does not modify normal config/status/state, Favorites, or History. WAV, state, and logs remain in the measurement-dedicated run directory within the cache. The distribution JSON saves the start position・errors and 0ms adoption judgment for all patches.

```powershell
& ./target/release/cat-plugin-player.exe measure-surge-start-delay --output ../cat-music-patterns/surge-xt-start-delay.json
```

Default is 10ms vs 100ms, 200ms recording, and 0ms allowance for onset difference within 1ms. `--candidate-wait-ms 0` can change the comparison wait; `--reference-wait-ms`, `--max-onset-delta-ms`, `--onset-ratio` can change judgment conditions. 0ms allowance is an adoption policy and does not treat 10ms vs 100ms results as actual 0ms measurements. `--jobs` is the number of parallel jobs (default 4), `--timeout-seconds` is the upper limit for each render (default 30 seconds), `--limit` is for operation confirmation, `--work-dir` is the parent directory for saving measurement runs. Silent/errors are categorized separately and skipped.

If only changing thresholds, re-rendering is not needed. You can re-select, for example, with an allowance of 2ms, while retaining the original measurement conditions and values.

```powershell
& ./target/release/cat-plugin-player.exe measure-surge-start-delay --reclassify ../cat-music-patterns/surge-xt-start-delay.json --max-onset-delta-ms 2 --output X:/measure/reclassified.json
```

The output table is replaced only upon successful completion. Committing/pushing to cat-music-patterns is performed as a separate, explicit operation. It does not wait for communication completion on startup, and table updates do not resume playback. Refer to [Key Points of Measurement and Adoption Judgment (ADR 0008)](docs/adr/0008-surge-xt-automatic-note-start-delay.md).

### Startup Time Measurement

Specifying an output destination for `CAT_STARTUP_TRACE` records each point in the startup process to CSV. If not specified, it does not record and does not change startup order or auto-playback conditions.
Example of execution in the root of a Release-built repository:

```powershell
$env:CAT_STARTUP_TRACE = Join-Path (Get-Location) 'target/startup.csv'
try {
    & ./target/release/cat-plugin-player.exe
} finally {
    Remove-Item Env:CAT_STARTUP_TRACE
}
Get-Content ./target/startup.csv
```

Create the parent directory for the output beforehand. Files with the same name are overwritten.
Each measurement point is recorded only for the first time in the process, so restart the application for each comparison.

- The baseline is the `main()` entry point in Rust; it does not include time before process creation or OS DLL loading.
- `scan_callback` is when the scan completion notification reaches the main thread. `load_call_returned` and `instance_callback` separate the generation API call and completion notification, and `gui_requested` to `app_creation` is the GUI initialization section.
- `first_audio_callback` is the start of the audio callback, and `first_signal_rendered` is after processing the first block that generated samples with an absolute value exceeding 0.000001 (-120 dBFS). This is not the time sound is emitted from speakers.
- The audio thread only obtains timestamps and records them atomically; CSV saving is done on the UI side. Normally, it saves after the first signal generation and catalog preparation are complete. If incomplete, it saves partial results after 10 seconds of UI update, or upon normal termination. Saving may not be possible during UI freeze or forced termination.
- Unreached measurement points are shown under `# missing:`. Check the screen and standard error for failure details. Refer to [src/startup.rs](src/startup.rs) for measurement point definitions, and [ADR 0034](docs/adr/0034-surge-xt-startup-minimal-data-home.md) for startup acceleration judgment and limitations.

### Recording

When reproducing initial setup for introduction videos, use `cargo build --release --features recording-mode`.
For each launch, it creates an empty save destination under `%LOCALAPPDATA%\cat-plugin-player-recordings\`,
does not read/write normal settings/history, and only detects CLAP Surge XT / Surge XT Effects.
It does not reference the cmrt catalog and retrieves a new Surge-specific catalog.
It does not fake Surge XT absence; operations involve actual human or coding agent uninstallation before recording.
After recording, revert to the normal exe with `cargo build --release`.
Refer to [ADR 0026](docs/adr/0026-recording-mode.md) for scope and limitations.

# Concept, What We Aim For
- Instrument
  - For example, a synthesizer with a MIDI keyboard plays sound when powered on and a key is pressed.
    - We aim for this level of ease of use.
      - Minimize operations to produce sound.
- Sounding
  - Aim to maintain "it sounds on the author's environment" as much as possible.
- Immediate Sound
  - Perceived 0.2 seconds from app launch to sound. Fastest path to playback.
    - Processing like GUI display preparation is done after the sound.
      - Sound playing before the GUI appears might be like a sound version of a splash screen.
- Educational
  - Geared more towards educational use than commercial.
- Experimentation, Exploration, Personal Use
  - Frequent breaking changes will occur.
