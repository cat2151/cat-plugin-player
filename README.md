# cat-plugin-player

A lightweight app for easily playing audio plugins. It utilizes [UAPMD](https://github.com/atsushieno/uapmd) and is written in Rust.

# Past Challenges and What This App Solves
- Audio plugin sounds are amazing!
- Often, to play them, you need to launch a DAW and perform setup tasks.
- Lightweight apps for easy playback sometimes require account registration or have a UI/UX that isn't for me.
- In modern times, if you have a desired UX, you can achieve it through vibecoding.
- So, I decided to do just that.

# Features
- Detection
  - Upon launch, automatically detects installed plugins
- Playback
  - After loading a plugin by pressing the `Load` button, playback starts automatically
- GUI
  - You can display the plugin's GUI by pressing the `Show UI` button
- Tone color
  - To change the tone color, use the plugin's GUI

- Detection
  - If plugin detection is successful but no instrument is found, a prompt will appear to install the free Surge XT via winget. It also appears if only effects are present. The prompt will be in Japanese if Windows' display language is Japanese, otherwise in English. Even if you choose `Later`, it will appear every time the app launches until an instrument is available.
  - `View License Agreement` opens the Surge XT license (GPLv3) in a browser. Pressing `Agree to License and Install` executes winget and displays stages and elapsed seconds: "1/4 Preparing", "2/4 Downloading", "3/4 Installing", "4/4 Loading". If a Windows confirmation screen (User Account Control) appears at 3/4, please select "Yes". Upon success, it automatically rescans the plugin list, loads Surge XT (CLAP), and starts playback, similar to `Load`. Previous instrument/effect restoration is not performed at this time. Even if you close the prompt, the installation continues, followed by rescanning and loading upon completion.
  - If winget is not available or installation fails, the winget message and manual download link are displayed and logged to `error.log`. Only Surge XT is included, and the download progress is not displayed. The reason for this choice is documented in [ADR 0024](docs/adr/0024-offer-surge-xt-via-winget.md).
- GUI
  - When the GUI is opened for the first time, it waits 2 seconds for rendering, automatically takes a screenshot, and scales it down to a PNG image that fits the list display frame and screen magnification, preserving the aspect ratio. It is saved in `%LOCALAPPDATA%\cat-plugin-player\plugin-icons\`, and plugins with matching names + manufacturers (ignoring leading/trailing spaces and case) share the same image across VST3 / CLAP. If the name or manufacturer is missing, it is distinguished by format + ID.
  - Previously saved format-specific images are also automatically migrated from list/favorite identification information to shared images and used. Tone color state and favorite load destinations are still distinguished by format + ID.
  - Plugin images are displayed in Plugins / Favorites / Routing. Within the row, they are scaled down to fit the button height while maintaining the aspect ratio. Hovering over an image allows viewing it at its saved size. Plugins with no GUI displayed show a temporary icon of the same height.
  - The GUI prioritizes placement to the immediate right of the main window, aligned with its top edge, within the screen's working area. If it doesn't fit, it's placed in the bottom-right of the main window's screen working area. Placement occurs upon display and GUI resizing, but it does not constantly follow the main window's movement. The GUI is not scaled down; if its width is greater than the screen, its left edge aligns with the working area; if its height is greater, its top edge aligns.
  - For blank images or failed captures, retries occur at 1-second intervals for up to 20 seconds from GUI display. Saved blank images are also treated as not captured, and opening the GUI replaces them with valid images. No re-capturing occurs after success.
  - If capturing fails after retries, an error is displayed. Opening the GUI again will retry. GUIs that do not support capture remain with a temporary icon. To recapture or if a saved PNG is corrupted, delete the shared PNG and any remaining old format-specific PNGs for that plugin, restart the app, and open the GUI (old PNGs are retained during migration).
- Playback
  - The last played instrument, connected effects, Bypass state, and playback pattern are saved to `%LOCALAPPDATA%\cat-plugin-player\status.json` and restored on the next launch. Stop state, selected playback pattern during stop, and confirmed MML/chord text are also restored. Unconfirmed edits are not saved.
  - CLAP Note On/Off is sent according to the plugin's supported input format. This includes sforzando CLAP, which only accepts MIDI. The scope of the fix and verification records are documented in [CLAP Note Format Description](patches/uapmd/clap-note-dialect/README.md).
  - In the top-left `Sequence` pane, you can select the playback type using the left/right arrows or the dropdown. The arrows cycle at both ends of the types and do not include stop. Switching during playback releases all notes in the current phrase and starts from the beginning of the new phrase. When stopped, selecting a type does not play; use `Play` to start and `Stop` to stop. You can also toggle start/stop with the `Space` key in the main window (except when typing text). Playback pattern selection including MML/chords and stop state are restored on the next launch.
  - To audition MML/chord progressions, open the input screen with the `i` key or the `Chord` button in `Sequence` (hover to see shortcuts and input methods). An example of a single note is `t120 c8r8d4e4r4`; an example of a chord progression is `C F G C`. Both are accepted in the same input field, with chord notation conversion attempted first. Uppercase `C` becomes a chord, lowercase `ceg` becomes MML.
  - Input is confirmed with `Enter`/`Confirm` and canceled with `Esc`/`Cancel`. Cancellation or conversion errors retain the previous valid phrase. `Space` and `i` within the input screen are used for text input, and `Space` for play/stop does not work.
  - Confirmed phrases loop playback with `Play`/`Stop`. Rests, note lengths, tempo changes, chords, and trailing rests are preserved. Opening the input screen pauses normal overall playback. If playing immediately before opening, after confirmation, the new phrase plays from the start; after cancellation, the original playback pattern resumes from the start. If opened while stopped, it remains stopped after confirmation/cancellation, and `Play` starts overall playback. You can also switch to normal playback patterns. The text, selection, and playback state are saved immediately after confirmation; the restored playback state is also saved on cancellation. These are restored on the next launch or from instrument favorites/History. Unconfirmed text is not saved; cancellation or conversion failure retains the last confirmed text.
  - Changing input or moving the cursor auditions the single note/chord at that position once. This also applies to mid-edit and pasting. Moving within the same articulation unit or redrawing alone does not re-trigger sound. Previous tempo, octave, and note length are reflected, and no sound is produced at rest or command positions. Normal playback stops when editing is opened, and overall playback does not resume after the audition sound ends. The audition sound is also released upon the next articulation unit, cancellation, confirmation, or instrument change. Auditioning does not alter the confirmed text or normal selection.
  - For confirmed MML loop playback, the `Velocity` field setting takes precedence over any specified velocity in the input. CC1 can also be controlled from the `CC1 modulation` field. If the event capacity is reached with very dense phrases, sounding notes are released, and new notes are stopped. You can restart with `Stop` → `Play`.
  - When changing patches via app Favorites/History, Browse patches/Random patch/Random effect/Browse effects, the stop/play state is maintained. During playback, it starts from the beginning of the phrase and does not carry over mid-phrase waits from the previous phrase. Initial rests specified in MML are preserved. While the patch browser/effect browser is open, `Space` for play/stop and MML input initiation in the background are suppressed. Tone color changes made through the plugin's own GUI are not detected.
  - For Six Sines/TyrellN6 CLAP, when audio processing is rebuilt due to loading, state restoration, or connection changes, it waits for the first phrase to start while continuing normal audio processing to preserve the initial sound. At 48kHz, the wait is about 21ms for Six Sines and about 85ms for TyrellN6. MML's initial rests are added further. See [ADR 0019](docs/adr/0019-random-patch-all-catalog.md) for application conditions and actual device verification.
  - In the `Velocity` field below the playback pattern, you can select `100`, `127`, `40-100`, `80-127` using the same left/right arrows or dropdown. The initial value is 100. Range specification increases values in Note On order within the phrase and then decreases them in the next loop, repeating this action. Changes are reflected from the next note without restarting the phrase and are restored on the next launch.
  - In the `CC1 modulation` field, you can select `0`, `127`, `sweep` using the left/right arrows or dropdown. The initial value is 0. `sweep` repeatedly changes from 0 to 127 in 2 seconds, then from 127 to 0 in the next 2 seconds. The selection is restored on the next launch.
  - Guitar open strings send MIDI note numbers 40, 45, 50, 55, 59, 64 (E, A, D, G, B, E) sequentially at 125ms intervals. 2 seconds after the last Note On, all 6 notes are simultaneously Note Off, and this repeats after 0.5 seconds.
  - The state is remembered upon successful `Load`, and when selecting/starting/stopping `Sequence` types. The memory persists even after stopping or `Remove`. Older history/favorites are restored with the conventional 4-note pattern.
  - Upon termination and `Remove`, the binary state of tone color/parameters etc. published by the plugin via the UAPMD state API is saved to `%LOCALAPPDATA%\cat-plugin-player\states\` per plugin. On the next launch or when reloading the same plugin, it is restored before playback begins.
  - `Load` of an instrument only replaces the sound source, maintaining connected effects and settings. It saves the state of the plugin being replaced and switches after successfully creating, restoring, and connecting the new plugin. If it fails, the original configuration is maintained, and an error is displayed.
  - The scope of state saving depends on the plugin and UAPMD's format-specific implementation. It also requests UI state, but the current UAPMD VST3 implementation only retrieves component state. It does not include replication of external samples or saving upon forced termination.
  - On startup, the previous instrument and effect are loaded directly, their state restored, and playback begins. The GUI is then initialized, and the list is scanned in the background.
  - If direct loading fails due to old history or file movement, it is restored from the scan results after the GUI appears. Old history is updated once played.
  - If the main sound source is CLAP Floe, when audio processing is rebuilt during loading or tone color restoration, the start of the first phrase is delayed by 100ms. MML's initial rests are added further. This is a provisional measure for observing symptoms of disappearing initial sounds, and its resolution on actual devices is unconfirmed. See [ADR 0018](docs/adr/0018-floe-automatic-note-start-delay.md) for application conditions and review policy.
  - Refer to [docs/startup-timing.md](docs/startup-timing.md) for startup time measurement methods and results.
- Effect Routing
  - The connection is a series: one instrument → multiple effects → output. After loading an instrument, press `Load` for the first effect, then `Add` to append subsequent effects to the end. `Remove` on a connected effect removes only that one. Duplicate connections of effects with the same format + ID are not allowed.
  - `Random effect` next to `Sequence` randomly selects a preset from installed CLAP effects, using the same catalog and selection targets as cmrt's effect selector. If there are 0 effects, it adds the first one; if 1, it replaces that effect; if multiple, it replaces one of the connected effects, chosen evenly. Repeated presses do not increase the number of effects, and the order, settings, and Bypass state of other effects are maintained. To avoid duplicate connections, effects with format + ID already connected (other than the replacement target) are excluded from candidates. If no suitable candidate is available for the target slot, it displays a reason and does not change.
  - Random effect requires an instrument. Candidates are obtained from default effect/preset locations scanned by the play-server shared core; no VST3 substitution is made. During preparation, the current playback continues, and loading, scanning, and patch operations are disabled. If stopped, it remains stopped; if playing, it restarts the current phrase from the beginning, maintaining overall MML/Velocity/CC1 selections. If generation, application, or connection fails, it reverts to the original configuration; no automatic selection of alternative candidates occurs. Upon success, the applied state and connection are saved for the next launch, and Favorites/History are not added. Save failures are displayed as applied.
  - Below `Random effect`, `Browse effects` or the `E`/`X` key opens a separate maximized effect browser window, allowing you to select presets from a list. It cannot be opened while editing MML. Filtering is done by Category→Kind on the left and search. Classification and selection targets are the same as cmrt's effect selector. Search uses case-insensitive regular expressions, space for AND, `-condition` for exclusion, applying to preset name, Category, Kind, or effect name (e.g., `hall -plate`, `dragonfly`). Invalid regex during input displays an error and retains the previous list. The top row contains Search, Target frame, and `Random`. The `/` key within the browser moves input to the search field. `R` randomly selects from filtered results. Multiple column display, navigation with arrow keys / `h` / `j` / `k` / `l` / number prefixes / `PageUp` / `PageDown`, and closing with `Enter` / `Esc` are the same as Browse patches. In results with mixed effects, effect names are appended, and if Kind differs, preset names are color-coded by Kind.
  - The target frame is chosen from `Add new effect` or `Replace n` of a connected effect. When opened, it defaults to the frame last written to by this browser, otherwise the last effect, or `Add new effect` if no effects are present. Applying with `Add new effect` makes the added effect the target, and subsequent selections replace that frame, so the number of effects does not increase even if you keep selecting. If the target frame is removed, the last effect becomes the target. Presets for effects connected to frames other than the target are displayed in gray, and selecting them shows a reason and does not change. Presets added to the target frame by this browser are marked with `▶`, and opening the browser selects them (no re-application).
  - Clicking, key movement, or filtering to another candidate immediately requests application. Simply opening does not change the effect. You can select the next even during preparation; unstarted selections are replaced by the latest one, and closing cancels them. An instrument is required, and ongoing playback during preparation, recovery on failure, and saving for the next launch are the same as Random effect. Category, Kind, search string, list selection position, and target frame are saved upon exit and restored on the next launch. Key movement starts from the restored selection. Category/Kind are restored by name; if missing, they revert to `ALL` in that field. Selection is restored by preset; if missing from the catalog, it becomes unselected, and key movement starts from the top. The target frame is restored by its position in the chain; if no effect exists at that position, it defaults to the default frame when opened.
  - `Routing` displays the connection order. You can change the order by dragging the `↕` button of an effect up or down. During drag, the moving effect name and insertion line are displayed. Instruments are not subject to reordering. You can edit tone colors and effects with `Show UI` for each plugin. `Instrument` / `Effect` are displayed with the same type color as the left list.
  - Removing all effects reverts to a direct connection from the instrument to the output. `Bypass effect` targets the entire chain, allowing it to pass through while retaining instance and settings. It can also be toggled with the `b` key (does not work in MML input screen, Browse patches/Browse effects display, or while typing text). When bypassed, connected effects in Routing are displayed in gray, with `Bypassed` appended.
  - `Sequence` is for instruments. Stopping the sequence continues audio processing to produce effect reverberations.
  - On the next launch, the instrument, the order of all effects, their respective states, and Bypass status are restored before playback. History of one old format effect can also be loaded. If effect restoration fails, an error is displayed, it reverts to a direct instrument connection, and the saved configuration is retained.
  - Additions, removals, and reordering are saved only if the new connection is successfully prepared. If it fails, the original configuration and playback are restored, and an error is displayed.
  - Supports mono/stereo for main input/output. Mono → stereo is duplication; stereo → mono is the average of left/right. Auxiliary inputs are silent.
  - Changing connections or Bypass may cause short audio dropouts, and sounding notes and reverberations may be interrupted. Sidechain, parallel connections, and host-side Dry/Wet are not supported.
- Tone color
  - `Browse patches` near `Random patch` or the `T` key opens a separate maximized patch browser window on the same screen as the main app. It does not change the main app's position or size. It cannot be opened while editing MML. Filtering is done by framed Role→Preset→Search, and the left condition area and right Patches list are individually scrollable. The list uses the remaining width and height, allowing operation even when unmaximized or in a narrow window. The top row contains Search, `Solo/Mute`, `Random`, and `☰`. The search field uses the remaining width, and the `/` key within the browser can move input to the search field. Details of instrument conditions can be found by hovering over `Solo/Mute`. Clicking this entire button or the `M` key within the browser opens a vertically stacked Solo/Mute overlay; `OK` or `Enter` confirms them all. Solo/Mute are stacked immediately to the right of the instrument name. Clicking the selected mode again reverts to normal; `Esc`/clicking outside the overlay discards changes. Multiple Solos are treated as OR, Mutes as exclusions. Search uses case-insensitive regular expressions, space for AND, `-condition` for exclusion, and `plugin:` condition (e.g., `pad -bright`, `plugin:floe`, `plugin:surgext -bass`). Aliases of merged patches can also be searched. Invalid regex causes an error and stops application, random selection, and condition saving. If 0 results, review conditions by editing the search field or changing Role/Preset. Catalog loading wait/failure is displayed separately from 0 results. Role, Preset, and search string are saved upon exit and restored on the next launch. Presets are restored by name; if the condition is deleted, it reverts to `ALL` for that Role.
  - The list displays single-line patch name cells without wrapping, arranged in multiple columns (left→right→next row) depending on width. In a narrow window, it reverts to a single column. Resizing maintains the selected patch; changing only the number of columns does not reload. Clicking a patch does not move the list's display position. Up/down/left/right arrow keys or `h`/`j`/`k`/`l` move as they appear visually. Left/right moves to the previous/next patch (to the end of the adjacent row at row edges); up/down moves to the row above/below, moving to the end of a short final row if no patch is directly below. Typing a number first, like `2j` or `10k` (vim-style), moves that many times (stops at edges; other keys cancel the number). `PageUp`/`PageDown` moves 10 times up/down, and when combined with a number, moves by that multiple. Key movement, Random, filtering, and column count changes scroll to make the selected row visible only if it's off-screen. If all patches fit, it does not scroll. For single instrument results, the instrument name is omitted; for mixed results, instrument names are retained. Text color indicates only one difference in the results. If instruments are mixed, the instrument name part is color-coded per instrument. For a single instrument, if Preset is `ALL`, the patch name is color-coded per relevant Preset; if that doesn't distinguish, it's color-coded per category. Colors are Monokai-based. If all are the same, it's normal text color. Colors cycle through 5, so distant groups might have the same color. Pink-colored patches prioritize "pink" in their name. Classification folders, etc., are omitted, and if same-named patches need distinction, necessary paths are retained. Dexed's program specification is maintained. Hovering over shows the full display path, original application path, active categories, and merged count if 2+. Load/Size are not always in the list, and `no category`/`1 merged` are not displayed. Normal patches immediately request application when selection changes via mouse click/key movement, and the same behavior occurs when a different candidate is chosen by condition change. Simply opening does not change the patch. When opened, if the currently playing patch (applied by Browse patches/Random patch) is in the current results, that patch is selected and scrolled into view (no re-application). The playing patch is saved at exit and inherited as the restored patch on the next launch. Add/delete/Random effect maintains this inheritance. If the playing patch is not in the results or unknown, the selection from the last close is maintained (unselected when first opened after launch). After changing patches via Favorites/History, or instrument load/delete, the playing patch is unknown, and selection is cleared. Key movement starts from the selection when opened; if unselected, it moves to the top. The next selection can be made even during preparation; unstarted requests are replaced by the latest one. Upon successful normal application, no duplicate patch names or fixed whitespace are displayed at the bottom. A short guide is shown only if the selected and applied patches differ, indicating that the previous patch might continue playing for unconfirmed pink patches, etc. Pink Space prompt and application failure/save errors are displayed.
  - Pink-colored patches with a sample capacity of 64,000,000 bytes or more are not applied automatically (unknown capacity is treated as normal). After selection, `Space` opens a confirmation overlay for instrument, patch, and capacity, and pressing `Enter` within it starts preparation/application. `Esc` during confirmation cancels without changes. Once applied, patches still require re-confirmation. During loading, a progress overlay is shown, and cancellation mid-process is not possible. `Space`/`Enter` in the search field, save menu, or Solo/Mute overlay are not used for patch application (`Enter` in Solo/Mute overlay is the same as `OK`).
  - `Random` or the `R` key within the browser selects evenly from the displayed results. While typing text, `T`/`R`/`M`/`/`/`h`/`j`/`k`/`l`/numbers/`Enter` shortcuts do not work, and `R`/`M` do not work while overlays/save menu are displayed within the browser. For pink patches, only selection is made; the same Space → Enter confirmation is required. The outer Random patch randomly selects evenly from all available patches as usual. `Esc`/`Enter` or OS close of the browser window closes only the browser, retaining the main app and the last successfully applied patch, discarding unstarted requests and old preparation results. Already initiated processes are completed. When the confirmation overlay, Solo/Mute, or save menu are open, `Esc`/clicking outside the overlay closes only the child, not passing the same input to the browser or background operations. OS close closes the entire browser. It can be reopened, and there is no undo operation to revert to the original patch.
  - Search conditions can be added to Role via `Save condition to Role` in the hamburger `☰` menu and deleted via `Delete` in Preset. The addition target from ALL is Etc. They are handled by common selector normalization/classification rules and saved to `patch-filter-presets.json` in cat's config directory. If loading is corrupted, the original file is protected, writing is stopped, and save failures are displayed on screen. Role/Preset/Search/Solo/Mute are retained during the same app launch, but only saved custom conditions are restored after restart. TUI conditions and Favorites are not shared or migrated.
  - Browse patches uses the same catalog, supported CLAP instruments, state application, and failure recovery as Random patch. It maintains overall MML/Velocity/CC1 selections, and effect order/state/Bypass, saving the applied state for the next launch upon success. Favorites/History are not automatically added. Application success and save failure are displayed separately. Preparation/application progress is updated even when the child window is in focus.
  - `Random patch` in `Sequence` randomly selects evenly from all patches that match installed instruments and format+ID from Surge XT, Dexed, Floe, sforzando, Six Sines, TyrellN6, and Vaporizer2 CLAP patches in the existing cmrt catalog. It's not an even selection per instrument; Dexed, having more candidates, will be selected more frequently. The tooltip displays the target instruments and total number of candidates. If no suitable candidates, the button is not displayed.
  - The Random patch catalog uses the existing `%LOCALAPPDATA%\clap-mml-render-tui\patch-catalog\catalog.json` in read-only mode. Random patch does not substitute VST3, randomly select effect patches, or target unknown instruments. For effect preset selection, use Random effect/Browse effects in the effect routing section. Dexed retains program specifications within its cartridge. Floe/sforzando external samples are needed in their original locations; there is no function to duplicate/save samples.
  - In environments without cmrt and thus without `catalog.json`, Surge XT patch list is retrieved from [cat-music-patterns](https://github.com/cat2151/cat-music-patterns) on each launch, saved to `%LOCALAPPDATA%\cat-plugin-player\patch-catalog\surge-xt.json`, and used as candidates for Browse patches/Random patch. If retrieval fails, the previously saved list is used; if that's also unavailable, Random patch is not displayed. A loading wait message is shown until retrieval completes (max 10 seconds). The list was created from Surge XT 1.3.4; Surge XT of different versions may not show added patches, and selecting a missing patch displays a preparation failure. If `catalog.json` exists but cannot be read, it does not switch. The reason is documented in [ADR 0025](docs/adr/0025-surge-xt-patch-catalog-without-cmrt.md).
  - During Random patch preparation, the current playback continues, and conflicting load, scan, and patch operations are disabled. There may be a wait for sample loading for Floe, etc. If stopped, it remains stopped after application; if playing, it restarts from the beginning of the current phrase. Overall MML/Velocity/CC1 selections and effect order/state/Bypass are maintained. Upon success, the applied state is saved for the next launch, and Random patch itself does not add to Favorites/History.
  - If preparation/application fails, the reason is displayed, and no alternative patch is automatically selected. The original configuration, state, and playback state are restored, and instances where state restoration fails prevent saving. Save failures after patch application are displayed as applied. Instrument-specific preparation/reflection conditions and verification scope are documented in [ADR 0019](docs/adr/0019-random-patch-all-catalog.md).
  - `★ Add favorite` for each plugin allows saving multiple tone colors/settings as favorites at that moment. For instruments, playback patterns, stopped selections, and confirmed MML/chord text are also saved. For effects, playback settings are not saved. Names are automatically generated and can be changed later.
  - Loading a different plugin automatically records the replacing plugin's tone color/settings/playback pattern to History before switching. The name is `Plugin Name Sequence Number`. It is not added for reloading the same plugin or restoration on launch. Confirmed MML/chord text and stopped selections for instruments are also recorded within the same scope as favorites. For effects, playback settings are not recorded. If saving fails, the switch is aborted.
  - During manual/auto saving, it checks for duplicates of the same plugin, role, playback pattern, confirmed MML text, and state, and reuses existing items and names. For History's automatic recording, only stop differences are treated as identical, but MML with different text is kept as separate items. Effects do not compare playback settings.
  - In [Plugin-specific processing policy/list (ADR 0002)](docs/adr/0002-plugin-specific-favorite-state-comparison.md), you can check product-specific exceptions, reasons, scope, and limitations. For the confirmed state format of TyrellN6 CLAP, compressed parts that change only with playback are excluded from duplicate judgment, and patches with the same text-based tone settings are grouped. Confirmed PCore `UI_op=9/10` and empty lines at the end of text are also excluded from comparison ([ADR 0011](docs/adr/0011-tyrell-n6-ui-operation-favorite-comparison.md)).   - Switch lists with the central `Favorites` / `History` / `Plugins` tabs. Favorites maintain manual order; new additions are placed at the top. Calling, resaving, or recording to History does not change the order. You can filter by favorite name, plugin name, and format.

  - Favorites are displayed one item per line. Long names/supplementary information are abbreviated, and the full text can be viewed by hovering. Waveform/spectrum are displayed below Routing on the right; the right-side width can be adjusted by dragging the border. `Audio analysis`'s `On right` toggles analysis display between bottom-right/bottom of screen (bottom-right on startup).
  - For the confirmed state format of sforzando CLAP, duplicate patches are not created solely based on differences in save counters and MIDI note/CC1 performance values; existing favorites are reused. Differences in patch settings are retained. See [ADR 0006](docs/adr/0006-sforzando-favorite-state-comparison.md) for application scope and limitations.
  - A colored `Instrument` / `Effect` is displayed to the left of each row. Clicking a favorite name restores its tone color/settings. For instrument favorites, the saved confirmed text and playback pattern selection are restored. If stopped, it remains stopped; `Play` plays the restored phrase. If playing, it switches to the saved pattern/MML. Favorites from the old format without text retain the current text; old format stop items maintain the current selection. If conversion or state loading/connection fails, the original text/selection/playback state is restored, and the failed content is not saved to the session. Instrument favorites retain connected effects; effect favorites retain the instrument and MML. An instrument is required to call an effect.
  - Connected effect favorites display `Connected - click again to remove`, and re-clicking the name removes that effect. This behavior is the same after editing settings post-call or during Bypass. The instrument, other effects, and saved favorites remain. A different patch with the same format + ID switches settings at the current position; unconnected effects are appended to the end. Selected favorites for each effect are also restored on the next launch.
  - Rename/Delete can be performed from `…` at the end of the row. Edits after calling or traditional auto-saves do not overwrite favorites. `Last favorite` indicates the last saved/called favorite.
  - Favorites are saved to `%LOCALAPPDATA%\cat-plugin-player\favorites\`. Short audio dropouts may occur during saving/restoring, and the savable range is the same as traditional state saving.
- Lissajous Display
  - `Lissajous` is displayed below the oscilloscope in the right analysis panel. If `☰` → `On right` in the oscilloscope is unchecked, spectrum, oscilloscope, and Lissajous appear side-by-side at the bottom of the screen.
  - A 45° rotated Lissajous curve draws the output of the most recent 50ms (max 4096 samples), reflecting effects and Bypass. A common automatic magnification preserves volume differences and aspect ratio; same-level in-phase results in a vertical line, out-of-phase in a horizontal line, and sine waves with phase difference in ellipses or circles. Left-only output results in a top-left to bottom-right diagonal line, right-only output in a top-right to bottom-left diagonal line, mono in a vertical line, and silence in a central dot.
  - It updates independently of notes, period counts, or trigger settings, and `Show analysis labels` displays headings. Axis and drawing methods can also be checked in the graph's tooltip.
  - `Correlation` directly below Lissajous displays the correlation between left and right channels for the most recent 150ms as a bar and numerical value from -1 to +1. +1 is in-phase, near 0 indicates weak correlation, and -1 is out-of-phase. Negative values are displayed in red, serving as a guideline for cancellation when mixed to mono. If silent or one side is silent, it displays "—".
- Waveform Display
  - The `Oscilloscope` at the bottom of the screen displays L (green) and R (blue) outputs, reflecting effects and Bypass, overlaid. Mono displays the same waveform for both.
  - The display width is determined from the last Note On MIDI note number (A4 = 440Hz), and `1`, `2`, `4`, `8 cycles` can be selected. After Note Off, the reverberation is displayed based on the last note. Output containing chords or detuning may not repeat perfectly within that width.
  - `Zero cross` aligns to the negative→positive crossing of the left channel. If the left channel is silent, the right channel is used; if no crossing, it displays from the beginning.
  - `Similarity` sweeps one sample at a time from the buffer start for the display width, finding the position with the maximum correlation coefficient to the previous display. In case of a tie, the earlier position is adopted, and the same starting position is used for both left and right. For the first display or if the comparison target is silent, zero cross is used.
  - The comparison history is reset when a note sounds, the playback pattern changes, the number of display cycles changes, the trigger method changes, or the audio stream changes. A waiting display is shown until sufficient data is collected.
  - Exploration is performed on a separate thread from audio processing. Display updates may be slow for low notes or many cycles. If display data is interrupted, the history is reset.
  - The default display setting on startup is 4 cycles and zero cross. Display settings are not saved.

## Window Position & Size Settings

In `%LOCALAPPDATA%\cat-plugin-player\config.toml`, you can specify the main window's launch position/size and the plugin GUI's placement method. Please edit it after closing the app. Session and favorite selection states are saved in `status.json` in the same directory, and normal saves do not overwrite the TOML. If the old TOML has mixed states, they are migrated on first launch, with the original file saved as `config.toml.before-status-migration.bak` and only status items removed. Configuration comments, format, and unknown items are preserved, and independent comments attached to removed items remain at the end. If an existing `status.json` is present, it takes precedence.

```toml
[window.main]
x = 100.0
y = 100.0
width = 1200.0
height = 800.0

[window.plugin]
placement = "right_then_bottom_right"
```

The main window's `x` and `y` are logical coordinates and are used as the launch position if both are specified. If omitted, it defaults to the conventional initial position. `width` and `height` are the inner width and height (logical coordinates) of the main window. You can specify only one; if omitted or if the value is 0 or less/non-finite, it reverts to 900 width and 600 height. Changes are reflected on the next launch. The plugin placement method is currently `right_then_bottom_right` only, and the behavior is the same if omitted. GUI size and placement are calculated based on the actual window frame, screen working area, and DPI. Automatic saving of positions moved manually for the main window or GUI, or plugin-specific position settings, are not implemented.

## Local Build and Execution

Clone this app, `uapmd`, `clap-mml-render-tui`, and `clap-mml-play-server` into the same parent directory, then run from this app's directory. TUI's `app` / `patches` / `patch-select` / `tui-core` and play-server's `core-lib` / `server-config` are always referenced locally from Cargo.toml. Play-server requires `prepare_catalog_clap_patch_state` / `supports_catalog_clap_plugin` in addition to the traditional `prepare_clap_patch_state` / `PatchStateError`, and TUI's `cmrt-patches` needs their re-export. The patch browser uses the public Role/Preset/filter API and tui-core's sample capacity determination. Random effect and Browse effects use play-server's `AudioEffectCatalog` / `EffectRenderer` and TUI's effect selector's selection conditions; Browse effects' search uses tui-core's search conditions. Insufficient checkout or API will result in a build error, and there is no automatic switch to the Git version.

```powershell
cargo build --release
& ./target/release/cat-plugin-player.exe
```

If UAPMD is not in the sibling `uapmd` directory, first set `$env:UAPMD_DIR = 'X:\projects\uapmd'`. The location of UAPMD during build is specified via an environment variable. `config.toml` is not read as a build setting.

Do not use `cargo install`; directly run the .exe generated in the default `target/release`. The build uses local code (including uncommitted changes) and existing `target/shim`, but source changes may require reconstruction and rebuild. If `target/shim` was created with a different version like VS 2022, it will continue to build with that version, so please delete `target/shim` before building ([ADR 0020](docs/adr/0020-visual-studio-2026-toolchain.md)). The shim DLL is bundled with the exe, extracted to the cache directory, and loaded upon GUI launch.

Refer to [ADR 0012](docs/adr/0012-local-dependencies-and-release-execution.md) for the 3-repo dependency configuration and operation policy. For cat's build, local switching of TUI is not required. If TUI itself is cross-built, use TUI's existing `python scripts/cross_repo_local.py on` procedure; 'off' is handled manually. Local references use uncommitted changes, and Cargo.lock does not fix the content of each checkout. When verifying, record the HEAD and diffs of each repo.

Launch the GUI without arguments. `--help` and `--version` are also available.

# Concept, What We Aim For
- Musical Instrument
  - For example, a synthesizer with a MIDI keyboard plays sound as soon as you power it on and press a key.
    - We aim for that level of ease of use.
      - Minimize operations required to produce sound.
- Sound Production
  - We aim to maintain "it plays in the author's environment" as much as possible.
- Instant Sound
  - Perceived 0.2 seconds from app launch to sound. Playback is made as fast as possible.
    - Processes like GUI display preparation are performed after the sound.
      - Sound playing before the GUI appears might be considered a "sound splash screen."
    - You need to directly run the release-built .exe (running via cargo involves timestamp checks, and debug builds include debug code, both of which add to startup latency).
- Educational Use
  - It is oriented more towards educational use than commercial.
- Experimentation, Exploration, Personal Use
  - Frequent breaking changes will occur.
