# cat-plugin-player

A lightweight app for easily playing audio plugins. It utilizes [UAPMD](https://github.com/atsushieno/uapmd) and is written in Rust.

# Previous Challenges and What This App Solves
- Audio plugin patches sound amazing!
- To play them, it often requires launching a DAW and performing preliminary setup for playback.
- Lightweight apps for easy playback sometimes require account registration for acquisition or have a workflow that's "not for me."
- Nowadays, if you have a desired UX, you can achieve it through vibe coding.
- So, we decided to do just that.

# Features
- Detection
  - Upon launch, it automatically detects installed plugins.
- Playback
  - Pressing the `Load` button automatically starts playback after the plugin is loaded.
- GUI
  - You can display the plugin's GUI by pressing the `Show UI` button.
- Patches
  - To change patches, use the plugin's GUI.

- Detection
  - If plugin detection succeeds but no instrument is found, it displays a guide to install the free Surge XT via winget. It also displays this if only effects are found. If Windows display language is Japanese, it shows in Japanese; otherwise, in English. Even if `Later` is chosen, it will display every launch as long as no instrument is found.
  - `View Terms of Service` opens Surge XT's terms of service (GPLv3) in a browser. Pressing `Agree to Terms and Install` executes winget and shows stages like "1/4 Preparing", "2/4 Downloading", "3/4 Installing", "4/4 Loading" with elapsed seconds. If Windows User Account Control appears at 3/4, select "Yes." On success, it automatically re-scans the plugin list, loads Surge XT (CLAP), and starts playback like `Load`. In this case, previous instrument/effect restoration is not performed. Even if the prompt is closed, installation continues, followed by re-scan and loading upon completion.
  - If winget is not present or installation fails, it displays winget's message and manual download links, and logs it to `error.log`. Only Surge XT is included, and download progress is not shown. The reason for this choice is in [ADR 0024](docs/adr/0024-offer-surge-xt-via-winget.md).
- GUI
  - When the GUI is opened for the first time, it waits 2 seconds for rendering, automatically takes a screenshot, and scales it down to a PNG with an aspect ratio maintained, fitting the list display frame and screen zoom level. It saves to `%LOCALAPPDATA%\cat-plugin-player\plugin-icons\`, and plugins with matching name + vendor share the same image across VST3 / CLAP (ignoring leading/trailing spaces and case). If name/vendor are insufficient, they are distinguished by format + ID.
  - Previously saved format-specific images are automatically migrated to shared images based on list/favorite identification and used. Patch states and favorite load destinations are distinguished by format + ID, as before.
  - Plugin images are displayed in Plugins / Favorites / Routing. Within a row, they are scaled down to fit the button height while maintaining aspect ratio. Hovering over an image shows it at its saved size. Plugins with no GUI displayed show a placeholder icon of the same height.
  - The GUI prioritizes placement to the right of the main window, aligned with the top edge, and within the screen's work area. If it doesn't fit, it's placed in the bottom-right of the main window's screen work area. This placement occurs when displayed and when the GUI is resized, but it does not constantly follow the main window's movement. The GUI is not scaled down; if its width is larger than the screen, its left edge aligns with the work area; if its height is larger, its top edge aligns.
  - For blank images or capture failures, it retries at 1-second intervals for up to 20 seconds from GUI display. Saved blank images are also treated as not captured, and opening the GUI will replace them with valid images. Once successful, it does not recapture.
  - If capture fails after retries, an error is displayed. Reopening the GUI will retry. GUIs that do not support capture remain with a placeholder icon. If you want to retake or if the saved PNG is corrupted, delete the shared PNG for the plugin and any remaining old format-specific PNGs, restart the app, and open the GUI (old PNGs are kept during migration).
- Playback
  - The last played instrument, connected effects, Bypass state, and playback pattern are saved to `%LOCALAPPDATA%\cat-plugin-player\status.json` and restored on the next launch. Stopped state, selected playback pattern when stopped, and confirmed MML/chord body are also restored. Unconfirmed edits are not saved.
  - CLAP Note On/Off messages are sent according to the input format supported by the plugin. This includes sforzando CLAP, which only accepts MIDI. The scope of repair and verification records are documented in [CLAP Note Format Description](patches/uapmd/clap-note-dialect/README.md).
  - In the top-left `Sequence` pane, you can select the playback type using left/right arrows or a dropdown. Arrows cycle at the ends of the types, and "Stop" is not included in the types. Switching during playback releases all notes of the current phrase and starts the new phrase from the beginning. When stopped, selecting a type does not start playback; use `Play` to start and `Stop` to stop. In the main window, the `Space` key can also toggle start/stop (except when typing). The selected MML/chord progression playback pattern and stopped state are restored on the next launch.
  - To preview MML/chord progressions, open the input screen with the `i` key or the `Chord` button in `Sequence` (hover to see shortcuts and input methods). Examples are `t120 c8r8d4e4r4` for single notes and `C F G C` for chord progressions. Both are accepted in the same input field, attempting chord notation conversion first. Uppercase `C` creates a chord, lowercase `ceg` becomes MML.
  - Input is confirmed with `Enter`/`Confirm` and canceled with `Esc`/`Cancel`. Cancellation or conversion errors retain the previous valid phrase. `Space` and `i` within the input screen are for typing and do not trigger playback/stop.
  - Confirmed phrases loop playback with `Play`/`Stop`. Rests, note lengths, tempo changes, chords, and trailing rests are preserved. Opening the input screen pauses normal overall playback. If playback was active just before opening, after confirming, the new phrase plays from the beginning; after canceling, the original playback pattern resumes from the beginning. If opened while stopped, it remains stopped after confirming/canceling, and `Play` starts overall playback. You can also switch to regular playback patterns. Immediately after confirmation, the body and selection/playback state are saved; when canceled, the reverted playback state is also saved. It restores from next launch or from instrument favorites/history. Unconfirmed body is not saved, and cancellation or conversion failure retains the last confirmed body.
  - Changing input or moving the cursor previews the single note/chord at that position once. This applies to mid-edit and paste operations as well. Moving within the same pronunciation unit or just redrawing does not re-trigger sound. It reflects previous tempo, octave, and note length, and does not produce sound at rest or command positions. Normal playback stops when editing is opened, and overall playback does not resume even after the preview sound ends. The preview sound is also released on the next pronunciation unit, cancellation, confirmation, or instrument change. Preview does not change the confirmed body or normal selection.
  - For confirmed MML loop playback, the `Velocity` field setting takes precedence over any velocity specified within the input. CC1 can also be controlled from the `CC1 modulation` field. If the performance event capacity is reached with a very dense phrase, active notes are released and sound production stops. You can restart with `Stop` -> `Play`.
  - When changing patches via app Favorites/History, Browse patches/Random patch/Random effect/Browse effects, the stopped/playing state is maintained. During playback, it plays from the beginning of the phrase and does not carry over mid-phrase waits from the previous phrase. Leading rests specified in MML are preserved. While the patch browser or effect browser is displayed, `Space` for playback/stop and MML input start are suppressed. Patch changes made through a plugin's native GUI are not detected.
  - For Six Sines/TyrellN6 CLAP, when audio processing is rebuilt during load, state restoration, or connection changes, it waits for the first phrase to start while continuing normal audio processing to preserve the initial sound. The wait time is approximately 21ms for Six Sines and 85ms for TyrellN6 at 48kHz. MML's leading rests are added to this. See [ADR 0019](docs/adr/0019-random-patch-all-catalog.md) for application conditions and validation records.
  - In the `Velocity` field below the playback pattern, you can select `100`, `127`, `40-100`, `80-127` using the same left/right arrows or dropdown. The initial value is 100. Range specification increases values in Note On order within the phrase and decreases them in the next loop, repeating the cycle. Changes are reflected from the next note without restarting the phrase and are restored on the next launch.
  - In the `CC1 modulation` field, you can select `0`, `127`, `sweep` using left/right arrows or a dropdown. The initial value is 0. `sweep` changes from 0 to 127 in 2 seconds, then from 127 to 0 in the next 2 seconds, repeating the cycle. The selection is restored on the next launch.
  - Guitar open strings send Note On for MIDI note numbers 40, 45, 50, 55, 59, 64 (E, A, D, G, B, E) sequentially at 125ms intervals. 2 seconds after the last Note On, all 6 notes are Note Offed simultaneously, and this repeats after 0.5 seconds.
  - On successful `Load`, it is remembered when `Sequence` type is selected, started, or stopped. The memory remains after stopping or `Remove`. Older history/favorites are restored with the traditional 4-note pattern.
  - On exit and `Remove`, the binary state of patches/parameters exposed by the plugin via UAPMD's state API is saved to `%LOCALAPPDATA%\cat-plugin-player\states\` per plugin. On the next launch or re-load of the same plugin, it is restored before playback starts.
  - `Load` for an instrument replaces only the instrument, maintaining connected effects and their settings. The state of the plugin being replaced is saved, and it switches after the new plugin is successfully created, restored, and connected. If it fails, the original configuration is maintained, and an error is displayed.
  - The scope of state saving depends on the plugin and UAPMD's format-specific implementation. It also requests UI state, but the current UAPMD VST3 implementation only retrieves component state. It does not include copying external samples or saving on forced termination.
  - On launch, it directly loads the previous instrument and effects, restores their states, and then starts playback. Afterwards, it initializes the GUI and scans the list in the background.
  - If direct loading fails due to old history or file movement, it restores from the scan results after GUI display. Old history is updated once played.
  - When the primary instrument is CLAP Floe, if audio processing is rebuilt during load or patch restoration, the start of the first phrase is delayed by 100ms. MML's leading rests are further added. This is a temporary measure to observe the symptom of missing initial sound, and resolution on actual hardware is unconfirmed. See [ADR 0018](docs/adr/0018-floe-automatic-note-start-delay.md) for application conditions and review policy.
  - Refer to [docs/startup-timing.md](docs/startup-timing.md) for startup time measurement methods and results.
- Effect Routing
  - Serial connection: one instrument → multiple effects → output. After loading an instrument, press `Load` for the first effect, then `Add` to append subsequent effects. `Remove` for a connected effect removes only that one. Duplicate connections of effects with the same format + ID are not allowed.
  - `Random effect` next to `Sequence` randomly selects a preset for an installed CLAP effect from the same catalog and selection targets as cmrt's effect selector. If there are 0 effects, it adds the first one; if 1, it replaces that effect; if multiple, it evenly selects and replaces one of the connected effects. Repeated clicks do not increase the number of effects, and the order, settings, and Bypass status of other effects are maintained. To avoid duplicate connections, effects with format + ID already connected (excluding the target for replacement) are excluded from candidates. If no candidates are available for the target slot, it displays a reason and makes no changes.
  - Random effect requires an instrument. Candidates are obtained from default effect/preset locations explored by the play-server shared core, and no VST3 fallback is performed. During preparation, current playback continues, and load/scan/patch operations are disabled. If stopped, it remains stopped after application; if playing, the current phrase restarts from the beginning, and overall MML/Velocity/CC1 selections are maintained. On failure of generation/application/connection, it reverts to the original configuration and does not automatically choose an alternative candidate. After success, the applied state and connection are saved for the next launch, and Favorites/History are not added. Save failures are displayed as applied.
  - `Browse effects` below `Random effect`, or the `E`/`X` keys, opens a separate maximized effect browser window where you can select presets from a list. It cannot be opened while MML is being edited. Filter by Category→Kind on the left and search. Classification and selection targets are the same as cmrt's effect selector. Search is case-insensitive regular expression, space-separated AND, and `-condition` for exclusion, applying to preset name, Category, Kind, or effect name (e.g., `hall -plate`, `dragonfly`). Invalid regular expressions during typing display an error and retain the previous list. The top row has Search, Target frame, and `Random`. The remaining width is used for the search field, and `/` key in the browser moves input to the search field. `R` randomly selects from filtered results. Multiple column display in the list, navigation with up/down/left/right keys / `h`/`j`/`k`/`l` / number prefixes for multiple moves / `PageUp`/`PageDown`, and closing with `Enter`/`Esc` are the same as Browse patches. In results with mixed effects, effect names are appended per effect, and if Kind differs, preset names are color-coded per Kind.
  - The target frame is chosen from `Add new effect` or `Replace n` of a connected effect. When opened, it defaults to the frame last written in this browser, otherwise the last effect, or `Add new effect` if no effects are present. Applying with `Add new effect` makes the added effect the target, and subsequent selections replace that frame, so the number of effects does not increase by continuous selection. If the target frame is removed, the last effect becomes the target. Presets of effects already connected in other frames are grayed out, and selecting them displays a reason and does not change. Presets entered into the target frame by this browser are marked with `▶`, and opening it selects that preset (it does not reapply).
  - Clicking/key navigation or filtering to a different candidate immediately requests application. Simply opening does not change the effect. You can select the next even during preparation; unstarted selections are replaced by the latest one, and closing cancels them. An instrument is required, and preparation's playback continuation, failure recovery, and saving for next launch are the same as Random effect. Category, Kind, search string, list selection position, and target frame are saved on exit and restored on the next launch. Key navigation starts from the restored selection. Category/Kind are restored by name, reverting to `ALL` for that field if missing. Selection is restored by preset; if missing from the catalog, it becomes unselected, and key navigation starts from the beginning. The target frame is restored by its position in the chain; if no effect is at that position, it defaults to the frame upon opening.
  - `Routing` displays the connection order. You can change the order by dragging an effect's `↕` button up or down. During drag, the moving effect name and insertion line are shown. Instruments are not subject to reordering. You can edit patches or effects using `Show UI` for each plugin. `Instrument`/`Effect` are displayed with the same type color as the left list.
  - Removing all effects reverts to a direct connection from instrument to output. `Bypass effect` targets the entire chain, allowing passthrough while retaining instance and settings. It can also be toggled with the `b` key (does not work in MML input screen, Browse patches/Browse effects display, or while typing). When bypassed, connected effects in Routing are grayed out, with `Bypassed` appended.
  - `Sequence` is for instruments. Stopping the Sequence continues audio processing to allow effect tails to decay.
  - On the next launch, the instrument, order of all effects, their respective states, and Bypass status are restored before playback. History of one old-format effect can also be loaded. If effect restoration fails, an error is displayed, it reverts to a direct instrument connection, and the saved configuration is retained.
  - Add/remove/reorder operations are saved only if the new connection prepares successfully. If it fails, the original configuration and playback are restored, and an error is displayed.
  - Supports mono/stereo for main input/output. Mono → stereo is duplication; stereo → mono is the average of left/right. Auxiliary inputs are silent.
  - Changing connections or Bypass may cause brief audio glitches, and currently playing notes and decays may be cut off. Sidechain, parallel connections, and host-side Dry/Wet are not supported.

Waveform/spectrum are displayed below Routing on the right; the right-side width can be adjusted by dragging the boundary. `Audio analysis`'s `On right` toggles analysis display to bottom-right / bottom of the screen (bottom-right on launch).
  - For sforzando CLAP's confirmed state format, it reuses existing favorites without creating new ones for patches that differ only by save counter and playback values of notes/CC1. Differences in patch settings are retained. See [ADR 0006](docs/adr/0006-sforzando-favorite-state-comparison.md) for scope and limitations.
  - Colored `Instrument` / `Effect` is displayed to the left of each row. Clicking a favorite name restores its patch/settings. For instrument favorites, it restores the saved confirmed body and playback pattern selection. If stopped, it remains stopped; `Play` plays the restored phrase. If playing, it switches to the saved pattern/MML. Favorites in old format without a body retain the current body, and old-format stopped items retain the current selection. If conversion or state load/connection fails, the original body/selection/playback state is restored, and the failed content is not saved to the session. Instrument favorites maintain connected effects; effect favorites maintain the instrument and MML. An instrument is required to call an effect.
  - For connected effect favorites, `Connected - click again to remove` is displayed; clicking the name again removes that effect. This applies even if settings were edited after calling or if bypassed. The instrument, other effects, and saved favorites remain. Another patch with the same format + ID switches settings at the current position, and unconnected effects are added to the end. The selected favorite for each effect is also restored on the next launch.
  - Rename/Delete are available from `…` at the end of the row. Edits after calling or traditional auto-saves do not overwrite favorites. `Last favorite` indicates the last saved/called favorite.
  - Favorites are saved to `%LOCAL_APP_DATA%\cat-plugin-player\favorites\`. Saving/restoring may cause brief audio glitches, and the savable range is the same as traditional state saving.
- Lissajous Display
  - `Lissajous` is displayed below the oscilloscope in the right analysis panel. If `☰` → `On right` is unchecked for the oscilloscope, the spectrum, oscilloscope, and Lissajous display horizontally at the bottom of the screen.
  - It draws the output of the most recent 50ms (max 4096 samples), reflecting effects and Bypass, in a 45° rotated Lissajous pattern. A common automatic magnification preserves volume differences and aspect ratio of the figure; same-level in-phase results in a vertical line, out-of-phase in a horizontal line, and sine waves with phase difference become ellipses or circles. Left-only output results in a diagonal line from top-left to bottom-right; right-only output from top-right to bottom-left; mono results in a vertical line; silence is a central dot.
  - It updates independently of note, period count, or trigger settings, and `Show analysis labels` can display headings. Axes and drawing method can also be checked in the graph's tooltip.
  - `Correlation` directly below Lissajous displays the left/right correlation for the most recent 150ms as a bar and numerical value from -1 to +1. +1 is in-phase, near 0 indicates weak correlation, and -1 is out-of-phase. Negative values are displayed in red, serving as a guideline to judge cancellation when mixed to mono. If silent or one side is silent, it displays "—".
- Waveform Display
  - `Oscilloscope` at the bottom of the screen displays the L (green) and R (blue) output, reflecting effects and Bypass, overlaid. Mono displays the same waveform on both.
  - The display width is determined from the last Note On MIDI note number (A4 = 440Hz), and you can select `1`, `2`, `4`, `8 cycles`. After Note Off, the decay is shown based on the last note. Output containing chords or detuning may not repeat perfectly at that width.
  - `Zero cross` aligns with the negative→positive crossing of the left channel. If the left channel is silent, it uses the right channel; if no crossing, it displays from the beginning.
  - `Similarity` sweeps through the buffer from the beginning by 1 sample increments for the display width, finding the position with the maximum correlation coefficient to the previous display. If ties, the earliest position is adopted, and the same start position is used for left and right. For the first display or if the comparison target is silent, zero cross is used.
  - Comparison history is reset when a note is played, playback pattern changes, display cycle count changes, trigger method changes, or audio stream changes. A "waiting" display is shown until sufficient data is collected.
  - Exploration is performed on a separate thread from audio processing. Display updates may be slow for low notes or high cycle counts. If display data is interrupted, the history is reset.
  - Default display settings on launch are 4 cycles and zero-cross. Display settings are not saved.

## Window Position and Size Settings

You can specify the main window's launch position/size and plugin GUI placement method in `%LOCALAPPDATA%\cat-plugin-player\config.toml`. Please edit it after closing the app. Session and favorite selection states are saved to `status.json` in the same directory, and regular saves do not rewrite the TOML. If previously mixed in the TOML, it migrates on first launch, saves the original file as `config.toml.before-status-migration.bak`, then removes only the state items. Comments, formatting, and unknown items are preserved, and independent comments attached to deleted items are moved to the end. If an existing `status.json` is present, it takes precedence.

```toml
[window.main]
x = 100.0
y = 100.0
width = 1200.0
height = 800.0

[window.plugin]
placement = "right_then_bottom_right"
```

`x` and `y` for the main window are logical coordinates and are used as the launch position if both are specified. If omitted, it defaults to the traditional initial position. `width` and `height` are the inner width and height (logical coordinates) of the main window. Either can be specified alone; if omitted or set to 0 or non-finite values, it reverts to 900 width and 600 height. Changes will be reflected on the next launch. The plugin placement method is currently only `right_then_bottom_right`; omitting it results in the same behavior. GUI size and placement are calculated based on the actual window frame, screen work area, and DPI. Automatic saving of positions moved manually for the main window or GUI, and per-plugin position specification are not implemented.

## Local Build and Execution

Clone this app, `uapmd`, `clap-mml-render-tui`, and `clap-mml-play-server` into the same parent directory, then execute from this app's directory. TUI's `app` / `patches` / `patch-select` / `tui-core` and play-server's `core-lib` / `server-config` are always referenced locally from Cargo.toml. Play-server requires `prepare_catalog_clap_patch_state` / `supports_catalog_clap_plugin` in addition to the traditional `prepare_clap_patch_state` / `PatchStateError`, and TUI's `cmrt-patches` needs their re-export. The patch browser uses public Role/Preset/filter APIs and tui-core's sample size judgment. Random effect and Browse effects use play-server's `AudioEffectCatalog` / `EffectRenderer` and TUI's effect selector conditions, while Browse effects search uses tui-core's search conditions. Insufficient checkout or API will result in a build error; no automatic switch to Git versions will occur.

```powershell
cargo build --release
& ./target/release/cat-plugin-player.exe
```

If UAPMD is not in the sibling `uapmd` directory, first set `$env:UAPMD_DIR = 'X:\projects\uapmd'`. The location of UAPMD during build is specified by an environment variable. `config.toml` is not read as build settings.

Do not use `cargo install`; directly execute the generated exe in the default `target/release`. The build uses local code (including uncommitted changes) and existing `target/shim`, but source changes may require reconstruction and rebuild. If `target/shim` was created with a different version like VS 2022, it will continue to build with that version, so delete `target/shim` before building (see [ADR 0020](docs/adr/0020-visual-studio-2026-toolchain.md)). The shim DLL is bundled with the exe and extracted to a cache directory and loaded when the GUI starts.

Refer to [ADR 0012](docs/adr/0012-local-dependencies-and-release-execution.md) for the 3-repo dependency configuration and operation policy. Local TUI switching is not necessary for building cat. If building TUI cross-repository itself, use TUI's existing `python scripts/cross_repo_local.py on` procedure; `off` is handled manually. Local references use uncommitted changes, and Cargo.lock does not fix the contents of each checkout. When verifying, record the HEAD and diffs of each repository.

Launch the GUI without arguments. `--help` and `--version` are also available.
