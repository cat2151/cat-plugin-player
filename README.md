# cat-plugin-player

A lightweight application for easily playing audio plugins. It utilizes [UAPMD](https://github.com/atsushieno/uapmd) and is written in Rust.

# Past Challenges and How This App Solves Them
- The sounds of audio plugins are amazing!
- To play them, it often requires launching a DAW and performing setup beforehand.
- Lightweight apps for casual playing sometimes required account registration or had interfaces that weren't intuitive for me.
- Nowadays, if you have a desired UX, you can achieve it through vibe coding.
- So I decided to do just that.

# Features
- Automatic Installation
  - If you haven't installed an audio plugin, the app will automatically install [Surge XT](https://surge-synthesizer.github.io/) as mentioned above.
- Detection
  - Upon launch, it automatically detects installed plugins.
- Playback
  - Clicking a plugin loads it and automatically starts playback.
  - It can play chord progressions like `F-G-Em-Am` and MML (Music Macro Language) like `cde`.
- GUI
  - Pressing the `Show UI` button displays the plugin's GUI, allowing you to edit sounds and effects.
- Sounds
  - Each plugin has a variety of preset sounds. You can easily select them using a unique sound browser (supported by some plugins only).
  - For plugins not supported by the sound browser, you can select sounds directly from the plugin's GUI.
- Effects
  - Each plugin has a variety of preset effects. You can easily select them using a unique effect browser (supported by some plugins only).
  - For plugins not supported by the effect browser, you can select effects directly from the plugin's GUI.

- Detection
  - For normal startup and editor integration, the full plugin list and instrument/effect classification are first restored from `%LOCALAPPDATA%\cat-plugin-player\plugin-list-cache.json`. If the cache is missing or unreadable on the first launch, it will be detected and created. If there are no loads or sound changes and operations stop for 2 seconds after startup, it will re-detect in the background. The cache and patch list are updated only if there are changes in the list; otherwise, the display is maintained. If re-detection fails, the existing cache is retained.
  - If plugin detection succeeds but no instruments are found, a prompt to install the free Surge XT via winget is displayed. It is also displayed if only effects are found. If the Windows display language is Japanese, it shows in Japanese; otherwise, in English. Even if "Later" is chosen, it will display every time the app starts until an instrument is present.
  - "View Terms" opens the Surge XT license (GPLv3) in a browser. Pressing "Agree to Terms and Install" executes winget and displays the stages "1/4 Preparing", "2/4 Downloading", "3/4 Installing", "4/4 Loading" with elapsed seconds. If a Windows confirmation screen (User Account Control) appears at 3/4, select "Yes". Upon success, the plugin list is automatically rescanned, Surge XT (CLAP) is loaded, and playback begins, similar to `Load`. In this case, the previous instrument/effect restoration is not performed. Even if the prompt is closed, installation continues, and upon completion, a rescan and load are performed.
  - If winget is not available or installation fails, a winget message and manual download link are displayed, and recorded in `error.log`. Only Surge XT is included, and the download progress is not shown. The reasons for this choice are in [ADR 0024](docs/adr/0024-offer-surge-xt-via-winget.md).
- GUI
  - When the GUI is opened for the first time, it waits 2 seconds for rendering, then automatically takes a screenshot, and scales it down to a PNG with size matching the list display frame and screen zoom ratio, while preserving the aspect ratio. It is saved in `%LOCALAPPDATA%\cat-plugin-player\plugin-icons\`, and plugins with matching name + manufacturer (ignoring leading/trailing spaces and case) will share the same image for VST3 / CLAP. If name/manufacturer are insufficient, they are distinguished by format + ID.
  - Previously saved format-specific images are also automatically migrated and used as shared images based on list/favorite identification information. Sound states and favorite load destinations are still distinguished by format + ID.
  - Plugin images are displayed in Plugins / Favorites / Routing. Within a row, they are scaled down to fit the button height while preserving aspect ratio. Hovering over an image allows viewing it at its saved size. For plugins with no GUI displayed, a temporary icon of the same height is shown.
  - The GUI prioritizes placement to the right of the main window, aligned to the top, fitting within the screen's working area. If it doesn't fit, it's placed in the bottom-right of the working area of the screen where the main window is located. It's placed when shown and when the GUI size changes, but doesn't continuously follow the main window's movement. The GUI is not scaled down; if its width is greater than the screen, its left edge aligns with the working area; if its height is greater, its top edge aligns.
  - For blank images or failed captures, retries occur at 1-second intervals for up to 20 seconds from GUI display. Saved blank images are also treated as uncaptured; opening the GUI will replace them with valid images. No re-captures occur after success.
  - If capture fails after retries, an error is displayed. Opening the GUI again will retry. GUIs that do not support capture will remain with a temporary icon. If you want to retake a screenshot or if the saved PNG is corrupted, delete the relevant plugin's shared PNG and any remaining old format-specific PNGs, restart the app, and open the GUI (old PNGs are kept during migration).
- Playback
  - The last played instrument, connected effects, Bypass status, and playback pattern are saved to `%LOCALAPPDATA%\cat-plugin-player\status.json` and restored on next launch. Stopped playback pattern selection, and confirmed MML/chord body are also restored. If there is only one instrument candidate in the Plugins list on startup, it is automatically loaded if not already loaded, and playback starts with the selected pattern even if saved in a stopped state. If multiple candidates exist, the stopped state is restored. If manually stopped after startup, it remains stopped. Unconfirmed edits are not saved.
  - CLAP Note On/Off messages are sent according to the plugin's supported input format. This includes sforzando CLAP, which only accepts MIDI. The scope of fixes and verification records are documented in [CLAP Note format explanation](patches/uapmd/clap-note-dialect/README.md).
  - In the top-left `Sequence` pane, you can select the playback type using left/right arrows or the dropdown. Arrows cycle at both ends of the types and do not include "Stop". Switching during playback releases all notes in the current phrase and starts from the beginning of the new phrase. When stopped, selecting a type does not play; use `Play` to start and `Stop` to stop. The main window's `Space` key also toggles start/stop (except when typing). Selection of playback patterns including MML/chords and stopped state are restored on next launch. However, if only one instrument candidate exists on startup, it will auto-play from a stopped state.
  - To preview MML/chord progressions, open the input screen with the `i` key or the `Chord` button in `Sequence` (hover to see shortcuts and input method). An example for single notes is `t120 c8r8d4e4r4`, and for chord progressions is `C F G C`. Both are accepted in the same input field, with chord notation conversion attempted first. Uppercase `C` denotes a chord, lowercase `ceg` becomes MML.
  - Input is confirmed with `Enter` / `Confirm` and cancelled with `Esc` / `Cancel`. Cancellation or conversion errors maintain the previous valid phrase. `Space` and `i` within the input screen are used for typing, and `Space` for play/stop does not work.
  - Confirmed phrases loop playback with `Play` / `Stop`. Rests, note lengths, tempo changes, chords, and trailing rests are preserved. Opening the input screen pauses overall normal playback. If playback was active just before opening, after confirmation, the new phrase plays from the beginning; after cancellation, the original playback pattern resumes. If opened while stopped, it remains stopped after confirmation/cancellation, and `Play` starts overall playback. You can also switch to regular playback patterns. The text and selection/playback state are saved immediately after confirmation, and the restored playback state is saved upon cancellation. It is restored on next startup or from instrument favorites/History. Unconfirmed text is not saved; cancellation or conversion failure preserves the last confirmed text.
  - Moving the cursor or changing input triggers a single preview of the note/chord at that position. This applies to mid-edit or paste operations. Moving within the same pronunciation unit or just redrawing will not re-trigger. Previous tempo, octave, and note length are reflected; no sound is produced at rest or command positions. Normal playback stops when editing opens, and overall playback does not resume after preview sound ends. Preview sounds are released upon the next pronunciation unit, cancellation, confirmation, or instrument change. Previews do not alter confirmed text or regular selection.
  - The playback Velocity for looped MML phrases prioritizes the setting in the `Velocity` field over any inline input specification. CC1 can also be controlled from the `CC1 modulation` field. If the event capacity is reached for a very dense phrase, active notes are released and sound production stops. You can restart with `Stop` -> `Play`.
  - When recalling from Favorites/History or changing sounds via Browse patches/Browse effects in normal startup, stop/play states are maintained. During playback, phrases start from the beginning and do not inherit mid-phrase waits from the previous phrase. Leading rests specified in MML are preserved. While the sound browser/effect browser is displayed, `Space` for play/stop and MML input initiation in the background are suppressed. Sound changes made via a plugin's native GUI are not detected.
  - In SMF selection mode (`--select-smf`), the input track loops playback with tempo, duration, and velocity. For bulk sound assignment, all tracks are previewed with the selected sound and the representative track's effects. Normal session sounds/effects/MML are not restored, and only sound snapshots are used for favorites. It does not return to the start when changing patches/effects/favorites/connections; it continues from the stopped position after a brief silence during the swap. The MML/normal pattern control fields are not used in this mode.
  - In SMF selection mode with `--master-effects`, the current track's sound/effects are retained for preview, and only master effects are edited and returned. The patch browser is not used. Master effects are saved in the conductor-specific meta of SMF format 1, and the results of their application to all tracks are confirmed back in the editor. Master effect support for format 0/2 is not added. Refer to [ADR 0030](docs/adr/0030-master-effects-selection.md).
  - cat-smf-editor can make one player resident with `--resident <name>`, bringing the patch/effect browser to the foreground on each `t` / `x`. A resident player does not load selected sounds/effects itself but sends the state to the editor, which then plays them with its own sound source. `Esc`, `q`, `×`, or closing the effect browser with `Enter` only hides the browser; the player exits when the editor terminates. Previous sounds are not restored, and the player's regular `status.json` is not updated. Role/Preset/Category/Kind and search strings (including Solo/Mute and exclusion conditions) are saved to the editor's `status.json` per song/track/patch/effect, and master effects are saved/restored independently per song. Saving occurs even if no sound is selected before closing. Patch list selections are also saved to the editor's `status.json` per song/track using patch name and instrument/original patch identification, and restored upon restart. Sound reapplication does not occur during selection restoration.
  - For Six Sines / TyrellN6 CLAP, when audio processing is rebuilt (e.g., loading, state restoration, connection changes), the first phrase start waits while normal audio processing continues to preserve initial sound. At 48kHz, the wait is about 21ms for Six Sines and 85ms for TyrellN6. MML's leading rests are added on top of this. Application conditions and empirical verification are in [ADR 0019](docs/adr/0019-random-patch-all-catalog.md).
  - In the `Velocity` field below the playback pattern, you can select `100`, `127`, `40-100`, `80-127` using the left/right arrows or dropdown. The initial value is 100. Range specification increases values sequentially for Note On events within the phrase and decreases them on the next loop, repeating this action. Changes are reflected from the next note played without restarting the phrase and are restored on next startup.
  - In the `CC1 modulation` field, you can select `0`, `127`, `sweep` using the left/right arrows or dropdown. The initial value is 0. `sweep` repeatedly changes from 0 to 127 over 2 seconds, then from 127 to 0 over the next 2 seconds. The selection is restored on next startup.
  - Guitar open strings send MIDI note numbers 40, 45, 50, 55, 59, 64 (E, A, D, G, B, E) in sequence with 125ms intervals for Note On. Two seconds after the last Note On, all six notes are Note Offed simultaneously, and the sequence repeats after 0.5 seconds.
  - On successful `Load`, and when selecting/starting/stopping a `Sequence` type, it is memorized. This memory persists after stopping or `Remove`. Older history/favorites are restored with the traditional 4-note pattern.
  - At the end of normal startup and on `Remove`, the binary state of the plugin's sounds, parameters, etc., exposed by the UAPMD state API, is saved per plugin to `%LOCALAPPDATA%\cat-plugin-player\states\`. On next startup or when reloading the same plugin, it is restored before playback begins.
  - An instrument `Load` replaces only the sound source, maintaining connected effects and settings. The state of the plugin being replaced is saved, and only after successful creation/restoration/connection of the new plugin does it switch. If it fails, the original configuration is maintained, and an error is displayed.
  - The scope of state saving depends on the plugin and UAPMD's format-specific implementation. UI state is also requested, but the current UAPMD VST3 implementation only retrieves component state. It does not include replication of external samples or saving upon forced termination.
  - On startup, it reads the saved full plugin list, directly loads the previous instrument and effects, restores their states, and starts playback. Afterwards, the GUI is initialized, and after operations settle, the list is re-detected in the background. On the first launch without a full list cache, it detects after GUI display.
  - If the previous instrument was Surge XT (CLAP / VST3), only this one instance is created on startup in a configuration that omits the patch, wavetable, and FX preset lists, to play faster. Since this configuration results in Surge's GUI menus being almost empty, pressing `Show UI` for that Surge XT will recreate it with the normal configuration while preserving the sound, then open the GUI. During this, the sound stops once and returns in about 0.3-0.4 seconds. Surge XT created via `Load`, sound browser, favorites, history, or effects uses the normal configuration. This can be disabled with the environment variable `CMRT_SURGE_MINIMAL_DATA_HOME=0`. See [ADR 0034](docs/adr/0034-surge-xt-startup-minimal-data-home.md) for reasons.
  - If direct loading fails due to old history or file relocation, it is restored from the scan results after GUI display. Old history items are updated once played.
  - If the main instrument is CLAP Floe, when audio processing is rebuilt (e.g., loading, sound restoration), the start of the first phrase is delayed by 100ms. MML's leading rests are added on top of this. This is a temporary measure to observe the symptom of initial sounds disappearing, and its resolution on actual hardware is unconfirmed. Application conditions and review policy are in [ADR 0018](docs/adr/0018-floe-automatic-note-start-delay.md).
  - For measurement methods and results of startup time, refer to [docs/startup-timing.md](docs/startup-timing.md).
- Effect Routing
  - When opening `Browse effects` / `E` / `X`, if there is only one compatible CLAP effect candidate, it is automatically loaded, and its slot becomes the target for preset changes. If already connected, it is not reloaded, and that slot is used. If an instrument is not loaded and there is only one instrument candidate, the instrument is loaded first, and playback begins. If multiple candidates exist, select an instrument first. The candidate count determination follows the CLAP priority setting in the Plugins list, and search strings do not reduce the candidate count.
  - The connection is series: one instrument → multiple effects → output. After loading an instrument, press `Load` for the first effect, then `Add` to append subsequent effects. A connected effect can be removed individually using `Remove`. Duplicate connections of effects with the same format + ID are not allowed.
  - Changing effects via Browse effects requires an instrument. Candidates are retrieved from the default effect/preset locations scanned by the play-server shared core, without fallback to VST3. During preparation, current playback continues, and loading, scanning, and sound operations are disabled. In normal startup, it remains stopped if stopped, or resumes the current phrase from the beginning if playing, maintaining overall selection of MML/Velocity/CC1 and the order/settings/Bypass of other effects. If generation, application, or connection fails, it reverts to the original configuration. After success, the applied state and connection are saved for next startup; Favorites/History are not added. Saving failures are displayed as applied.
  - `Browse effects` next to `Sequence` or the `E` / `X` keys open an independent maximized effect browser window, allowing selection of presets from a list. It cannot be opened while editing MML. Filtering is done by Category → Kind on the left, and by search. Classification and selection targets are the same as cmrt's effect selector. Search uses case-insensitive regular expressions, space-separated AND, and `-condition` for exclusion, applying to preset name, Category, Kind, or effect name (e.g., `hall -plate`, `dragonfly`). Invalid regular expressions entered during typing display an error and retain the previous list. The top line contains Search, Target Slot, and `Random`. The search field uses the remaining width, and `/` key in the browser moves focus to the search field. `R` picks a random item from the filtered results, and `W` toggles column width between fitting all preset names and default width. Multiple column display in the list, navigation using up/down/left/right keys / `h` / `j` / `k` / `l` with numeric repeat, and `PageUp` / `PageDown`, as well as closing with `Enter` / `Esc`, are the same as Browse patches. In results with mixed effects, effect names are appended for each effect, and if Kinds differ, preset names are colored by Kind. For names that don't fit in the cell, the end of the preset name (part excluding folders) is always preserved, while folder names and effect names to its left are truncated to the first character + `...`, displaying longer parts closer to the preset name. Full names are visible on hover.
  - The target slot is chosen from `Add new effect` or `Replace n` of a connected effect. When opened, it defaults to the slot last written by this browser, otherwise the last effect, or `Add new effect` if no effects are present. Applying with `Add new effect` makes the added effect the target, and subsequent selections replace that slot, so the number of effects does not increase by continuous selection. If the target slot is removed, the last effect becomes the target. Presets of connected effects in slots other than the target are displayed in gray; selecting them shows a reason and does not change them. Presets put into the target slot by this browser are marked with `▶`, and opening the browser selects them (does not re-apply).
  - Clicking, key movement, or filtering to another candidate immediately requests application. Simply opening does not change the effect. You can select the next item during preparation; unstarted selections are replaced by the latest one and cancelled on closing. Category, Kind, search string, list selection position, and target slot are saved on exit and restored on next startup. Key movement starts from the restored selection. Category/Kind are restored by name; if they no longer exist, they revert to `ALL` in their respective fields. Selection is restored by preset; if it no longer exists in the catalog, it becomes unselected, and key movement starts from the beginning. The target slot is restored by its position in the chain; if no effect exists at that position, it defaults to the slot chosen on opening.
  - When the effect before or after replacement is CLAP Surge XT Effects in Browse effects, the sound immediately before the switch fades out over about 50ms, and the sound after the switch fades in over about 50ms. This is a temporary measure to suppress a loud "pop" that can occur if lingering sound from the instrument passes through the new effect (especially distortion-type effects). The switch is delayed by that amount (up to about 70ms), and lingering sound might be faintly heard during the fade-in. Other effect switches or sound/instrument changes do not fade. Reasons and scope are in [ADR 0027](docs/adr/0027-surge-xt-effect-swap-fade.md).
  - Surge XT Effects presets are obtained from a table of pre-prepared states from [cat-music-patterns](https://github.com/cat2151/cat-music-patterns) on each launch (saved to `%LOCALAPPDATA%\cat-plugin-player\patch-catalog\surge-xt-fx-states.json`), instead of temporarily launching the plugin for preparation. This is to avoid a bug where the app crashes if you keep selecting presets. If it cannot be obtained, the previously saved table is used; if that is also missing, Surge XT Effects presets do not appear as candidates in the effect browser, and a reason is displayed. The table is created from Surge XT 1.3.4 presets; presets with different content (e.g., different Surge XT versions) are excluded from candidates, and the number excluded is shown. Reasons are in [ADR 0028](docs/adr/0028-surge-xt-fx-prepared-states.md).
  - `Routing` displays the connection order. Effects can be reordered by dragging the `↕` button up or down. While dragging, the moving effect name and insertion line are displayed. Instruments are not subject to reordering. `Show UI` for each plugin allows editing sounds and effects. `Instrument` / `Effect` are displayed with the same type color as the left list.
  - Removing all effects reverts to a direct connection from the instrument to the output. `Bypass effect` targets the entire chain, allowing it to pass through while retaining instance and settings. It can also be toggled with the `b` key (does not work in MML input screen, Browse patches/Browse effects display, or while typing). While bypassed, connected effects in Routing are grayed out, with `Bypassed` appended.
  - `Sequence` is for instruments. Stopping the sequence continues audio processing, allowing effects to trail off.
  - On next startup, the instrument, order of all effects, their respective states, and Bypass status are restored before playback. History items for a single old-format effect can also be loaded. If effect restoration fails, an error is displayed, reverting to a direct instrument connection, and the saved configuration is preserved.
  - Additions, removals, and reordering are saved only if the new connection is successfully prepared. If it fails, the original configuration and playback are restored, and an error is displayed.
  - Supports mono/stereo for main input/output. Mono → stereo is duplication, stereo → mono is an average of left and right. Auxiliary input is silent.
  - There may be brief audio dropouts when changing connections or Bypass, and active notes and reverbs may be cut off. Sidechain, parallel connections, and host-side Dry/Wet are not supported.

- Lissajous Display
  - `Lissajous` is displayed below the oscilloscope in the right-side analysis pane. If `☰` → `On right` is unchecked in the oscilloscope, spectrum, oscilloscope, and Lissajous display side-by-side at the bottom of the screen.
  - Displays the output of the last 50ms, reflecting effects/Bypass, on a 45° rotated Lissajous curve (max 4096 samples). A common automatic scaling preserves volume differences and aspect ratio; in-phase signals at the same level form vertical lines, anti-phase signals form horizontal lines, and sine waves with phase differences form ellipses or circles. Output from only the left channel creates a diagonal line from top-left to bottom-right; from only the right, top-right to bottom-left; mono creates a vertical line; silence creates a central dot.
  - It updates independently of notes, period counts, or trigger settings, and `Show analysis labels` displays headings. Axes and rendering methods can also be checked in the graph's tooltip.
  - `Correlation` directly below Lissajous displays the left/right correlation for the last 150ms as a bar and numerical value from -1 to +1. +1 is in-phase, near 0 indicates weak correlation, and -1 is anti-phase. Negative values are displayed in red, serving as an indicator for cancellation when mixed to mono. Displays "—" for silence or if one side is silent.
- Waveform Display
  - `Oscilloscope` at the bottom of the screen displays the output's L (green) and R (blue) channels superimposed, reflecting effects/Bypass. For mono, the same waveform is shown on both.
  - The display width is determined from the last Note On MIDI note number (A4 = 440Hz), and `1`, `2`, `4`, `8 cycles` can be selected. After Note Off, the last note remains the reference for displaying reverb. Output containing chords or detuning may not perfectly repeat within that width.
  - `Zero cross` aligns to the left channel's negative-to-positive crossing. If the left channel is silent, it uses the right channel; if no crossing, it displays from the beginning.
  - `Similarity` comprehensively scans for the position that maximizes correlation with the previous display, from the start of the buffer for the display width, at 1-sample intervals. For ties, the earlier position is adopted; the same start position is used for left and right. For the first display or if the comparison target is silent, zero-cross is used.
  - Comparison history is reset when a note is played, playback pattern changes, display period count changes, trigger method changes, or audio stream changes. It will show a "waiting" display until sufficient data is collected.
  - Scanning runs on a separate thread from audio processing. Display updates may be slow for low notes or high period counts. If display data is interrupted, history is reset.
  - Default display settings on startup are 4 cycles and zero-cross. Display settings are not saved.

## Settings: Window Position and Size

`%LOCALAPPDATA%\cat-plugin-player\config.toml` can specify the main window's startup position/size and plugin GUI placement method. Please edit it after closing the application. Session and favorite selection states are saved to `status.json` in the same directory, and normal saves do not overwrite the TOML. If states are mixed in an old TOML, they are migrated on first launch: the original file is saved as `config.toml.before-status-migration.bak`, then only state items are removed. Setting comments, formatting, and unknown items are preserved; independent comments attached to deleted items are moved to the end. If an existing `status.json` is present, it takes precedence.

```toml
[window.main]
x = 100.0
y = 100.0
width = 1200.0
height = 800.0

[window.plugin]
placement = "right_then_bottom_right"
```

The main window's `x` and `y` are logical coordinates and are used as the startup position if both are specified. If omitted, it uses the traditional initial position. `width` and `height` are the inner width/height (logical coordinates) of the main window. Either can be specified alone; omitted sides or values <= 0 / non-finite revert to width 900 / height 600. Changes are reflected on next startup. The plugin placement method is currently only `right_then_bottom_right`, and omitting it results in the same behavior. GUI size and placement are calculated based on actual window frame, screen working area, and DPI. Automatic saving of positions moved manually, or per-plugin position specification, is not performed.

## Local Build and Run

Clone this app, `uapmd`, `clap-mml-render-tui`, and `clap-mml-play-server` into the same parent directory, then run from this app's directory. TUI's `app` / `patches` / `patch-select` / `tui-core` and play-server's `core-lib` / `server-config` are always locally referenced from Cargo.toml. Play-server requires `prepare_catalog_clap_patch_state` / `supports_catalog_clap_plugin` in addition to traditional `prepare_clap_patch_state` / `PatchStateError`, and TUI's `cmrt-patches` needs their re-export. The sound browser uses public Role/Preset/filter APIs and tui-core's sample size determination. Browse effects uses play-server's `AudioEffectCatalog` / `EffectRenderer` and TUI's effect selector conditions, and tui-core's search conditions. Insufficient checkouts or missing APIs will result in build errors; no automatic switch to Git versions will occur.

```powershell
cargo build --release
& ./target/release/cat-plugin-player.exe
```

If UAPMD is not in the sibling `uapmd` directory, first set `$env:UAPMD_DIR = 'X:\projects\uapmd'`. UAPMD's location during build is specified via environment variable. `config.toml` is not read as build configuration.

Do not use `cargo install`; directly run the exe generated in the default `target/release`. Builds use local code (including uncommitted changes) and existing `target/shim`, but source changes may require re-configuration/re-build. If `target/shim` was created with a different version (e.g., VS 2022), it will continue to build with that version; delete `target/shim` before building ([ADR 0020](docs/adr/0020-visual-studio-2026-toolchain.md)). The shim DLL is bundled with the exe, extracted to the cache directory, and loaded when the GUI starts.

For the 3-repo dependency structure and operational policy, refer to [ADR 0012](docs/adr/0012-local-dependencies-and-release-execution.md). Local switching of TUI is not necessary for `cat` builds. If cross-building TUI itself, use TUI's existing `python scripts/cross_repo_local.py on` procedure; `off` is handled manually. Local references use uncommitted changes, and Cargo.lock does not fix the content of each checkout. When verifying, record the HEAD and diffs of each repo.

The first-time installation of Surge XT is consolidated in `shared/first_instrument_install.rs`; cat-smf-editor also references the same instrument absence detection, terms screen, and winget process. Each app handles rescanning and loading after successful installation.

Host Rust/native and SMF processing are consolidated in `shared/`; cat-smf-editor also references the same canonical modules. No independent crates are added; each app bundles its own DLL from the default `target/shim`.

Run without arguments to launch the normal GUI. `--help` and `--version` are also available.

SMF selection mode is `--select-smf <SMF> --browser patch|effect --preserve-position`. If `browser` is omitted, it defaults to `patch`; position preservation requires explicit specification. Passing `--patch-filter <program name>` searches the patch browser with that name from the ALL condition. Regular expression symbols in the name are treated as literal characters, and spaces are AND. If 0 results after catalog loading, it switches once to an OR search where words are joined by `|` (e.g., `church organ` → `church|organ`). `--patch-filter-file <JSON>` restores search/Role/Preset as is and saves back to the same file on successful exit. If no file, it uses initial search; existing file conditions take precedence. An empty search is also retained, and restored conditions do not auto-switch to word OR. Not used for effect/master selection. The search field can be edited as a case-insensitive regular expression as usual. `--preview-smf <SMF>` specifies a separate SMF for previewing all tracks, different from the return destination. It sends all track MIDI events to the selected instrument/effect and reflects per-track tempo for format 2. The preview SMF is not modified. `--start-seconds <sec>` specifies the initial preview position, `--loop-end-seconds <sec>` specifies the loop end beyond the input SMF. If omitted, it plays from the start to the end of the input SMF. Uses finite, non-negative seconds, and the start position must be before the loop end. It restores controllers/sustained notes at the start point, and natural loop boundaries return to the beginning. Original SMF events are not changed. Adding `--browser-only` does not display the main screen, but brings the browser to the foreground. This option is for selection mode only. In normal track selection, buttons within the browser can navigate to other browsers. `--master-effects` starts with the effect browser and does not proceed to the patch browser. The main screen can be displayed from `Favorites / routing` only when favorites/routing are needed. Closing the browser with Enter is also treated as saving/terminating the entire player. On save failure or during change processing, the browser is retained, and errors are displayed within the browser. Esc, 'q' not used for input, and the '×' button of the main window/browser save instrument/ordered effect/bypass states to the input SMF and exit. `--master-effects` saves only the conductor's master effect/bypass and retains track settings. 'q' in the search field is for typing. During change processing, it waits for confirmation; on save failure, it retains the screen and selection, allowing retry. Normal `status.json` is not updated. Existing state saving/favorite operations for selected items use the usual save locations. State compatibility across OS/plugin versions and duplication of external samples are not guaranteed. See [Saving Contract and Shared Host (ADR 0029)](docs/adr/0029-shared-host-smf-selection.md).

# Concept, What We Aim For
- Instrument
  - For example, a synthesizer with a MIDI keyboard makes sound when powered on and a key is pressed.
    - We aim for that level of ease of use.
      - Minimize operations to produce sound.
- Sound Production
  - We aim to maintain "it works in the author's environment" as much as possible.
- Instant Sound
  - From app launch to sound production, an experienced 0.2 seconds. We've optimized for the fastest possible playback.
    - Processes like GUI display preparation also occur after sound production.
      - Sound playing before GUI display might be considered a sound-based splash screen.
- Educational Use
  - This project is oriented more towards educational use than commercial use.
- Experimentation, Exploration, Personal Use
  - Destructive changes will be frequent.
