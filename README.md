# cat-plugin-player

A lightweight app for easily playing audio plugins. It utilizes [UAPMD](https://github.com/atsushieno/uapmd) and is written in Rust.

# Previous Challenges and What This App Solves
- Audio plugin sounds are fantastic!
- To play them, you often need to launch a DAW and perform setup tasks.
- Lightweight apps for casual playing sometimes require account registration for acquisition, or their operation feel "not for me".
- Nowadays, if you have a desired UX, you can achieve it through vibe coding.
- So, I decided to do just that.

# Features
- Automatic Installation
  - As mentioned, if you haven't installed an audio plugin, the app will automatically install [Surge XT](https://surge-synthesizer.github.io/)
- Detection
  - Upon launch, it automatically detects installed plugins
- Playback
  - Clicking a plugin will load it and automatically start playback
  - It can play chord progressions like `F-G-Em-Am` and MML (Music Macro Language) like `cde`
- GUI
  - Pressing the `Show UI` button displays the plugin's GUI, allowing you to edit sounds and effects
- Patches
  - Each plugin has a variety of preset patches. You can easily select them using a custom patch browser (supported by some plugins only)
  - For plugins not supported by the patch browser, you can select patches directly from the plugin's GUI
- Effects
  - Each plugin has a variety of preset effects. You can easily select them using a custom effect browser (supported by some plugins only)
  - For plugins not supported by the effect browser, you can select effects directly from the plugin's GUI

- Detection
  - For normal launch and editor integration, the complete plugin list and instrument/effect classification are first restored from `%LOCALAPPDATA%\cat-plugin-player\plugin-list-cache.json`. If the cache is missing or unreadable on the first run, it will detect and create it. After launch, if no loading or patch changes occur and operations stop for 2 seconds, it will re-detect in the background. The cache and patch list are updated only if there are changes in the list; otherwise, the display is maintained. If re-detection fails, the existing cache is retained.
  - If plugin detection is successful but no instruments are found, a prompt to install the free Surge XT via winget is displayed. It's also displayed if only effects are present. The prompt is in Japanese if Windows' display language is Japanese, otherwise in English. Even if `Later` is chosen, it will be displayed on every launch as long as no instruments are present.
  - `View Terms` opens the Surge XT terms of use (GPLv3) in a browser. Pressing `Agree to Terms and Install` executes winget and shows the stages and elapsed seconds: "1/4 Preparing", "2/4 Downloading", "3/4 Installing", "4/4 Loading". If a Windows confirmation screen (User Account Control) appears at 3/4, select "Yes". Upon success, the plugin list is automatically rescanned, Surge XT (CLAP) is loaded, and playback begins, similar to `Load`. In this case, previous instrument/effect restoration is not performed. Installation continues even if the prompt is closed, and rescanning and loading occur once finished.
  - If winget is missing or installation fails, the winget message and manual download link are displayed, and recorded in `error.log`. Only Surge XT is included, and download progress is not shown. The reasons for this choice are in [ADR 0024](docs/adr/0024-offer-surge-xt-via-winget.md).
- GUI
  - The first time the GUI is opened, it waits 2 seconds for rendering, then automatically takes a screenshot, scaling it down to a PNG with an aspect ratio maintained, sized to fit the list display frame and screen magnification. It's saved to `%LOCALAPPDPAATA%\cat-plugin-player\plugin-icons\`, and plugins with matching names + manufacturers (case-insensitive, ignoring leading/trailing spaces) share the same image for VST3/CLAP. If name/manufacturer are insufficient, they are distinguished by format + ID.
  - Previously saved format-specific images are also automatically migrated and used as shared images from the list/favorite identification information. Patch state and favorite load destinations are still distinguished by format + ID as before.
  - Plugin images are displayed in Plugins / Favorites / Routing. Within the row, they are scaled down to fit the button height while maintaining aspect ratio. Hovering over an image shows it at its saved size. Plugins with no GUI displayed show a temporary icon of the same height.
  - The GUI prioritizes placement to the immediate right of the main window, aligned with its top edge, and within the screen's work area. If it doesn't fit, it's placed in the bottom right of the work area of the screen where the main window is located. It's positioned when displayed and when the GUI is resized, but does not constantly follow the main window's movement. The GUI is not scaled down; if its width is greater than the screen, its left edge aligns with the work area; if its height is greater, its top edge aligns.
  - For blank images or failed captures, it retries at 1-second intervals for up to 20 seconds from GUI display. Saved blank images are also treated as uncaptured, and opening the GUI replaces them with a valid image. It doesn't re-capture after a successful capture.
  - If capture fails after retries, an error is displayed. Opening the GUI again retries. GUIs that don't support capture remain with a temporary icon. To retake or if a saved PNG is corrupted, delete the relevant plugin's shared PNG and any remaining old format-specific PNGs, restart the app, and open the GUI (old PNGs are kept during migration).
- Playback
  - The last played instrument, connected effects, bypass status, and playback pattern are saved to `%LOCALAPPDATA%\cat-plugin-player\status.json` and restored on the next launch. The stopped playback pattern selection and confirmed MML/chord text are also restored. If there's only one instrument candidate in the Plugins list at launch, it's automatically loaded if not already, and playback starts with the selected pattern even if it was saved in a stopped state. If there are multiple candidates, the stopped state is restored. If manually stopped after launch, it remains stopped. Unconfirmed edits are not saved.
  - CLAP Note On/Off messages are sent according to the plugin's supported input format. This includes sforzando CLAP, which only accepts MIDI. The scope of the fix and verification records are documented in [CLAP Note format description](patches/uapmd/clap-note-dialect/README.md).
  - In the top-left `Sequence` pane, you can select the playback type using left/right arrows or a dropdown. The arrows cycle at both ends of the types, and "stop" is not included as a type. Switching during playback releases all notes in the current phrase and starts from the beginning of the new phrase. When stopped, selecting a type does not start playback; use `Play` to start and `Stop` to stop. In the main window, the `Space` key also toggles start/stop (except when typing text). Playback pattern selection including MML/chords and stop state are restored on the next launch. However, if launched with only one instrument candidate, it will auto-play from a stopped state.
  - To audition MML/chord progressions, open the input screen with the `i` key or the `Chord` button in `Sequence` (hover to see shortcuts and input method). An example for single notes is `t120 c8r8d4e4r4`, and for chord progressions, `C F G C`. Both are accepted in the same input field; chord notation conversion is attempted first. Capital `C` indicates a chord, lowercase `ceg` indicates MML.
  - Confirm input with `Enter`/`Confirm` and cancel with `Esc`/`Cancel`. Cancellation or conversion errors retain the previous valid phrase. `Space` and `i` within the input screen are used for text entry, and `Space` for play/stop does not work.
  - Confirmed phrases loop playback with `Play`/`Stop`. Rests, note lengths, tempo changes, chords, and trailing rests are preserved. Opening the input screen pauses the overall normal playback. If it was playing immediately before opening, after confirmation, the new phrase plays from the beginning; after cancellation, the original playback pattern plays from the beginning. If opened while stopped, it remains stopped after confirmation/cancellation, and `Play` starts overall playback. It can also be switched to normal playback patterns. The text, selection, and playback state are saved immediately after confirmation, and the restored playback state is also saved upon cancellation. It's restored on the next launch or from instrument favorites/History. Unconfirmed text is not saved, and cancellation or conversion failures retain the previous confirmed text.
  - Moving the cursor or changing input auditions the single note/chord at that position once. This also applies to mid-edit and pasting. Moving within the same pronunciation unit or merely redrawing does not re-audition. Previous tempo, octave, and note length are reflected; it doesn't sound at rest or command positions. Normal playback stops when editing is opened, and overall playback does not start even after the audition sound ends. The audition sound is released on the next pronunciation unit, cancellation, confirmation, or instrument change. Auditioning does not alter confirmed text or normal selection.
  - For loop playback of confirmed MML, the `Velocity` field setting takes precedence over any velocity specified within the input. CC1 can also be controlled from the `CC1 modulation` field. If the capacity for playback events is reached with a very dense phrase, sounding notes are released, and playback stops. It can be restarted with `Stop` → `Play`.
  - When calling from Favorites/History in normal launch or changing patches via Browse patches/Browse effects, the stop/play state is maintained. During playback, the phrase plays from the beginning, not inheriting waits from the middle of the previous phrase. Leading rests specified in MML are preserved. While the patch browser/effect browser is displayed, `Space` for play/stop and starting MML input are suppressed in the background. Patch changes via the plugin's own GUI are not detected.
  - In SMF selection mode (`--select-smf`), the input track loops with tempo, duration, and velocity. For batch patch assignment, all tracks are auditioned with the selected patch and the representative track's effects. Normal session patches, effects, and MML are not restored, and only sound snapshots are used for favorites. It does not return to the beginning on patch/effect/favorite/connection changes, but continues from the stopped position after a short silence during the swap. The MML/normal pattern controls are not used in this mode.
  - In SMF selection mode with `--master-effects`, the current track's patch and effect are retained for auditioning, and only master effects are edited and returned. The patch browser is not used. The master is saved in the conductor-specific meta of SMF format 1, and the results of applying to all tracks are confirmed back in the editor. Master support for format 0/2 has not been added. See [ADR 0030](docs/adr/0030-master-effects-selection.md).
  - cat-smf-editor uses `--resident <name>` to keep one player resident, bringing the patch/effect browser to the foreground on each `t`/`x`. The resident player does not load selected patches/effects itself, but sends the state to the editor, which then plays with its own sound source. Esc, `q`, ×, or closing the effect browser with Enter only hide the browser; the player exits when the editor terminates. The previous patch is not restored, and the player's normal status.json is not updated. Role/Preset/Category/Kind and search strings (including Solo/Mute and exclusion conditions) are saved to the editor's status.json per song/track/patch/effect, and master effects are saved and restored independently per song. Saving occurs even if no patch is selected before closing. Patch list selection is also saved to the editor's status.json per song/track by patch name and instrument/original patch identification information, and restored after restart. Patch reapplies are not performed on selection restoration.
  - For Six Sines/TyrellN6 CLAP, when audio processing is rebuilt during load, state restoration, or connection changes, it waits for the first phrase to start while continuing normal audio processing to preserve the initial sound. At 48kHz, the wait is approximately 21ms for Six Sines and 85ms for TyrellN6. Leading MML rests are added on top of this. Application conditions and empirical verification are in [ADR 0019](docs/adr/0019-random-patch-all-catalog.md).
  - In the `Velocity` field below the playback pattern, you can choose `100`, `127`, `40-100`, `80-127` from the same left/right arrows or dropdown. The initial value is 100. Range specification increases values in Note On order within the phrase, then decreases them in the next loop, repeating the cycle. Changes are reflected from the next note without restarting the phrase and are restored on the next launch.
  - In the `CC1 modulation` field, you can choose `0`, `127`, `sweep` from the left/right arrows or dropdown. The initial value is 0. `sweep` repeats a cycle of changing from 0 to 127 in 2 seconds, then from 127 to 0 in the next 2 seconds. The selection is restored on the next launch.
  - Guitar open strings send Note On for MIDI note numbers 40, 45, 50, 55, 59, 64 (E, A, D, G, B, E) sequentially at 125ms intervals. 2 seconds after the last Note On, all 6 notes are Note Off simultaneously, repeating after 0.5 seconds.
  - Upon successful `Load`, it's memorized when selecting sequence types, starting, or stopping. The memory persists even after stopping or `Remove`. Older history/favorites are restored with the traditional 4-note pattern.
  - Upon normal launch termination and `Remove`, the binary state (patches, parameters, etc.) exposed by the plugin via UAPMD's state API is saved to `%LOCALAPPDATA%\cat-plugin-player\states\` per plugin. On the next launch or re-loading the same plugin, it's restored before playback begins.
  - `Load` for an instrument replaces only the sound source, maintaining connected effects and settings. The state of the plugin being replaced is saved, and it switches only after successful generation, restoration, and connection of the new plugin. If it fails, the original configuration is maintained, and an error is displayed.
  - The scope of state saving depends on the plugin and UAPMD's format-specific implementation. UI state is also requested, but the current UAPMD VST3 implementation only captures component state. It does not include replication of external samples or saving upon forced termination.
  - On launch, it reads the saved complete plugin list, directly loads the previous instrument and effect, restores their states, and starts playback. Afterwards, the GUI is initialized, and after operations settle, the list is re-detected in the background. If there's no complete list cache on the first run, it detects after the GUI is displayed.
  - If direct loading fails due to old history or file movement, it's restored from the scan results after the GUI display. Old history is updated once played.
  - If the main sound source is CLAP Floe, when rebuilding audio processing during load or patch restoration, it delays the start of the first phrase by 100ms. MML leading rests are added on top of this. This is a provisional measure for observing the symptom of missing initial sound, and its resolution in actual use is unconfirmed. Application conditions and review policy are in [ADR 0018](docs/adr/0018-floe-automatic-note-start-delay.md).
  - For measurement methods and results of startup time, refer to [docs/startup-timing.md](docs/startup-timing.md).

  - Additions, removals, and reordering are saved only if the new connection is successfully prepared. If it fails, the original configuration and playback are restored, and an error is displayed.

  - The patch browser catalog uses the existing `%LOCALAPPDATA%\clap-mml-render-tui\patch-catalog\catalog.json` in read-only mode. VST3 fallback and unknown instruments are excluded. Effect preset selection uses Browse effects in the Effect Routing section. Dexed retains program specification within cartridges. Floe/sforzando external samples are needed in their original locations; there is no function to duplicate/save samples.
  - In environments without cmrt and where `catalog.json` does not exist, Surge XT's patch list is obtained at each launch from [cat-music-patterns](https://github.com/cat2151/cat-music-patterns), saved to `%LOCALAPPDATA%\cat-plugin-player\patch-catalog\surge-xt.json`, and used as candidates for Browse patches. If it cannot be obtained, it uses the previously saved list; if that is also unavailable, the patch browser displays a loading failure. It shows "loading" until acquisition is complete (up to 10 seconds). The list is made from Surge XT 1.3.4; Surge XT versions with different patches will not show added patches, and selecting a non-existent patch will display a preparation failure. It does not switch if `catalog.json` exists but cannot be read. Reasons are in [ADR 0025](docs/adr/0025-surge-xt-patch-catalog-without-cmrt.md).
  - If preparation/application fails, the reason is displayed. The original configuration, state, and playback state are restored, and instances where state restoration also fails are prevented from saving. Save failures after patch application are displayed as "applied". Instrument-specific preparation/application conditions and verification scope are recorded in [ADR 0019](docs/adr/0019-random-patch-all-catalog.md).
  - `★ Add favorite` for each plugin allows saving multiple instances of the current patch/settings as favorites. On the main screen and in Browse patches, the `F` key saves the currently loaded instrument; in Browse effects, it saves the effect connected to the target slot (unapplied candidates are not saved). It does not work while typing text or displaying dialogs, nor can it save during loading/preparation. For instruments, it also saves the playback pattern, stopped selection, and confirmed MML/chord text. For effects, it does not save playback settings. The name for new items prioritizes the stem (patch/preset name excluding path and corresponding preset file extension) from the recorded patch/preset name, formatted as `stem serial_number`. Effect plugin name prefixes are also removed. Dots and program numbers in patch names are retained (e.g., `.../TX7-34.SYX/22 <Flute.22>` → `22 <Flute.22> 1`). The full name is retained for search/hover display. If the name is not obtained or blank, it becomes `Plugin Name serial_number`. It can be changed later. Existing items are not renamed, and re-saving the same state retains the existing name.
  - Loading a different plugin automatically records the replacing plugin's patch, settings, and playback pattern to History before switching. The name for new items follows the same rules as favorites, prioritizing the patch/preset name. It does not add entries for reloading the same plugin or restoring on launch. Confirmed MML/chord text and stopped selection for instruments are also recorded, within the same scope as favorites. For effects, playback settings are not recorded. If saving fails, the switch is canceled.
  - During manual/automatic saving, it checks for duplicates of the same plugin, role, playback pattern, confirmed MML text, and state, reusing saved items and names. For automatic History recording, differences only in stop state are treated as identical, but MML with different text is kept as separate items. Effects do not compare playback settings.
  - [Plugin-specific processing policies/list (ADR 0002)](docs/adr/0002-plugin-specific-favorite-state-comparison.md) provides exceptions, reasons, scope, and limitations for each product. For confirmed TyrellN6 CLAP state format, compressed parts that change only with playback are excluded from duplicate determination, and patches with the same text patch settings are grouped. Confirmed PCore `UI_op=9/10` and empty lines at the end of text are also excluded from comparison ([ADR 0011](docs/adr/0011-tyrell-n6-ui-operation-favorite-comparison.md)). For confirmed Vaporizer2 CLAP format, minute differences in MSEG time/coordinates (absolute difference of specified items: time ≤ `0.00011` ms, normalized coordinates ≤ `0.000001`. See [ADR 0010](docs/adr/0010-vaporizer2-mseg-recalculation-drift.md)) resulting from load/save are treated as identical. Edits within this margin are indistinguishable. Saved data is retained as is.
  - Switch lists with the central `Favorites` / `History` / `Plugins` tabs. Favorites maintain manual order, with new additions placed at the top. Calling, re-saving, or recording to History does not change the order. It can be filtered by favorite name, plugin name, format, and the saved patch/effect preset name (case-insensitive partial match). Names successfully applied by Browse patches/Browse effects are recorded separately and displayed in Favorites/History supplementary information. This persists across restarts and favorite calls. Name changes/preset changes within the plugin GUI are not tracked; the last name applied via the browser is retained. Existing items without names can be searched with traditional information; reapplying the same patch from the browser and re-saving completes the name. The `/` key on the main screen moves focus to the filter field (common to all tabs; does not work while typing text, MML input screen, browser, or dialogs are displayed).
  - In the Favorites hamburger menu, turning `Reorder favorites` ON enables sorting with `↑` / `↓` at the end of the row, saving immediately. Loading by clicking a row and removing effects remain as before. `Sort by plugin name` sorts once by plugin name in ascending order and saves (case-insensitive, preserving relative order for items with same name). Manual adjustments are still possible afterward. Sorting is disabled during filtering, and sorting mode is OFF at launch. Refer to [ADR 0017](docs/adr/0017-manual-favorites-order.md) for background and specifications.
  - History is in order of most recent registration. If the same patch is detected, the saved patch is reused, its registration time is updated, and it is moved to the top. Elapsed time is displayed in units of `1s`, `1m`, `1h`, `1d`, `1w`, `1mon`, `1y` (month is 30 days, year is 365 days). Manual Favorites are maintained. All old format items are migrated to History, and all items not starting with `auto ` are also retained in Favorites (because old formats do not record the origin of auto-saves, thus including all renamed auto-saves in History). Refer to [ADR 0016](docs/adr/0016-history-instead-of-automatic-favorites.md) for policy and reasons.

  - `Show only CLAP for duplicate plugins` in the global settings `☰` is ON by default. If CLAP plugins with the same name, manufacturer, and type exist, VST3 plugins in the Plugins list are hidden (ignoring leading/trailing spaces and case differences in name/manufacturer; if name or manufacturer is empty, both are shown). Turning it OFF displays both formats. The setting is saved to `[plugins] prefer_clap` in `config.toml` and persists on the next launch. It does not change Favorites or the format loaded/restored.
  - On both tabs, clicking a name/image loads it, and clicking again can disconnect connected effects. The currently loaded/connected row is highlighted, and the color is maintained even when an effect is bypassed. The `Load` / `Add` / `Remove` buttons in Plugins perform the same operations.
  - Favorites are displayed one item per line. Long names/supplementary info are truncated; hover to see full text. Waveform/spectrum are displayed below Routing on the right; the right-side width can be adjusted by dragging the boundary. `Audio analysis`'s `On right` toggles analysis display between bottom-right / bottom of screen (default bottom-right on launch).
  - For confirmed sforzando CLAP state format, it does not add duplicate patches based only on save counter and playback values of notes/CC1, but reuses existing favorites. Differences in patch settings are preserved. The scope and limitations are in [ADR 0006](docs/adr/0006-sforzando-favorite-state-comparison.md).

In normal launch, confirmed text and playback pattern selection saved from instrument favorites are restored. In SMF selection mode, only the patch state is used, retaining the input SMF. If stopped, it remains stopped; `Play` plays the restored phrase. If playing, it switches to the saved pattern/MML. Old format favorites without text retain the current text, and old format stopped items retain the current selection. Instrument favorites retain connected effects, and effect favorites retain the instrument and MML. An instrument is required to call an effect.

- Lissajous Display
  - `Lissajous` is displayed below the oscilloscope in the right analysis panel. If `☰` → `On right` is unchecked for the oscilloscope, spectrum, oscilloscope, and Lissajous appear side-by-side at the bottom of the screen.
  - It draws the output of the most recent 50ms, reflecting effects and Bypass (up to 4096 samples), on a Lissajous figure rotated 45°. A common automatic magnification maintains volume differences and the aspect ratio of the figure; in-phase at the same level results in a vertical line, out-of-phase in a horizontal line, and sine waves with phase differences result in ellipses or circles. Output only on the left is a diagonal from top-left to bottom-right, only on the right is a diagonal from top-right to bottom-left, mono is a vertical line, and silence is a central dot.
  - It updates independently of note, cycle count, or trigger settings, and `Show analysis labels` can display headings. Axes and drawing methods can also be checked in the graph tooltips.
  - `Correlation` directly below Lissajous displays the left/right correlation over the most recent 150ms as a bar and numerical value from -1 to +1. +1 is in-phase, near 0 indicates weak correlation, and -1 indicates out-of-phase. Negative values are displayed in red, serving as a guide for cancellation when mixed to mono. It shows "—" if silent or one side is silent.
- Waveform Display
  - `Oscilloscope` at the bottom of the screen displays the L (green) and R (blue) outputs, reflecting effects and Bypass, superimposed. Mono displays the same waveform for both.
  - The display width is determined from the last Note On MIDI note number (A4 = 440Hz), and you can choose `1`, `2`, `4`, `8 cycles`. After Note Off, it displays the decay based on the last note. Output containing chords or detuning may not repeat perfectly at that width.
  - `Zero cross` aligns to the negative → positive crossing of the left channel. If the left channel is silent, it uses the right channel; if no crossing, it displays from the beginning.
  - `Similarity` exhaustively scans from the beginning of the buffer by 1 sample increment for the display width, finding the position with maximum correlation to the previous display. Ties prefer the earlier position, and the same starting position is used for left and right. Zero cross is used for the first display or if the comparison target is silent.
  - Comparison history is reset when a note sounds, playback pattern changes, display cycle count changes, trigger method changes, or the audio stream changes. It shows "waiting" until sufficient data is collected.
  - Exploration is performed on a separate thread from audio processing. Display updates may be slow for low notes or many cycles. If display data is interrupted, the history is reset.
  - Default display settings on launch are 4 cycles and zero cross. Display settings are not saved.

## Settings: Window Position/Size

You can specify the launch position/size of the main window and the placement method for plugin GUIs in `%LOCALAPPDATA%\cat-plugin-player\config.toml`. Please edit it after closing the app. Session and favorite selection states are saved in `status.json` in the same directory, and normal saves do not overwrite the TOML. If states are mixed in the old TOML, they are migrated on the first launch; the original file is saved as `config.toml.before-status-migration.bak`, then only state items are removed. Settings comments, format, and unknown items are retained, and independent comments attached to deleted items are moved to the end. If an existing `status.json` is present, it takes precedence.

```toml
[window.main]
x = 100.0
y = 100.0
width = 1200.0
height = 800.0

[window.plugin]
placement = "right_then_bottom_right"
```

The `x` and `y` for the main window are logical coordinates and are used as the launch position if both are specified. If omitted, it uses the traditional initial position. `width` and `height` are the inner width and height of the main window (logical coordinates). Either can be specified; if omitted or set to 0 or less, or a non-finite value, it reverts to width 900, height 600. Changes are reflected on the next launch. The plugin placement method is currently only `right_then_bottom_right`, and omitting it results in the same behavior. GUI size and placement are calculated based on the actual window frame, screen work area, and DPI. Automatic saving of positions moved manually, or per-plugin position specification, is not performed.

## Local Build and Run

Clone this app, `uapmd`, `clap-mml-render-tui`, and `clap-mml-play-server` into the same parent directory, then run from this app's directory. TUI's `app` / `patches` / `patch-select` / `tui-core` and play-server's `core-lib` / `server-config` are always referenced locally from Cargo.toml. play-server requires `prepare_catalog_clap_patch_state` / `supports_catalog_clap_plugin` in addition to traditional `prepare_clap_patch_state` / `PatchStateError`, and TUI's `cmrt-patches` requires their re-export. The patch browser uses public Role/Preset/filter APIs and tui-core's sample capacity determination. Browse effects uses play-server's `AudioEffectCatalog` / `EffectRenderer`, TUI's effect selector conditions, and tui-core's search conditions. Insufficient checkout or API will result in a build error; no automatic switch to Git versions will occur.

```powershell
cargo build --release
& ./target/release/cat-plugin-player.exe
```

If UAPMD is not in the sibling `uapmd` directory, first set `$env:UAPMD_DIR = 'X:\projects\uapmd'`. The location of UAPMD at build time is specified by an environment variable. `config.toml` is not read as a build setting.

`cargo install` is not used; the exe generated in the default `target/release` is run directly. The build uses local code (including uncommitted changes) and existing `target/shim`, but source changes may require reconstruction/rebuild. If `target/shim` was created with a different version (e.g., VS 2022), it will continue to build with that version, so delete `target/shim` before building ([ADR 0020](docs/adr/0020-visual-studio-2026-toolchain.md)). The shim DLL is bundled with the exe, expanded to the cache directory, and loaded when the GUI starts.

For the 3-repo dependency configuration and operational policy, refer to [ADR 0012](docs/adr/0012-local-dependencies-and-release-execution.md). Local TUI switching is not needed for building cat. For cross-repo builds within TUI itself, use TUI's existing `python scripts/cross_repo_local.py on` procedure; `off` is handled manually. Local references use uncommitted changes, and Cargo.lock does not fix the content of each checkout. When verifying, record the HEAD and diff of each repo.

Host Rust/native and SMF processing are aggregated in `shared/`, and cat-smf-editor also references the same authoritative source as a module. No independent crates are added; each app bundles its own DLL from its default target/shim.

Running without arguments launches the normal GUI. `--help` and `--version` are also available.

SMF selection mode is `--select-smf <SMF> --browser patch|effect --preserve-position`. If browser is omitted, it defaults to patch; position preservation requires explicit specification. Passing `--patch-filter <program name>` searches the patch browser with that name from ALL conditions. Regular expression symbols in the name are treated as literal characters, and spaces are AND. Only if 0 items after catalog load will it switch once to an OR search with words joined by `|` (e.g., `church organ` → `church|organ`). `--patch-filter-file <JSON>` restores search/Role/Preset as is and returns to the same file on successful exit. If the file doesn't exist, it uses initial search; existing file conditions take precedence. Empty searches are also preserved, and automatic switching to word OR is not performed for restore conditions. Not used for effect/master selection. The search field can be edited as a case-insensitive regular expression as usual. `--preview-smf <SMF>` allows specifying a separate SMF for auditioning all tracks, sending all track MIDI events to the selected instrument/effect, and reflecting per-track tempo for format 2. The preview SMF is not modified. `--start-seconds <seconds>` specifies the initial audition position, and `--loop-end-seconds <seconds>` specifies the loop end beyond the input SMF. If omitted, it's from the beginning to the end of the input SMF. Use finite, non-negative seconds, and the start position must be before the loop end. Controllers and sustained notes at the start position are restored, and natural loop boundaries revert to the beginning. The original SMF events are not modified. Adding `--browser-only` does not display the main screen, opening the browser to the foreground. This option is for selection mode only. In normal track selection, you can proceed to another browser via buttons within the browser. `--master-effects` starts with the effect browser and does not proceed to the patch browser. The main screen can be displayed from `Favorites / routing` only when favorites/routing are needed. Closing the browser with Enter is also treated as saving and terminating the entire player. On save failure or during change processing, the browser is retained, and errors are displayed within the browser. Esc, 'q' (not used for search input), and the close button (×) of the main window/browser save the instrument, ordered effects, and bypass state to the input SMF and exit. For `--master-effects`, only the conductor's master effect/bypass is saved, retaining track settings. 'q' in the search field is for text input. During change processing, it waits for confirmation; on save failure, it retains the screen and selection, allowing retries. The normal status.json is not updated. Existing state saving/favorite operations for selected items use the usual save destination. State compatibility across OS/plugin versions or external sample duplication is not guaranteed. Refer to [ADR 0029](docs/adr/0029-shared-host-smf-selection.md).

# Concept, What We Aim For
- Instrument
  - For example, a synthesizer with a MIDI keyboard makes sound when you turn it on and press keys.
    - We aim for that level of ease of use.
      - Minimize operations to produce sound.
- Playability
  - We aim to maintain "it works in the author's environment" as much as possible.
- Instant Playback
  - Perceptual 0.2 seconds from app launch to sound. Playback is made as fast as possible.

- Educational Use
  - It leans more towards educational use than commercial.
- Experimentation, Exploration, Personal Use
  - Frequent breaking changes will occur.
