# cat-plugin-player

A lightweight app to easily play audio plugins, utilizing [UAPMD](https://github.com/atsushieno/uapmd). Written in Rust.

# Challenges Addressed by This App
- Audio plugin timbres are amazing!
- To play them, you often need to launch a DAW and perform preparatory steps.
- Lightweight apps for casual playing sometimes require account registration for acquisition, or their operation felt "not for me."
- Nowadays, if you have a desired UX, you can achieve it through vibe coding.
- So I decided to do just that.

# Features
- Detection
  - Upon startup, automatically detects installed plugins.
- Playback
  - Pressing the `Load` button automatically starts playback after the plugin is loaded.
- GUI
  - Pressing the `Show UI` button displays the plugin's GUI.
- Patch Selection
  - To change patches, use the plugin's GUI.

- Detection
  - If plugin detection succeeds but no instrument is found, a prompt to install the free Surge XT via winget is displayed. This also appears if only effects are present. If Windows' display language is Japanese, the prompt is in Japanese; otherwise, it's in English. Even if `Later` is chosen, the prompt will reappear every time the app starts as long as no instrument is available.
  - Clicking `View Terms of Use` opens Surge XT's terms (GPLv3) in a browser. Pressing `Agree to Terms and Install` executes winget and displays the installation stages: "1/4 Preparing", "2/4 Downloading", "3/4 Installing", "4/4 Loading", along with elapsed seconds. If a Windows confirmation screen (User Account Control) appears during "3/4", select "Yes". Upon success, the plugin list is automatically rescanned, Surge XT (CLAP) is loaded, and playback begins, similar to pressing `Load`. Previous instrument/effect states are not restored at this time. Even if the prompt is closed, installation continues, followed by rescanning and loading upon completion.
  - If winget is not present or installation fails, winget's message and manual download links are displayed and logged to `error.log`. Only Surge XT is included, and download progress is not shown. The reason for this choice is documented in [ADR 0024](docs/adr/0024-offer-surge-xt-via-winget.md).
- GUI
  - When the GUI is opened for the first time, it waits 2 seconds for rendering, then automatically takes a screenshot, which is scaled down to a PNG size that fits the list display frame and screen zoom level while maintaining aspect ratio. It is saved to `%LOCALAPPDATA%\cat-plugin-player\plugin-icons\`. Plugins with matching name + manufacturer will share the same image for both VST3 / CLAP (ignoring leading/trailing spaces and case). If name/manufacturer are missing, plugins are distinguished by format + ID.
  - Previously saved format-specific images are also automatically migrated and used as shared images based on list/favorite identification information. Patch states and favorite load destinations continue to be distinguished by format + ID as before.
  - Plugin images are displayed in Plugins / Favorites / Routing. Within a row, they are scaled down to fit the button height while maintaining aspect ratio. Hovering over an image displays it at its saved size. Plugins without a GUI displayed show a temporary icon of the same height.
  - The GUI prioritizes placement to the right of the main window, aligned with its top edge, within the screen's working area. If it doesn't fit, it's placed in the bottom-right of the screen's working area where the main window resides. This placement occurs when displayed and when the GUI is resized; it does not constantly follow the main window's movement. The GUI is not scaled down; if its width is greater than the screen, its left edge aligns with the working area; if its height is greater, its top edge aligns.
  - In case of blank images or capture failure, retries occur every 1 second, for up to 20 seconds from GUI display. Saved blank images are also treated as not captured and are replaced with a valid image when the GUI is opened. No further captures are performed after a success.
  - If capture still fails after retries, an error is displayed. Reopening the GUI retries the capture. GUIs that do not support capture remain with a temporary icon. If you wish to retake a screenshot or if a saved PNG is corrupted, delete the shared PNG for the relevant plugin and any remaining old format-specific PNGs, then restart the app and open the GUI (old PNGs are retained during migration).
- Playback
  - The last played instrument, connected effect, Bypass status, and playback pattern are saved to `%LOCALAPPDATA%\cat-plugin-player\status.json` and restored on the next launch. Stop status, selected playback pattern while stopped, and confirmed MML/chord text are also restored. Unconfirmed edits are not saved.
  - CLAP Note On/Off messages are sent according to the plugin's supported input format. This includes sforzando CLAP, which only accepts MIDI. The scope of the fix and verification records are documented in [CLAP Note Format Description](patches/uapmd/clap-note-dialect/README.md).
  - In the top-left `Sequence` pane, you can select the playback type using left/right arrows or the dropdown. The arrows cycle through the ends of the types; stop is not included in the types. Switching during playback releases all notes of the current phrase and starts from the beginning of the new phrase. When stopped, selecting a type does not start playback; use `Play` to start and `Stop` to stop. In the main window, the `Space` key also toggles start/stop (except when typing). The selected playback pattern, including MML/chords, and the stop state are restored on the next launch.
  - To audition MML/chord progressions, open the input screen with the `i` key or the `Chord` button in `Sequence` (hover to see shortcuts and input methods). An example of a single note is `t120 c8r8d4e4r4`; an example of a chord progression is `C F G C`. Both are accepted in the same input field, with chord notation conversion attempted first. Uppercase `C` becomes a chord, lowercase `ceg` becomes MML.
  - Input is confirmed with `Enter` / `Confirm` and cancelled with `Esc` / `Cancel`. Cancellation or conversion errors retain the previous valid phrase. `Space` and `i` within the input screen are used for text input; `Space` for playback/stop does not function.
  - Confirmed phrases loop with `Play` / `Stop`. Rests, note lengths, tempo changes, chords, and trailing rests are preserved. Opening the input screen pauses general playback. If playback was active just before opening, confirming uses the new phrase, while cancelling resumes the original pattern from the beginning. If opened while stopped, it remains stopped after confirming/cancelling, and `Play` starts general playback. You can also switch to regular playback patterns. Immediately after confirmation, the text and selected playback state are saved; upon cancellation, the reverted playback state is saved. These are restored on next launch or from instrument favorites/History. Unconfirmed text is not saved; cancellation or conversion failure preserves the last confirmed text.
  - Changing input or moving the cursor will audition the single note/chord at that position once. This applies to mid-edit changes and pastes. Moving within the same phonological unit or simply redrawing does not retrigger the sound. Previous tempo, octave, and note length are reflected; no sound is produced at rests or command positions. General playback stops when editing is opened, and does not resume after the audition sound finishes. The audition sound is released on the next phonological unit, cancellation, confirmation, or instrument change. Auditioning does not alter the confirmed text or regular selection.
  - For confirmed MML loop playback, the `Velocity` field's setting takes precedence over any velocity specified within the input. CC1 can also be controlled from the `CC1 modulation` field. If the performance event capacity is reached due to a very dense phrase, active notes are released and playback stops. You can restart by `Stop` → `Play`.
  - When changing patches via Favorites/History, Browse patches/Random patch/Random effect/Browse effects, the stop/playback state is maintained. During playback, the phrase restarts from the beginning, and waits in the middle of the previous phrase are not carried over. MML-specified leading rests are preserved. While the patch browser/effect browser is open, `Space` key for playback/stop and MML input initiation in the background are suppressed. Patch changes made via the plugin's native GUI are not detected.
  - For Six Sines/TyrellN6 CLAP, when audio processing is reconstructed due to loading, state restoration, or connection changes, it waits for the first phrase to start while continuing normal audio processing to preserve the initial sound. At 48kHz, the wait is about 21ms for Six Sines and about 85ms for TyrellN6. Any leading rests in MML are added to this. Refer to [ADR 0019](docs/adr/0019-random-patch-all-catalog.md) for application conditions and actual device verification.
  - In the `Velocity` field below the playback pattern, you can choose `100`, `127`, `40-100`, `80-127` using the same left/right arrows or dropdown. The initial value is 100. Range specification increases the value in the order of Note On events within the phrase and then decreases it in the next loop. Changes are applied from the next note without restarting the phrase and are restored on the next launch.
  - In the `CC1 modulation` field, you can choose `0`, `127`, `sweep` using left/right arrows or dropdown. The initial value is 0. `sweep` repeats a cycle of changing from 0 to 127 in 2 seconds, then from 127 to 0 in the next 2 seconds. The selection is restored on the next launch.
  - Guitar open strings send Note On for MIDI note numbers 40, 45, 50, 55, 59, 64 (E, A, D, G, B, E) sequentially at 125ms intervals. 2 seconds after the last Note On, all 6 notes are simultaneously Note Off, and the sequence repeats after 0.5 seconds.
  - Upon successful `Load`, selection of `Sequence` type, start, and stop are remembered. This memory persists after stopping or `Remove`. Older history/favorites are restored with the traditional 4-note pattern.
  - Upon exit and `Remove`, the plugin's binary state (patch, parameters, etc.) exposed by UAPMD's state API is saved to `%LOCALAPPDATA%\cat-plugin-player\states\` for each plugin. This state is restored before playback starts on the next launch or when the same plugin is reloaded.
  - Loading an instrument (`Load`) replaces only the sound source, maintaining connected effects and their settings. The state of the plugin being replaced is saved, and the switch occurs only after successful creation, restoration, and connection of the new plugin. If it fails, the original configuration is maintained, and an error is displayed.
  - The scope of state saving depends on the plugin and UAPMD's format-specific implementation. UI state is also requested, but the current UAPMD VST3 implementation only retrieves component state. This does not include duplication of external samples or saving during abnormal termination.
  - On startup, the previous instrument and effect are directly loaded, their states restored, and then playback begins. Afterward, the GUI is initialized, and the plugin list is scanned in the background.
  - If direct loading is not possible due to old history or file movement, restoration occurs from the scan results after the GUI is displayed. Old history entries are updated once played.
  - If the main sound source is CLAP Floe, when audio processing is reconstructed (e.g., during load or patch restoration), the start of the first phrase is delayed by 100ms. Any leading rests in MML are added to this. This is a provisional measure for observing initial sound dropout symptoms, and its resolution on actual devices is unconfirmed. Refer to [ADR 0018](docs/adr/0018-floe-automatic-note-start-delay.md) for application conditions and revision policy.
  - Refer to [docs/startup-timing.md](docs/startup-timing.md) for startup time measurement methods and results.
- Effect Routing
  - This is a serial connection: one instrument → multiple effects → output. After loading an instrument, press `Load` for the first effect, then `Add` to append subsequent effects to the end. Connected effects can be removed one by one using `Remove`. Duplicate connections of effects with the same format + ID are not allowed.
  - The `Random effect` next to `Sequence` draws an installed CLAP effect preset from the same catalog and selection pool as cmrt's effect selector. If there are 0 effects, it adds the first one; if 1, it replaces that effect; if multiple, it replaces one of the connected effects, chosen evenly. Rapid clicks do not increase the number of effects and preserve the order, settings, and Bypass state of other effects. To prevent duplicate connections, any format + ID already connected (excluding the one being replaced) is excluded from candidates. If no suitable candidates are available for the target slot, a reason is displayed, and no change is made.
  - Random effect requires an instrument. Candidates are retrieved from default effect/preset locations scanned by the play-server shared core; VST3 alternatives are not used. During preparation, current playback continues, and load, scan, and patch operations are disabled. If stopped, it remains stopped; if playing, the current phrase restarts from the beginning, maintaining global MML, Velocity, and CC1 selections. In case of generation, application, or connection failure, it reverts to the original configuration, and no automatic re-selection of other candidates occurs. After success, the applied state and connection are saved for the next launch, and no Favorites/History entries are added. Save failures are displayed as "Applied".
  - Below `Random effect`, `Browse effects` or the `E` / `X` keys open an independent, maximized effect browser window where you can select presets from a list. It cannot be opened while MML is being edited. Filter by Category → Kind on the left and by search. Classification and selection targets are the same as cmrt's effect selector. Search uses case-insensitive regular expressions, space-separated AND logic, and `-condition` for exclusion, applying to preset name, Category, Kind, or effect name (e.g., `hall -plate`, `dragonfly`). Invalid regular expressions during input display an error and retain the previous list. The top row displays Search, Target Slot, and `Random`. `/` within the browser moves input to the search field, and `R` randomly selects from filtered results. Multi-column list display, movement with arrow keys / `h` / `j` / `k` / `l` and number-based repetitions, `PageUp` / `PageDown` for scrolling, and `Enter` / `Esc` for closing are the same as Browse patches. In results with mixed effects, effect names are given per effect, and preset names are color-coded per Kind if Kinds differ.
  - The target slot is chosen from `Add new effect` or `Replace n` of a connected effect. When opened, it defaults to the slot last written by this browser, otherwise the last effect, or `Add new effect` if no effects exist. Applying `Add new effect` makes the newly added effect the target, and subsequent selections replace that slot, so the number of effects does not increase by continuous selection. If the target slot is removed, the last effect becomes the target. Presets for effects connected to non-target slots are greyed out; selecting them displays a reason and prevents changes. Presets placed into the target slot by this browser are marked with `▶` and become selected when opened (not reapplied).
  - Clicking, key navigation, or filtering to select a different candidate immediately requests application. Simply opening the browser does not change the effect. You can select the next candidate even during preparation; uninitiated selections are replaced by the latest one, and closing cancels them. An instrument is required, and playback continuity during preparation, rollback on failure, and saving for the next launch are the same as Random effect. Category, Kind, search string, list selection position, and target slot are saved upon exit and restored on the next launch. Key navigation starts from the restored selection. Category and Kind are restored by name; if they no longer exist, they revert to `ALL` in their respective fields. Selection is restored by preset; if it's no longer in the catalog, it becomes unselected, and key navigation starts from the beginning. The target slot is restored by its position in the chain; if no effect exists at that position, it defaults to the slot used when opened.
  - The `Routing` tab displays the connection order. Effects can be reordered by dragging their `↕` buttons up or down. During drag, the moving effect's name and an insertion line are shown. Instruments are not sortable. You can edit patches or effects for each plugin via `Show UI`. `Instrument` / `Effect` are displayed in the same type color as the left-side list.
  - Removing all effects reverts to a direct connection from instrument to output. `Bypass effect` targets the entire chain, allowing it to pass through transparently while retaining instances and settings. It can also be toggled with the `b` key (does not work in MML input screen, Browse patches/Browse effects display, or while typing). While bypassed, connected effects in Routing are greyed out and labeled `Bypassed`.
  - `Sequence` is for instruments. Even if `Sequence` is stopped, audio processing continues, allowing effect tails to decay.
  - On the next launch, the instrument, the order of all effects, their respective states, and Bypass status are restored before playback begins. History for a single effect from older formats can also be loaded. If effect restoration fails, an error is displayed, the instrument reverts to a direct connection, and the saved configuration is retained.
  - Addition, removal, and reordering are saved only upon successful preparation of the new connection. If it fails, the original configuration and playback are restored, and an error is displayed.
  - Supports mono/stereo for main input/output. Mono to stereo is duplication; stereo to mono is the average of left and right. Auxiliary inputs are silent.
  - Changes to connections or Bypass may cause a brief audio glitch, and active notes and decay tails might be interrupted. Sidechain, parallel connections, and host-side Dry/Wet are not supported.
- Patch Selection
  - Near `Random patch`, `Browse patches` or the `T` key opens an independent, maximized patch browser window on the same screen as the main app. The main app's position and size are not altered. It cannot be opened while MML is being edited. Filter by Role → Preset → Search using framed sections. The left condition area and right Patches list are individually scrollable. The list uses the remaining width and height, allowing operation even when unmaximized or in a narrow window. The top row contains Search, `Solo/Mute`, `Random`, and `☰`. The search field uses the remaining width; the `/` key within the browser moves input to the search field. Detailed instrument conditions can be checked by hovering over `Solo/Mute`. Clicking this button or pressing `M` within the browser opens a vertical Solo/Mute overlay, which is confirmed collectively with `OK` or `Enter`. Solo/Mute appears directly to the right of the instrument name. Clicking the currently selected mode again reverts to normal; `Esc` / clicking outside the overlay discards changes. Multiple Solo selections are treated as OR; Mute selections are exclusions. Search uses case-insensitive regular expressions, space-separated AND logic, `-condition` for exclusion, and `plugin:` condition (e.g., `pad -bright`, `plugin:floe`, `plugin:surgext -bass`). Aliases of integrated patches can also be searched. Invalid regular expressions result in an error, stopping application, random selection, and condition saving. If 0 results, review conditions by editing the search field or changing Role/Preset. Catalog loading wait/failure is displayed separately from 0 results. Role, Preset, and search string are saved upon exit and restored on the next launch. Presets are restored by name; if a condition is deleted, it reverts to `ALL` for that Role.
  - The list displays single-line patch name cells without wrapping, arranged in multiple columns (left-to-right, then next row) according to width. In narrow windows, it reverts to a single column. Resizing maintains the selected patch; changing only the number of columns does not trigger a reload. Clicking a patch does not move the list's display position. Arrow keys or `h` / `j` / `k` / `l` move according to the visual layout. Left/right move to the previous/next patch (to the end of an adjacent row at row edges); up/down move to the corresponding row. For short final rows without a patch directly below, it moves to the end of that row. Entering a number first, like `2j` or `10k` (Vim-style), moves that many times (stops at ends; numbers are cleared by non-movement keys). `PageUp` / `PageDown` move by 10 rows; combined with a number, they move by that multiple. Key movement, Random, filtering, and column count changes scroll the selected row into view only if it's off-screen. If all patches fit, no scrolling occurs. For single-instrument results, the instrument name is omitted; it's retained when mixed. Text color indicates only one difference within the results. If instruments are mixed, the instrument name portion is color-coded per instrument. For a single instrument, if Preset is `ALL`, patch names are color-coded per relevant Preset; if not distinguishable that way, then per category. Colors are Monokai-based. If all are the same, normal text color is used. Colors cycle through 5 hues, so distant, separate groups might share the same color. Patch names for "pink" patches prioritize "pink". Classification folders, etc., are omitted; if distinguishing similarly named patches, necessary paths are retained. Dexed program specification is maintained. Hovering over a patch displays its full display path, source path, active category, and number of merged entries (if 2 or more). Load/Size are not permanently displayed in the list, nor are `no category` / `1 merged`. For regular patches, changing selection via mouse or key movement immediately requests application; the same behavior applies when a different candidate is chosen by condition change. Simply opening the browser does not change the patch. When opened, if the currently playing patch (applied via Browse patches/Random patch) is in the current results, that patch is selected and scrolled into view (not reapplied). The playing patch is saved upon exit and carried over as the restored patch on the next launch. Effect addition/deletion/Random effect preserves this continuity. If the playing patch is not in the results or unknown, the selection from the last closure is maintained (it's unselected when opened for the first time after launch). After changing patches via Favorites/History, instrument loading, or deletion, the playing patch becomes unknown, and selection is cleared. Key movement starts from the selected patch when opened; if unselected, it moves to the beginning. The next selection can be made even during preparation; uninitiated requests are replaced by the latest one. Upon successful regular application, duplicate patch names or fixed padding at the bottom are not displayed. A brief notice is displayed only if the selected and applied patches differ, indicating that the previous patch might continue playing for unconfirmed "pink" patches. "Pink" Space prompt and application/save errors are displayed.
  - Pink patches with sample capacities of 64,000,000 bytes or more are not applied automatically (unknown capacities are treated as normal). After selection, `Space` opens a confirmation overlay for instrument, patch, and capacity; pressing `Enter` within it initiates preparation and application. `Esc` during confirmation cancels without changing. Even once applied, patches require re-confirmation. A progress overlay is shown during loading, and cancellation is not possible mid-way. `Space` / `Enter` in the search field, save menu, or Solo/Mute overlay are not used for patch application (`Enter` in Solo/Mute overlay is equivalent to `OK`).
  - The `Random` button or `R` key within the browser selects evenly from the displayed results. During text input, shortcuts like `T` / `R` / `M` / `/` / `h` / `j` / `k` / `l` / numbers / `Enter` do not work; `R` / `M` also do not work while a browser overlay or save menu is displayed. For "pink" patches, selection alone is sufficient, but the same Space→Enter confirmation is required. The outer Random patch continues to draw evenly from all available patches as before. `Esc`, `Enter`, or OS close of the browser window closes only the browser, preserving the main app and the last successfully applied patch, while discarding uninitiated requests and old preparation results. Processes that have already started application are allowed to complete. When confirmation overlay, Solo/Mute, or save menu is open, `Esc` / clicking outside the overlay closes only the child, and does not pass the same input to the browser or background operations. OS close closes the entire browser. It can be reopened, and there is no undo operation to revert to the original patch.

They are handled by common selector normalization and classification rules and saved to `patch-filter-presets.json` in cat's config directory. If loading is corrupted, the original file is protected, writing is stopped, and save failures are displayed on screen. Role / Preset / Search / Solo/Mute are retained during the same app session; only saved user-defined conditions are restored after restart. TUI conditions and Favorites are not shared or migrated.

It maintains global MML, Velocity, CC1 selections, effect order, state, and Bypass. Upon success, the state is saved for the next launch. Favorites/History are not automatically added. Application success and save failure are displayed distinctly. Preparation and application progress are updated even when child windows are in focus.
  - The `Random patch` in `Sequence` draws evenly from all CLAP patches for Surge XT, Dexed, Floe, sforzando, Six Sines, TyrellN6, and Vaporizer2 found in the existing cmrt catalog, matching installed instruments by format + ID. It's not an even draw per instrument; Dexed, having more candidates, will be selected more frequently. The tooltip displays the target instruments and total number of candidates. The button is not displayed if there are no suitable candidates.
  - Random patch uses the existing `%LOCALAPPDATA%\clap-mml-render-tui\patch-catalog\catalog.json` in read-only mode. VST3 alternatives, effect patch selection, and unknown instruments are not targeted by Random patch. Effect preset selection uses Random effect/Browse effects in the effect routing section. Dexed retains program specification within cartridges. Floe/sforzando external samples are required at their original locations; there is no function to duplicate or save samples.
  - During Random patch preparation, current playback continues, and conflicting load, scan, and patch operations are disabled. There may be a wait for sample loading for Floe, etc. If stopped, it remains stopped after application; if playing, the current phrase restarts from the beginning. Global MML, Velocity, CC1 selections, effect order, state, and Bypass are maintained. Upon success, the applied state is saved for the next launch, and Random patch itself does not add to Favorites/History.
  - If preparation/application fails, the reason is displayed, and no other patch is automatically drawn. The original configuration, state, and playback state are restored, and instances where state restoration also failed will suppress saving. Save failures after patch application are displayed as "Applied". Instrument-specific preparation/reflection conditions and verification scope are documented in [ADR 0019](docs/adr/0019-random-patch-all-catalog.md).
  - With `★ Add favorite` for each plugin, multiple snapshots of the current patch and settings can be saved as favorites. For instruments, playback patterns, selections while stopped, and confirmed MML/chord text are also saved. For effects, playback settings are not saved. Names are automatically assigned and can be changed later.
  - Loading a different plugin (`Load`) automatically records the patch, settings, and playback pattern of the plugin being replaced to History before the switch. The name is `Plugin Name Sequence Number`. No addition occurs for reloading the same plugin or restoring on startup. Confirmed MML/chord text and selections while stopped for instruments are also recorded within the same scope as favorites. For effects, playback settings are not recorded.   - During manual and automatic saving, duplicates of the same plugin, role, playback pattern, confirmed MML text, and state are checked, and existing items and names are reused. For automatic History recording, only differences in stop status are treated as identical, but MML with different text is kept as a separate item. Effects do not compare playback settings.
  - Refer to [Plugin-Specific Processing Policy/List (ADR 0002)](docs/adr/0002-plugin-specific-favorite-state-comparison.md) to check exceptions, reasons, scope, and limitations for each product. For TyrellN6 CLAP's verified state format, compressed parts that change only during playback are excluded from duplication checks, and patches with identical text-based settings are grouped. Verified PCore `UI_op=9/10` and blank lines at the end of the text are also excluded from comparison ([ADR 0011](docs/adr/0011-tyrell-n6-ui-operation-favorite-comparison.md)). For Vaporizer2 CLAP's verified format, minute differences in MSEG time/coordinates (absolute difference of specified items: time `0.00011` ms or less, normalized coordinates `0.000001` or less. Details in [ADR 0010](docs/adr/0010-vaporizer2-mseg-recalculation-drift.md)) caused by loading/saving are treated as identical. Edits within this tolerance cannot be distinguished. Saved data remains in its original form.
  - Switch lists using the central `Favorites` / `History` / `Plugins` tabs. Favorites maintain manual order; new additions are placed at the beginning. Calling, re-saving, or recording to History does not change the order. You can filter by favorite name, plugin name, and format.

Row-click loading and effect removal remain as before. `Sort by plugin name` sorts by plugin name in ascending order once and saves (case-insensitive, maintains relative order for same-named items). Manual adjustments are still possible afterward. Sorting is disabled during filtering, and sorting mode is OFF at startup. Refer to [ADR 0017](docs/adr/0017-manual-favorites-order.md) for background and specifications.

Elapsed time is displayed in units of `1s`, `1m`, `1h`, `1d`, `1w`, `1mon`, `1y` (month is 30 days, year is 365 days). Manual Favorites are preserved. Differences in patch settings are preserved. Refer to [ADR 0006](docs/adr/0006-sforzando-favorite-state-comparison.md) for application scope and limitations.
  - Each row displays a colored `Instrument` / `Effect` on the left. Clicking a favorite name restores its patch and settings. For instrument favorites, the saved confirmed text and playback pattern selection are restored. If stopped, it remains stopped; `Play` plays the restored phrase. During playback, it switches to the saved pattern/MML. Favorites from old formats without text retain the current text; old format stop items retain the current selection. If conversion, state loading, or connection fails, the original text, selection, and playback state are restored, and the failed content is not saved to the session. Instrument favorites maintain connected effects; effect favorites maintain the instrument and MML. An instrument is required to load an effect favorite.
  - Favorites for connected effects display `Connected - click again to remove`; clicking the name again removes that effect. This also applies if settings were edited after calling or if bypassed. The instrument, other effects, and saved favorites remain. Another patch with the same format + ID switches settings at the current position, and unconnected effects are appended to the end. The selected favorite for each effect is also restored on the next launch.
  - Rename/Delete can be done from `…` at the end of the row. Edits after calling or traditional auto-saves do not overwrite favorites. `Last favorite` indicates the last saved/called favorite.
  - Favorites are saved to `%LOCALAPPDATA%\cat-plugin-player\favorites\`. Brief audio glitches may occur during saving/restoration, and the scope of what can be saved is the same as traditional state saving.
- Lissajous Display
  - Below the oscilloscope in the right analysis panel, `Lissajous` is displayed. If `☰` → `On right` is unchecked for the oscilloscope, spectrum, oscilloscope, and Lissajous appear side-by-side at the bottom of the screen.
  - A 45° rotated Lissajous displays the most recent 50ms of output (up to 4096 samples), reflecting effects and Bypass. A common automatic magnification for left/right preserves volume differences and aspect ratio: same-level in-phase is a vertical line, out-of-phase is a horizontal line, and sine waves with phase differences form ellipses or circles. Left-only output appears as a diagonal from top-left to bottom-right, right-only as top-right to bottom-left, mono as a vertical line, and silence as a central dot.
  - Updates independently of notes, cycle counts, or trigger settings. `Show analysis labels` can display headings. Axis and rendering methods can also be checked in graph tooltips.
  - Directly below Lissajous, `Correlation` displays the left/right correlation for the most recent 150ms as a bar and numerical value from -1 to +1. +1 indicates in-phase, near 0 indicates weak correlation, and -1 indicates out-of-phase. Negative values are displayed in red, serving as a guide to judge cancellation when mixed to mono. If silent or one side is silent, it shows "—".
- Waveform Display
  - The `Oscilloscope` at the bottom of the screen displays L (green) and R (blue) outputs, reflecting effects and Bypass, superimposed. For mono, the same waveform is displayed for both.
  - The display width is determined from the last Note On MIDI note number (A4 = 440Hz), and `1`, `2`, `4`, `8 cycles` can be selected. After Note Off, the decay is displayed based on the last note. Output containing chords or detuning may not perfectly repeat within that width.
  - `Zero cross` aligns to the left channel's negative-to-positive crossing. If the left channel is silent, the right channel is used; if no crossing, it displays from the beginning.
  - `Similarity` exhaustively searches for the position where the correlation coefficient with the previous display is maximized, iterating 1 sample at a time for the display width from the start of the buffer. In case of ties, the earlier position is chosen, and the same start position is used for left and right. For the first time or if the comparison target is silent, zero crossing is used.
  - The comparison history is reset when note articulation, playback pattern, display cycle count, trigger method, or audio stream changes. A waiting display is shown until sufficient data is collected.
  - Exploration is performed on a separate thread from audio processing. Display updates may be slow for low notes or a large number of cycles. If display data is interrupted, the history is reset.
  - The default display settings at startup are 4 cycles and zero cross. Display settings are not saved.

## Window Position & Size Settings

You can specify the main window's startup position/size and the plugin GUI's placement method in `%LOCALAPPDATA%\cat-plugin-player\config.toml`. Please edit it after closing the application. Session and favorite selection states are saved to `status.json` in the same directory, and regular saves do not overwrite the TOML. If states are mixed in the old TOML, they will be migrated on first launch: the original file is saved as `config.toml.before-status-migration.bak`, then only state-related entries are removed. Configuration comments, formatting, and unknown entries are preserved; standalone comments for deleted entries remain at the end. If an existing `status.json` is present, it takes precedence.

```toml
[window.main]
x = 100.0
y = 100.0
width = 1200.0
height = 800.0

[window.plugin]
placement = "right_then_bottom_right"
```

The main window's `x` and `y` are logical coordinates, used as the startup position if both are specified. If omitted, it reverts to the traditional default position. `width` and `height` are the inner width and height (logical coordinates) of the main window. You can specify only one; if omitted or if values are 0 or less, or non-finite, they revert to 900 width and 600 height. Changes are reflected on the next launch. The plugin placement method is currently `right_then_bottom_right` only, with the same behavior if omitted. GUI size and placement are calculated based on the actual window frame, screen working area, and DPI. Automatic saving of manually moved main window or GUI positions, and per-plugin position specification are not implemented.

## Local Build and Execution

Clone this app, `uapmd`, `clap-mml-render-tui`, and `clap-mml-play-server` into the same parent directory, and execute from this app's directory. TUI's `app` / `patches` / `patch-select` / `tui-core` and play-server's `core-lib` / `server-config` are always locally referenced from Cargo.toml. Play-server requires `prepare_catalog_clap_patch_state` / `supports_catalog_clap_plugin` in addition to the traditional `prepare_clap_patch_state` / `PatchStateError`, and TUI's `cmrt-patches` requires re-exporting them. The patch browser uses the public Role/Preset/filter API and tui-core's sample capacity determination. Random effect and Browse effects use play-server's `AudioEffectCatalog` / `EffectRenderer` and TUI's effect selector's selection conditions; Browse effects search uses tui-core's search conditions. Insufficient checkouts or missing APIs will result in build errors, and no automatic switch to Git versions will occur.

```powershell
cargo build --release
& ./target/release/cat-plugin-player.exe
```

If UAPMD is not in a sibling `uapmd` directory, first set `$env:UAPMD_DIR = 'X:\projects\uapmd'`. The location of UAPMD during build is specified by an environment variable. `config.toml` is not read as a build configuration.

`cargo install` is not used; the exe generated in the default `target/release` is run directly. The build uses local code (including uncommitted changes) and the existing `target/shim`, but source changes may require reconstruction/rebuilding. If `target/shim` was created with a different version (e.g., VS 2022), it will continue to build with that version; therefore, delete `target/shim` before building ([ADR 0020](docs/adr/0020-visual-studio-2026-toolchain.md)). The shim DLL is bundled with the exe, extracted to a cache directory, and loaded when the GUI starts.

Refer to [ADR 0012](docs/adr/0012-local-dependencies-and-release-execution.md) for the 3-repo dependency configuration and operational policy. TUI's local switching is not required for building with `cat`. For cross-repository builds with TUI itself, use TUI's existing `python scripts/cross_repo_local.py on` procedure; `off` is handled manually. Local references also use uncommitted changes, and Cargo.lock does not fix the content of each checkout. During verification, record the HEAD and diff of each repository.

Launch the GUI without arguments. `--help` and `--version` are also available.

# Concepts, Goals

  - For example, a synthesizer with a MIDI keyboard plays sound when you power it on and press a key.

  - We aim to maintain "playing in the author's environment" as much as possible.
