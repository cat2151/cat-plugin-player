# cat-plugin-player

A lightweight application for easily playing audio plugins, leveraging [UAPMD](https://github.com/atsushieno/uapmd). Written in Rust.

# Past Challenges and What This App Solves
- Audio plugins offer fantastic sounds!
- To play them, it often requires launching a DAW and preparing the environment.
- Lightweight apps for casual playing sometimes required account registration to obtain, or their user experience wasn't quite right for me.
- Nowadays, if you have a desired UX, you can achieve it through "vibe coding."
- So, I decided to do just that.

# Features
- Automatic Installation
  - If you haven't installed an audio plugin, the app will automatically install [Surge XT](https://surge-synthesizer.github.io/) as mentioned above.
- Detection
  - Upon startup, it automatically detects installed plugins.
- Playback
  - Clicking a plugin will load it and automatically start playback.
  - It can play chord progressions like `F-G-Em-Am` and MML (Music Macro Language) like `cde`.
- GUI
  - Pressing the `Show UI` button displays the plugin's GUI, allowing you to edit sounds and effects.
- Tones/Patches
  - Each plugin has a variety of preset sounds. You can easily select them using a proprietary patch browser (supported by some plugins only).
  - For plugins not supported by the patch browser, you can select sounds using the plugin's GUI as usual.
- Effects
  - Each plugin has a variety of preset effects. You can easily select them using a proprietary effect browser (supported by some plugins only).
  - For plugins not supported by the effect browser, you can select effects using the plugin's GUI as usual.

- Detection
  - For normal startup and editor integration, the full plugin list and instrument/effect classification are first restored from `%LOCALAPPDATA%\cat-plugin-player\plugin-list-cache.json`. If the cache is missing or unreadable, it will be detected and created on the first run. After startup, if no loading or tone changes occur and operations cease for 2 seconds, a re-detection is performed in the background. The cache and patch list are updated only if changes are detected; otherwise, the display is maintained. If re-detection fails, the existing cache is retained.
  - If plugin detection succeeds but no instruments are found, a prompt to install the free Surge XT via winget is displayed. This also appears if only effects are present. The prompt will be in Japanese if Windows' display language is Japanese, otherwise in English. Even if "Later" is chosen, it will appear on every startup until an instrument is present.
  - "View Terms of Service" opens Surge XT's terms (GPLv3) in a browser. Pressing "Agree to Terms and Install" executes winget, showing stages like "1/4 Preparing", "2/4 Downloading", "3/4 Installing", "4/4 Loading", along with elapsed time. If a Windows confirmation screen (User Account Control) appears at 3/4, choose "Yes". Upon success, the plugin list is automatically rescanned, Surge XT (CLAP) is loaded, and playback begins, similar to `Load`. In this case, previous instrument/effect restoration is skipped. The installation continues even if the prompt is closed, followed by rescanning and loading upon completion.
  - If winget is missing or installation fails, winget's message and a manual download link are displayed and logged to `error.log`. Only Surge XT is included, and no download progress is shown. The reasons for this choice are in [ADR 0024](docs/adr/0024-offer-surge-xt-via-winget.md).
- GUI
  - When the GUI is opened for the first time, it waits 2 seconds for rendering, automatically takes a screenshot, and scales it down to a PNG with an aspect ratio maintained, fitting the list display frame and screen zoom level. It is saved to `%LOCALAPPDATA%\cat-plugin-player\plugin-icons\`, and plugins matching by name + manufacturer (ignoring leading/trailing spaces and case) share the same image across VST3 / CLAP. If name/manufacturer are insufficient, they are distinguished by format + ID.
  - Previously saved format-specific images are also automatically migrated to shared images from list/favorite identification information. Tone state and favorite load destinations continue to be distinguished by format + ID as before.
  - Plugin images are displayed in Plugins / Favorites / Routing. Within a row, they are scaled down to fit the button height while maintaining aspect ratio. Hovering over an image displays it at its saved size. Plugins without GUI display a temporary icon of the same height.
  - The GUI prioritizes placement to the right of the main window, aligned with its top edge, and within the screen's working area. If it doesn't fit, it's placed in the bottom-right of the working area of the screen where the main window is located. It is positioned on display and when the GUI is resized, but does not constantly follow the main window's movement. The GUI is not scaled down; if its width is greater than the screen's, its left edge aligns with the working area; if its height is greater, its top edge aligns.
  - For blank images or failed captures, retries occur at 1-second intervals for up to 20 seconds from GUI display. Saved blank images are treated as uncaptured and replaced with valid images when the GUI is opened. No re-captures occur after success.
  - If capture fails after retries, an error is displayed. Reopening the GUI retries the capture. GUIs not supporting capture remain with a temporary icon. If you want to retake or if a saved PNG is corrupted, delete the shared PNG for that plugin and any remaining old format-specific PNGs, restart the app, and open the GUI (old PNGs are retained during migration).
- Playback
  - The last played instrument, connected effects, Bypass status, and playback pattern are saved to `%LOCALAPPDATA%\cat-plugin-player\status.json` and restored on next startup. Selected playback patterns (even when stopped), and confirmed MML/chord text are also restored. If only one instrument candidate exists in the Plugins list on startup, it is automatically loaded if not already loaded, and playback begins with the selected pattern even if a stopped state was saved. If multiple candidates exist, the stopped state is restored. If manually stopped after startup, it remains stopped. Unconfirmed edits are not saved.
  - CLAP Note On/Off messages are sent according to the plugin's supported input format. This includes sforzando CLAP, which only accepts MIDI. The scope and verification records of the patch are recorded in [CLAP Note format description](patches/uapmd/clap-note-dialect/README.md).
  - In the top-left `Sequence` pane, you can select the playback type using left/right arrows or the dropdown. Arrows cycle through the ends of the types, and "Stop" is not included as a type. Switching during playback releases all notes in the current phrase and starts from the beginning of the new phrase. When stopped, selecting a type does not play; use `Play` to start and `Stop` to stop. In the main window, the `Space` key also toggles start/stop (except when typing text). Playback pattern selection including MML/chords and stop status are restored on the next startup. However, if only one instrument candidate is present at startup, it auto-plays from the stopped state.
  - To preview MML/chord progressions, open the input screen with the `i` key or the `Chord` button in `Sequence` (hover to see shortcuts and input methods). A single note example is `t120 c8r8d4e4r4`; a chord progression example is `C F G C`. Both are accepted in the same input field, with chord notation conversion attempted first. Uppercase `C` denotes a chord, lowercase `ceg` becomes MML.
  - Input is confirmed with `Enter`/`Confirm` and canceled with `Esc`/`Cancel`. Cancellation or conversion errors retain the previous valid phrase. `Space` or `i` within the input screen are for text input, and `Space` for play/stop does not work.
  - Confirmed phrases loop playback with `Play`/`Stop`. Rests, note lengths, tempo changes, chords, and trailing rests are preserved. Opening the input screen pauses the overall normal playback. If playback was active just before opening, it resumes with the new phrase after confirmation, or with the original playback pattern from the start after cancellation. If opened while stopped, it remains stopped after confirmation/cancellation, and `Play` starts overall playback. Switching to normal playback patterns is also possible. Immediately after confirmation, the text and selected/playback state are saved; on cancellation, the restored playback state is also saved. These are restored on next startup or from instrument favorites/history. Unconfirmed text is not saved, and cancellation or conversion failure retains the previous confirmed text.
  - Changing input or moving the cursor triggers a single preview of the note/chord at that position. This applies to mid-edit and paste operations. Moving or redrawing within the same pronunciation unit does not re-trigger sound. It reflects previous tempo, octave, and note length, and does not sound at rest or command positions. Normal playback stops when editing is opened, and overall playback does not resume after the preview sound ends. The preview sound is released upon the next pronunciation unit, cancellation, confirmation, or instrument change. Previewing does not change confirmed text or normal selection.
  - For MML loop playback, the Velocity setting in the `Velocity` field takes precedence over any specified within the input. CC1 can also be controlled from the `CC1 modulation` field. If the playback event capacity is reached due to an extremely dense phrase, sounding notes are released, and new notes stop playing. You can restart by `Stop` → `Play`.
  - When recalling from Favorites/History in normal startup, or changing patches via Browse patches/Browse effects, the stop/playback state is maintained. During playback, the phrase starts from the beginning, without inheriting any waits from the middle of the previous phrase. Leading rests specified in MML are preserved. While the patch browser/effect browser is open, `Space` for play/stop and starting MML input are suppressed. Tone changes via the plugin's own GUI are not detected.
  - In SMF selection mode (`--select-smf`), the input track loops playback with tempo, duration, and velocity. For batch tone assignment, all tracks are previewed with the selected tone and effects of the representative track. Normal session tones, effects, and MML are not restored, and only sound snapshots are used for favorites. It does not return to the beginning on patch/effect/favorite or connection changes; instead, it continues from the stopped position after a brief silence during the swap. MML/normal pattern operation fields are not used in this mode.
  - In SMF selection mode with `--master-effects`, the current track's tone and effects are retained for preview, and only master effects are edited and returned. The patch browser is not used. Master effects are saved in the conductor's dedicated meta in SMF format 1, and the results of applying to all tracks are confirmed back in the editor. Format 0/2 master support is not added. Refer to [ADR 0030](docs/adr/0030-master-effects-selection.md).
  - cat-smf-editor uses `--resident <name>` to keep one player resident, bringing the patch/effect browser to the foreground on each `t`/`x` command. The resident player does not load the chosen tone/effect itself, but sends the state to the editor, which then plays it with its own instrument. `Esc`, `q`, `×`, or `Enter` closing the effect browser only hides the browser; the player exits when the editor terminates. The previous tone is not restored, and the player's normal status.json is not updated. Role/Preset/Category/Kind and search strings (including Solo/Mute and exclusion conditions) are saved to the editor's status.json per song/track/patch/effect, and master effects are saved/restored independently per song. Saving occurs even if no tone is chosen before closing. Patch list selection is also saved to the editor's status.json per song/track, identified by patch name, instrument, and original patch info, and restored on restart. Tone is not reapplied on selection restoration.
  - For Six Sines/TyrellN6 CLAP, when audio processing is reconstructed due to loading, state restoration, or connection changes, the system waits for the first phrase to start while continuing normal audio processing to preserve the initial sound. At 48kHz, this wait is about 21ms for Six Sines and about 85ms for TyrellN6. Leading rests in MML are added to this. Application conditions and verification records are in [ADR 0019](docs/adr/0019-random-patch-all-catalog.md).
  - In the `Velocity` field below the playback pattern, you can select `100`, `127`, `40-100`, `80-127` using the same left/right arrows or dropdown. The initial value is 100. Range specification increases values in Note On order within a phrase, then decreases them in the next loop, repeating the cycle. Changes apply from the next note without restarting the phrase and are restored on next startup.
  - In the `CC1 modulation` field, you can select `0`, `127`, `sweep` using left/right arrows or dropdown. The initial value is 0. `sweep` repeatedly changes from 0 to 127 in 2 seconds, then from 127 to 0 in the next 2 seconds. The selection is restored on next startup.
  - Guitar open strings send MIDI note numbers 40, 45, 50, 55, 59, 64 (E, A, D, G, B, E) sequentially with 125ms intervals. 2 seconds after the last Note On, all 6 notes are Note Offed simultaneously, repeating after 0.5 seconds.
  - On successful `Load`, it is remembered when `Sequence` type is selected, started, or stopped. The memory remains even after stopping or `Remove`. Older history/favorites are restored with the traditional 4-note pattern.
  - On normal startup termination and `Remove`, the binary state of patches/parameters etc. exposed by the plugin via the UAPMD state API is saved for each plugin in `%LOCALAPPDATA%\cat-plugin-player\states\`. On next startup or re-load of the same plugin, it is restored before playback begins.
  - `Load` for an instrument replaces only the instrument, maintaining connected effects and settings. The state of the plugin being replaced is saved, and it switches after the new plugin is successfully generated, restored, and connected. If it fails, the original configuration is maintained, and an error is displayed.
  - The scope of state saving depends on the plugin and UAPMD's format-specific implementation. UI state is also requested, but the current UAPMD VST3 implementation only retrieves component state. It does not include replication of external samples or saving on forced termination.
  - On startup, it reads all saved plugin lists, directly loads the previous instrument and effect, restores their states, and starts playback. Afterwards, the GUI is initialized, and after a period of user inactivity, the list is re-detected in the background. On the first run without a full list cache, detection occurs after GUI display.
  - If direct loading fails due to old history or file movement, it is restored from the scan results after GUI display. Old history items are updated once played.
  - If the main instrument is CLAP Floe, when audio processing is reconstructed during loading or patch restoration, the start of the first phrase is delayed by 100ms. Leading rests in MML are added to this. This is a provisional measure to observe symptoms of missing initial sound, and its resolution in actual hardware is unconfirmed. Application conditions and review policy are recorded in [ADR 0018](docs/adr/0018-floe-automatic-note-start-delay.md).
  - Refer to [docs/startup-timing.md](docs/startup-timing.md) for startup time measurement methods and results.

- Lissajous Display
  - `Lissajous` is displayed below the oscilloscope in the right analysis panel. If `☰` → `On right` is unchecked for the oscilloscope, spectrum, oscilloscope, and Lissajous are arranged horizontally at the bottom of the screen.
  - A 45° rotated Lissajous curve displays the output of the most recent 50ms (up to 4096 samples), reflecting effects and Bypass. A common automatic gain keeps volume differences and aspect ratio; in-phase at same level becomes a vertical line, anti-phase a horizontal line, sine waves with phase difference become ellipses or circles. Left-only output is top-left to bottom-right diagonal, right-only output is top-right to bottom-left diagonal, mono is a vertical line, silence is a central dot.
  - It updates independently of notes, cycle counts, or trigger settings, and `Show analysis labels` can display headings. Axes and drawing methods can also be checked in the graph's tooltip.
  - `Correlation` directly below Lissajous displays the left/right correlation for the most recent 150ms as a bar and numerical value from -1 to +1. +1 is in-phase, near 0 indicates weak correlation, -1 is anti-phase. Negative values are shown in red and serve as a guide for judging cancellation when mixed to mono. It shows "—" for silence or one side silent.
- Waveform Display
  - The `Oscilloscope` at the bottom of the screen displays L (green) and R (blue) outputs, reflecting effects and Bypass, superimposed. Mono displays the same waveform for both.
  - The display width is determined from the last Note On MIDI note number (A4 = 440Hz), and `1`, `2`, `4`, `8 cycles` can be selected. After Note Off, the tail is displayed based on the last note. Output containing chords or detuning may not repeat perfectly at that width.
  - `Zero cross` aligns to the negative-to-positive crossing of the left channel. If the left channel is silent, the right channel is used; if no crossing, it displays from the beginning.
  - `Similarity` sweeps from the start of the buffer for the display width, 1 sample at a time, to find the position with the maximum correlation coefficient to the previous display. Ties prefer the earlier position, and the same start position is used for left/right. Zero-cross is used for the first display or when the comparison target is silent.
  - The comparison history is reset when a note is sounded, playback pattern changes, display cycle count changes, trigger method changes, or audio stream changes. A waiting display is shown until sufficient data is collected.
  - Exploration is performed in a separate thread from audio processing. Display updates may be slower for low notes or high cycle counts. If display data is interrupted, the history is reset.
  - Default display settings at startup are 4 cycles and zero-cross. Display settings are not saved.

## Settings: Window Position/Size

You can specify the main window's startup position/size and plugin GUI placement method in `%LOCALAPPDATA%\cat-plugin-player\config.toml`. Please edit after closing the application. Session and favorite selection states are saved in `status.json` in the same directory, and normal saves do not overwrite TOML. If status was mixed in old TOML, it will be migrated on first startup, the original file saved as `config.toml.before-status-migration.bak`, and only status items removed. Comments, formatting, and unknown items in settings are preserved; independent comments attached to deleted items remain at the end. If an existing `status.json` is present, it takes precedence.

```toml
[window.main]
x = 100.0
y = 100.0
width = 1200.0
height = 800.0

[window.plugin]
placement = "right_then_bottom_right"
```

The main window's `x`/`y` are logical coordinates and are used as the startup position if both are specified. If omitted, it defaults to the traditional initial position. `width`/`height` are the internal width/height of the main window (logical coordinates). Either can be specified alone; omitted sides or values <= 0 / non-finite revert to 900 width / 600 height. Changes apply on the next startup. The plugin placement method is currently only `right_then_bottom_right`, and the behavior is the same if omitted. GUI size and placement are calculated based on actual window frame, screen working area, and DPI. Automatic saving of manually moved main window/GUI positions, or per-plugin position specification, is not performed.

## Local Build and Run

Clone this application, `uapmd`, `clap-mml-render-tui`, and `clap-mml-play-server` into the same parent directory, then execute from this application's directory. TUI's `app` / `patches` / `patch-select` / `tui-core` and play-server's `core-lib` / `server-config` are always referenced locally via Cargo.toml. play-server requires `prepare_catalog_clap_patch_state` / `supports_catalog_clap_plugin` in addition to traditional `prepare_clap_patch_state` / `PatchStateError`, and TUI's `cmrt-patches` requires their re-export. The patch browser uses public Role/Preset/filter APIs and tui-core's sample capacity check. Browse effects uses play-server's `AudioEffectCatalog` / `EffectRenderer`, TUI's effect selector's selection conditions, and tui-core's search conditions. Missing checkouts or APIs will result in build errors; no automatic switching to Git versions occurs.

```powershell
cargo build --release
& ./target/release/cat-plugin-player.exe
```

If UAPMD is not in the sibling `uapmd` directory, first set `$env:UAPMD_DIR = 'X:\projects\uapmd'`. The UAPMD location during build is specified via environment variable. `config.toml` is not read as a build setting.

Do not use `cargo install`; directly execute the `exe` generated in the default `target/release`. The build uses local code (including uncommitted changes) and existing `target/shim`, but source changes may necessitate reconstruction/rebuild. If `target/shim` was created with a different version (e.g., VS 2022), it will continue to build with that version, so delete `target/shim` before building ([ADR 0020](docs/adr/0020-visual-studio-2026-toolchain.md)). The shim DLL is bundled with the exe and unpacked into the cache directory for loading on GUI startup.

Refer to [ADR 0012](docs/adr/0012-local-dependencies-and-release-execution.md) for the 3-repo dependency structure and operational policy. Local switching for TUI is not required for cat's build. If building TUI cross-repo itself, use TUI's existing `python scripts/cross_repo_local.py on` procedure; `off` is handled manually. Local references use uncommitted changes, and Cargo.lock does not fix the contents of each checkout. When verifying, record the HEAD and diff of each repo.

Surge XT's initial setup is centralized in `shared/first_instrument_install.rs`; cat-smf-editor also references the same instrument absence check, terms screen, and winget process. Each app is responsible for rescanning and loading after successful setup.

Host Rust/native and SMF processing are centralized in `shared/`; cat-smf-editor also references the same canonical modules. No independent crates are added; each app bundles its own DLL from the default target/shim.

Launch the normal GUI without arguments. `--help` and `--version` are also available.

SMF selection mode is `--select-smf <SMF> --browser patch|effect --preserve-position`. If browser is omitted, it defaults to patch; position preservation must be explicitly specified. Passing `--patch-filter <program name>` searches the patch browser with that name from ALL conditions. Regex symbols in names are treated as characters, spaces are AND. Only if 0 items after catalog loading, it switches once to an OR search with words joined by `|` (e.g., `church organ` → `church|organ`). `--patch-filter-file <JSON>` restores search/Role/Preset as is and returns to the same file on successful exit. If no file, it uses the initial search; existing file conditions take precedence. Empty search is also retained, and no automatic switch to word OR occurs for restored conditions. Not used for effect/master selection. The search field can be edited as case-insensitive regex as usual. `--preview-smf <SMF>` can specify a separate SMF for previewing all tracks, distinct from the return destination. It sends all track MIDI events to the selected instrument/effect, and for format 2, reflects tempo per track. The preview SMF is not overwritten. `--start-seconds <seconds>` specifies the initial preview position, and `--loop-end-seconds <seconds>` specifies the loop end beyond the input SMF. If omitted, it's from the start to the end of the input SMF. Use finite, non-negative seconds; the start position must be before the loop end. It restores controllers and sustained notes at the start, and natural loop boundaries return to the beginning. The original SMF events are not changed. Adding `--browser-only` does not display the main screen, instead opening the browser to the foreground. This option is for selection mode only. In normal track selection, you can proceed to another browser using buttons within the browser. `--master-effects` starts with the effect browser and does not proceed to the patch browser. The main screen can be displayed from `Favorites / routing` only when favorites/routing are needed. Closing the browser with Enter also acts as saving and exiting the entire player. On save failure or during change processing, the browser is retained, and errors are displayed within the browser. Esc, q not used for search input, or closing the main app/browser saves instrument/ordered effect/bypass states to the input SMF and exits. `--master-effects` saves only the conductor's master effect/bypass and retains track settings. q in the search field is for text input. During change processing, it waits for confirmation; on save failure, it retains the screen and selection, allowing retry. The normal status.json is not updated. Existing state saving/favorite operations for selected items use the usual save locations. State compatibility across OS/plugin versions and external sample replication are not guaranteed. Refer to [ADR 0029](docs/adr/0029-shared-host-smf-selection.md) for save contracts and common hosts.

# Concept, What We Aim For
- An Instrument
  - For example, a synthesizer with a MIDI keyboard makes sound when you power it on and press a key.
    - We aim for that level of ease of use.
      - Minimize operations to produce sound.
- Sound Production
  - We aim to maintain "it makes sound in the author's environment" as much as possible.
- Immediate Sound
  - From app launch to sound production, a perceived 0.2 seconds. Playback is prioritized for speed.
    - Processes like GUI display preparation are performed after the sound starts.
      - Sound before GUI display might be considered the audio equivalent of a splash screen.
- Educational Use
  - More oriented towards educational use than commercial use.
- Experimentation, Exploration, Personal Use
  - Frequent breaking changes will occur.
