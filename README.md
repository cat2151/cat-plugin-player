# cat-plugin-player

A lightweight app for easily playing audio plugins. It utilizes [UAPMD](https://github.com/atsushieno/uapmd) and is written in Rust.

# Past Challenges and What This App Solves
- Audio plugin patches sound great!
- To play them, you often need to launch a DAW and perform setup tasks.
- Lightweight apps for casual playback sometimes required account registration to obtain, or their user experience wasn't quite for me.
- In modern times, if you have a desired UX, you can achieve it through vibecoding.
- So I decided to do just that.

# Features
- Detection
  - Upon launch, it automatically detects installed plugins.
- Playback
  - Pressing the `Load` button automatically starts playback after the plugin is loaded.
- GUI
  - Pressing the `Show UI` button displays the plugin's GUI.
- Patch
  - To change patches, use the plugin's GUI.

- GUI
  - When opening the GUI for the first time, it waits 2 seconds for rendering, automatically takes a screenshot, and scales it down to a PNG image that fits the list display frame and screen zoom level while maintaining its aspect ratio. It saves to `%LOCALAPPDATA%\cat-plugin-player\plugin-icons\`, and plugins with matching names + manufacturers (ignoring leading/trailing spaces and case) share the same image across VST3 / CLAP. If the name/manufacturer is insufficient, they are distinguished by format + ID.
  - Previously saved format-specific images are also automatically migrated and used as shared images from the list/favorite identification information. Patch states and favorite load destinations are still distinguished by format + ID as before.
  - Plugin images are displayed in Plugins / Favorites / Routing. Within the row, they are scaled down to fit the button height while maintaining aspect ratio. Hovering over an image displays it at its saved size. Plugins without a GUI displayed show a temporary icon of the same height.
  - GUIs prioritize placement next to the main window, aligned to the top edge, within the screen's work area. If it doesn't fit, it's placed at the bottom-right of the main window's screen work area. This placement occurs when displayed and when the GUI is resized, but it does not constantly follow the main window's movement. The GUI is not scaled down; if its width is larger than the screen, its left edge is aligned to the work area; if its height is larger, its top edge is aligned.
  - For blank images or failed captures, it retries every second, up to a maximum of 20 seconds from the GUI display. Saved blank images are also treated as uncaptured, and opening the GUI replaces them with a valid image. After success, it does not re-capture.
  - If capturing fails even after retries, an error is displayed. Opening the GUI again retries the capture. For GUIs that do not support capture, a temporary icon remains. If you want to re-capture or if the saved PNG is corrupted, delete the shared PNG for that plugin and any remaining old format-specific PNGs, restart the app, and open the GUI (old PNGs are kept during migration).
- Playback
  - The last played instrument, connected effects, Bypass status, and playback pattern are saved to `%LOCALAPPDATA%\cat-plugin-player\status.json` and restored on the next launch. The stopped state, selected playback pattern while stopped, and confirmed MML/chord text are also restored. Unconfirmed edits are not saved.
  - CLAP Note On/Off messages are sent according to the input format supported by the plugin. This includes sforzando CLAP, which only accepts MIDI. The scope of the patch and verification records are documented in [CLAP Note Format Description](patches/uapmd/clap-note-dialect/README.md).
  - In the top-left `Sequence` pane, you can select the playback type using left/right arrows or a dropdown. The arrows cycle at both ends of the types, and stop is not included as a type. Switching during playback releases all notes in the current phrase and starts from the beginning of the new phrase. When stopped, selecting a type does not start playback; use `Play` to start and `Stop` to stop. In the main window, the `Space` key also toggles start/stop (except when typing). The selection of playback patterns including MML/chords and the stopped state are restored on the next launch.
  - To preview MML/chord progressions, open the input screen with the `i` key or the `Chord` button in `Sequence` (hover to see shortcuts and input methods). An example of a single note is `t120 c8r8d4e4r4`, and a chord progression example is `C F G C`. Both are accepted in the same input field; chord notation conversion is attempted first. Capital `C` indicates a chord, lowercase `ceg` indicates MML.
  - Confirm input with `Enter` / `Confirm`, and cancel with `Esc` / `Cancel`. Cancellation or conversion errors retain the previous valid phrase. `Space` and `i` within the input screen are used for text input; `Space` for play/stop does not work.
  - Confirmed phrases loop playback with `Play` / `Stop`. Rests, note lengths, tempo changes, chords, and trailing rests are preserved. Opening the input screen pauses the overall normal playback. If it was playing just before opening, after confirmation, the new phrase plays from the beginning; after cancellation, the original playback pattern resumes. If opened while stopped, it remains stopped after confirmation/cancellation, and `Play` starts overall playback. You can also switch to regular playback patterns. The text and selection/playback state are saved immediately after confirmation, and the restored playback state is also saved upon cancellation. These are restored on the next launch or from instrument favorites/history. Unconfirmed text is not saved, and cancellation or conversion failure retains the previous confirmed text.
  - Input changes or cursor movements trigger a single preview of the note/chord at that position. This includes mid-edit and paste operations. Moving within the same pronunciation unit or merely redrawing does not re-trigger. Previous tempo, octave, and note length are reflected, and no sound is produced at rests or command positions. Normal playback stops when editing is opened, and overall playback does not resume after the preview sound ends. The preview sound is released upon moving to the next pronunciation unit, cancellation, confirmation, or instrument change. Preview does not alter the confirmed text or normal selection.
  - For MML loop playback, the `Velocity` field setting takes precedence over any velocity specified within the input. CC1 can also be controlled from the `CC1 modulation` field. If the playback event capacity is reached due to a very dense phrase, sounding notes are released, and playback stops. You can restart by `Stop` → `Play`.
  - When changing patches via Favorites/History, Browse patches/Random patch/Random effect/Browse effects, the stopped/playing state is maintained. During playback, it plays from the beginning of the phrase and does not inherit any waiting in the middle of the previous phrase. Leading rests specified in MML are preserved. While the patch browser/effect browser is open, `Space` for play/stop and starting MML input are suppressed. Patch changes made via the plugin's own GUI are not detected.
  - For Six Sines/TyrellN6 CLAP, when audio processing is rebuilt due to loading, state restoration, or connection changes, it waits for the first phrase to start while continuing normal audio processing to preserve the initial sound. At 48kHz, the wait is approximately 21ms for Six Sines and 85ms for TyrellN6. MML's leading rests are added to this. Refer to [ADR 0019](docs/adr/0019-random-patch-all-catalog.md) for application conditions and actual machine verification.
  - In the `Velocity` field below the playback pattern, you can select `100`, `127`, `40-100`, or `80-127` using the same left/right arrows or dropdown. The initial value is 100. Range specification increases values sequentially for Note On events within the phrase and then decreases them in the next loop, repeating this behavior. Changes are reflected from the next note without restarting the phrase and are restored on the next launch.
  - In the `CC1 modulation` field, you can select `0`, `127`, or `sweep` using left/right arrows or a dropdown. The initial value is 0. `sweep` repeats a sweep from 0 to 127 over 2 seconds, then from 127 to 0 over the next 2 seconds. The selection is restored on the next launch.
  - Open guitar strings sequentially trigger Note On for MIDI note numbers 40, 45, 50, 55, 59, 64 (E, A, D, G, B, E) at 125ms intervals. 2 seconds after the last Note On, all six notes are Note Off simultaneously, and this repeats after 0.5 seconds.
  - It records on successful `Load`, and when selecting, starting, or stopping `Sequence` types. The memory persists even after stopping or `Remove`. Older history/favorites are restored with the traditional 4-note pattern.
  - On exit and `Remove`, the plugin's binary state (patch, parameters, etc.) exposed by UAPMD's state API is saved per plugin to `%LOCALAPPDATA%\cat-plugin-player\states\`. On the next launch or when reloading the same plugin, it is restored before playback begins.
  - `Load` for an instrument only replaces the sound source, maintaining connected effects and their settings. The state of the plugin to be replaced is saved, and it switches after the new plugin is successfully generated, restored, and connected. If it fails, the original configuration is maintained, and an error is displayed.
  - The scope of state saving depends on the plugin and UAPMD's format-specific implementation. It also requests UI state, but the current UAPMD VST3 implementation only retrieves component state. It does not include duplicating external samples or saving during a forced shutdown.
  - On launch, it directly loads the previous instrument and effects, restores their states, and then starts playback. After that, it initializes the GUI and scans the list in the background.
  - If direct loading fails due to old history or file movement, it restores from the scan results after the GUI is displayed. Old history is updated once played.
  - If the main instrument is CLAP Floe, when audio processing is rebuilt due to loading or patch restoration, the start of the first phrase is delayed by 100ms. MML's leading rests are added to this. This is a temporary measure for observing symptoms where initial sounds disappear, and resolution on actual hardware is unconfirmed. Refer to [ADR 0018](docs/adr/0018-floe-automatic-note-start-delay.md) for application conditions and revision policy.
  - Refer to [docs/startup-timing.md](docs/startup-timing.md) for startup time measurement methods and results.
- Effect Routing
  - Serial connection: one instrument → multiple effects → output. After loading an instrument, press `Load` for the first effect, then `Add` to append subsequent effects. For connected effects, `Remove` removes only that one. You cannot connect duplicate effects (same format + ID).
  - `Random effect` next to `Sequence` randomly selects a preset for an installed CLAP effect from the same catalog and selection targets as cmrt's effect selector. If there are 0 effects, it adds the first one; if 1, it replaces that effect; if multiple, it replaces one of the connected effects equally. Repeatedly pressing it does not increase the number of effects, and it maintains the order, settings, and Bypass state of other effects. To avoid duplicate connections, effects with the same format + ID already connected (excluding the target of replacement) are excluded from candidates. If no candidates are available for the target slot, it displays a reason and makes no changes.
  - `Random effect` requires an instrument. Candidates are retrieved from default effect/preset locations scanned by the play-server shared core, and there is no VST3 fallback. During preparation, the current playback continues, and loading, scanning, and patch operations are disabled. While stopped, it remains stopped; while playing, the current phrase restarts from the beginning, and overall MML, Velocity, and CC1 selections are maintained. If generation, application, or connection fails, it reverts to the original configuration, and no automatic re-selection of other candidates occurs. After success, the applied state and connection are saved for the next launch, and Favorites/History are not added. Save failures are displayed as applied.
  - `Browse effects` below `Random effect` or the `E` / `X` keys open a separate, maximized effect browser window where you can choose presets from a list. It cannot be opened while editing MML. Filter by Category → Kind on the left and by search. Classification and selection targets are the same as cmrt's effect selector. Search uses case-insensitive regular expressions, space for AND, `-condition` for exclusion, and applies to preset name, Category, Kind, or effect name (e.g., `hall -plate`, `dragonfly`). Invalid regular expressions during input display an error and retain the previous list. The top row has Search, Target frame, and `Random`. Press `/` within the browser to move input to the search field, and `R` to randomly select from filtered results. Operations for multi-column list display, moving with arrow keys / `h` / `j` / `k` / `l` / number of times, `PageUp` / `PageDown`, and closing with `Enter` / `Esc` are the same as Browse patches. In results with multiple effects mixed, effect names are added per effect, and if Kinds differ, preset names are colored by Kind.
  - Select the target frame from `Add new effect` or `Replace n` for a connected effect. When opened, it defaults to the last frame written by this browser; if none, the last effect; if no effects, `Add new effect`. Applying via `Add new effect` makes the added effect the target, and subsequent selections replace that frame, so choosing repeatedly does not increase the number of effects. If the target frame is removed, the last effect becomes the target. Presets of effects connected to frames other than the target are grayed out; selecting them displays a reason and does not change. Presets entered into the target frame by this browser are marked with `▶`, and opening the browser selects them (does not re-apply).
  - When another candidate is selected by click, key movement, or filtering, an immediate application is requested. Simply opening does not change the effect. You can select the next even during preparation; unstarted selections are replaced by the latest one, and closing cancels. An instrument is required, and playback continuation during preparation, reverting on failure, and saving for the next launch are the same as Random effect. Category, Kind, search string, list selection position, and target frame are saved on exit and restored on the next launch. Key movement starts from the restored selection. Category/Kind are restored by name; if gone, it reverts to `ALL` in that field. Selection is restored by preset; if it no longer exists in the catalog, it becomes unselected, and key movement starts from the beginning. The target frame is restored by its position in the chain; if no effect is at that position, it defaults to the frame active when opened.
  - `Routing` displays the connection order. You can change the order by dragging an effect's `↕` button up or down. While dragging, the moving effect name and insertion line are displayed. The instrument is not subject to reordering. You can edit patches or effects using `Show UI` for each plugin. `Instrument` / `Effect` are displayed with the same type color as the left list.
  - Removing all effects reverts to a direct connection from the instrument to the output. `Bypass effect` targets the entire chain, allowing it to pass through while retaining instances and settings. It can also be toggled with the `b` key (does not work in MML input screen, Browse patches/Browse effects, or while typing). While bypassed, connected effects in Routing are grayed out and `Bypassed` is appended.
  - `Sequence` is for instruments. Stopping the sequence continues audio processing, allowing effects to trail off.
  - On the next launch, the instrument, the order of all effects, their respective states, and Bypass status are restored before playback. History for one effect in the old format can also be loaded. If an effect fails to restore, an error is displayed, and it reverts to a direct connection from the instrument, while preserving the saved configuration.
  - Addition, removal, and reordering are saved only if the new connection is successfully prepared. If it fails, the original configuration and playback are restored, and an error is displayed.
  - Supports mono/stereo for main input/output. Mono to stereo is duplication; stereo to mono is the average of left and right. Auxiliary inputs are silent.
  - Changing connections or Bypass may cause brief audio glitches, and sounding notes and decay may be cut off. Sidechain, parallel connections, and host-side Dry/Wet are not supported.

  - Favorites are saved to `%LOCALAPPDATA%\cat-plugin-player\favorites\`. Short audio glitches may occur during saving/restoration, and the savable scope is the same as traditional state saving.
- Lissajous Display
  - `Lissajous` is displayed below the oscilloscope in the right-side analysis pane. If `☰` → `On right` is unchecked for the oscilloscope, spectrum, oscilloscope, and Lissajous are arranged horizontally at the bottom of the screen.
  - It draws the output of the most recent 50ms (max 4096 samples), reflecting effects/Bypass, on a 45° rotated Lissajous curve. Common auto-scaling maintains volume differences and aspect ratio; in-phase signals at the same level form a vertical line, out-of-phase form a horizontal line, and sine waves with phase differences form ellipses or circles. Output only on the left forms a diagonal from top-left to bottom-right; output only on the right forms a diagonal from top-right to bottom-left; mono forms a vertical line; silence is a central dot.
  - It updates independently of notes, cycle counts, or trigger settings, and `Show analysis labels` can display headings. Axis and drawing methods can also be checked in the graph's tooltip.
  - `Correlation` directly below Lissajous displays the left/right correlation of the most recent 150ms as a bar and numerical value from -1 to +1. +1 is in-phase, near 0 indicates weak correlation, and -1 is out-of-phase. Negative values are shown in red and serve as a guide for judging cancellation when mixed to mono. It shows "—" if silent or one side is silent.
- Waveform Display
  - `Oscilloscope` at the bottom of the screen overlays and displays the L (green) and R (blue) outputs, reflecting effects/Bypass. Mono displays the same waveform on both.
  - The display width is determined from the last Note On MIDI note number (A4 = 440Hz), and you can select `1`, `2`, `4`, `8 cycles`. After Note Off, it displays the decay based on the last note. Output containing chords or detuning may not repeat perfectly within that width.
  - `Zero cross` aligns with the negative-to-positive crossing of the left channel. If the left channel is silent, it uses the right channel; if no crossing, it displays from the beginning.
  - `Similarity` sweeps the buffer from the beginning by display width, one sample at a time, to find the position with the maximum correlation coefficient to the previous display. Ties are resolved by choosing the earlier position, and the same start position is used for left and right. For the first display or if the comparison target is silent, zero crossing is used.
  - Comparison history is reset when a note is sounded, playback pattern changes, display cycle count changes, trigger method changes, or audio stream changes. It shows a waiting display until sufficient data is collected.
  - Exploration is performed on a separate thread from audio processing. Display updates may be slow for low notes or high cycle counts. If display data is interrupted, the history is reset.
  - Default display settings on startup are 4 cycles and zero-cross. Display settings are not saved.

## Window Position and Size Settings

You can specify the main window's startup position/size and plugin GUI placement in `%LOCALAPPDATA%\cat-plugin-player\config.toml`. Please edit it after closing the app. Session and favorite selection states are saved in `status.json` in the same directory, and regular saves do not rewrite the TOML. If status is mixed in the old TOML, it's migrated on first launch, the original file is saved as `config.toml.before-status-migration.bak`, and only status items are removed. Setting comments, formatting, and unknown items are preserved, and independent comments attached to deleted items are moved to the end. If an existing `status.json` is present, it takes precedence.

```toml
[window.main]
x = 100.0
y = 100.0
width = 1200.0
height = 800.0

[window.plugin]
placement = "right_then_bottom_right"
```

The main window's `x` and `y` are logical coordinates and are used as the startup position if both are specified. If omitted, it uses the traditional initial position. `width` and `height` are the inner width/height (logical coordinates) of the main window. You can specify only one; if omitted or if values are 0 or less / non-finite, they revert to 900 width / 600 height. Changes are reflected on the next launch. The plugin placement method is currently only `right_then_bottom_right`; omitting it results in the same behavior. GUI size and placement are calculated based on the actual window frame, screen work area, and DPI. Automatic saving of positions moved manually for the main window or GUI, and per-plugin position specification are not performed.

## Local Build and Execution

Clone this app, `uapmd`, `clap-mml-render-tui`, and `clap-mml-play-server` into the same parent directory, then run from this app's directory. TUI's `app` / `patches` / `patch-select` / `tui-core` and play-server's `core-lib` / `server-config` are always locally referenced from Cargo.toml. The play-server needs `prepare_catalog_clap_patch_state` / `supports_catalog_clap_plugin` in addition to the traditional `prepare_clap_patch_state` / `PatchStateError`, and TUI's `cmrt-patches` needs their re-export. The patch browser uses the public Role/Preset/filter API and tui-core's sample capacity determination. Random effect and Browse effects use play-server's `AudioEffectCatalog` / `EffectRenderer` and TUI's effect selector's selection conditions, while Browse effects' search uses tui-core's search conditions. Insufficient checkout or missing APIs will result in a build error, and there is no automatic fallback to Git versions.

```powershell
cargo build --release
& ./target/release/cat-plugin-player.exe
```

If UAPMD is not in the sibling `uapmd` directory, first set `$env:UAPMD_DIR = 'X:\projects\uapmd'`. The location of UAPMD during build is specified by an environment variable. `config.toml` is not read as build settings.

Do not use `cargo install`; directly execute the `.exe` generated in the default `target/release`. The build uses local code (including uncommitted changes) and existing `target/shim`, but source changes may require re-configuration and re-build. The shim DLL is bundled with the `.exe` and extracted to a cache directory for loading when the GUI starts.

Refer to [ADR 0012](docs/adr/0012-local-dependencies-and-release-execution.md) for the 3-repo dependency structure and operational policy. Local switching of TUI is not required for building cat. If building cross-repository with TUI itself, use TUI's existing `python scripts/cross_repo_local.py on` procedure; `off` is handled manually. Local references use uncommitted changes, and Cargo.lock does not fix the content of each checkout. When verifying, record the HEAD and diffs of each repo.

Launch the GUI without arguments. `--help` and `--version` are also available.

# Concept, What We Aim For
- Instrument
  - For example, a synthesizer with a MIDI keyboard plays sound when powered on and a key is pressed.
    - We aim for that level of ease of use.
      - Minimize operations to produce sound.
- Sound Production
  - Aim to maintain "it sounds on the author's environment" as much as possible.
- Immediate Sound
  - Perceptible 0.2 seconds from app launch to sound. Fastest path to playback.
    - Processes like GUI display preparation are done *after* sound production.
      - Sound playing before the GUI appears might be considered a sound-based splash screen.
    - Requires direct execution of the release-built .exe (cargo via timestamp checks, and debug builds via debug code, each add startup latency).
- Educational Use
  - More oriented towards educational use than commercial.
- Experimentation, Exploration, Personal Use
  - Frequent breaking changes are made.
