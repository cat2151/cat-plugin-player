# cat-plugin-player

A lightweight application that can easily play audio plugins. It utilizes [UAPMD](https://github.com/atsushieno/uapmd) and is written in Rust.

# Past Challenges and What This App Solves
-   Audio plugin timbres are amazing!
-   However, to play them, you often need to launch a DAW and perform setup.
-   Lightweight applications for easy playback sometimes require account registration or have a UI/UX that isn't for me.
-   Nowadays, if you have a desired UX, you can implement it through custom coding.
-   So, that's what I decided to do.

# Features
-   **Detection**
    -   Automatically detects installed plugins upon launch.
-   **Playback**
    -   Pressing the `Load` button automatically starts playback after the plugin loads.
-   **GUI**
    -   Pressing the `Show UI` button displays the plugin's GUI.
-   **Timbre**
    -   To change the timbre, use the plugin's GUI.

# Features (Detailed additions by AI. Intended to be refined later due to readability.)

Oscilloscope display methods and constraints are documented in [ADR 0001](docs/adr/0001-scope-follows-waveform-position.md).

-   **GUI**
    -   The first time a GUI is opened, it waits 2 seconds for rendering, automatically takes a screenshot, and scales it down to a PNG with its aspect ratio preserved, fitting the list's display frame and screen zoom level. It's saved to `%LOCALAPPDATA%\cat-plugin-player\plugin-icons\`, and plugins with matching names + manufacturers share the same image across VST3 / CLAP (ignoring leading/trailing spaces and case). If the name/manufacturer is missing, it's distinguished by format + ID.
    -   Previously saved format-specific images are also automatically migrated and used as shared images based on list/favorites identification. Timbre state and favorite load destinations are still distinguished by format + ID as before.
    -   Plugin images are displayed in Plugins / Favorites / Routing. Within a row, they are scaled down to fit the button height while maintaining aspect ratio. Hovering over an image shows it at its saved size. Plugins without a displayed GUI show a temporary icon of the same height.
    -   GUIs prioritize positions that fit within the screen's working area, aligned with the right and top edges of the main application window. If it doesn't fit, it's placed in the bottom-right of the main window's screen working area. This placement occurs on display and when the GUI is resized, but it does not constantly follow the main window's movement. The GUI is not scaled down; if its width is larger than the screen, its left edge aligns with the working area; if its height is larger, its top edge aligns.
    -   For blank images or failed captures, retries occur every second for up to 20 seconds from GUI display. Saved blank images are treated as not yet captured, and opening the GUI will replace them with a valid image. No re-capturing occurs after success.
    -   If capturing fails after retries, an error is displayed. Opening the GUI again will retry. GUIs not supporting capture will remain with a temporary icon. If you want to retake or if the saved PNG is corrupted, delete the relevant shared PNG and any remaining old format-specific PNGs for that plugin, restart the app, and open the GUI (old PNGs are retained during migration).
-   **Playback**
    -   The last played instrument, connected effects, bypass status, and playback pattern are saved to `%LOCALAPPDATA%\cat-plugin-player\status.json` and restored on the next launch. Stopped status, selected playback pattern while stopped, and confirmed MML/chord body are also restored. Unconfirmed edits are not saved.
    -   CLAP Note On/Off messages are sent according to the input format supported by the plugin. This includes sforzando CLAP, which only accepts MIDI. The scope of the fix and verification records are documented in [CLAP Note format explanation](patches/uapmd/clap-note-dialect/README.md).
    -   In the top-left `Sequence` pane, you can select the playback type using left/right arrows or the dropdown. The arrows cycle at the ends of the types and do not include stop. Switching during playback releases all notes of the current phrase and starts the new phrase from the beginning. When stopped, selecting a type does not start playback; use `Play` to start and `Stop` to stop. In the main window, the `Space` key also toggles start/stop (except when typing text). Selection of playback patterns including MML/chords and the stopped state are restored on the next launch.
    -   To audition MML/chord progressions, open the input screen with the `i` key or the `Chord` button in `Sequence` (hover for shortcuts and input methods). Examples: `t120 c8r8d4e4r4` for single notes, `C F G C` for chord progressions. Both are accepted in the same input field; chord notation conversion is attempted first. Capital `C` denotes a chord, lowercase `ceg` denotes MML.
    -   Confirm input with `Enter`/`Confirm` and cancel with `Esc`/`Cancel`. Cancellation or conversion errors retain the previous valid phrase. `Space` and `i` within the input screen are used for text entry, and `Space` for play/stop is disabled.
    -   Confirmed phrases loop playback with `Play`/`Stop`. Rests, note lengths, tempo changes, chords, and trailing rests are preserved. Opening the input screen pauses overall normal playback. If playback was active just before opening, after confirmation, the new phrase plays from the beginning; after cancellation, the original playback pattern resumes from the beginning. If opened while stopped, it remains stopped after confirmation/cancellation, and `Play` starts overall playback. You can also switch to regular playback patterns. The confirmed text and selection/playback state are saved immediately after confirmation, and the restored playback state is also saved upon cancellation. These are restored on the next launch or from timbre favorites/history. Unconfirmed text is not saved, and cancellation or conversion failure preserves the previous confirmed text.
    -   When changing input or moving the cursor, the single note/chord at that position is auditioned once. This includes inline editing and pasting. Moving within the same phonetic unit or just redrawing will not re-audition. It reflects the previous tempo, octave, and note length, and does not sound at rest or command positions. Normal playback stops when editing is opened, and overall playback does not start after the audition sound ends. The audition sound is also released on the next phonetic unit, cancellation, confirmation, or sound source change. Auditioning does not alter confirmed text or regular selection.
    -   For loop playback of confirmed MML, the `Velocity` field setting takes precedence over any specified velocity in the input. CC1 can also be controlled from the `CC1 modulation` field. If the capacity for playback events is reached with a very dense phrase, sounding notes are released, and playback stops. You can restart with `Stop` -> `Play`.
    -   Calling from app Favorites/History, or changing timbres via Browse patches/Random patch/Random effect/Browse effects, maintains the stopped/playing state. During playback, it plays from the beginning of the phrase and does not inherit any waiting in the middle of the previous phrase. Leading rests specified in MML are preserved. While the timbre browser or effect browser is displayed, `Space` for play/stop and MML input initiation are suppressed. Timbre changes made via the plugin's unique GUI are not detected.
    -   For Six Sines/TyrellN6 CLAP, when audio processing is rebuilt due to loading, state restoration, or connection changes, it waits for the first phrase to start while continuing normal audio processing to preserve the initial sound. At 48kHz, the wait is approximately 21ms for Six Sines and 85ms for TyrellN6. MML's leading rests are added to this. Refer to [ADR 0019](docs/adr/0019-random-patch-all-catalog.md) for application conditions and actual machine verification.
    -   In the `Velocity` field below the playback pattern, you can select `100`, `127`, `40-100`, `80-127` using the same left/right arrows or dropdown. The initial value is 100. Range specification increases the value in Note On order within the phrase and repeats the action of decreasing it in the next loop. Changes are reflected from the next note without restarting the phrase and are restored on the next launch.
    -   In the `CC1 modulation` field, you can select `0`, `127`, `sweep` using left/right arrows or dropdown. The initial value is 0. `sweep` repeats an action of changing from 0 to 127 in 2 seconds, then from 127 to 0 in the next 2 seconds. The selection is restored on the next launch.
    -   Guitar open strings play MIDI note numbers 40, 45, 50, 55, 59, 64 (E, A, D, G, B, E) sequentially with Note On at 125ms intervals. Two seconds after the last Note On, all 6 notes are Note Off simultaneously, repeating after 0.5 seconds.
    -   On `Load` success, the `Sequence` type selection, start, and stop times are remembered. This memory persists after stopping or `Remove`. Older history/favorites are restored with the traditional 4-note pattern.
    -   Upon exit and `Remove`, the binary state of timbre/parameters etc. exposed by the plugin via UAPMD's state API is saved to `%LOCALAPPDATA%\cat-plugin-player\states\` for each plugin. This is restored before playback starts on the next launch or when the same plugin is reloaded.
    -   `Load` for an instrument replaces only the sound source, maintaining connected effects and settings. The state of the plugin to be replaced is saved, and then it switches after successfully generating, restoring, and connecting the new plugin. If it fails, the original configuration is maintained, and an error is displayed.
    -   The scope of state saving depends on the plugin and UAPMD's format-specific implementation. UI state is also requested, but the current UAPMD VST3 implementation only retrieves component state. It does not include external sample replication or saving on crash.
    -   On launch, the previous instrument and effect are loaded directly, and playback starts after restoring the state. Afterward, the GUI is initialized, and the list is scanned in the background.
    -   If direct loading is not possible due to old history or file movement, it is restored from the scan results after GUI display. Old history is updated once played.
    -   If the main sound source is CLAP Floe, when audio processing is rebuilt due to loading or timbre restoration, the start of the first phrase is delayed by 100ms. MML's leading rests are further added. This is a provisional measure for observing initial sound dropout symptoms, and its resolution on actual hardware is unconfirmed. Refer to [ADR 0018](docs/adr/0018-floe-automatic-note-start-delay.md) for application conditions and review policy.
    -   Refer to [docs/startup-timing.md](docs/startup-timing.md) for startup time measurement methods and results.
-   **Effect Routing**
    -   A serial connection of one instrument → multiple effects → output. After loading the instrument, press `Load` for the first effect, then `Add` to append subsequent effects. Connected effects can be removed one by one with `Remove`. Duplicate connections of effects with the same format + ID are not allowed.
    -   `Random effect` next to `Sequence` randomly selects a preset from installed CLAP effects from the same catalog and selection targets as the cmrt effect selector. If there are 0 effects, it adds the first one; if 1, it replaces that effect; if multiple, it replaces one of the connected effects equally. Repeated presses do not increase the number of effects, and the order, settings, and bypass status of other effects are maintained. To avoid duplicate connections, format + IDs already connected (excluding the target for replacement) are excluded from candidates. If no suitable candidate is available for the target slot, it displays a reason and does not change.
    -   Random effect requires a sound source. Candidates are retrieved from default effect/preset locations scanned by the play-server shared core, and no fallback to VST3 is made. During preparation, current playback continues, and load/scan/timbre operations are disabled. If stopped, it remains stopped; if playing, the current phrase restarts from the beginning, and global selections for MML/Velocity/CC1 are maintained. If generation/application/connection fails, it reverts to the original configuration, and no automatic re-selection of another candidate occurs. After success, the applied state and connection are saved for the next launch, and Favorites/History are not added. Save failures are displayed as applied.
    -   `Browse effects` below `Random effect`, or the `E`/`X` keys, opens a separate maximized effect browser window where presets can be selected from a list. It cannot be opened while editing MML. Filter by Category→Kind on the left and by search. Classification and selection targets are the same as the cmrt effect selector. Search uses case-insensitive regular expressions, space for AND, `-condition` for exclusion, applying to preset name, Category, Kind, or effect name (e.g., `hall -plate`, `dragonfly`). Invalid regex during input displays an error and preserves the previous list. The top line displays Search, Target frame, and `Random`. `/` within the browser moves input to the search field, and `R` selects randomly from filtered results. Multiple-column display for the list, movement with arrow keys/`h`/`j`/`k`/`l` + numeric repetitions, `PageUp`/`PageDown`, and closing with `Enter`/`Esc` are the same as Browse patches. In results with mixed effects, effect names are added for each effect; if Kinds differ, preset names are color-coded by Kind.
    -   The target frame is chosen from `Add new effect` or `Replace n` of a connected effect. When opened, it defaults to the frame last written to by this browser, otherwise the last effect, or `Add new effect` if no effects are present. Applying with `Add new effect` makes the added effect the target, and subsequent selections replace that frame, so the number of effects doesn't increase by continued selection. If the target frame is removed, the last effect becomes the target. Presets for effects connected to frames other than the target are grayed out; selecting them displays a reason and prevents change. Presets added to the target frame via this browser are marked `▶`, and opening it selects them (no reapplication).
    -   Clicking, key navigation, or filtering to another candidate immediately requests application. Simply opening does not change the effect. You can select the next item during preparation, uninitiated selections are replaced by the latest one, and closing cancels. A sound source is required, and playback continuation during preparation, fallback on failure, and saving for the next launch are the same as Random effect. Category, Kind, search string, list selection position, and target frame are saved on exit and restored on the next launch. Key navigation starts from the restored selection. Category/Kind are restored by name; if they no longer exist, they revert to `ALL` in that field. Selection is restored by preset; if it no longer exists in the catalog, it becomes unselected, and key navigation starts from the beginning. The target frame is restored by its position in the chain; if no effect is at that position, it defaults to the frame when opened.
    -   `Routing` displays the connection order. Drag the `↕` button of an effect up or down to change its order. While dragging, the moving effect name and insertion line are displayed. Instruments are not reorderable. `Show UI` for each plugin can edit timbre or effect. `Instrument`/`Effect` are displayed with the same type color as the left list.
    -   Removing all effects reverts to a direct connection from sound source to output. `Bypass effect` targets the entire chain, allowing it to pass through while retaining instance and settings. It can also be toggled with the `b` key (does not work in MML input screen, Browse patches/Browse effects display, or while typing text). While bypassed, connected effects in Routing are grayed out and `Bypassed` is appended.
    -   `Sequence` is for the instrument. Stopping the Sequence continues audio processing, allowing effect tails to decay.
    -   On next launch, the instrument, order of all effects, their respective states, and bypass status are restored before playback starts. History of one old-format effect can also be loaded. If effect restoration fails, an error is displayed, it reverts to a direct sound source connection, and the saved configuration is retained.
    -   Additions, removals, and reordering are saved only if the new connection is successfully prepared. If it fails, the original configuration and playback are restored, and an error is displayed.
    -   Supports mono/stereo for main input/output. Mono → stereo is duplication, stereo → mono is the average of left/right. Auxiliary input is silent.
    -   Changes in connections or Bypass may cause a short audio dropout, and sounding notes and tails may be cut off. Sidechain, parallel connections, and host-side Dry/Wet are not supported.
-   **Timbre**
    -   `Browse patches` near `Random patch`, or the `T` key, opens a separate maximized timbre browser window on the same screen as the main app. It does not change the main app's position/size. It cannot be opened while editing MML. Filter by Role→Preset→Search with frames, and both the left condition area and right Patches list are scrollable. The list uses the remaining width and height, operable even when unmaximized or in a narrow window. The top line displays Search, `Solo/Mute`, `Random`, `☰`. The search field uses the remaining width, and `/` key within the browser can move input to the search field. Details of sound source conditions can be seen by hovering `Solo/Mute`. Clicking this button or the `M` key within the browser opens a vertical Solo/Mute overlay, confirming all at once with `OK` or `Enter`. Solo/Mute are placed immediately to the right of the sound source name. Clicking the selected mode again reverts to normal; `Esc`/clicking outside the overlay discards changes. Multiple Solos are treated as OR, Mute as exclusion. Search uses case-insensitive regular expressions, space for AND, `-condition` for exclusion, and `plugin:`condition (e.g., `pad -bright`, `plugin:floe`, `plugin:surgext -bass`). Aliases for integrated timbres are also searchable. Invalid regex results in an error, stopping application, random selection, and condition saving. If 0 items, review conditions by editing the search field or changing Role/Preset. Catalog loading wait/failure is displayed separately from 0 items. Role, Preset, and search string are saved on exit and restored on the next launch. Presets are restored by name; if the condition is deleted, it reverts to `ALL` for that Role.
    -   The list displays non-wrapping single-line timbre name cells, arranged in multiple columns (left→right→next row) according to width. In a narrow window, it reverts to 1 column. Resizing maintains the selected timbre, and only column count changes do not reload. Clicking a timbre does not move the list's display position. Up/down/left/right keys, or `h`/`j`/`k`/`l`, move according to visual arrangement. Left/right move to previous/next timbre (at row ends, to the end of the adjacent row), up/down move to adjacent rows; for short final rows without a timbre directly below, it moves to the end of that row. Typing a number first, like `2j` or `10k` (vim-style), moves that many times (stops at ends; other keys cancel the number). `PageUp`/`PageDown` move 10 times up/down, and combined with a number, move by that multiple. Key navigation, Random, filtering, and column count changes only scroll the selected row into view if it's off-screen. If all timbres fit, it doesn't scroll. For single sound source results, the sound source name is omitted; for mixed sources, it's retained. Text color shows only one difference within the results. If sound sources are mixed, the sound source name part is color-coded per source. For a single sound source, if Preset is `ALL`, timbre names are color-coded per Preset; if not distinguishable that way, then per category. Colors are Monokai-based. If all are the same, it's regular text color. Colors repeat in a sequence of 5, so distant groups might share the same color. Timbre names of "pink patches" prioritize pink color. Classification folders etc. are omitted; if same-named timbres need distinction, necessary paths are retained. Dexed program specification is maintained. Hovering shows the full display path, source path, valid categories, and merged count if 2+. Load/Size are not always in the list; `no category`/`1 merged` are also not shown. Normal timbres, when selected by mouse/key, immediately request application; the same behavior occurs when a condition change selects another candidate. Simply opening does not change the timbre. When opened, if the currently playing timbre (applied via Browse patches/Random patch) is in the current results, that timbre is selected and scrolled into view (no reapplication). The playing timbre is saved on exit and inherited as the restored timbre on next launch. Adding/removing effects or Random effect preserves this inheritance. If the playing timbre is not in the results or unknown, the selection from when it was last closed is maintained (unselected when opened for the first time after launch). After changing timbre via Favorites/History, or instrument load/remove, the playing timbre is unknown, and selection is cleared. Key navigation starts from the selection when opened; if unselected, it moves to the beginning. The next selection can be made during preparation, uninitiated requests are replaced by the latest one. On successful normal application, duplicate timbre names or fixed margins at the bottom are not displayed. A brief message is displayed only if the selected and applied timbres differ, indicating that the previous timbre might continue playing for unconfirmed "pink patches," etc. Pink Space confirmation and application failure/save errors are displayed.
    -   "Pink patches" with sample capacity of 64,000,000 bytes or more are not automatically applied (unknown capacity is treated as normal). After selection, `Space` opens a confirmation overlay for sound source, timbre, and capacity; pressing `Enter` within it starts preparation/application. `Esc` during confirmation cancels without changing. Once applied, a patch still requires re-confirmation. A progress overlay is shown during loading, and cancellation mid-process is not possible. `Space`/`Enter` in the search field, save menu, or Solo/Mute overlay are not used for timbre application (`Enter` in Solo/Mute overlay is the same as `OK`).
    -   `Random` or `R` key within the browser selects evenly from the displayed results. During text input, `T`/`R`/`M`/`/`/`h`/`j`/`k`/`l`/numbers/`Enter` shortcuts are disabled, and `R`/`M` are disabled while the browser overlay/save menu is displayed. For "pink patches", only selection occurs; the same Space→Enter confirmation is required. The external `Random patch` button continues to select evenly from all available patches as before. `Esc`/`Enter` or OS close of the browser window closes only the browser, retaining the main app and the last successfully applied timbre, discarding uninitiated requests and old preparation results. Processes already started for application will complete. `Esc`/clicking outside the overlay when a confirmation overlay, Solo/Mute, or save menu is open only closes the child, and does not pass the same input to the browser or background operations. OS close closes the entire browser. It can be reopened, and there is no undo operation to revert to the original timbre.
    -   Search conditions can be added to a Role via `Save condition to Role` in the hamburger `☰` menu and deleted via `Delete` in Preset. Adding from ALL goes to Etc. They are handled by common selector normalization/classification rules and saved to `patch-filter-presets.json` in the cat config directory. If loading is corrupted, the original file is protected, writing is stopped, and save failure is displayed on screen. Role/Preset/Search/Solo/Mute are retained during the same app session; only saved custom conditions are restored after restart. TUI conditions and Favorites are not shared/migrated.
    -   Browse patches uses the same catalog, supported CLAP instruments, state application, and failure recovery as Random patch. It maintains global selection of MML/Velocity/CC1, and effect order/state/Bypass; upon success, it saves the state for the next launch. Favorites/History are not automatically added. Application success and save failure are displayed separately. Progress of preparation/application is updated even when the child window is focused.
    -   `Random patch` in `Sequence` evenly selects all patches from the existing cmrt catalog (Surge XT, Dexed, Floe, sforzando, Six Sines, TyrellN6, Vaporizer2 CLAP timbres) that match installed instruments and format+ID. It's not an even selection per sound source, so Dexed, which has many candidates, will be selected more frequently. The tooltip displays target sound sources and total candidate count. If no compatible candidates, the button is not displayed.
    -   The Random patch catalog uses the existing `%LOCALAPPDATA%\clap-mml-render-tui\patch-catalog\catalog.json` read-only. Random patch does not substitute VST3, randomly select effect timbres, or target unknown sound sources. For effect preset selection, use Random effect/Browse effects in the effect routing section. Dexed retains program specification within cartridges. Floe/sforzando external samples are needed in their original locations; there is no function to duplicate/save samples.
    -   During Random patch preparation, current playback continues, and conflicting load/scan/timbre operations are disabled. There may be a wait for sample loading for Floe, etc. If stopped, it remains stopped after application; if playing, the current phrase restarts from the beginning. Global selection of MML/Velocity/CC1 and effect order/state/Bypass are maintained. On success, the applied state is saved for the next launch, and Random patch itself does not add to Favorites/History.
    -   If preparation/application fails, the reason is displayed, and no other patch is automatically selected. The original configuration/state/playback status is restored, and instances where state restoration also failed are suppressed from saving. Save failures after timbre application are displayed as applied. Sound source-specific preparation/reflection conditions and verification scope are documented in [ADR 0019](docs/adr/0019-random-patch-all-catalog.md).
    -   `★ Add favorite` for each plugin allows saving multiple instances of the current timbre/settings as favorites. For instruments, playback pattern, stopped selection, and confirmed MML/chord body are also saved. For effects, playback settings are not saved. Names are automatically assigned and can be changed later.
    -   When another plugin is `Load`ed, the timbre/settings/playback pattern of the plugin being replaced are automatically recorded to History before switching. The name is `PluginName SequenceNumber`. It is not added on reloading the same plugin or on restoration at launch. Confirmed MML/chord body of the instrument and stopped selection are also recorded within the same scope as favorites. For effects, playback settings are not recorded. If saving fails, the switch is canceled.
    -   During manual/automatic saving, duplicate items with the same plugin, role, playback pattern, confirmed MML body, and state are checked, and existing items and names are reused. For automatic History recording, differences only in stopped state are treated as identical, but MMLs with different bodies are kept as separate items. Effects do not compare playback settings.
    -   [Plugin-specific processing policy/list (ADR 0002)](docs/adr/0002-plugin-specific-favorite-state-comparison.md) provides information on product-specific exceptions, reasons, scope, and limitations. For confirmed state formats of TyrellN6 CLAP, the compressed part that changes only with playback is excluded from duplicate detection, and timbres with identical text-based timbre settings are grouped. Confirmed PCore `UI_op=9/10` and empty lines at the end of text are also excluded from comparison ([ADR 0011](docs/adr/0011-tyrell-n6-ui-operation-favorite-comparison.md)). For confirmed formats of Vaporizer2 CLAP, minute differences in MSEG time/coordinates that occur during loading/saving (absolute difference of specified items: time <= `0.00011` ms, normalized coordinates <= `0.000001`. See [ADR 0010](docs/adr/0010-vaporizer2-mseg-recalculation-drift.md) for details) are treated as identical. Edits within this range are indistinguishable. Saved data is retained as is.
    -   Switch between lists using the central `Favorites` / `History` / `Plugins` tabs. Favorites maintain manual order, with new additions placed at the top. Calling, resaving, or recording to History does not change the order. Filterable by favorite name, plugin name, and format.
    -   In the Favorites hamburger menu, turning `Reorder favorites` ON allows reordering with `↑` / `↓` at the end of the row, saving immediately. Row clicks for loading/effect removal work as before. `Sort by plugin name` sorts once in ascending plugin name order and saves (case-insensitive, preserving relative order for same-named items). Manual adjustment is still possible afterward. Sorting is disabled during filtering, and reorder mode is OFF on startup. Refer to [ADR 0017](docs/adr/0017-manual-favorites-order.md) for background and specifications.
    -   History is in order of most recent registration. If determined to be the same timbre, the existing timbre is reused, its registration time updated, and moved to the top. Elapsed time is displayed in units of `1s`, `1m`, `1h`, `1d`, `1w`, `1mon`, `1y` (month is 30 days, year is 365 days). Manual Favorites are maintained. All old-format items are migrated to History, and all items not starting with `auto ` are also kept in Favorites (because old formats do not record the origin of auto-saves, thus all renamed auto-saves are included in History). Refer to [ADR 0016](docs/adr/0016-history-instead-of-automatic-favorites.md) for policy and reasons.
    -   History does not display Rename/Delete operation menus. Renaming/deleting is done in Favorites.
    -   `Show only CLAP for duplicate plugins` in the global settings `☰` is ON by default. If there are CLAP plugins with the same name, manufacturer, and type, VST3s in the Plugins list are hidden (ignoring leading/trailing spaces and case differences in name/manufacturer; if name or manufacturer is empty, both formats are shown). Turning it OFF displays both formats. The setting is saved to `[plugins] prefer_clap` in `config.toml` and retained on next launch. It does not change the format for Favorites or loading/restoring.
    -   On both tabs, clicking the name/image loads; for connected effects, clicking again removes them. The currently loaded/connected row is highlighted, and the color persists during effect bypass. The same operations can be done with `Load` / `Add` / `Remove` buttons in Plugins.
    -   Favorites are displayed one item per line. Long names/supplementary information are abbreviated; hovering shows the full text. Waveform/spectrum are displayed below Routing on the right; the right panel width can be adjusted by dragging the boundary. `Audio analysis` `On right` toggles analysis display to bottom-right/bottom of screen (bottom-right on launch).
    -   For sforzando CLAP's confirmed state format, it avoids creating duplicate timbres based only on differences in save counter and Note/CC1 playback values, instead reusing existing favorites. Differences in timbre settings are preserved. Refer to [ADR 0006](docs/adr/0006-sforzando-favorite-state-comparison.md) for scope and limitations.
    -   Colored `Instrument` / `Effect` are displayed to the left of each row. One click on a favorite name restores the timbre/settings. For instrument favorites, the saved confirmed text and playback pattern selection are restored. If stopped, it remains stopped; `Play` plays the restored phrase. If playing, it switches to the saved pattern/MML. Favorites without old-format text retain the current text; old-format stopped items maintain the current selection. If conversion or state loading/connection fails, the original text/selection/playback state is restored, and the failed content is not saved to the session. Instrument favorites maintain connected effects; effect favorites maintain the instrument and MML. An instrument is required to call an effect.

The instrument, other effects, and saved favorites remain. Another timbre of the same format + ID switches settings at the current position, and unconnected effects are added to the end. The selected favorite for each effect is also restored on the next launch.
    -   Rename/Delete operations are available from `…` at the end of the row. Edits after calling or traditional auto-saves do not overwrite favorites. `Last favorite` indicates the last saved/called favorite.
    -   Favorites are saved to `%LOCALAPPDATA%\cat-plugin-player\favorites\`. Short audio dropouts may occur during saving/restoring, and the savable range is the same as traditional state saving.
-   **Lissajous Display**
    -   `Lissajous` is displayed below the oscilloscope in the right analysis panel. If `☰` → `On right` is unchecked for the oscilloscope, spectrum, oscilloscope, and Lissajous appear horizontally at the bottom of the screen.
    -   It draws the output of the most recent 50ms (max 4096 samples), reflecting effects/Bypass, on a 45° rotated Lissajous curve. A shared automatic scale preserves volume differences and aspect ratio; same-level in-phase results in a vertical line, out-of-phase in a horizontal line, and sine waves with phase differences result in ellipses or circles. Output only from the left is a diagonal line from top-left to bottom-right; output only from the right is top-right to bottom-left; mono is a vertical line; silence is a central dot.
    -   It updates independently of notes, cycle counts, or trigger settings, and `Show analysis labels` can display headings. Axis and drawing methods can also be checked in the graph's tooltip.
    -   `Correlation` directly below Lissajous displays the left-right correlation of the most recent 150ms as a bar and numerical value from -1 to +1. +1 is in-phase, near 0 indicates weak correlation, and -1 is out-of-phase. Negative values are shown in red, serving as a guide to judge cancellation when mixed to mono. It shows "—" if silent or one side is silent.
-   **Waveform Display**
    -   `Oscilloscope` at the bottom of the screen displays the output's L (green) and R (blue) channels superimposed, reflecting effects/Bypass. Mono displays the same waveform on both.
    -   The display width is determined from the MIDI note number of the last Note On (A4 = 440Hz), allowing selection of `1`, `2`, `4`, `8 cycles`. After Note Off, the tail is displayed based on the last note. Output containing chords or detuning may not perfectly repeat within that width.
    -   `Zero cross` aligns with the negative→positive crossing of the left channel. If the left channel is silent, it uses the right channel; if no crossing, it displays from the beginning.
    -   `Similarity` exhaustively searches for the position that maximizes correlation with the previous display, from the beginning of the buffer for the display width, one sample at a time. In case of ties, the earlier position is chosen, and the same start position is used for both left and right. For the first display or if the comparison target is silent, it uses zero cross.
    -   The comparison history is reset when a note is sounded, playback pattern changes, display cycle count changes, trigger method changes, or the audio stream changes. It displays a waiting message until enough data is collected.
    -   The search is performed in a separate thread from audio processing. Display updates may be slow for low notes or high cycle counts. If display data is interrupted, the history is reset.
    -   Initial display settings on startup are 4 cycles and zero cross. Display settings are not saved.

## Window Position/Size Settings

You can specify the main application's launch position/size and plugin GUI placement method in `%LOCALAPPDATA%\cat-plugin-player\config.toml`. Please edit it after closing the application. Session and favorite selection states are saved to `status.json` in the same directory, and regular saves do not rewrite the TOML. If states are mixed in the old TOML, they will be migrated on first launch, saving the original file as `config.toml.before-status-migration.bak` before removing only the state items. Comments, formatting, and unknown items in settings are preserved, and independent comments attached to deleted items are retained at the end. If an existing `status.json` is present, it takes precedence.

```toml
[window.main]
x = 100.0
y = 100.0
width = 1200.0
height = 800.0

[window.plugin]
placement = "right_then_bottom_right"
```

The main application's `x` and `y` are logical coordinates and are used as the launch position if both are specified. If omitted, it uses the traditional initial position. `width` and `height` are the inner width and height (logical coordinates) of the main application. Either can be specified; if omitted or set to 0 or less, or a non-finite value, it reverts to width 900 and height 600. Changes are reflected on the next launch. The plugin placement method is currently `right_then_bottom_right` only, and the same behavior applies if omitted. GUI size and placement are calculated based on the actual window frame, screen working area, and DPI. Automatic saving of positions moved manually for the main app or GUI, or per-plugin position specification, is not performed.
