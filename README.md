# cat-plugin-player

A lightweight app to easily play audio plugins, utilizing [UAPMD](https://github.com/atsushieno/uapmd). Written in Rust.

# Challenges Addressed by This App
-   Audio plugins offer fantastic sounds!
-   However, playing them often requires launching a DAW and going through setup procedures.
-   Lightweight apps for casual playing sometimes require account registration or have an operation feel that's "not for me."
-   Nowadays, if you have a desired UX, you can achieve it through "vibe coding" (implementing the desired UX from scratch).
-   So, we decided to do just that.

# Installation, Browsing Sounds & Effects

Windows binaries are generated daily. Please refer to the [releases section](https://github.com/cat2151/cat-plugin-player/releases).

If you don't have an audio plugin installed, the app will automatically install [Surge XT](https://surge-synthesizer.github.io/) for you, as shown below. Easy!

# Features
-   **Automatic Installation**
    -   If no audio plugin is installed, the app will automatically install [Surge XT](https://surge-synthesizer.github.io/) as mentioned above.
-   **Detection**
    -   Upon launch, it automatically detects installed plugins.
-   **Playback**
    -   Clicking a plugin loads it and automatically starts playback.
    -   It can play chord progressions like `F-G-Em-Am` and MML (Music Macro Language) like `cde`.
-   **GUI**
    -   Pressing the `Show UI` button displays the plugin's GUI, allowing you to edit sounds and effects.
-   **Sounds (Patches)**
    -   Each plugin has a wide variety of preset sounds. These can be easily selected using a unique sound browser (supported by some plugins only).
    -   For plugins not supported by the sound browser, you can select sounds directly from the plugin's GUI.
-   **Effects**
    -   Each plugin has a wide variety of preset effects. These can be easily selected using a unique effect browser (supported by some plugins only).
    -   For plugins not supported by the effect browser, you can select effects directly from the plugin's GUI.

# Features (Detailed additions by AI. Will be refined later due to readability)

The oscilloscope display method and constraints are recorded in [ADR 0001](docs/adr/0001-scope-follows-waveform-position.md).

-   **Detection**
    -   If plugin detection succeeds but no instrument is found, a prompt will appear to install the free Surge XT via winget. It also appears if only effects are present. The prompt will be in Japanese if Windows' display language is Japanese, otherwise in English. Even if `Later` is selected, it will appear every time the app launches as long as no instrument is present.
    -   `View Terms of Service` opens Surge XT's terms (GPLv3) in a browser. Pressing `Agree to Terms and Install` executes winget and displays the stages "1/4 Preparing", "2/4 Downloading", "3/4 Installing", "4/4 Loading" with elapsed seconds. If a Windows confirmation screen (User Account Control) appears at 3/4, select "Yes". Upon success, the plugin list is automatically rescanned, Surge XT (CLAP) is loaded, and playback begins, similar to `Load`. In this case, the previous instrument/effect configuration is not restored. If the prompt is closed, installation continues, and upon completion, a rescan and load are performed.
    -   If winget is not available or installation fails, winget's message and a manual download link are displayed, and an `error.log` is created. Only Surge XT is included, and no download progress is shown. The reason for choosing Surge XT is in [ADR 0024](docs/adr/0024-offer-surge-xt-via-winget.md).
-   **GUI**
    -   When the GUI is opened for the first time, it waits 2 seconds for rendering, then automatically takes a screenshot, and scales it down to a PNG with an aspect ratio maintained, fitting the list display frame and screen magnification. It is saved in `%LOCALAPPDATA%\cat-plugin-player\plugin-icons\`, and plugins with matching names + manufacturers (ignoring leading/trailing spaces and case) share the same image for VST3 / CLAP. If name/manufacturer is insufficient, it is distinguished by format + ID.
    -   Previously saved format-specific images are automatically migrated to shared images based on list/favorite identification information. Sound state and favorite load destinations are still distinguished by format + ID.
    -   Plugin images are displayed in Plugins / Favorites / Routing. Within a row, they are scaled down to fit the button height while maintaining aspect ratio. Hovering over an image shows it at its saved size. Plugins with no GUI displayed show a temporary icon of the same height.
    -   The GUI prioritizes placement to the right of the main window, aligned with the top edge, within the screen's work area. If it doesn't fit, it is placed in the bottom-right of the main window's screen work area. This placement occurs on display and GUI resize, but it does not continuously track main window movement. The GUI is not scaled down; if its width is larger than the screen, its left edge aligns with the work area; if its height is larger, its top edge aligns.
    -   For blank images or failed captures, retries occur at 1-second intervals for up to 20 seconds from GUI display. Saved blank images are treated as uncaptured, and opening the GUI replaces them with a valid image. After success, no further captures are attempted.
    -   If capture fails even after retries, an error is displayed. Opening the GUI again initiates a retry. GUIs that do not support capture remain with a temporary icon. To retake or if a saved PNG is corrupted, delete the relevant plugin's shared PNG and any remaining old format-specific PNGs, restart the app, and open the GUI (old PNGs are kept during migration).
-   **Playback**
    -   The last played instrument, connected effects, Bypass state, and playback pattern are saved to `%LOCALAPPDATA%\cat-plugin-player\status.json` and restored on next launch. Stopped state, selected playback pattern while stopped, and confirmed MML/chord text are also restored. Unconfirmed edits are not saved.
    -   CLAP Note On/Off messages are sent according to the plugin's supported input format. This includes sforzando CLAP, which only accepts MIDI. The scope of the fix and validation records are in [CLAP Note Format Description](patches/uapmd/clap-note-dialect/README.md).
    -   In the top-left `Sequence` pane, you can select the playback type using left/right arrows or the dropdown. Arrows cycle through the types, excluding "Stop". Switching during playback releases all sounding notes of the current phrase and starts the new phrase from the beginning. When stopped, selecting a type does not start playback; use `Play` to start and `Stop` to stop. In the main window, the `Space` key also toggles start/stop (except during text input). The selected MML/chord progression playback pattern and stopped state are restored on next launch.
    -   To audition MML/chord progressions, open the input screen with the `i` key or the `Chord` button in `Sequence` (hover to see shortcuts and input methods). An example for single notes is `t120 c8r8d4e4r4`; for a chord progression, `C F G C`. Both are accepted in the same input field; chord notation conversion is attempted first. Capital `C` becomes a chord, lowercase `ceg` becomes MML.
    -   Input is confirmed with `Enter` / `Confirm` and canceled with `Esc` / `Cancel`. Cancellation or conversion errors retain the previous valid phrase. `Space` and `i` within the input screen are used for text input; `Space` for play/stop does not work.
    -   Confirmed phrases loop playback with `Play` / `Stop`. Rests, note lengths, tempo changes, chords, and trailing rests are preserved. Opening the input screen pauses normal overall playback. If playing just before opening, after confirmation, the new phrase plays from the start; after cancellation, the original playback pattern resumes from the start. If opened while stopped, it remains stopped after confirmation/cancellation, and `Play` starts overall playback. You can also switch to normal playback patterns. The text and selection/playback state are saved immediately after confirmation; the restored playback state is also saved upon cancellation. These are restored on next launch or from instrument favorites/History. Unconfirmed text is not saved, and cancellation or conversion failure retains the previous confirmed text.
    -   Changing input or moving the cursor auditions the single note/chord at that position once. This includes in-progress edits and pasting. Moving within the same pronunciation unit or merely redrawing does not re-trigger sound. Previous tempo, octave, and note length are reflected; no sound is made at rest or command positions. Normal playback stops when editing is opened, and overall playback does not resume after the audition sound ends. The audition sound is released on the next pronunciation unit, cancellation, confirmation, or instrument change. Auditioning does not alter the confirmed text or normal selection.
    -   The Velocity for loop playback of confirmed MML prioritizes the `Velocity` field setting over any in-input specification. CC1 can also be controlled from the `CC1 modulation` field. If the playback event capacity is reached due to a very dense phrase, sounding notes are released, and playback stops. You can restart with `Stop` → `Play`.
    -   When changing sounds (patches) via app Favorites/History, Browse patches, Random patch, Random effect, or Browse effects, the stop/play state is maintained. During playback, the phrase plays from the beginning, not inheriting waits from the middle of the previous phrase. Leading rests specified in MML are preserved. While the sound browser/effect browser is displayed, `Space` for play/stop and MML input start in the background are suppressed. Sound changes in a plugin's own GUI are not detected.
    -   For Six Sines/TyrellN6 CLAP, when audio processing is reconstructed due to loading, state restoration, or connection changes, a wait is introduced before the first phrase starts while normal audio processing continues, to preserve the initial sound. At 48kHz, the wait is approximately 21ms for Six Sines and 85ms for TyrellN6. MML's leading rests are added to this. See [ADR 0019](docs/adr/0019-random-patch-all-catalog.md) for application conditions and validation records.
    -   In the `Velocity` field below the playback pattern, you can select `100`, `127`, `40-100`, `80-127` using left/right arrows or the dropdown. The initial value is 100. Range specification increases the value in the order of Note On within the phrase, then decreases it in the next loop, repeating this action. Changes are reflected from the next note without restarting the phrase and are restored on next launch.
    -   In the `CC1 modulation` field, you can select `0`, `127`, `sweep` using left/right arrows or the dropdown. The initial value is 0. `sweep` cycles from 0 to 127 in 2 seconds, then 127 to 0 in the next 2 seconds. The selection is restored on next launch.
    -   Open guitar strings send MIDI note numbers 40, 45, 50, 55, 59, 64 (E, A, D, G, B, E) sequentially with 125ms intervals. 2 seconds after the last Note On, all 6 notes are Note Offed simultaneously, and this repeats after 0.5 seconds.
    -   On successful `Load`, and when selecting, starting, or stopping `Sequence` types, the state is remembered. The memory persists even after stopping or `Remove`. Older history/favorites are restored with the conventional 4-note pattern.
    -   Upon exit and `Remove`, the binary state (patches, parameters, etc.) exposed by plugins via UAPMD's state API is saved to `%LOCALAPPDATA%\cat-plugin-player\states\` per plugin. On next launch or when reloading the same plugin, this state is restored before playback begins.
    -   `Load` for an instrument replaces only the instrument, maintaining connected effects and settings. The state of the plugin being replaced is saved, and it switches only after successful creation, restoration, and connection of the new plugin. If it fails, the original configuration is maintained, and an error is displayed.
    -   The scope of state saving depends on the plugin and UAPMD's format-specific implementation. UI state is requested, but current UAPMD's VST3 implementation only obtains component state. This does not include duplication of external samples or saving upon forced termination.
    -   On launch, the previous instrument and effects are loaded directly, state is restored, and playback begins. The GUI is then initialized, and the plugin list is scanned in the background.
    -   If direct loading fails due to old history or file movement, it is restored from the scan results after GUI display. Old history is updated once played.
    -   For CLAP Floe as the main instrument, when audio processing is reconstructed (e.g., on load or patch restoration), the start of the first phrase is delayed by 100ms. MML's leading rests are added to this. This is a provisional measure to observe symptoms of missing initial notes, and an actual fix is unconfirmed. See [ADR 0018](docs/adr/0018-floe-automatic-note-start-delay.md) for application conditions and review policy.
    -   See [docs/startup-timing.md](docs/startup-timing.md) for startup measurement methods and results.
-   **Effect Routing**
    -   It supports serial connection: one instrument → multiple effects → output. After loading an instrument, press `Load` for the first effect, then `Add` to append subsequent effects. `Remove` for a connected effect disconnects only that one. Duplicate connection of effects with the same format + ID is not allowed.
    -   `Random effect` next to `Sequence` randomly selects presets for installed CLAP effects from the same catalog and selection targets as cmrt's effect selector. If there are 0 effects, it adds the first one; if 1, it replaces that effect; if multiple, it uniformly selects and replaces one of the connected effects. Repeated clicks do not increase the number of effects, and the order/settings/Bypass of other effects are maintained. To avoid duplicate connections, format+ID of currently connected effects are excluded from candidates other than the target. If no suitable candidates are available for the target slot, a reason is displayed, and no change occurs.
    -   Random effect requires an instrument. Candidates are obtained from default effect/preset locations explored by the play-server shared core; no VST3 substitution is made. During preparation, current playback continues, and loading/scanning/patch operations are disabled. If stopped, it remains stopped after application; if playing, the current phrase restarts from the beginning, maintaining overall MML/Velocity/CC1 selections. On failure of generation/application/connection, it reverts to the original configuration; no automatic selection of alternative candidates occurs. Upon success, the applied state and connection are saved for the next launch, and no Favorites/History entry is added. Save failures are displayed as "applied".
    -   `Browse effects` below `Random effect` or `E` / `X` keys open a separate maximized effect browser window, allowing selection of presets from a list. It cannot be opened while editing MML. Filtering is done by Category→Kind on the left and search. Classification and selection targets are the same as cmrt's effect selector. Search uses case-insensitive regex, space for AND, `-condition` for exclusion, applying to preset name, Category, Kind, or effect name (e.g., `hall -plate`, `dragonfly`). Invalid regex during input shows an error, retaining the previous list. The top line displays Search, target frame, and `Random`. `/` within the browser moves input to the search field. `R` randomly selects from filtered results. Multiple column display in the list, navigation with arrow keys / `h` / `j` / `k` / `l` / number prefixes / `PageUp` / `PageDown`, and closing with `Enter` / `Esc` are the same as Browse patches. In results with mixed effects, effect names are shown per effect, and preset names are color-coded per Kind if kinds differ.
    -   The target frame is chosen from `Add new effect` or `Replace n` of a connected effect. When opened, it defaults to the last frame written by this browser, otherwise the last effect, or `Add new effect` if no effects. Applying `Add new effect` makes the added effect the target; subsequent selections replace that frame, so choosing continuously does not increase the number of effects. If the target frame is removed, the last effect becomes the target. Presets of effects connected to frames other than the target are displayed in gray; selecting them shows a reason and prevents change. Presets applied to the target frame via this browser are marked with `▶`, and opening makes them selected (not reapplied).
    -   Clicking, key navigation, or filtering selects another candidate and immediately requests application. Simply opening does not change the effect. You can select the next even during preparation; unstarted selections are replaced by the latest one, and closing cancels them. An instrument is required, and preparation's continuous playback, failure recovery, and saving for next launch are the same as Random effect. Category, Kind, search string, list selection position, and target frame are saved on exit and restored on next launch. Key navigation starts from the restored selection; if unselected, it moves to the top. Category/Kind are restored by name; if missing, they revert to `ALL` in that field. Selection is restored by preset; if missing from the catalog, it becomes unselected, and key navigation starts from the top. The target frame is restored by its position in the chain; if no effect is at that position, it defaults to the frame chosen on opening.
    -   `Routing` displays the connection order. Dragging an effect's `↕` button up/down changes its order. While dragging, the moving effect name and insertion line are displayed. Instruments are not reorderable. `Show UI` for each plugin allows editing sounds and effects. `Instrument` / `Effect` are displayed with the same type color as the left list.
    -   Removing all effects reverts to a direct connection from instrument to output. `Bypass effect` applies to the entire chain, allowing passthrough while retaining instance and settings. It can also be toggled with the `b` key (does not work in MML input screen, Browse patches/Browse effects display, or during text input). When bypassed, connected effects in Routing are displayed in gray with `Bypassed`.
    -   `Sequence` is for the instrument. Stopping `Sequence` continues audio processing to allow effect tails.
    -   On next launch, instrument, all effect orders, their respective states, and Bypass status are restored before playback. History of 1 old-format effect can also be loaded. If effect restoration fails, an error is displayed, and it reverts to direct instrument connection, while the saved configuration is retained.
    -   Additions, removals, and reordering are saved only if the new connection preparation succeeds. If it fails, the original configuration and playback are restored, and an error is displayed.
    -   Supports mono/stereo for main input/output. Mono → stereo is duplication; stereo → mono is left/right average. Auxiliary inputs are silent.
    -   Changing connections or Bypass may cause a short audio dropout, interrupting sounding notes and tails. Sidechain, parallel connections, and host-side Dry/Wet are not supported.
-   **Sounds (Patches)**
    -   `Browse patches` near `Random patch` or the `T` key opens a separate maximized patch browser window on the same screen as the main app. The main app's position/size do not change. It cannot be opened while editing MML. Filtering is by Role→Preset→Search with frames; the left condition area and right Patches list are scrollable. The list uses the remaining width and height, operable even when unmaximized or in a narrow window. The top line displays Search, `Solo/Mute`, `Random`, and `☰`. The search field uses remaining width, and `/` within the browser moves input to the search field. Details of instrument conditions can be checked by hovering over `Solo/Mute`. Clicking this button or the `M` key within the browser opens a vertical Solo/Mute overlay; `OK` or `Enter` confirms all at once. Solo/Mute are displayed immediately to the right of the instrument name. Re-clicking the selected mode reverts to normal; `Esc` / clicking outside the overlay discards changes. Multiple Solos are treated as OR, Mutes as exclusions. Search uses case-insensitive regex, space for AND, `-condition` for exclusion, and `plugin:` condition (e.g., `pad -bright`, `plugin:floe`, `plugin:surgext -bass`). Aliases of integrated patches can also be searched. Invalid regex results in an error, stopping application, random selection, and condition saving. If 0 results, the search field or Role/Preset changes can be used to revise conditions. Waiting for catalog loading / failure is displayed separately from 0 results. Role, Preset, and search string are saved on exit and restored on next launch. Preset is restored by name; if the condition is deleted, it reverts to `ALL` for that Role.
    -   The list displays one-line patch name cells, wrapping into multiple columns (left→right→next row) depending on width. In a narrow window, it reverts to 1 column. Resizing maintains the selected patch; only changing the number of columns does not reload. Clicking a patch does not move the list's display position. Arrow keys or `h` / `j` / `k` / `l` move according to the visual layout. Left/right move to previous/next patch (or the end of an adjacent row at row ends); up/down move to the row above/below, or to the end of a short final row if no patch is directly below. Typing a number first, like `2j` or `10k`, moves that many times (stops at ends; other keys cancel the number). `PageUp` / `PageDown` move 10 times up/down, and combined with a number, move by that multiple. Key navigation, Random, filtering, and column count changes scroll to a visible position only if the selected row is off-screen. If all patches fit, it does not scroll. For single-instrument results, the instrument name is omitted; for mixed, it is retained. Text color indicates only one difference in results. If instruments are mixed, the instrument name part is color-coded per instrument. For a single instrument, if Preset is `ALL`, patch names are color-coded per relevant Preset; if not distinguishable, then per category. Colors are Monokai-based. If all are the same, normal text color is used. Colors cycle through 5, so distant groups might have the same color. Pink patch names prioritize "pink". Classification folders etc. are omitted; if distinguishing same-named patches, necessary paths are retained. Dexed program specification is maintained. Hovering shows the full display path, source path, valid category, and merged count (if 2 or more). Load/Size are not always shown in the list; `no category` / `1 merged` are also not shown. Normal patches immediately request application when selection changes via mouse click/key navigation, and similarly when a different candidate is selected by condition change. Simply opening does not change the patch. When opened, if the currently playing patch (applied via Browse patches/Random patch) is in the current results, that patch is selected and scrolled into view (not reapplied). The playing patch is saved on exit and inherited as the restored patch on next launch. This inheritance is maintained during effect addition/removal/Random effect. If the playing patch is not in the results or unknown, the selection from the last close is maintained (unselected when opening for the first time after launch). After changing patches via Favorites/History, or instrument load/removal, the playing patch is unknown, and selection is cleared. Key navigation starts from the selection when opened; if unselected, it moves to the top. Next selections can be made during preparation; unstarted requests are replaced by the latest one. On successful normal application, redundant patch names or fixed whitespace at the bottom are not displayed. A short message is displayed only if the selected and applied patch differ, indicating that the previous patch might continue playing for unconfirmed pink patches. Pink Space prompts and application/save failure errors are displayed.
    -   Pink patches with sample capacity 64,000,000 bytes or more are not automatically applied (unknown capacity is treated as normal). After selection, `Space` opens a confirmation overlay for instrument/patch/capacity, and pressing `Enter` within it starts preparation/application. `Esc` during confirmation cancels without change. Even once applied, reconfirmation is required. During loading, a progress overlay is displayed, and cancellation is not possible. `Space` / `Enter` in the search field, save menu, or Solo/Mute overlay are not used for patch application ( `Enter` in Solo/Mute overlay is equivalent to `OK`).
    -   `Random` within the browser or the `R` key selects uniformly from the displayed results. During text input, `T` / `R` / `M` / `/` / `h` / `j` / `k` / `l` / numbers / `Enter` shortcuts do not work, nor do `R` / `M` while the browser overlay / save menu is displayed. For pink patches, selection alone is not enough; the same Space→Enter confirmation is required. The external `Random patch` still uniformly selects from all available patches. `Esc` / `Enter` or OS close of the browser window only closes the browser, preserving the main app and the last successfully applied patch, discarding unstarted requests and old preparation results. Already initiated processes are completed. When confirmation overlay, Solo/Mute, or save menu are open, `Esc` / clicking outside the overlay closes only the child, not passing the same input to the browser or background operations. OS close closes the entire browser. It can be reopened, and there is no undo operation to revert to the original patch.
    -   Search conditions can be added to Role via `Save condition to Role` in the hamburger `☰` menu and deleted via `Delete` in Preset. Adding from ALL goes to Etc. They are handled by common selector normalization/classification rules and saved to `patch-filter-presets.json` in the cat config directory. If corrupted on load, the original file is protected, writing is stopped, and save failures are displayed on screen. Role/Preset/Search/Solo/Mute are maintained during the same app launch; only saved custom conditions are restored after restart. TUI conditions and Favorites are not shared or migrated.
    -   Browse patches uses the same catalog, compatible CLAP instruments, state application, and failure recovery as Random patch. Overall MML/Velocity/CC1 selection, effect order/state/Bypass are maintained, and on success, the state is saved for next launch. Favorites/History are not automatically added. Application success and save failure are displayed distinctly. Progress of preparation/application is updated even when the child window is focused.
    -   `Random patch` in `Sequence` uniformly selects from all CLAP patches of Surge XT, Dexed, Floe, sforzando, Six Sines, TyrellN6, and Vaporizer2 present in the existing cmrt catalog that match installed instruments by format+ID. It is not uniform per instrument; Dexed, having more candidates, will be selected more frequently. The tooltip displays target instruments and total candidates. If no compatible candidates, the button is not displayed.
    -   Random patch's catalog uses the existing `%LOCALAPPDATA%\clap-mml-render-tui\patch-catalog\catalog.json` read-only. Random patch does not substitute VST3, randomly select effect patches, or target unknown instruments. Effect preset selection uses Random effect / Browse effects in the Effect Routing section. Dexed retains program specification within cartridges. Floe/sforzando external samples are required at their original locations; there is no function to duplicate/save samples.
    -   In environments without cmrt and thus `catalog.json`, Surge XT patch lists are retrieved from [cat-music-patterns](https://github.com/cat2151/cat-music-patterns) on each launch, saved to `%LOCALAPPDATA%\cat-plugin-player\patch-catalog\surge-xt.json`, and used as candidates for Browse patches/Random patch. If retrieval fails, the previously saved list is used; if none, Random patch is not displayed. A loading message is shown until retrieval finishes (max 10 seconds). The list is generated from Surge XT 1.3.4; for different versions, new patches may not appear, and selecting a missing patch will show a preparation failure. If `catalog.json` exists but cannot be read, it does not switch. The reason is in [ADR 0025](docs/adr/0025-surge-xt-patch-catalog-without-cmrt.md).
    -   During Random patch preparation, current playback continues, and conflicting load/scan/patch operations are disabled. There may be a wait for sample loading for Floe, etc. If stopped, it remains stopped after application; if playing, the current phrase restarts from the beginning. Overall MML/Velocity/CC1 selection and effect order/state/Bypass are maintained. On success, the applied state is saved for next launch, and Random patch itself does not add to Favorites/History.
    -   If preparation/application fails, a reason is displayed, and no alternative patch is automatically selected. The original configuration/state/playback state is restored, and instances where state restoration also failed are prevented from saving. Save failures after patch application are displayed as "applied". Instrument-specific preparation/reflection conditions and validation scope are recorded in [ADR 0019](docs/adr/0019-random-patch-all-catalog.md).
    -   `★ Add favorite` for each plugin allows saving multiple instances of the current sound/settings as favorites. For instruments, playback pattern, selection while stopped, and confirmed MML/chord text are also saved. For effects, playback settings are not saved. Names are automatically generated and can be changed later.
    -   When `Load`ing a different plugin, the sound/settings/playback pattern of the plugin being replaced are automatically recorded to History before switching. The name is `Plugin Name Sequence Number`. It is not added for reloading the same plugin or restoration on launch. Confirmed MML/chord text and selection while stopped for instruments are also recorded within the same scope as favorites. For effects, playback settings are not recorded. If saving fails, the switch is aborted.
    -   During manual/automatic saving, it checks for duplicates (same plugin, role, playback pattern, confirmed MML text, state) and reuses existing entry and name. For History's automatic recording, only differences in stop state are treated as identical, but MML with different text is kept as a separate entry. Effects do not compare playback settings.
    -   [Plugin-specific Processing Policies/List (ADR 0002)](docs/adr/0002-plugin-specific-favorite-state-comparison.md) shows exceptions, reasons, scope, and limitations for each product. For TyrellN6 CLAP's confirmed state format, compressed parts that change only with playback are excluded from duplicate judgment, and patches with identical text patch settings are grouped. Confirmed PCore `UI_op=9/10` and empty lines at the end of text are also excluded from comparison ([ADR 0011](docs/adr/0011-tyrell-n6-ui-operation-favorite-comparison.md)). For Vaporizer2 CLAP's confirmed format, minute differences in MSEG time/coordinates that arise during loading/saving (absolute difference of specified items: time < `0.00011` ms, normalized coordinates < `0.000001`. See [ADR 0010](docs/adr/0010-vaporizer2-mseg-recalculation-drift.md)) are treated as identical. Edits within this range cannot be distinguished. Saved data is retained as is.
    -   Switch lists using `Favorites` / `History` / `Plugins` tabs in the center. Favorites maintain manual order; new additions are placed at the top. Calling, resaving, or recording to History does not change the order. You can filter by favorite name, plugin name, and format.
    -   In Favorites' hamburger menu, turning `Reorder favorites` ON enables reordering with `↑` / `↓` at the end of the row and saves immediately. Loading by clicking a row and removing effects work as before. `Sort by plugin name` sorts once in ascending order of plugin name and saves (case-insensitive, same-named items maintain relative order). Manual adjustments are still possible afterwards. Reordering is disabled during filtering; reorder mode is OFF on launch. See [ADR 0017](docs/adr/0017-manual-favorites-order.md) for adoption background and specifications.
    -   History is in latest registered order. If a patch is deemed identical, the saved patch is reused, its registration time is updated, and it moves to the top. Elapsed time is shown in units of `1s`, `1m`, `1h`, `1d`, `1w`, `1mon`, `1y` (month is 30 days, year is 365 days). Manual Favorites are maintained. All old-format items are migrated to History, and items not starting with `auto ` are also kept in Favorites (because old formats did not record the origin of automatic saves, ensuring all renamed automatic saves are included in History). See [ADR 0016](docs/adr/0016-history-instead-of-automatic-favorites.md) for policy and reasons.
    -   History does not display Rename/Delete operation menus. Renaming/deleting is done in Favorites.
    -   In the global settings `☰`, `Show only CLAP for duplicate plugins` is ON by default. If a CLAP plugin with the same name, manufacturer, and type exists, VST3 plugins in the Plugins list are hidden (ignoring leading/trailing spaces and case differences in name/manufacturer; if name or manufacturer is empty, both are displayed). Turning it OFF shows both formats. The setting is saved to `[plugins] prefer_clap` in `config.toml` and retained on next launch. It does not change Favorites or the format loaded/restored.
    -   In both tabs, clicking the name/image loads; for connected effects, clicking again removes it. The currently loaded/connected row is highlighted, and the color remains even when effects are bypassed. The same operations can be done with `Load` / `Add` / `Remove` buttons in Plugins.
    -   Favorites are displayed one item per line. Long names/additional info are truncated; hover to see full text. Waveform/spectrum are displayed below Routing on the right; the right panel width can be adjusted by dragging the boundary. `Audio analysis`'s `On right` toggles analysis display between bottom-right / bottom of the screen (defaulting to bottom-right on launch).
    -   For sforzando CLAP's confirmed state format, it does not create new identical patches based solely on save counters and differences in note/CC1 playback values; it reuses existing favorites. Differences in patch settings are retained. See [ADR 0006](docs/adr/0006-sforzando-favorite-state-comparison.md) for scope and limitations.
    -   Colored `Instrument` / `Effect` is displayed to the left of each row. Clicking a favorite name restores the sound/settings. For instrument favorites, the saved confirmed text and playback pattern selection are restored. If stopped, it remains stopped; `Play` plays the restored phrase. If playing, it switches to the saved pattern/MML. Favorites without old-format text retain current text, and old-format stopped items maintain current selection. If conversion or state load/connection fails, the original text/selection/playback state is restored, and the failed content is not saved to the session. Instrument favorites maintain connected effects; effect favorites maintain the instrument and MML. An instrument is required to call an effect.
    -   For connected effect favorites, `Connected - click again to remove` is displayed; clicking the name again removes that effect. This applies even if settings were edited after calling or if bypassed. The instrument, other effects, and saved favorites remain. Another patch of the same format + ID switches settings at the current position, and unconnected effects are appended to the end. The selected favorite for each effect is also restored on next launch.
    -   `…` at the end of the row allows renaming/deletion. Edits after calling or traditional auto-saves do not overwrite favorites. `Last favorite` indicates the last saved/called favorite.
    -   Favorites are saved to `%LOCALAPPDATA%\cat-plugin-player\favorites\`. Short audio dropouts may occur during saving/restoring, and the scope of what can be saved is the same as traditional state saving.
-   **Lissajous Display**
    -   `Lissajous` is displayed below the oscilloscope in the right analysis panel. If `☰` → `On right` of the oscilloscope is deselected, spectrum, oscilloscope, and Lissajous appear side-by-side at the bottom of the screen.
    -   It draws the most recent 50ms of output (max 4096 samples), reflecting effect and Bypass, on a 45° rotated Lissajous graph. Common auto-scaling for left and right maintains volume differences and aspect ratio; in-phase at the same level forms a vertical line, out-of-phase forms a horizontal line, and sine waves with phase differences form ellipses or circles. Output only on the left forms a diagonal from top-left to bottom-right; only on the right, top-right to bottom-left; mono forms a vertical line; silence forms a central dot.
    -   It updates independently of notes, cycle counts, or trigger settings. `Show analysis labels` displays headings. Axes and drawing methods can also be checked in the graph's tooltip.
    -   `Correlation` directly below Lissajous displays the correlation between left and right channels for the most recent 150ms as a bar and numerical value from -1 to +1. +1 is in-phase, near 0 indicates weak correlation, and -1 is out-of-phase. Negative values are displayed in red, serving as a guideline for judging cancellation when mixed into mono. If silent or one side is silent, it shows "—".
-   **Waveform Display**
    -   `Oscilloscope` at the bottom of the screen displays L (green) and R (blue) outputs, reflecting effects and Bypass, overlaid. Mono displays the same waveform for both.
    -   The display width is determined from the last Note On MIDI note number (A4 = 440Hz), and you can choose `1`, `2`, `4`, `8 cycles`. After Note Off, the tail is displayed based on the last note. Outputs containing chords or detuning may not repeat perfectly at that width.
    -   `Zero cross` aligns to the left channel's negative-to-positive crossing. If the left channel is silent, it uses the right channel; if no crossing, it displays from the beginning.
    -   `Similarity` exhaustively checks (sample by sample) the position that yields the maximum correlation coefficient with the previous display, from the start of the buffer for the display width. Ties prefer the earlier position, and the same starting position is used for both left and right. For the first display or if the comparison target is silent, zero cross is used.
    -   Comparison history is reset when a note is played, playback pattern changes, display cycle count changes, trigger method changes, or audio stream changes. A waiting display appears until sufficient data is collected.
    -   Exploration runs on a separate thread from audio processing. Display updates may be slow for low notes or high cycle counts. If display data is interrupted, history is reset.
    -   Default display settings on launch are 4 cycles and zero cross. Display settings are not saved.

## Window Position and Size Settings

You can specify the main window's launch position/size and plugin GUI placement method in `%LOCALAPPDATA%\cat-plugin-player\config.toml`. Please edit it after closing the app. Session and favorite selection states are saved to `status.json` in the same directory; normal saving does not overwrite TOML. If states are mixed in an old TOML, they are migrated on first launch, the original file is saved as `config.toml.before-status-migration.bak`, and only state items are removed. Setting comments, formatting, and unknown items are preserved, and independent comments attached to deleted items remain at the end. If an existing `status.json` is present, it takes precedence.

```toml
[window.main]
x = 100.0
y = 100.0
width = 1200.0
height = 800.0

[window.plugin]
placement = "right_then_bottom_right"
```

The `x` and `y` for the main window are logical coordinates and are used as the launch position if both are specified. If omitted, it defaults to the conventional initial position. `width` and `height` are the inner width and height (logical coordinates) of the main window. You can specify only one, or if omitted or less than or equal to 0, or a non-finite value, it reverts to 900 width and 600 height. Changes are reflected on the next launch. The plugin placement method is currently only `right_then_bottom_right`; omitting it results in the same behavior. GUI size and placement are calculated based on actual window frames, screen work area, and DPI. Automatic saving of manually moved main window/GUI positions and per-plugin position specification are not implemented.

## Local Build and Execution

Clone this app, `uapmd`, `clap-mml-render-tui`, and `clap-mml-play-server` into the same parent directory, then execute from this app's directory. TUI's `app` / `patches` / `patch-select` / `tui-core` and play-server's `core-lib` / `server-config` are always referenced locally from Cargo.toml. Play-server requires `prepare_catalog_clap_patch_state` / `supports_catalog_clap_plugin` in addition to conventional `prepare_clap_patch_state` / `PatchStateError`, and TUI's `cmrt-patches` requires their re-export. The patch browser uses public Role/Preset/filter APIs and tui-core's sample capacity determination. Random effect and Browse effects use play-server's `AudioEffectCatalog` / `EffectRenderer` and TUI's effect selector's selection conditions; Browse effects' search uses tui-core's search conditions. Insufficient checkouts or API definitions will result in build errors, and automatic switching to Git versions is not performed.

```powershell
cargo build --release
& ./target/release/cat-plugin-player.exe
```

If UAPMD is not in the sibling `uapmd` directory, first set `$env:UAPMD_DIR = 'X:\projects\uapmd'`. The UAPMD location during build is specified via environment variable. `config.toml` is not read as a build setting.

Do not use `cargo install`; directly execute the generated exe in the default `target/release`. The build uses local code (including uncommitted changes) and existing `target/shim`, but source changes may require reconstruction and rebuilding. If `target/shim` was created with a different version of VS 2022, etc., it will continue to build with that version, so delete `target/shim` before building ([ADR 0020](docs/adr/0020-visual-studio-2026-toolchain.md)). The shim DLL is bundled with the exe, extracted to a cache directory, and loaded when the GUI starts.

The dependency structure of the 3 repos and operational policy are described in [ADR 0012](docs/adr/0012-local-dependencies-and-release-execution.md). For building cat, local TUI switching is not needed. If building TUI itself cross-repo, use TUI's existing `python scripts/cross_repo_local.py on` procedure; `off` is handled manually. Local references use uncommitted changes, and Cargo.lock does not fix the contents of each checkout. When validating, record the HEAD and diffs of each repo.

Launches the GUI with no arguments. `--help` and `--version` are also available.
