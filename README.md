# cat-plugin-player

A lightweight application for easily playing audio plugins. It utilizes [UAPMD](https://github.com/atsushieno/uapmd) and is written in Rust.

# Past Challenges and What This App Solves
- Audio plugin patches sound amazing!
- To play them, it often requires launching a DAW and performing preliminary setup.
- Lightweight apps for easy playback sometimes require account registration to obtain, or their user experience was just not for me.
- In modern times, if you have a desired UX, you can achieve it through vibe coding.
- So, I decided to do just that.

# Features
- Automatic Installation
  - If you haven't installed an audio plugin, the app will automatically install [Surge XT](https://surge-synthesizer.github.io/) as mentioned above.
- Detection
  - Upon startup, it automatically detects installed plugins.
- Playback
  - Clicking a plugin loads it and automatically starts playback.
  - It can play chord progressions like `F-G-Em-Am` and MML (Music Macro Language) like `cde`.
- GUI
  - Pressing the `Show UI` button displays the plugin's GUI, allowing you to edit patches and effects.
- Patches
  - Each plugin has a variety of preset patches. You can easily select them using a custom patch browser (supported by some plugins only).
  - For plugins not supported by the patch browser, you can select patches directly from the plugin's GUI.
- Effects
  - Each plugin has a variety of preset effects. You can easily select them using a custom effect browser (supported by some plugins only).
  - For plugins not supported by the effect browser, you can select effects directly from the plugin's GUI.

- Detection
  - For normal startup and editor integration, the full plugin list and instrument/effect classification are first restored from `%LOCALAPPDATA%\cat-plugin-player\plugin-list-cache.json`. If no cache exists or it cannot be loaded, it will be detected and created on first run. If no loading or patch changes occur and the operation stops for 2 seconds after startup, re-detection will run in the background. The cache and patch list are updated only if changes are detected; otherwise, the display is maintained. If re-detection fails, the existing cache is kept.
  - If plugin detection succeeds but no instruments are found, a prompt will appear to install the free Surge XT via winget. It will also appear if only effects are found. The prompt will be in Japanese if Windows' display language is Japanese, otherwise in English. Even if `Later` is chosen, it will appear at every startup until an instrument is found.
  - `View Terms of Service` opens Surge XT's terms (GPLv3) in a browser. Pressing `Agree to Terms and Install` executes winget and displays the stages "1/4 Preparing", "2/4 Downloading", "3/4 Installing", "4/4 Loading" with elapsed seconds. If a Windows confirmation screen (User Account Control) appears at 3/4, select "Yes". Upon success, the plugin list is automatically rescanned, Surge XT (CLAP) is loaded, and playback starts as with `Load`. In this case, previous instrument/effect restoration is skipped. Even if the prompt is closed, installation continues, and upon completion, rescanning and loading occur.
  - If winget is not available or installation fails, winget's message and manual download links are displayed, and logged to `error.log`. Only Surge XT is included, and download progress is not shown. The reasons for this choice are in [ADR 0024](docs/adr/0024-offer-surge-xt-via-winget.md).
- GUI
  - The first time the GUI is opened, it waits 2 seconds for rendering, then automatically takes a screenshot, scales it to a PNG with dimensions matching the list display frame and screen zoom ratio while preserving aspect ratio. It saves to `%LOCALAPPDATA%\cat-plugin-player\plugin-icons\`, and plugins with matching names + manufacturers (ignoring leading/trailing spaces, case) share the same image for VST3 / CLAP. If name/manufacturer is missing, it distinguishes by format + ID.

  - Plugin images are displayed in Plugins / Favorites / Routing. Within a row, they are scaled down to fit the button height while preserving aspect ratio. Hovering over an image shows its saved size. Plugins without GUI display a placeholder icon of the same height.
  - The GUI prioritizes placement next to the main window, aligned to the top edge, within the screen's working area. If it doesn't fit, it's placed at the bottom right of the main window's screen working area. Placement occurs on display and GUI resizing, but does not constantly follow main window movement. The GUI is not scaled down; if its width is greater than the screen, its left edge aligns with the working area; if its height is greater, its top edge aligns.
  - For blank images or failed captures, it retries at 1-second intervals for up to 20 seconds from GUI display. Saved blank images are treated as uncaptured and replaced with a valid image when the GUI is opened. No re-capture after success.

Pressing `?` / `F1` or `Esc` again closes only the help, returning to the original menu. Other key operations are disabled while help is displayed. `?` when typing text is input as a character.

- Playback
  - Surge XT typically waits 100ms for the first phrase to start when audio processing is rebuilt. For CLAP catalog patches allowed by the distribution judgment table, this is set to 0ms and linked to its state for subsequent startups. The table is fetched in the background from GitHub and kept in `%LOCALAPPDATA%\cat-plugin-player\patch-catalog\surge-xt-start-delay.json`. It is not bundled; 100ms is used for first runs, unlisted items, or mismatching entries, and the saved table is used if communication fails. Opening the plugin GUI disables this permission because edits cannot be tracked. Closing the GUI and re-selecting a known patch from the browser re-evaluates. 0ms adoption prioritizes UX; refer to [ADR 0008](docs/adr/0008-surge-xt-automatic-note-start-delay.md) for actual measurement conditions and limitations.

Selected stopped playback patterns and confirmed MML/chord text are also restored. If there's only one instrument candidate in the Plugins list on startup, it's automatically loaded if not already, and playback starts with the selected pattern even if previously stopped. If multiple candidates exist, the stopped state is restored. If manually stopped after startup, it remains stopped. Unconfirmed edits are not saved.
  - CLAP Note On/Off is sent according to the plugin's supported input format. This includes sforzando CLAP, which only accepts MIDI. The scope of fixes and verification records are in [CLAP Note Format Description](patches/uapmd/clap-note-dialect/README.md).
  - In the top-left `Sequence` pane, you can select the playback type using left/right arrows or a dropdown. Arrows cycle through the types, but 'Stop' is not included. The `s` key in the main window also cycles to the next type. Switching during playback releases all sounding notes of the current phrase and starts the new phrase from the beginning. When stopped, selecting a type does not start playback; use `Play` to start and `Stop` to stop. The `Space` key in the main window also toggles start/stop (except when typing text). Playback pattern selection including MML/chords and stop state are restored on next startup. However, if there's only one instrument candidate on startup, it auto-plays from the stopped state.
  - To preview MML/chord progressions, open the input screen with the `i` key or the `Chord` button in `Sequence` (hover to see shortcuts and input methods). Example for single notes: `t120 c8r8d4e4r4`; for chord progression: `C F G C`. Both are accepted in the same input field; chord notation conversion is attempted first. Capital `C` becomes a chord, lowercase `ceg` becomes MML.
  - Confirm input with `Enter` / `Confirm`, and cancel with `Esc` / `Cancel`. Cancellation or conversion errors retain the previous valid phrase. `Space` or `i` within the input screen are used for text input, and `Space` for play/stop does not work.
  - Confirmed phrases loop playback with `Play` / `Stop`. Rests, note lengths, tempo changes, chords, and trailing rests are preserved. Opening the input screen pauses overall normal playback. If playing just before opening, after confirmation it plays the new phrase from the beginning; after cancellation, it resumes the original playback pattern from the start. If opened while stopped, it remains stopped after confirmation/cancellation, and `Play` starts overall playback. It can also switch to normal playback patterns. The text and selection/playback state are saved immediately after confirmation; the restored playback state is also saved on cancellation. This is restored on next startup or from instrument favorites/History. Unconfirmed text is not saved, and on cancellation or conversion failure, the previous confirmed text is retained.
  - When input changes or the cursor moves, the single note/chord at that position is auditioned once. This also applies to mid-edit or paste operations. Moving within the same pronunciation unit or merely redrawing does not re-trigger. It reflects the previous tempo, octave, and note length, and does not sound at rest or command positions. Normal playback stops when editing is opened, and overall playback does not resume after the auditioned sound ends. The auditioned sound is also released upon the next pronunciation unit, cancellation, confirmation, or instrument change. Auditioning does not alter the confirmed text or normal selection.
  - For looped MML playback, the velocity of sounding notes prioritizes the setting in the `Velocity` field over any in-input specification. CC1 can also be controlled from the `CC1 modulation` field. If the event capacity is reached for a very dense phrase, sounding notes are released, and playback stops. It can be restarted with `Stop` → `Play`.
  - For normal startup, calling from Favorites/History or changing patches via Browse patches/Browse effects maintains the stop/play state. During playback, it plays from the beginning of the phrase and does not carry over mid-phrase waits from before the change. Leading rests specified in MML are preserved. While the patch browser/effect browser is displayed, `Space` for play/stop and MML input initiation in the background are suppressed. Patch changes within a plugin's own GUI are not detected.

Normal session patches, effects, and MML are not restored, and only sound snapshots are used for favorites. It does not return to the beginning on patch/effect/favorite or connection changes, but continues from the stopped position after a brief silence during the swap. The MML/normal pattern operation fields are not used in this mode.

Master effects are saved in the SMF format 1 conductor-specific meta, and the application results to all tracks are confirmed back in the editor. Master support for format 0/2 is not added. Refer to [ADR 0030](docs/adr/0030-master-effects-selection.md).

Refer to [ADR 0019](docs/adr/0019-random-patch-all-catalog.md) for application conditions and real-device verification.

The `v` key cycles through the options. Range specification increases values in Note On order within a phrase and then decreases them in the next loop, repeating the cycle. Changes are reflected from the next note without restarting the phrase, and are restored on next startup.

The initial value `-` sends nothing and does not change the instrument's modulation wheel value. `sweep` cycles from 0 to 127 in 2 seconds, then from 127 to 0 in the next 2 seconds. Dragging the value display bar to the right sends a value between 0 and 127, increasing/decreasing from the start of the drag (moves 0-127 across the bar's width. If `sweep` is active, it stops, and the field becomes that value. Clicking alone does not change it). The selection and dragged value are restored on next startup.

If the patch has named a Macro something like `LFO Speed`, that name appears instead of `CC41 Macro 1` (hovering over the name shows `CC41 Macro 1`). Options and dragging the value display bar are the same as CC1; `sweep` cycles for each Macro at different periods from CC1 and each other (one way from 0 to 127 is 2.9 / 3.7 / 4.3 / 5.3 / 6.1 / 7.1 / 7.9 / 8.9 seconds for Macro 1-8 respectively. CC1 is 2 seconds). The initial value `-` sends nothing and does not change the Macro value saved in the patch. In Surge XT, when `-` is selected, the displayed value is the patch's value read when the patch changed or when `-` was selected (moving knobs in Surge XT's GUI does not change this display). When changing patches via Browse patches, Favorites, History, or Surge XT's GUI, `0`, `127`, and dragged values for CC1 and Macro revert to `-`, and it plays with the values saved in the new patch (`sweep` continues). The `M` key sets Macro 1-8 to `sweep` collectively, and pressing it again when all displayed Macros are `sweep` reverts them all to `-`. The selection is saved like CC1 and carried over to the next startup. Duplicate detection for Favorites ignores differences in Macro values, similar to CC1. If the patch is changed in Surge XT's GUI, the field display/hide switches immediately. See [ADR 0036](docs/adr/0036-surge-xt-macro-sweep.md) for details.

If the patch's Usage field has a description like `Ctrl A = bass dominator`, that description is used as the heading. Options, dragging, `M` key, saving, and behavior on patch change are the same as Surge XT's Macro, with a one-way `sweep` of 2.9 seconds for Control A and 3.7 seconds for Control B. When `-` is selected, the displayed value is the value sent, and the patch's value cannot be displayed. If the patch is changed in TyrellN6's GUI, the fields do not switch; they switch when the patch is changed via Browse patches, Favorites, or History. See [ADR 0038](docs/adr/0038-tyrell-n6-control-ab-sweep.md) for details.
  - For Vaporizer2, Six Sines, and Floe (CLAP), a field appears in the same location for each Macro that the current patch uses for modulation (Custom modulator 1-4 for Vaporizer2, Macro 1-6 for Six Sines, Macro 1-4 for Floe). The heading is the name the patch gave to the Macro; if no name, it appears as `Custom modulator 1`, `Macro 1`, etc. (No CC number as it doesn't send CC). These three instruments directly control instrument parameters instead of CC, mapping 0-127 in the field to the instrument's value range (Six Sines: -1 to 1, others: 0 to 1). Options, dragging, `sweep` period, `M` key, saving, and behavior on patch change are the same as Surge XT's Macro. When `-` is selected, the displayed value is the patch's value read when the patch changed or when `-` was selected. For Floe, Macros assigned to CC1 (Macro 1 by default) do not appear in this field but are controlled by the `CC1 modulation` field (to prevent two fields from contending for the same Macro). When the patch is changed in the instrument's GUI, the fields may not switch; they switch when the patch is changed via Browse patches, Favorites, or History. Duplicate detection for Favorites ignores differences in Macro values. Macros for plugins other than those mentioned above are not supported. See [ADR 0039](docs/adr/0039-parameter-macro-sweep.md) for details.
  - Guitar open strings send MIDI note numbers 40, 45, 50, 55, 59, 64 (E, A, D, G, B, E) sequentially with 125ms intervals. After 2 seconds from the last Note On, all 6 notes are Note Offed simultaneously, and the sequence repeats after 0.5 seconds.
  - Upon successful `Load`, it is remembered when `Sequence` type is selected, started, or stopped. Memory remains after stopping or `Remove`. Old history/favorites are restored with the traditional 4-note pattern.
  - On application exit and `Remove` in normal startup, the binary state (patches, parameters, etc.) exposed by the plugin via the UAPMD state API is saved per plugin to `%LOCALAPPDATA%\cat-plugin-player\states\`. It is restored before playback starts on the next startup or when the same plugin is reloaded.
  - `Load` for an instrument only replaces the instrument, maintaining connected effects and settings. It saves the state of the plugin being replaced, and switches after successfully generating, restoring, and connecting the new plugin. If it fails, the original configuration is maintained, and an error is displayed. Only when reloading a minimal Surge XT (at startup) into the same instrument, it uses the same preservation, regeneration, and recovery path as `Show UI` below.
  - The scope of state saving depends on the plugin and UAPMD's format-specific implementation. UI state is also requested, but the current UAPMD VST3 implementation only gets component state. It does not include duplicating external samples or saving on abnormal termination.
  - On startup, it reads the saved full plugin list, directly loads the previous instrument and effects, restores their states, and starts playback. Afterwards, the GUI is initialized, and after operations settle, the list is re-detected in the background. If the full list cache is not present on first run, it detects after GUI display.
  - If the previous instrument was Surge XT (CLAP / VST3), only this one instance on startup is created with a configuration that omits patch, wavetable, and FX preset lists to enable faster playback. Since the Surge GUI menus would be almost empty in this configuration, pressing `Show UI` for that Surge recreates it in a normal configuration while preserving the latest patch, edits, Favorite selection, playback settings, and connected effects, then opens the GUI. Audio stops once during this process. If it cannot be saved, it doesn't recreate, maintaining the original instrument. If generation, restoration, or connection fails, it recovers once from the saved content and displays an error. If recovery also fails, it stops, leaving the saved content, so please retry with `Load`. Repeated presses do not increase recreation attempts. Surge XT created via `Load`, patch browser, favorites, history, or effects uses the normal configuration. This can be disabled with environment variable `CMRT_SURGE_MINIMAL_DATA_HOME=0`. Refer to [ADR 0034](docs/adr/0034-surge-xt-startup-minimal-data-home.md) for reasons, measured latency, and verification scope.
  - If direct loading is not possible due to old history or file movement, it is restored from the scan results after GUI display. Old history is updated once played.
  - If the main instrument is CLAP Floe, when audio processing is rebuilt (e.g., on load or patch restoration), the start of the first phrase is delayed by 100ms. MML leading rests are added further. This is a provisional measure for observing symptoms of disappearing initial notes, and real-device resolution is unconfirmed. Refer to [ADR 0018](docs/adr/0018-floe-automatic-note-start-delay.md) for application conditions and review policy.
  - For the background of startup speed optimization, bugs that occurred with Show UI, and changes to the destruction order, see [ADR 0034](docs/adr/0034-surge-xt-startup-minimal-data-home.md). For measurement methods, see [Developer's Guide](#measuring-startup-time).
- Effect Routing
  - Opening `Browse effects` / `E` / `X` automatically loads the single available CLAP effect candidate, if any, and designates its slot for preset changes. If already connected, it uses that slot without reloading. If no instrument is loaded and there's only one instrument candidate, it first loads the instrument and starts playback. If multiple instrument candidates exist, select an instrument first. The number of candidates is determined by the CLAP preference setting in the Plugins list, and search strings do not reduce the candidate count.
  - Series connection: one instrument → multiple effects → output. After loading an instrument, press `Load` for the first effect, then `Add` to append subsequent effects. Connected effects can be removed one by one with `Remove`. Duplicate connections of effects with the same format + ID are not allowed.
  - Changing effects in Browse effects requires an instrument. Candidates are fetched from default effect/preset locations scanned by the play-server shared core; no fallback to VST3. During preparation, current playback continues, and loading, scanning, and patch operations are disabled. In normal startup, it remains stopped if stopped, or resumes the current phrase from the beginning if playing, maintaining MML, Velocity, CC1 global selection, and other effects' order, settings, and Bypass. On failure of generation, application, or connection, it reverts to the original configuration. After success, the applied state and connection are saved for the next startup; Favorites/History are not added. Save failure is displayed as applied.
  - `Browse effects` next to `Sequence` or the `E` / `X` key opens an independent, maximized effect browser window, allowing preset selection from a list. It cannot be opened while editing MML. Filtering is done by Category → Kind on the left and then by search. Classification and selection targets are the same as cmrt's effect selector. Search is case-insensitive regular expression, space for AND, `-condition` for exclusion, applying to preset name, Category, Kind, or effect name (e.g., `hall -plate`, `dragonfly`). Invalid regex during input displays an error and retains the previous list. The top line displays Search, target slot, `Random`, and `W`. `/` within the browser moves focus to the search field. `R` randomly selects from filtered results. `W` toggles column width between fitting all preset names and default width. Multi-column list display, movement with arrow keys / `h` / `j` / `k` / `l` / number of times, `PageUp` / `PageDown`, and `Enter` / `Esc` to close operate the same as Browse patches. In results with mixed effects, effect names are appended for each effect; if Kinds differ, preset names are color-coded by Kind. Names not fitting in a cell always retain the tail end of the preset name (excluding folder), shortening the folder name / effect name to the left to `1 char + ...`, displaying more of the part closer to the preset name. Full names are visible on hover.
  - The target slot is chosen from `Add new effect` or `Replace n` of a connected effect. When opened, it defaults to the slot last written to by this browser, otherwise the last effect, or `Add new effect` if no effects are present. Applying with `Add new effect` makes the added effect the target, and subsequent selections replace that slot, so the number of effects does not increase by continuous selection. If the target slot is removed, the last effect becomes the target. Presets for effects connected to non-target slots are greyed out; selecting them displays a reason and does not change the effect. Presets added to the target slot by this browser are marked with `▶`, and opening the browser selects them (not reapplied).
  - Clicking, key movement, or filtering to another candidate immediately requests application. Opening alone does not change the effect. You can select the next item during preparation, unstarted selections are replaced by the latest one, and closing cancels them. Category, Kind, search string, list selection position, and target slot are saved on exit and restored on next startup. Key movement starts from the restored selection. Category/Kind are restored by name; if missing, they revert to `ALL` in that field. Selection is restored by preset; if missing from the catalog, it becomes unselected, and key movement starts from the top. The target slot is restored by its position in the chain; if no effect is at that position, it defaults to the slot upon opening.
  - If the effect before or after replacement in Browse effects is CLAP Surge XT Effects, the sound immediately before the switch fades out over ~50ms, and the sound after switches fades in over ~50ms. This is a provisional measure to suppress loud "pops" caused by lingering instrument sounds passing through the new effect (especially Distortion types). The switch is delayed by that amount (max ~70ms), and lingering sounds may be faintly audible during fade-in. No fading occurs for switches between other effects or changes to patches/instruments. Refer to [ADR 0027](docs/adr/0027-surge-xt-effect-swap-fade.md) for reasons and scope.
  - Surge XT Effects presets use a table of prepared states (saved in `%LOCALAPPDATA%\cat-plugin-player\patch-catalog\surge-xt-fx-states.json`) fetched from [cat-music-patterns](https://github.com/cat2151/cat-music-patterns) on each startup, instead of temporarily launching the plugin to prepare them. This avoids a bug where the app crashes when continuously selecting presets. If not obtainable, it uses the previously saved table; if that's also unavailable, Surge XT Effects presets do not appear as candidates in the effect browser, and a reason is displayed. The table was created from Surge XT 1.3.4 presets; presets with different content (e.g., different Surge XT versions) are excluded from candidates, and the number excluded is shown. Refer to [ADR 0028](docs/adr/0028-surge-xt-fx-prepared-states.md) for reasons.
  - `Routing` displays the connection order. You can reorder effects by dragging the `↕` button up/down. While dragging, the moving effect name and insertion line are displayed. Instruments are not subject to reordering. Each plugin's `Show UI` allows editing patches and effects. `Instrument` / `Effect` are displayed with the same type color as the left-side list.
  - Removing all effects reverts to a direct connection from instrument to output. `Bypass effect` applies to the entire chain, allowing audio to pass through while retaining instance and settings. It can also be toggled with the `b` key (does not work in MML input screen, Browse patches/Browse effects display, or text input). During Bypass, connected effects in Routing are greyed out and accompanied by `Bypassed`.
  - `Sequence` is for instruments. Stopping the Sequence continues audio processing to allow effect tails to decay.
  - On next startup, it restores the instrument, all effects' order, their states, and Bypass status before playback. History for a single old-format effect can also be loaded. If effect restoration fails, an error is displayed, it reverts to direct instrument connection, and the saved configuration is retained.
  - Additions, removals, and reordering are saved only if the new connection is successfully prepared. If it fails, the original configuration and playback are restored, and an error is displayed.
  - Supports mono/stereo for main input/output. Mono to stereo is duplicated; stereo to mono is averaged. Auxiliary inputs are silent.
  - Connection or Bypass changes may cause a brief audio glitch, and notes in progress or tails may be cut off. Side-chaining, parallel connections, and host-side Dry/Wet are not supported.
- Patches
  - If no instrument is loaded and there's only one instrument candidate, `Browse patches` / `T` automatically loads it and starts playback. Requests during loading/scanning are processed after completion, and if the list is closed, unstarted automatic loads are canceled. If multiple candidates exist, it does not auto-select. The number of candidates is determined by the CLAP preference setting in the Plugins list, and search strings do not reduce the candidate count. Load failures are displayed, and no automatic retries. The supported formats and catalog limitations for the patch list itself remain as before.
  - `Browse patches` next to `Sequence` or the `T` key opens an independent, maximized patch browser window on the same screen as the main window. It does not change the main window's position or size. It cannot be opened while editing MML. Filtering is done by Role → Preset → Search with frames. Roles/Presets with no patches are not displayed. ## Settings: Window Position/Size

You can specify the main window's startup position/size and plugin GUI placement in `%LOCALAPPDATA%\cat-plugin-player\config.toml`. Please edit after closing the application. Session and favorite selections are saved in `status.json` in the same directory, and normal saves do not overwrite the TOML. If old TOML has mixed state, it is migrated on first launch: the original file is saved as `config.toml.before-status-migration.bak`, then only state items are removed. Configuration comments, formatting, and unknown items are retained; independent comments associated with deleted items are kept at the end. If an existing `status.json` is present, it takes precedence.

```toml
[window.main]
x = 100.0
y = 100.0
width = 1200.0
height = 800.0

[window.plugin]
placement = "right_then_bottom_right"
```

For the main window, `x` and `y` are logical coordinates and are used for startup position if both are specified. If omitted, it defaults to the traditional initial position. `width` and `height` are the inner width and height (logical coordinates) of the main window. Either can be specified alone; if omitted or zero/non-finite, it defaults to 900 width and 600 height. Changes will be reflected on next startup. The plugin placement method is currently only `right_then_bottom_right`, and omission results in the same behavior. GUI size and placement are calculated based on the actual window frame, screen working area, and DPI. Automatic saving of manually moved main window or GUI positions, or plugin-specific position settings, are not implemented.

Clone this app, `uapmd`, `clap-mml-render-tui`, and `clap-mml-play-server` into the same parent directory, then run from this app's directory. TUI's `app` / `patches` / `patch-select` / `tui-core` and play-server's `core-lib` / `server-config` always use local references from Cargo.toml. Play-server requires `prepare_catalog_clap_patch_state` / `supports_catalog_clap_plugin` in addition to the traditional `prepare_clap_patch_state` / `PatchStateError`, and TUI's `cmrt-patches` needs their re-export. The patch browser uses public Role/Preset/filter APIs and tui-core's sample size determination.
```powershell
cargo build --release
& ./target/release/cat-plugin-player.exe
```

Building uses local code (including uncommitted changes) and existing `target/shim`, but source changes may require reconstruction/rebuilds. For cross-repo builds within TUI itself, use TUI's existing `python scripts/cross_repo_local.py on` procedure; `off` is handled manually. Local references use uncommitted changes, and Cargo.lock does not fix the contents of each checkout. When verifying, record the HEAD and diff of each repo.

The first-time Surge XT installation is consolidated in `shared/first_instrument_install.rs`; `cat-smf-editor` also references the same instrument absence detection, terms screen, and winget process. Each app is responsible for rescanning and loading after successful installation.

Host Rust/native and SMF processing are consolidated in `shared/`; `cat-smf-editor` also references the same canonical modules. No independent crates are added; each app bundles its own DLL from its default target/shim.

The common host supports direct parameter automation for CLAP plain values and VST3 normalized values. The UI enumerates parameters and retrieves value notations, passing resolved targets to audio processing in fixed-size batches. The editor's dedicated track and the player's Macro fields for Vaporizer2, Six Sines, and Floe use this path. For conditions of generation/fix, reapplication, regression verification, and unsubmitted author reports, see [Parameter Automation Fixes](patches/uapmd/parameter-automation/README.md); for reasons, see [ADR 0037](docs/adr/0037-direct-parameter-automation.md).

Launch with no arguments for the normal GUI. `--help` and `--version` are also available.

## For Developers

### Obtaining Offline WAV

`--render-wav` generates a new host and instrument for each call, loads the specified binary state, acquires the initial 200ms sound of note 48, velocity 100, CC1=0, and exits. It does not use GUI, audio device, external effects, or restoration of normal sessions.

```powershell
& ./target/release/cat-plugin-player.exe --render-wav X:/measure/out.wav --plugin-format CLAP --plugin-id org.surge-synth-team.surge-xt --plugin-path 'C:/Program Files/Common Files/CLAP/Surge Synth Team/Surge XT.clap' --state-file X:/measure/state.bin --wait-ms 10
```

Format is `CLAP` or `VST3`; ID and path are specified according to the plugin whose state was saved. Create the output parent folder beforehand and use a new name for the WAV that does not have an existing `.json` file with the same name. It does not overwrite input state, Favorites, History, or normal config/status/state.

It saves a 32-bit float WAV at 48kHz, 256 frames, stereo, 9600 frames from note on. `--wait-ms` is a non-negative integer audio sample time. During this time, it processes empty events and renders without syncing to real-time, including after initial sound production. It does not add normal startup's automatic wait. JSON records SHA-256 of state/PCM, plugin identification info, wait time, onset position/processed frames, silence determination, and time taken for generation, state application, audio processing, and saving. Time spent waiting for generation callback is a separate item. Recording all-zero samples results in `status=silent`, leaving WAV/JSON and exiting non-zero; load/processing errors also exit non-zero. PCM may not match across plugins even with identical input.

### Surge XT CLAP Initial Note Delay Determination Table

All catalog patches are measured once for each condition (new process, new instance) with fast offline measurement. Normal config/status/state, Favorites, and History are not overwritten. WAV, state, and logs are kept in a measurement-specific run directory within the cache; the distributed JSON saves the start position, errors, and 0ms adoption decision for all patches.

```powershell
& ./target/release/cat-plugin-player.exe measure-surge-start-delay --output ../cat-music-patterns/surge-xt-start-delay.json
```

Default is 10ms vs 100ms, 200ms recording, onset difference within 1ms for 0ms permission. Comparison wait can be changed with `--candidate-wait-ms 0`, and determination conditions with `--reference-wait-ms`, `--max-onset-delta-ms`, `--onset-ratio`. 0ms permission is an adoption policy and is not treated as 0ms actual measurement result for 10ms vs 100ms. `--jobs` is concurrency (default 4), `--timeout-seconds` is per-render limit (default 30 seconds), `--limit` is for operation verification, `--work-dir` is parent directory for saving measurement runs. Silent/errors are handled separately and processing continues.

If only changing thresholds, re-rendering is not necessary. You can re-select, for example, with a 2ms tolerance, while retaining original measurement conditions and values.

```powershell
& ./target/release/cat-plugin-player.exe measure-surge-start-delay --reclassify ../cat-music-patterns/surge-xt-start-delay.json --max-onset-delta-ms 2 --output X:/measure/reclassified.json
```

The output table is replaced only upon successful completion. Committing/pushing to cat-music-patterns is a separate explicit operation. It does not wait for communication completion on startup, and table updates do not restart playback. Refer to [ADR 0008](docs/adr/0008-surge-xt-automatic-note-start-delay.md) for measurement key points and adoption decision.

### Measuring Startup Time

Specifying an output destination for `CAT_STARTUP_TRACE` records each point of the startup process to a CSV. If not specified, it does not record, and startup order or automatic playback conditions are not changed.
Example of running from the root of a release-built repository:

```powershell
$env:CAT_STARTUP_TRACE = Join-Path (Get-Location) 'target/startup.csv'
try {
    & ./target/release/cat-plugin-player.exe
} finally {
    Remove-Item Env:CAT_STARTUP_TRACE
}
Get-Content ./target/startup.csv
```

Create the parent directory for the output destination in advance. An existing file with the same name will be overwritten.
Each measurement point is recorded only once per process, so restart the app for each comparison.

- The baseline is Rust's `main()` entry, excluding time before that like process generation or OS DLL loading.
- `scan_callback` is when the scan completion notification reaches the main thread. `load_call_returned` and `instance_callback` separate the generation API call and completion notification, and `gui_requested` to `app_creation` is the GUI initialization section.
- `first_audio_callback` is the start of the audio callback, `first_signal_rendered` is after processing the first block that generated samples with an absolute value exceeding 0.000001 (-120 dBFS). This is not the time sound is output from speakers.
- The audio thread only obtains time and records it atomically; CSV saving is done on the UI side. Typically, it saves after the first signal generation and catalog preparation completion. If not completed, it saves partial results after 10 seconds of UI update, or on normal exit. Saving may not be possible if the UI is stopped or forced closed.
- Unreached measurement points appear under `# missing:`. For detailed failures, check the screen and standard error. For definitions of measurement points, see [src/startup.rs](src/startup.rs), and for startup speed optimization decisions and limitations, see [ADR 0034](docs/adr/0034-surge-xt-startup-minimal-data-home.md).

### Recording

For reproducing first-time installation in introductory recordings, use `cargo build --release --features recording-mode`.
It creates an empty save location under `%LOCALAPPDATA%\cat-plugin-player-recordings\` for each launch,
does not read/write normal settings/history, and only detects Surge XT / Surge XT Effects CLAP.

# Concept, What We Aim For
- Musical Instrument
  - For example, a synthesizer with a MIDI keyboard makes sound when powered on and a key is pressed.
    - We aim for that level of ease of use.
      - Minimize operations until sound is produced.
- Sound Production
  - We aim to maintain "sound production in the author's environment" as much as possible.
- Instant Playback
  - Perceived 0.2 seconds from app launch to sound. The fastest path to playback.
    - Processing for GUI display preparation, etc., is done after the sound.
      - Sound playing before GUI display is, so to speak, the sound version of a splash screen.
- For Education
  - Leans more towards educational use than commercial.
- Experimentation, Exploration, Personal Use
  - Frequent breaking changes will be made.
