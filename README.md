# cat-plugin-player

A lightweight application that allows you to easily play audio plugins. It uses [UAPMD](https://github.com/atsushieno/uapmd). Written in Rust.

# Previous Challenges and What This App Solves
- Audio plugin timbres are amazing!
- To play them, you often need to launch a DAW and perform setup.
- Lightweight apps for easy playback sometimes require account registration or have a UI/UX that's just not for me.
- Nowadays, if you have a desired UX, you can achieve it through vibecoding.
- So, that's what we decided to do.

# Features
- Automatic Installation
  - If you haven't installed an audio plugin, the app will automatically install [Surge XT](https://surge-synthesizer.github.io/) as mentioned above.
- Detection
  - Upon startup, it automatically detects installed plugins.
- Playback
  - Clicking a plugin loads it and automatically starts playback.
  - You can play chord progressions like `F-G-Em-Am` or MML (Music Macro Language) like `cde`.
- GUI
  - Pressing the `Show UI` button displays the plugin's GUI, allowing you to edit timbres and effects.
- Presets
  - Each plugin has a wide variety of preset timbres. You can easily select them using a unique preset browser (supported by some plugins only).
  - For plugins not supported by the preset browser, you can select timbres directly via the plugin's GUI.
- Effects
  - Each plugin has a wide variety of preset effects. You can easily select them using a unique effect browser (supported by some plugins only).
  - For plugins not supported by the effect browser, you can select effects directly via the plugin's GUI.

- Detection
  - For normal startup and editor integration, the app first restores the full plugin list and instrument/effect classification from `%LOCALAPPDATA%\cat-plugin-player\plugin-list-cache.json`. If no cache exists or it cannot be loaded, it detects and creates it for the first time. If no loading or timbre changes occur for 2 seconds after startup, it re-detects in the background. The cache and patch list are updated only if changes are found; otherwise, the display is maintained. If re-detection fails, the existing cache is kept.
  - If plugin detection is successful but no instruments are found, a prompt to install free Surge XT via winget is displayed. It is also displayed if only effects are present. The prompt is in Japanese if Windows' display language is Japanese, otherwise in English. Even if "Later" is chosen, it will be displayed every time the app starts until an instrument is found.
  - "View Terms of Use" opens Surge XT's terms (GPLv3) in a browser. Pressing "Agree to Terms and Install" executes winget and displays stages and elapsed seconds: "1/4 Preparing", "2/4 Downloading", "3/4 Installing", "4/4 Loading". If Windows' UAC prompt appears at 3/4, select "Yes". Upon success, the plugin list is automatically rescanned, Surge XT (CLAP) is loaded, and playback starts, similar to `Load`. In this case, previous instrument/effect restoration is skipped. Installation continues even if the prompt is closed, with rescanning and loading occurring upon completion.
  - If winget is not present or installation fails, winget's message and manual download link are displayed, and recorded in `error.log`. Only Surge XT is installed, and download progress is not shown. The reasons for this choice are in [ADR 0024](docs/adr/0024-offer-surge-xt-via-winget.md).
- GUI
  - When the GUI is opened for the first time, it waits 2 seconds for rendering, automatically takes a screenshot, and scales it down to a PNG with the correct aspect ratio and size to fit the list display frame and screen magnification. It is saved to `%LOCALAPPDATA%\cat-plugin-player\plugin-icons\`, and plugins with matching names + manufacturers (case-insensitive, ignoring leading/trailing spaces) share the same image for VST3 / CLAP. If name/manufacturer is insufficient, it distinguishes by format + ID.
  - Previously saved format-specific images are automatically migrated and used as shared images based on list/favorite identification. Timbre state and favorite load destinations are still distinguished by format + ID.
  - Plugin images are displayed in Plugins / Favorites / Routing. Within a row, they are scaled down to fit the button height while maintaining aspect ratio. Hovering over an image shows it at its saved size. Plugins without a GUI display a temporary icon of the same height.
  - The GUI prioritizes placement to fit within the screen's work area, right next to the main window and aligned to its top edge. If it doesn't fit, it's placed in the bottom-right of the main window's screen work area. This placement occurs when displayed and when the GUI is resized, but it does not constantly follow the main window's movement. The GUI is not scaled down; if its width is greater than the screen, its left edge aligns with the work area; if its height is greater, its top edge aligns.
  - For blank images or failed captures, retries occur at 1-second intervals, up to 20 seconds from GUI display. Saved blank images are also treated as uncaptured; opening the GUI replaces them with a valid image. No re-capturing occurs after success.
  - If capturing fails after retries, an error is displayed. Opening the GUI again retries. GUIs not supporting capture will remain with temporary icons. To retake or if a saved PNG is corrupted, delete the relevant shared PNG and any remaining old format-specific PNGs, restart the app, and open the GUI (old PNGs are kept during migration).

The main help includes entry points for `d` / `a` menus; each item key opens the corresponding menu, and `?` / `F1` or the `Help (? / F1)` button displays its help. Pressing `?` / `F1` or `Esc` again closes only the help, returning to the original menu. Other key operations are disabled while help is shown. `?` entered while typing is input as a character.
  - Single-letter English key operations (described in each function's explanation) in the main window do not work while the MML input screen, Browse patches/Browse effects, or text input is active. - Playback
  - Surge XT typically waits 100ms for the first phrase to start when audio processing is rebuilt. For CLAP catalog patches that are allowed by the distribution judgment table, this is set to 0ms and linked to their state, carrying over to the next startup. The table is fetched in the background from GitHub and stored in `%LOCALAPPDATA%\cat-plugin-player\patch-catalog\surge-xt-start-delay.json`. It is not bundled; for the first time, unlisted, or mismatching entries, it's 100ms; if communication fails, the saved table is used. Opening the plugin GUI disables permission as edits cannot be tracked. Closing the GUI and re-selecting a known patch from the browser re-evaluates. 0ms is adopted prioritizing UX; refer to [ADR 0008](docs/adr/0008-surge-xt-automatic-note-start-delay.md) for actual measurement conditions and limitations.

Selected stopped playback patterns, confirmed MML/chord text are also restored. If only one instrument candidate exists in the Plugins list on startup, it's automatically loaded if not already, and playback starts with the selected pattern even if previously stopped. If multiple candidates exist, the stopped state is restored. If manually stopped after startup, it remains stopped. Unconfirmed edits are not saved.
  - CLAP Note On/Off messages are sent in the input format supported by the plugin. This includes sforzando CLAP, which only accepts MIDI. The scope of the fix and verification records are documented in [CLAP Note Format Description](patches/uapmd/clap-note-dialect/README.md).
  - In the top-left `Sequence` pane, you can select the playback type using left/right arrows or the dropdown. Arrows cycle through the types, not including "Stop". The `s` key in the main window also cycles to the next type. Switching during playback releases all sounding notes of the current phrase and starts the new phrase from the beginning. When stopped, selecting a type doesn't start playback; use `Play` to start and `Stop` to stop. The `Space` key in the main window also toggles start/stop (except during text input). The selection of playback patterns including MML/chords and the stopped state are restored on next startup. However, if only one instrument candidate exists on startup, it auto-plays from the stopped state.
  - To preview MML/chord progressions, open the input screen with the `i` key or the `Chord` button in `Sequence` (hover to see shortcut and input method). Examples: `t120 c8r8d4e4r4` for single notes, `C F G C` for chord progressions. Both are accepted in the same input field; chord notation conversion is attempted first. Uppercase `C` becomes a chord, lowercase `ceg` becomes MML.
  - Confirm input with `Enter` / `Confirm`, or cancel with `Esc` / `Cancel`. Cancellation or conversion errors preserve the previous valid phrase. `Space` and `i` within the input screen are used for text input, and `Space` for play/stop is disabled.
  - Confirmed phrases loop playback with `Play` / `Stop`. Rests, note lengths, tempo changes, chords, and trailing rests are preserved. Opening the input screen pauses the overall regular playback. If playing just before opening, after confirmation, the new phrase plays from the beginning; after cancellation, the original playback pattern resumes from the beginning. If opened while stopped, it remains stopped after confirmation/cancellation, and `Play` starts overall playback. You can also switch to regular playback patterns. The text and selected/playback state are saved immediately after confirmation; the restored playback state is saved on cancellation. This is restored on next startup or from instrument favorites/history. Unconfirmed text is not saved, and cancellation/conversion failures preserve the last confirmed text.
  - Changing input or moving the cursor previews the single note/chord at that position once. This applies to mid-edit and paste operations. Moving or redrawing within the same pronunciation unit does not re-trigger. Previous tempo, octave, and note length are reflected; no sound is produced at rests or command positions. Regular playback stops when editing is opened, and overall playback does not resume after the preview sound ends. The preview sound is also released on the next pronunciation unit, cancellation, confirmation, or instrument change. Previewing does not change the confirmed text or regular selection.

If the event capacity is reached with a very dense phrase, sounding notes are released, and playback stops. It can be restarted with `Stop` → `Play`.
  - When calling from Favorites/History or changing patches via Browse patches/Browse effects during normal startup, the stop/play state is maintained. During playback, it plays from the beginning of the phrase and does not carry over mid-phrase waits from the previous phrase. Leading rests specified in MML are preserved. While the patch browser or effect browser is displayed, `Space` for play/stop and starting MML input in the background is suppressed. Timbre changes made within a plugin's own GUI are not detected.

Normal session timbres/effects/MML are not restored, and only sound snapshots are used for favorites. It does not return to the beginning on patch/effect/favorite/connection changes; it continues from the stopped position after a brief silence during the swap. The MML/normal pattern control fields are not used in this mode.
  - In SMF selection mode with `--master-effects`, the current track's timbre/effects are preserved for preview, and only master effects are edited/returned. The patch browser is not used. Master effects are saved to the conductor-specific meta of SMF format 1, and the results of applying them to all tracks are confirmed by returning to the editor. Master support for format 0/2 is not added. See [ADR 0030](docs/adr/0030-master-effects-selection.md).

Role/Preset/Category/Kind and search strings (including Solo/Mute and exclusion criteria) are saved to the editor's `status.json` per song/track/patch/effect, and master effects are saved/restored independently per song. Saving occurs even if closed without selecting a timbre. Timbre is not reapplied on selection restoration.

The wait time at 48kHz is about 21ms for Six Sines and 85ms for TyrellN6. MML leading rests are added further. The initial value `-` sends nothing and does not change the instrument's modulation wheel value. `sweep` repeatedly changes from 0 to 127 in 2 seconds, then 127 to 0 in the next 2 seconds. Dragging the value display bar to the right of the field sends values from 0-127, increasing/decreasing from the value at the start of the drag (0-127 moves across the bar width. If `sweep` is active, it stops, and the field takes that value. Clicking alone doesn't change it). The selected and dragged values are restored on next startup.

The heading is the name given by the patch to the Macro; if no name, it displays as `Custom modulator 1` or `Macro 1` (no CC number as it's not sent via CC). These three instruments directly control instrument parameters instead of CCs, mapping field values 0-127 to the instrument's value range (Six Sines is -1 to 1, others 0 to 1). Options, dragging, `sweep` period, `M` key, saving, and behavior on patch change are the same as Surge XT's Macros. Favorite duplicate detection ignores Macro value differences. Macros for other plugins are not supported. See [ADR 0039](docs/adr/0039-parameter-macro-sweep.md) for details.
  - Guitar open strings sequentially Note On MIDI note numbers 40, 45, 50, 55, 59, 64 (E, A, D, G, B, E) at 125ms intervals. 2 seconds after the last Note On, all 6 notes simultaneously Note Off, repeating after 0.5 seconds.
  - On successful `Load`, the `Sequence` type selection, start, and stop times are remembered. This memory persists even after stopping or `Remove`. Old history/favorites are restored with the traditional 4-note pattern.
  - On normal startup exit and `Remove`, the plugin's binary state (timbre, parameters, etc.) exposed by UAPMD's state API is saved to `%LOCALAPPDATA%\cat-plugin-player\states\` for each plugin. On next startup or re-loading the same plugin, it's restored before playback begins.
  - `Load` for an instrument replaces only the instrument, maintaining connected effects and settings. The state of the plugin being replaced is saved, and then it switches after successful generation, restoration, and connection of the new plugin. If it fails, the original configuration is maintained, and an error is displayed. Only when reloading Surge XT (minimal configuration) into the same instrument on startup, the same preservation, regeneration, and recovery path as `Show UI` below is used.
  - The scope of state saving depends on the plugin and UAPMD's format-specific implementation. UI state is also requested, but UAPMD's current VST3 implementation only obtains component state. It does not include duplicating external samples or saving upon forced termination.
  - On startup, it reads the saved full plugin list, directly loads the previous instrument and effect, restores their states, and starts playback. Audio stops once during this process. If saving fails, it does not recreate and retains the original instrument. If generation, restoration, or connection fails, it recovers once from the saved content and displays an error. If recovery also fails, it stops while retaining the saved content; please retry with `Load`. Repeated presses do not increase recreation attempts. Surge XT created via `Load`, patch browser, favorites, history, or effects uses the normal configuration. This can be disabled with the environment variable `CMRT_SURGE_MINIMAL_DATA_HOME=0`.   - If direct loading is not possible due to old history or file movement, it is restored from the scan results after GUI display. Old history is updated once played.

Refer to [ADR 0018](docs/adr/0018-floe-automatic-note-start-delay.md) for application conditions and review policy.

- Effect Routing
  - Opening `Browse effects` / `E` / `X` automatically loads the CLAP effect candidate if only one is available and sets that slot as the target for preset changes. If already connected, it uses that slot without reloading. If no instrument is loaded and only one instrument candidate exists, it first loads the instrument and starts playback. If multiple instrument candidates exist, please select an instrument first. The candidate count determination follows the CLAP priority setting in the Plugins list and does not reduce candidates based on search strings.
  - Serial connection: one instrument → multiple effects → output. After loading an instrument, press `Load` for the first effect, then `Add` to append subsequent effects. Connected effects are removed one by one with `Remove`. Duplicate connections of effects with the same format + ID are not allowed.
  - Changing effects in Browse effects requires an instrument. Candidates are fetched from default effect/preset locations scanned by the play-server shared core and are not substituted with VST3. During preparation, current playback continues, and loading, scanning, and timbre operations are disabled. In normal startup, it remains stopped if stopped, or resumes the current phrase from the beginning if playing, maintaining overall MML/Velocity/CC1 selection and the order/settings/Bypass of other effects. If generation, application, or connection fails, it reverts to the original configuration. After success, the applied state and connection are saved for the next startup; Favorites/History are not added. Saving failures are displayed as applied.
  - `Browse effects` next to `Sequence` or the `E` / `X` key opens a separate, maximized effect browser window where you can select presets from a list. It cannot be opened while MML is being edited. Filter by Category → Kind on the left and by search. Classification and selection targets are the same as `cmrt`'s effect selector. Search is case-insensitive regular expression, space-delimited AND, `-condition` for exclusion, applying to preset name, Category, Kind, or effect name (e.g., `hall -plate`, `dragonfly`). Invalid regex during input displays an error and keeps the previous list. The top line displays Search, target slot, `Random`, and `W` (for column width). `/` within the browser moves input to the search field. `R` randomly selects from filtered results. `W` toggles column width between fitting all preset names and default width. Multiple column display, moving with arrow keys / `h` / `j` / `k` / `l` / number repetitions / `PageUp` / `PageDown`, and closing with `Enter` / `Esc` are the same as Browse patches. In results with mixed effects, effect names are appended per effect, and preset names are color-coded per Kind if different. For names not fitting in a cell, the trailing preset name (excluding folder) is always preserved; the folder/effect name to its left is truncated to the first character + `...`, displaying longer for parts closer to the preset name. Full names are visible on hover.
  - The target slot is selected from `Add new effect` or `Replace n` of a connected effect. When opened, it defaults to the slot last written by this browser, otherwise the last effect, or `Add new effect` if no effects are present. Applying with `Add new effect` makes the added effect the target, and subsequent selections replace that slot, so the number of effects does not increase. If the target slot is removed, the last effect becomes the target. Presets of effects connected to slots other than the target are displayed in gray; selecting them shows a reason and does not change them. Presets inserted into the target slot by this browser are marked with `▶`, and opening the browser selects them (does not reapply).
  - Clicking, key navigation, or filtering to another candidate immediately requests application. Simply opening does not change the effect. You can select the next even while preparing; unstarted selections are replaced by the latest one and canceled if closed. Category, Kind, search string, list selection position, and target slot are saved on exit and restored on next startup. Key navigation starts from the restored selection. Category/Kind are restored by name; if missing, they revert to `ALL` in that field. Selection is restored by preset; if missing from the catalog, it becomes unselected, and key navigation starts from the beginning. The target slot is restored by its position in the chain; if no effect exists at that position, it defaults to the initial slot when opened.
  - If the effect before or after replacement in Browse effects is CLAP Surge XT Effects, the sound immediately before the switch fades out over approximately 50ms, and the sound after the switch fades in over approximately 50ms. This is a temporary measure to suppress loud "clicks" that occur when residual instrument sound passes through new effects (especially Distortion). Switching is delayed by this amount (up to approx. 70ms), and residual sound may be faintly audible during fade-in. Fading does not occur for switches between other effects or for timbre/instrument changes. Refer to [ADR 0027](docs/adr/0027-surge-xt-effect-swap-fade.md) for reasons and scope.
  - Surge XT Effects presets use a table of pre-prepared states obtained from [cat-music-patterns](https://github.com/cat2151/cat-music-patterns) on each startup (saved in `%LOCALAPPDATA%\cat-plugin-player\patch-catalog\surge-xt-fx-states.json`), instead of temporarily launching the plugin. This avoids a bug where the app crashes if you keep selecting presets. If not obtainable, the previously saved table is used; if that's also missing, Surge XT Effects presets do not appear as candidates in the effect browser, and a reason is displayed. The table is created from Surge XT 1.3.4 presets; presets with different content (e.g., different Surge XT versions) are excluded, and the number of excluded items is shown. See [ADR 0028](docs/adr/0028-surge-xt-fx-prepared-states.md) for reasons.
  - `Routing` displays the connection order. You can reorder effects by dragging the `↕` button up or down. While dragging, the moving effect name and insertion line are displayed. Instruments are not reorderable. You can edit timbres and effects via `Show UI` for each plugin. `Instrument` / `Effect` are displayed with the same type color as the left-side list.
  - Removing all effects reverts to a direct connection from instrument to output. `Bypass effect` targets the entire chain, allowing audio to pass through without processing while retaining the instance and settings. It can also be toggled with the `b` key (does not work while MML input screen, Browse patches/Browse effects, or text input is active). While bypassed, connected effects in Routing are grayed out, with `Bypassed` appended.
  - `Sequence` is for the instrument. Stopping the sequence continues audio processing, allowing effects to trail off.
  - On next startup, the instrument, all effect order, their respective states, and Bypass status are restored before playback. Single-effect history from older formats can also be loaded. If effect restoration fails, an error is displayed, reverting to a direct instrument connection, while the saved configuration is retained.
  - Additions, removals, and reordering are saved only if the new connection is successfully prepared. If it fails, the original configuration and playback are restored, and an error is displayed.
  - Supports mono/stereo for main input/output. Mono → stereo is duplication; stereo → mono is the average of left/right. Auxiliary inputs are silent.
  - Changes in connections or Bypass may cause brief audio dropouts, and sounding notes or tails may be cut off. Sidechain, parallel connections, and host-side Dry/Wet are not supported.

## Settings: Window Position and Size

You can specify the main window's startup position/size and plugin GUI placement method in `%LOCALAPPDATA%\cat-plugin-player\config.toml`. Please edit it after closing the application. Session and favorite selection states are saved in `status.json` in the same directory, and normal saves do not overwrite TOML. If status items are mixed in old TOML, they are migrated on first startup; the original file is saved as `config.toml.before-status-migration.bak`, then only status items are removed. Settings comments, formatting, and unknown items are preserved, and independent comments attached to deleted items are left at the end. If an existing `status.json` is present, it takes precedence.

```toml
[window.main]
x = 100.0
y = 100.0
width = 1200.0
height = 800.0

[window.plugin]
placement = "right_then_bottom_right"
```

The main window's `x` and `y` are logical coordinates and are used as the startup position if both are specified. If omitted, it uses the traditional initial position. `width` and `height` are the inner width/height (logical coordinates) of the main window. You can specify only one; omitted sides or values <= 0 / non-finite values revert to width 900 / height 600. Changes are reflected on next startup. The plugin placement method is currently `right_then_bottom_right` only, and the behavior is the same if omitted. GUI size and placement are calculated based on the actual window frame, screen work area, and DPI. Automatic saving of manually moved main window/GUI positions and per-plugin position specification are not performed.

## Local Build and Execution

Clone this app, `uapmd`, `clap-mml-render-tui`, and `clap-mml-play-server` into the same parent directory, then execute from this app's directory. `app` / `patches` / `patch-select` / `tui-core` from TUI and `core-lib` / `server-config` from play-server are always referenced locally from Cargo.toml. play-server requires `prepare_catalog_clap_patch_state` / `supports_catalog_clap_plugin` in addition to the traditional `prepare_clap_patch_state` / `PatchStateError`, and TUI's `cmrt-patches` requires their re-export. The patch browser uses the public Role/Preset/filter API and tui-core's sample size determination. Browse effects uses play-server's `AudioEffectCatalog` / `EffectRenderer` and TUI's effect selector's selection conditions, and tui-core's search conditions. Insufficient checkout or API will result in a build error; no automatic switching to Git versions.

```powershell
cargo build --release
& ./target/release/cat-plugin-player.exe
```

If UAPMD is not in the sibling `uapmd` directory, first set `$env:UAPMD_DIR = 'X:\projects\uapmd'`. The UAPMD location during build is specified via environment variable. `config.toml` is not read as a build setting.

Do not use `cargo install`; directly execute the generated exe in the default `target/release`. Builds use local code (including uncommitted changes) and existing `target/shim`, but source changes may require reconstruction/rebuilds. If `target/shim` was created with a different version (e.g., VS 2022), it will continue to build with that version, so delete `target/shim` before building ([ADR 0020](docs/adr/0020-visual-studio-2026-toolchain.md)). The shim DLL is bundled with the exe, extracted to the cache directory, and loaded when the GUI starts.

Refer to [ADR 0012](docs/adr/0012-local-dependencies-and-release-execution.md) for the 3-repo dependency configuration and operation policy. Local switching of TUI is not necessary for building with cat. If cross-building TUI itself, use TUI's existing `python scripts/cross_repo_local.py on` procedure; `off` is handled manually. Local references also use uncommitted changes, and Cargo.lock does not fix the content of each checkout. When verifying, record the HEAD and diffs of each repo.

Surge XT's initial installation is consolidated in `shared/first_instrument_install.rs`; `cat-smf-editor` also references the same instrument absence detection, terms screen, and winget process. Each app is responsible for rescanning and loading after successful installation.

Host Rust/native and SMF processing are consolidated in `shared/`; `cat-smf-editor` also references the same canonical modules. No independent crates are added; each app bundles its own DLL from the default `target/shim`.

The common host supports direct parameter automation for CLAP plain values and VST3 normalized values. The UI enumerates parameters and obtains value notations, passing resolved targets to audio processing in fixed-capacity batches. The editor's dedicated track and the player's Vaporizer2, Six Sines, and Floe Macro fields use this path. For generation fixes, reapplication, regression testing, and unsent reports for authors, see [Parameter Automation Fixes](patches/uapmd/parameter-automation/README.md). For adoption reasons, see [ADR 0037](docs/adr/0037-direct-parameter-automation.md).

Launch the normal GUI without arguments. `--help` and `--version` are also available.

SMF selection mode is `--select-smf <SMF> --browser patch|effect --preserve-position`. If browser is omitted, it defaults to patch; position preservation requires explicit specification. Passing `--patch-filter <program_name>` searches the patch browser for that name from ALL conditions. Regular expression symbols in the name are treated as literal characters; spaces are AND. If 0 items after catalog loading, it switches once to an OR search with words joined by `|` (e.g., `church organ` → `church|organ`). `--patch-filter-file <JSON>` restores search, Role, and Preset as is, returning to the same file on normal exit. If no file exists, it uses the initial search, prioritizing conditions in existing files. Empty searches are also retained, and no automatic word-OR switching occurs for restoration conditions. Not used for effect/master selection. The search field can be edited as usual for case-insensitive regular expressions. `--preview-smf <SMF>` specifies an SMF for all-track preview separate from the return destination. It sends all track MIDI events to the selected instrument/effect; for format 2, tempo per track is reflected. The preview SMF is not modified. `--start-seconds <seconds>` specifies the initial preview position, and `--loop-end-seconds <seconds>` specifies a loop end greater than the input SMF. If omitted, it's from the beginning to the end of the input SMF. Finite, non-negative seconds are used, and the start position must be before the loop end. Controllers and sustained notes at the start point are restored, and natural loop boundaries return to the beginning. Original SMF events are not changed. Adding `--browser-only` does not display the main screen, opening the browser in front. This option is for selection mode only. In normal track selection, you can proceed to another browser via buttons within the browser. `--master-effects` starts with the effect browser and does not proceed to the patch browser. The main screen can be displayed from `Favorites / routing` only when favorites/routing are needed. Closing the browser with `Enter` is also treated as saving and terminating the entire player. ### Obtaining Offline WAV

`--render-wav` generates a new host and instrument for each call, loads the specified binary state, obtains the initial 200ms sound of note 48, velocity 100, CC1=0, and then exits. It does not use GUI, audio device, external effects, or normal session restoration.

```powershell
& ./target/release/cat-plugin-player.exe --render-wav X:/measure/out.wav --plugin-format CLAP --plugin-id org.surge-synth-team.surge-xt --plugin-path 'C:/Program Files/Common Files/CLAP/Surge Synth Team/Surge XT.clap' --state-file X:/measure/state.bin --wait-ms 10
```

Format can be `CLAP` or `VST3`; specify ID and path to match the plugin from which the state was saved. Create the parent folder for the output beforehand and use a new name for the WAV that does not have a `.json` file of the same name. It does not overwrite input state, Favorites, History, or normal config/status/state.

Saves 9600 frames from note on as a 48kHz, 256 frames, stereo 32-bit float WAV. `--wait-ms` is a non-negative integer audio sample time. During this time, it processes empty events, rendering without synchronizing to real-time, even after the sound has started. It does not add automatic waits from normal startup. The JSON records SHA-256 of state/PCM, plugin identification, wait, onset position/processed frames, silence detection, and time taken for generation, state application, audio processing, and saving. Time spent waiting for generation callback is a separate item. Recording all-zero samples results in a non-zero exit with `status=silent`, leaving WAV/JSON; load/processing errors also result in a non-zero exit. PCM may not match across plugins even with identical input.

### Surge XT CLAP First Note Delay Determination Table

All catalog patches are measured once for each condition (new process, new instance) with fast offline measurement. Normal config/status/state, Favorites, and History are not overwritten. WAV, state, and logs are kept in a measurement-specific run directory within the cache; the distributed JSON stores the start position, errors, and 0ms adoption decision for all patches.

```powershell
& ./target/release/cat-plugin-player.exe measure-surge-start-delay --output ../cat-music-patterns/surge-xt-start-delay.json
```

Default is 10ms vs 100ms, 200ms recording, and an onset difference within 1ms is allowed as 0ms. `--candidate-wait-ms 0` etc. can change comparison waits; `--reference-wait-ms`, `--max-onset-delta-ms`, `--onset-ratio` can change determination conditions. 0ms allowance is an adoption policy and is not treated as actual 0ms measurement from a 10ms vs 100ms result. `--jobs` is concurrency (default 4), `--timeout-seconds` is the upper limit for each render (default 30 seconds), `--limit` is a count limit for operational check, `--work-dir` is the parent directory for saving measurement runs. Silence and errors are classified separately and processing continues.

If only changing thresholds, re-rendering is not required. You can re-select, for example, with a 2ms tolerance, while retaining the original measurement conditions and values.

```powershell
& ./target/release/cat-plugin-player.exe measure-surge-start-delay --reclassify ../cat-music-patterns/surge-xt-start-delay.json --max-onset-delta-ms 2 --output X:/measure/reclassified.json
```

The output table is replaced only upon successful completion. Committing and pushing to cat-music-patterns are separate, explicitly stated operations. It does not wait for communication to complete at startup, and table updates do not resume playback. See [Key points of measurement and adoption decision (ADR 0008)](docs/adr/0008-surge-xt-automatic-note-start-delay.md).

### Startup Time Measurement

Specifying an output destination for `CAT_STARTUP_TRACE` records each point of startup processing in a CSV. If not specified, no recording occurs, and startup order or auto-playback conditions are not changed.
Example of execution from the root of a Release-built repository:

```powershell
$env:CAT_STARTUP_TRACE = Join-Path (Get-Location) 'target/startup.csv'
try {
    & ./target/release/cat-plugin-player.exe
} finally {
    Remove-Item Env:CAT_STARTUP_TRACE
}
Get-Content ./target/startup.csv
```

Create the parent directory for the output beforehand. Files with the same name will be overwritten.
Each measurement point is recorded only once per process, so restart the app for each comparison.

- The baseline is the entry point of Rust's `main()`, not including time before process creation or OS DLL loading.
- `scan_callback` is when the scan completion notification reaches the main thread. `load_call_returned` and `instance_callback` separate API call and completion notification for generation; `gui_requested` to `app_creation` is the GUI initialization section.
- `first_audio_callback` is the start of the audio callback; `first_signal_rendered` is after processing the first block that generated samples with an absolute value exceeding 0.000001 (-120 dBFS). This is not the time of sound output from speakers.
- The audio thread only obtains time and records it atomically; CSV saving is done on the UI side. Normally, it's saved after the first signal generation and catalog preparation completion. If incomplete, it saves partial results after 10 seconds of UI update or upon normal exit. It may not be savable if the UI is stopped or forced closed.
- Unreached measurement points appear under `# missing:`. Check the screen and standard error for failure details. See [src/startup.rs](src/startup.rs) for measurement point definitions, and [ADR 0034](docs/adr/0034-surge-xt-startup-minimal-data-home.md) for startup acceleration decisions and limitations.

# Concept, What We Aim For
- Instrument
  - For example, a synthesizer with a MIDI keyboard produces sound when powered on and keys are pressed.
    - We aim for that level of ease of use.
      - Minimize operations until sound is produced.
- Sounding
  - We aim to maintain "sounding in the author's environment" as much as possible.
- Immediate Sound
  - Perceptibly 0.2 seconds from app launch to sound production. We prioritize the fastest path to playback.
    - Processes like GUI display preparation are done *after* sound production.
      - Sound playing before the GUI appears might be considered a sound version of a splash screen.
- Educational Use
  - More oriented towards educational use than commercial.
- Experimentation, Exploration, Personal Use
  - Frequent breaking changes will occur.
