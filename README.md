# cat-plugin-player

A lightweight application to easily play audio plugins. It utilizes [UAPMD](https://github.com/atsushieno/uapmd) and is written in Rust.

# Previous Challenges and What This App Solves
- Audio plugin sounds are amazing!
- To play them, it often requires launching a DAW and performing pre-setup for performance.
- Lightweight apps for casual playing sometimes required account registration for acquisition, or their operation felt "not for me".
- Nowadays, if you have a desired UX, you can achieve it through vibecoding.
- So, that's what we did.

# Features
- Automatic Installation
  - If you haven't installed an audio plugin, the app will automatically install [Surge XT](https://surge-synthesizer.github.io/) as described above.
- Detection
  - Upon launch, it automatically detects installed plugins.
- Playback
  - Clicking on a plugin will load it and automatically start playback.
  - It can play chord progressions like `F-G-Em-Am` and MML (Music Macro Language) like `cde`.
- GUI
  - Pressing the `Show UI` button displays the plugin's GUI, allowing you to edit sounds and effects.
- Patches
  - Each plugin has a wide variety of preset patches. You can easily select them using a unique patch browser (supported by some plugins only).
  - For plugins not supported by the patch browser, you can select patches directly from the plugin's GUI.
- Effects
  - Each plugin has a wide variety of preset effects. You can easily select them using a unique effect browser (supported by some plugins only).
  - For plugins not supported by the effect browser, you can select effects directly from the plugin's GUI.

- Detection
  - For normal startup and editor integration, the full plugin list and instrument/effect classification are first restored from `%LOCALAPPDATA%\cat-plugin-player\plugin-list-cache.json`. If the cache is missing or unreadable on first launch, it will be detected and created. After startup, if no loading or patch changes occur and operations stop for 2 seconds, it will re-detect in the background. The cache and patch list are updated only if there are changes in the list; otherwise, the display is maintained. If re-detection fails, the existing cache is retained.
  - If plugin detection is successful but no instruments are found, it displays a prompt to install the free Surge XT via winget. It also displays this if only effects are found. If the Windows display language is Japanese, it displays in Japanese; otherwise, in English. Even if "Later" is chosen, it will display every time the app starts as long as no instrument is available.
  - Clicking `View Terms of Use` opens Surge XT's terms of use (GPLv3) in a browser. Pressing `Agree to Terms and Install` executes winget, displaying stages "1/4 Preparing", "2/4 Downloading", "3/4 Installing", "4/4 Loading" and elapsed seconds. If a Windows confirmation screen (User Account Control) appears at 3/4, select "Yes". Upon success, it automatically re-scans the plugin list, loads Surge XT (CLAP), and starts playback as with `Load`. In this case, previous instrument/effect restoration is not performed. Even if the prompt is closed, installation continues, followed by a rescan and load upon completion.
  - If winget is not available or installation fails, it displays the winget message and manual download location, and logs it to `error.log`. Only Surge XT is included, and download progress is not shown. The reasons for this choice are in [ADR 0024](docs/adr/0024-offer-surge-xt-via-winget.md).
- GUI
  - When the GUI is opened for the first time, it waits 2 seconds for rendering, automatically takes a screenshot, and scales it down to a PNG with size appropriate for the list display frame and screen zoom factor, preserving the aspect ratio. It is saved to `%LOCALAPPDATA%\cat-plugin-player\plugin-icons\`, and plugins with matching name + manufacturer (ignoring leading/trailing spaces and case) share the same image for VST3 / CLAP. If name or manufacturer is missing, they are distinguished by format + ID.
  - Previously saved format-specific images are also automatically migrated to shared images from list/favorite identification information. Patch state and favorite load destinations are still distinguished by format + ID.
  - Plugin images are displayed in Plugins / Favorites / Routing. Within a row, they are scaled down to fit the button height while preserving aspect ratio. Hovering over an image allows viewing it at its saved size. Plugins with no GUI displayed show a temporary icon of the same height.
  - The GUI prioritizes positions that fit within the screen's work area, aligned with the right and top edge of the main window. If it doesn't fit, it's placed in the bottom right of the work area of the screen where the main window is located. It is positioned when displayed and when the GUI size changes, but does not constantly follow the main window's movement. The GUI is not scaled down; if its width is larger than the screen, its left edge aligns with the work area; if its height is larger, its top edge aligns.
  - For blank images or failed captures, retries are made at 1-second intervals, up to 20 seconds from GUI display. Saved blank images are also treated as uncaptured; opening the GUI replaces them with a valid image. No re-capture occurs after success.
  - If capturing fails even after retries, an error is displayed. Opening the GUI again retries. GUIs that do not support capture remain with a temporary icon. To retake a picture or if a saved PNG is corrupted, delete the relevant plugin's shared PNG and any remaining old format-specific PNGs, restart the app, and open the GUI (old PNGs are retained during migration).
- Playback
  - The last played instrument, connected effects, Bypass status, and playback pattern are saved to `%LOCALAPPDATA%\cat-plugin-player\status.json` and restored on next startup. Selected stopped playback patterns and confirmed MML/chord text are also restored. If there's only one instrument candidate in the Plugins list on startup, and it's not loaded, it's automatically loaded, and playback starts with the selected pattern even if a stopped state was saved. If there are multiple candidates, the stopped state is restored. If manually stopped after startup, it remains stopped. Unconfirmed edits are not saved.
  - CLAP Note On/Off messages are sent according to the input format supported by the plugin. This includes sforzando CLAP, which only accepts MIDI. The scope of fixes and validation records are documented in [CLAP Note format explanation](patches/uapmd/clap-note-dialect/README.md).
  - In the top-left `Sequence` pane, you can select the playback type using left/right arrows or the dropdown. Arrows cycle through the ends of the types, and 'Stop' is not included as a type. Switching during playback releases all notes of the current phrase and starts from the beginning of the new phrase. When stopped, selecting a type does not play; use `Play` to start and `Stop` to stop. In the main window, the `Space` key also toggles start/stop (except when typing text). Selection of playback patterns including MML/chords and stopped state are restored on next startup. However, when starting with only one instrument candidate, it auto-plays from the stopped state.
  - To preview MML/chord progressions, open the input screen with the `i` key or the `Chord` button in `Sequence` (hover to see shortcuts and input methods). Examples: `t120 c8r8d4e4r4` for single notes, `C F G C` for chord progressions. Both are accepted in the same input field; chord notation conversion is attempted first. Capital `C` indicates a chord; lowercase `ceg` becomes MML.
  - Input is confirmed with `Enter`/`Confirm` and cancelled with `Esc`/`Cancel`. Cancellation or conversion errors retain the previous valid phrase. `Space` and `i` within the input screen are used for text input; `Space` for playback/stop does not work.
  - Confirmed phrases loop playback with `Play`/`Stop`. Rests, note lengths, tempo changes, chords, and trailing rests are preserved. Opening the input screen pauses overall normal playback. If playback was active just before opening, after confirmation it plays the new phrase from the start; after cancellation, it plays the original pattern. If opened while stopped, it remains stopped after confirmation/cancellation, and `Play` starts overall playback. It can also switch to normal playback patterns. The text, selection, and playback state are saved immediately after confirmation, and the restored playback state is also saved upon cancellation. It's restored on next startup or from instrument Favorites/History. Unconfirmed text is not saved; cancellation or conversion failure retains the previous confirmed text.
  - Changing input or moving the cursor previews the single note/chord at that position once. This also applies to mid-edit or paste. Moving or redrawing within the same pronunciation unit does not retrigger sound. It reflects previous tempo, octave, and note length, and does not sound at rest or command positions. Normal playback stops when editing is opened, and overall playback does not resume after preview sound ends. Preview sound is also released on the next pronunciation unit, cancellation, confirmation, or instrument change. Preview does not change the confirmed text or normal selection.
  - For MML loop playback, the Velocity setting in the `Velocity` field takes precedence over any velocity specified within the input. CC1 can also be controlled from the `CC1 modulation` field. If the volume of playback events is reached with a very dense phrase, sounding notes are released, and playback stops. It can be restarted with `Stop` -> `Play`.
  - When recalling from Favorites/History or changing patches via Browse patches/Browse effects in normal startup, the stop/playback state is maintained. During playback, it plays from the beginning of the phrase and does not carry over any waits from the middle of the previous phrase. Leading rests specified in MML are preserved. While the patch browser or effect browser is open, `Space` for playback/stop and starting MML input are suppressed in the background. Patch changes via plugin's own GUI are not detected.
  - In SMF selection mode (`--select-smf`), the input track is loop-played with tempo, duration, and velocity. For bulk patch assignment, all tracks are previewed with the selected patch and the primary track's effects. Normal session patches, effects, and MML are not restored; only sound snapshots are used for favorites. It does not return to the beginning on patch/effect/favorite/connection changes, but continues from the stopped position after a brief silence during the swap. MML/normal pattern operation fields are not used in this mode.
  - In SMF selection mode with `--master-effects`, the current track's patch/effects are retained for preview, and only master effects are edited and returned. The patch browser is not used. Master effects are saved in the conductor-specific meta of SMF format 1, and the results of their application to all tracks are confirmed by returning to the editor. Master support for formats 0/2 has not been added. See [ADR 0030](docs/adr/0030-master-effects-selection.md).
  - cat-smf-editor uses `--resident <name>` to keep one player resident, bringing the patch/effect browser to the foreground on each `t`/`x`. The resident player does not load the selected patch/effect itself; it sends the state to the editor, which plays it with its own instrument. Esc, `q`, ×, or closing the effect browser with Enter only hides the browser; the player exits when the editor terminates. The previous patch is not restored, and the player's normal status.json is not updated. Role/Preset/Category/Kind and search string (including Solo/Mute and exclusion conditions) are saved per song/track/patch/effect to the editor's status.json, and master effects are saved/restored independently per song. Saving occurs even if no patch is selected before closing. Patch list selection is also saved per song/track to the editor's status.json using patch name and instrument/original patch identification information, and restored on restart. Patch reapplication does not occur during selection restoration.
  - For Six Sines/TyrellN6 CLAP, when audio processing is rebuilt during loading, state restoration, or connection changes, the system waits for the first phrase to start while continuing normal audio processing to preserve the initial sound. The wait is approximately 21ms for Six Sines and 85ms for TyrellN6 at 48kHz. MML leading rests are added on top of this. Application conditions and validation records are in [ADR 0019](docs/adr/0019-random-patch-all-catalog.md).
  - In the `Velocity` field below the playback pattern, you can select `100`, `127`, `40-100`, `80-127` using the left/right arrows or dropdown. The initial value is 100. Range selection increases values in the order of Note On within the phrase, then decreases them in the next loop, repeating this action. Changes reflect from the next note without restarting the phrase and are restored on next startup.
  - In the `CC1 modulation` field, you can select `0`, `127`, `sweep` using the left/right arrows or dropdown. The initial value is 0. `sweep` repeats a change from 0 to 127 in 2 seconds, then from 127 to 0 in the next 2 seconds. The selection is restored on next startup.
  - Guitar open strings send MIDI note numbers 40, 45, 50, 55, 59, 64 (E, A, D, G, B, E) sequentially with 125ms intervals for Note On. Two seconds after the last Note On, all six notes are Note Offed simultaneously, and this repeats after 0.5 seconds.
  - On successful `Load`, it is remembered when `Sequence` type is selected, started, or stopped. The memory remains even after stopping or `Remove`. Older history/favorites are restored with the traditional 4-note pattern.
  - On normal startup termination and `Remove`, the binary state of patches/parameters exposed by the plugin via the UAPMD state API is saved to `%LOCALAPPDATA%\cat-plugin-player\states\` per plugin. On next startup or re-loading the same plugin, it is restored before playback starts.
  - `Load` for an instrument replaces only the instrument, maintaining connected effects and settings. The state of the plugin being replaced is saved, and it switches only after successful generation, restoration, and connection of the new plugin. If it fails, the original configuration is maintained, and an error is displayed. Only when reloading the minimal Surge XT from startup into the same instrument, the same preservation, regeneration, and recovery path as `Show UI` below is used.
  - The scope of state saving depends on the plugin and UAPMD format-specific implementations. UI state is also requested, but the current UAPMD VST3 implementation only retrieves component state. It does not include duplication of external samples or saving upon forced termination.
  - On startup, it reads the saved full plugin list, directly loads the previous instrument and effect, restores their states, and begins playback. After that, it initializes the GUI, and after operations settle, re-detects the list in the background. If there is no full list cache on first startup, it detects after GUI display.
  - If the previous instrument was Surge XT (CLAP / VST3), only this one instance is created on startup in a configuration that omits patch, wavetable, and FX preset lists to enable faster playback. Since the Surge GUI menus would be almost empty in this configuration, pressing `Show UI` for that Surge recreates it with a normal configuration, preserving the latest patch, edits, Favorite selection, playback settings, and connected effects, then opens the GUI. Audio stops once during this process. If saving fails, it does not recreate, maintaining the original instrument. If generation, restoration, or connection fails, it recovers once from the saved content and displays an error. If recovery also fails, it stops while preserving the saved content, so try `Load` again. Repeated presses do not increase recreation attempts. Surge XT created via `Load`, patch browser, favorites, history, or effects is in a normal configuration. This can be disabled with the environment variable `CMRT_SURGE_MINIMAL_DATA_HOME=0`. Reasons, measured latency, and validation scope are in [ADR 0034](docs/adr/0034-surge-xt-startup-minimal-data-home.md).
  - If direct loading is not possible due to old history or file moves, it restores from the scan results after GUI display. Old history is updated once played.
  - If the main instrument is CLAP Floe, when rebuilding audio processing during loading or patch restoration, the start of the first phrase is delayed by 100ms. MML leading rests are added on top of this. This is a temporary measure for observing symptoms where initial sounds disappear, and resolution on actual hardware is unconfirmed. Application conditions and review policy are in [ADR 0018](docs/adr/0018-floe-automatic-note-start-delay.md).
  - For the adoption history of faster startup, bugs encountered with Show UI, and changes in disposal order, see [ADR 0034](docs/adr/0034-surge-xt-startup-minimal-data-home.md). For measurement methods, see [Developer's Guide](#起動時間の計測).
- Effect Routing
  - Opening `Browse effects`/`E`/`X`: if there's only one compatible CLAP effect candidate, it's automatically loaded, and its slot becomes the target for preset changes. If already connected, it's not reloaded, and that slot is used. If the instrument is not loaded and there's only one instrument candidate, the instrument is loaded first, and playback starts. If there are multiple instrument candidates, select an instrument first. The number of candidates is determined according to the CLAP priority setting in the Plugins list, and search strings do not reduce the number of candidates.
  - It's a serial connection of one instrument → multiple effects → output. After loading an instrument, press `Load` for the first effect, then `Add` to append subsequent effects. Connected effects can be removed one by one with `Remove`. Duplicate effects with the same format + ID cannot be connected.
  - Effect changes via Browse effects require an instrument. Candidates are retrieved from default effect/preset locations scanned by the play-server shared core, without VST3 fallback. During preparation, current playback continues, and loading, scanning, and patch operations are disabled. In normal startup, it remains stopped if stopped, or restarts the current phrase from the beginning if playing. Overall selection of MML/Velocity/CC1 and the order/settings/Bypass of other effects are maintained. If generation, application, or connection fails, it reverts to the original configuration. Upon success, the applied state and connection are saved for next startup, and Favorites/History are not added. Save failures are displayed as applied.
  - `Browse effects` next to `Sequence` or the `E`/`X` keys open an independent, maximized effect browser window where presets can be selected from a list. It cannot be opened while MML is being edited. Filter by Category → Kind on the left and by search. The classification and selection targets are the same as cmrt's effect selector. Search is case-insensitive regular expression, space-AND, `-condition` for exclusion, applying to preset name, Category, Kind, or effect name (e.g., `hall -plate`, `dragonfly`). Invalid regular expressions during input display an error and retain the previous list. The top row has Search, target slot, `Random`. `/` within the browser moves input to the search field, `R` selects randomly from filtered results, and `W` toggles column width between fitting all preset names and default width. Multiple column display, navigation with arrow keys / `h` / `j` / `k` / `l` / number repetitions / `PageUp` / `PageDown`, and closing with `Enter` / `Esc` are the same as Browse patches. In results with mixed effects, effect names are given per effect, and if Kind differs, preset names are color-coded per Kind. Names not fitting cells always keep the trailing preset name (part excluding folder), and left folder/effect names are truncated to the first character + `...`, displaying longer parts closer to the preset name. Full names can be seen by hovering.
  - The target slot is chosen from `Add new effect` or `Replace n` of a connected effect. When opened, it defaults to the slot last written by this browser, otherwise the last effect, or `Add new effect` if no effects are present. Applying with `Add new effect` makes the added effect the target, and subsequent selections replace that slot, so the number of effects does not increase by continuing to select. If the target slot is removed, the last effect becomes the target. Presets of connected effects in non-target slots are grayed out, and selecting them displays a reason and does not change. Presets added to the target slot via this browser are marked with `▶`, and opening the browser selects them (does not reapply).
  - Clicking/key navigation or filtering to a different candidate immediately requests application. Simply opening does not change the effect. You can select the next item during preparation; unstarted selections are replaced by the latest one, and cancelled by closing. Category, Kind, search string, list selection position, and target slot are saved on exit and restored on next startup. Key navigation starts from the restored selection. Category/Kind are restored by name; if missing, they revert to `ALL` in that field. Selection is restored by preset; if missing from the catalog, it becomes unselected, and key navigation starts from the beginning. The target slot is restored by its position in the chain; if no effect is at that position, it defaults to the slot upon opening.
  - If the effect before or after replacement in Browse effects is CLAP Surge XT Effects, the sound just before switching fades out in approximately 50ms, and the sound after switching fades in in approximately 50ms. This is a temporary measure to prevent a loud "pop" when remaining instrument sound passes through a new effect (especially Distortion types). Switching is delayed by that amount (up to approximately 70ms), and residual sound may be faintly audible during fade-in. No fading occurs for switches between other effects or changes in patches/instruments. Reasons and application scope are in [ADR 0027](docs/adr/0027-surge-xt-effect-swap-fade.md).
  - Surge XT Effects presets are obtained from [cat-music-patterns](https://github.com/cat2151/cat-music-patterns) on each startup using a pre-prepared state table (saved in `%LOCALAPPDATA%\cat-plugin-player\patch-catalog\surge-xt-fx-states.json`), instead of temporarily launching the plugin for preparation. This avoids a bug where the app crashes if you keep selecting presets. If acquisition fails, the last saved table is used; if that is also unavailable, Surge XT Effects presets do not appear as candidates in the effect browser, and a reason is displayed. The table is created from Surge XT 1.3.4 presets; presets with different content (e.g., different Surge XT versions) are excluded from candidates, and the number of excluded items is shown. Reasons are in [ADR 0028](docs/adr/0028-surge-xt-fx-prepared-states.md).
  - `Routing` displays the connection order. Effects can be reordered by dragging the `↕` button up or down. While dragging, the moving effect name and insertion line are displayed. Instruments are not subject to reordering. `Show UI` for each plugin can be used to edit patches or effects. `Instrument`/`Effect` are displayed with the same type color as the left list.
  - Removing all effects reverts to a direct connection from instrument to output. `Bypass effect` targets the entire chain, allowing passthrough while retaining instance and settings. It can also be toggled with the `b` key (does not work in MML input screen, Browse patches/Browse effects, or while typing text). While bypassed, connected effects in Routing are grayed out and `Bypassed` is appended.
  - `Sequence` is for instruments. Even if Sequence is stopped, audio processing continues to allow effect decay.
  - On next startup, the instrument, order of all effects, their respective states, and Bypass status are restored before playback. History of one effect in old format can also be read. If effect restoration fails, an error is displayed, reverting to direct instrument connection, while retaining the saved configuration.
  - Add, remove, or reorder operations are saved only if preparation of the new connection is successful. If it fails, the original configuration and playback are restored, and an error is displayed.
  - Supports mono/stereo for main input/output. Mono → stereo is duplication; stereo → mono is the average of left/right. Auxiliary inputs are silent.
  - Changing connections or Bypass may cause brief audio glitches, and sounding notes and decay may be interrupted. Sidechain, parallel connections, and host-side Dry/Wet are not supported.

If saving fails, the switch is aborted.

- Lissajous Display
  - `Lissajous` is displayed below the oscilloscope in the right analysis panel. If `☰` → `On right` of the oscilloscope is unchecked, spectrum, oscilloscope, and Lissajous appear side-by-side at the bottom of the screen.
  - Draws the most recent 50ms of output (up to 4096 samples), reflecting effects and Bypass, on a 45° rotated Lissajous curve. Common auto-scaling preserves volume differences and aspect ratio; in-phase at same level is a vertical line, out-of-phase is a horizontal line, sine waves with phase difference are ellipses or circles. Left-only output is a diagonal from top-left to bottom-right, right-only output is a diagonal from top-right to bottom-left, mono is a vertical line, silence is a central dot.
  - Updates independently of note, cycle count, or trigger settings. `Show analysis labels` can display headings. Axis and rendering method can also be checked in the graph tooltip.
  - `Correlation` directly below Lissajous displays the left/right correlation for the most recent 150ms as a bar and numerical value from -1 to +1. +1 is in-phase, near 0 is weak correlation, -1 is out-of-phase. Negative values are shown in red, serving as a guideline for cancellation when mixed to mono. If silent or one side is silent, it shows "—".
- Waveform Display
  - `Oscilloscope` at the bottom of the screen displays the output of L (green) and R (blue), reflecting effects and Bypass, superimposed. Mono displays the same waveform for both.
  - The display width is determined from the last Note On MIDI note number (A4 = 440Hz), and `1`, `2`, `4`, `8 cycles` can be selected. After Note Off, the decay is displayed based on the last note. Output containing chords or detuning may not perfectly repeat within that width.
  - `Zero cross` aligns with the negative → positive crossing of the left channel. If the left channel is silent, it uses the right channel; if no crossing, it displays from the beginning.
  - `Similarity` sweeps from the beginning of the buffer for the display width, one sample at a time, to find the position with maximum correlation to the previous display. Ties prefer the earlier position, and the same start position is used for left/right. For the first display or if the comparison target is silent, zero cross is used.
  - Comparison history is reset when note playback, playback pattern, display cycle count, trigger method, or audio stream changes. It will show a waiting indicator until sufficient data is collected.
  - Exploration is performed on a separate thread from audio processing. Display updates may be slow for low notes or high cycle counts. If display data is interrupted, the history is reset.
  - Default display settings on startup are 4 cycles and zero-cross. Display settings are not saved.

## Settings: Window Position and Size

`%LOCALAPPDATA%\cat-plugin-player\config.toml` allows specifying the main window's startup position/size and plugin GUI placement method. Edit it after closing the application. Session and favorite selection states are saved to `status.json` in the same directory, and normal saves do not overwrite TOML. If states are mixed in the old TOML, they are migrated on first launch; the original file is saved as `config.toml.before-status-migration.bak`, then only state items are removed. Settings comments, format, and unknown items are retained, and independent comments attached to deleted items remain at the end. If an existing `status.json` is present, it takes precedence.

```toml
[window.main]
x = 100.0
y = 100.0
width = 1200.0
height = 800.0

[window.plugin]
placement = "right_then_bottom_right"
```

`x` and `y` for the main window are logical coordinates and are used as the startup position if both are specified. If omitted, the default initial position is used. `width` and `height` are the inner width and height (logical coordinates) of the main window. Either can be specified alone; omitted sides or values <= 0 or non-finite revert to width 900, height 600. Changes are reflected on next startup. The plugin placement method is currently `right_then_bottom_right` only, and the default behavior is the same if omitted. GUI size and placement are calculated based on actual window frame, screen work area, and DPI. Automatic saving of manually moved positions for the main window or GUI, or per-plugin position specification, is not performed.

## Local Build and Run

Clone this app, `uapmd`, `clap-mml-render-tui`, and `clap-mml-play-server` into the same parent directory, then run from this app's directory. TUI's `app` / `patches` / `patch-select` / `tui-core` and play-server's `core-lib` / `server-config` are always locally referenced from Cargo.toml. Play-server requires `prepare_catalog_clap_patch_state` / `supports_catalog_clap_plugin` in addition to traditional `prepare_clap_patch_state` / `PatchStateError`, and TUI's `cmrt-patches` requires their re-export. The patch browser uses public Role/Preset/filter APIs and tui-core's sample size determination. Browse effects uses play-server's `AudioEffectCatalog` / `EffectRenderer` and TUI's effect selector conditions, and tui-core's search conditions. Missing checkouts or insufficient APIs will result in build errors; no automatic switch to Git versions is performed.

```powershell
cargo build --release
& ./target/release/cat-plugin-player.exe
```

If UAPMD is not in the sibling `uapmd` directory, first set `$env:UAPMD_DIR = 'X:\projects\uapmd'`. UAPMD's location during build is specified by an environment variable. `config.toml` is not read as build settings.

Do not use `cargo install`; directly run the exe generated in the default `target/release`. The build uses local code (including uncommitted changes) and existing `target/shim`, but source changes may require reconstruction/rebuild. If `target/shim` was created with VS 2022 or another version, it will continue to build with that version, so delete `target/shim` before building ([ADR 0020](docs/adr/0020-visual-studio-2026-toolchain.md)). The shim DLL is bundled with the exe, extracted to the cache directory, and loaded when the GUI starts.

For the 3-repo dependency structure and operational policy, refer to [ADR 0012](docs/adr/0012-local-dependencies-and-release-execution.md). Local TUI switching is not needed for `cat` builds. If cross-building TUI itself, use TUI's existing `python scripts/cross_repo_local.py on` procedure; `off` is handled manually. Local references use uncommitted changes, and Cargo.lock does not fix the contents of each checkout. When validating, record the HEAD and diffs of each repo.

Surge XT's initial introduction is centralized in `shared/first_instrument_install.rs`; cat-smf-editor also references the same instrument absence detection, terms screen, and winget process. Each app is responsible for re-scanning and loading after successful introduction.

Host Rust/native and SMF processing are centralized in `shared/`; cat-smf-editor also references the same canonical module. No separate crates are added; each app bundles its own DLL from the default `target/shim`.

Launch the normal GUI without arguments. `--help` and `--version` are also available.

SMF selection mode is `--select-smf <SMF> --browser patch|effect --preserve-position`. If `browser` is omitted, it defaults to patch; position preservation must be explicitly specified. Passing `--patch-filter <program_name>` searches the patch browser with that name from ALL conditions. Regular expression symbols in the name are treated as literal characters, and spaces are AND. If 0 items after catalog loading, it switches once to an OR search with words joined by `|` (e.g., `church organ` → `church|organ`). `--patch-filter-file <JSON>` restores search, Role, and Preset as is, and returns to the same file on successful exit. If the file is missing, it uses the initial search; existing file conditions take precedence. An empty search is also retained, and no automatic word OR switching is performed for restored conditions. Not used for effect/master selection. The search field can be edited as a case-insensitive regular expression as usual. `--preview-smf <SMF>` can specify a separate SMF for all-track preview, different from the return destination. It sends all tracks' MIDI events to the selected instrument/effect, and for format 2, reflects tempo per track. The preview SMF is not overwritten. `--start-seconds <seconds>` specifies the initial preview position, and `--loop-end-seconds <seconds>` specifies the loop end beyond the input SMF. If omitted, it's from the beginning to the end of the input SMF. Use finite, non-negative seconds, and the start position must be before the loop end. Controller/sustained notes at the start position are restored, and natural loop boundaries revert to the beginning. Original SMF events are not modified. Adding `--browser-only` prevents the main screen from displaying, opening the browser in the foreground. This option is for selection mode only. In normal track selection, buttons within the browser can navigate to other browsers. `--master-effects` starts with the effect browser and does not proceed to the patch browser. The main screen can be displayed from `Favorites / routing` only when favorites/routing are needed. Closing the browser with Enter is also treated as saving/terminating the entire player. If saving fails or during a modification process, the browser is retained, and errors are displayed within the browser. Esc, 'q' not used for input, or closing the main/browser window saves instrument/ordered effect/bypass state to the input SMF and exits. For `--master-effects`, only the conductor's master effect/bypass is saved, and track settings are retained. 'q' in the search field is for text input. During a modification process, it waits for confirmation; if saving fails, it retains the screen and selection, allowing retry. The normal status.json is not updated. Existing state saving/favorite operations for selected items use the usual save destination. State compatibility across OS/plugin versions or duplication of external samples is not guaranteed. See [ADR 0029](docs/adr/0029-shared-host-smf-selection.md).

## For Developers

### Measuring Startup Time

Specifying an output destination in `CAT_STARTUP_TRACE` records each point in the startup process to a CSV. If not specified, no recording occurs, and startup order or auto-playback conditions are not changed.
Example of running from the root of a release-built repository:

```powershell
$env:CAT_STARTUP_TRACE = Join-Path (Get-Location) 'target/startup.csv'
try {
    & ./target/release/cat-plugin-player.exe
} finally {
    Remove-Item Env:CAT_STARTUP_TRACE
}
Get-Content ./target/startup.csv
```

Please create the parent directory for the output destination in advance. Files with the same name will be overwritten.
Each measurement point is recorded only once per process, so restart the application each time you compare.

- The baseline is the entry point of Rust's `main()`, not including process generation or OS DLL loading before that.
- `scan_callback` is when the scan completion notification reaches the main thread. `load_call_returned` and `instance_callback` separate the generation API call from its completion notification, and `gui_requested` to `app_creation` is the GUI initialization section.
- `first_audio_callback` is the start of the audio callback, and `first_signal_rendered` is after processing the block that first generated a sample with an absolute value exceeding 0.000001 (-120 dBFS). This is not the time sound is emitted from speakers.
- The audio thread only obtains time and records it atomically; CSV saving is done on the UI side. Typically, it saves after the first signal generation and catalog preparation are complete. If not complete, it saves partial results after 10 seconds of UI update, or upon normal termination. Saving may not be possible if the UI is stopped or during a forced termination.
- Unreached measurement points appear under `# missing:`. For detailed failures, check the screen and standard error. Measurement point definitions are in [src/startup.rs](src/startup.rs), and the decisions and limitations for startup acceleration are in [ADR 0034](docs/adr/0034-surge-xt-startup-minimal-data-home.md).

### Recording

When reproducing first-time installation for promotional recordings, use `cargo build --release --features recording-mode`.
It creates an empty save destination under `%LOCALAPPDATA%\cat-plugin-player-recordings\` on each launch.
It does not read/write normal settings/history, and only detects CLAP plugins for Surge XT/Surge XT Effects.
It does not refer to the cmrt catalog; it newly acquires a catalog for Surge.
The absence of Surge XT is not faked; the workflow assumes a human or coding agent actually uninstalls it before recording.
After recording, revert to the normal exe with `cargo build --release`.
The scope and limitations are in [ADR 0026](docs/adr/0026-recording-mode.md).

# Concept, What We Aim For
- Instrument
  - For example, a synthesizer with a MIDI keyboard makes sound when you power it on and press keys.
    - We aim for that level of ease of use.
      - Minimize operations until sound is produced.
- Sound Production
  - We aim to maintain "it produces sound in the author's environment" as much as possible.
- Instant Sound
  - From app launch to sound production, aim for 0.2 seconds. We prioritize the fastest possible playback.
    - Processes like GUI display preparation are done after the sound.
      - Sound playing before the GUI appears might be considered a sound version of a splash screen.
- Educational Use
  - Rather than commercial use, we lean towards educational purposes.
- Experimentation, Exploration, Personal Use
  - Frequent breaking changes will occur.
