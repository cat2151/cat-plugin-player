# cat-plugin-player

A lightweight app that makes it easy to play audio plugins. It utilizes [UAPMD](https://github.com/atsushieno/uapmd) and is written in Rust.

# Past Challenges and What This App Solves
- Audio plugin sounds are fantastic!
- To play them, you often need to launch a DAW and perform preliminary setup.
- Lightweight apps for easy playback sometimes require account registration to obtain, or their user interface felt "not for me."
- Nowadays, if you have a desired UX, you can achieve it through intuitive coding.
- So, that's what we decided to do.

# Features
- Automatic Installation
  - As mentioned, if no audio plugin is installed, the app will automatically install [Surge XT](https://surge-synthesizer.github.io/).
- Detection
  - Upon launch, it automatically detects installed plugins.
- Playback
  - Clicking a plugin loads it and automatically starts playback.
  - It can play chord progressions like `F-G-Em-Am` and MML (Music Macro Language) like `cde`.
- GUI
  - Pressing the `Show UI` button displays the plugin's GUI, allowing you to edit sounds and effects.
- Sound Patches
  - Each plugin has a variety of preset sounds. You can easily select them using a unique sound browser (supported by some plugins only).
  - For plugins not supported by the sound browser, you can select sounds directly from the plugin's GUI.
- Effects
  - Each plugin has a variety of preset effects. You can easily select them using a unique effect browser (supported by some plugins only).
  - For plugins not supported by the effect browser, you can select effects directly from the plugin's GUI.

The cache and patch list are updated only if changes are found; otherwise, the display remains. If re-detection fails, the existing cache is retained.
  - If plugin detection succeeds but no instruments are found, a prompt is displayed to install the free Surge XT via winget. It also appears if only effects are present. If Windows display language is Japanese, it shows in Japanese; otherwise, in English. Even if `Later` is chosen, it will show on every startup until an instrument is present.
  - `View Terms of Service` opens Surge XT's terms (GPLv3) in a browser. Clone this application, `uapmd`, `clap-mml-render-tui`, and `clap-mml-play-server` into the same parent directory, then execute from this application's directory. cargo build --release
```powershell
& ./target/release/cat-plugin-player.exe
```

## For Developers

### Obtaining Offline WAV

`--render-wav` generates a new host and instrument for each call, loads the specified binary state, acquires the first 200ms of sound for note 48, velocity 100, CC1=0, and then exits. It does not use GUI, audio device, external effects, or normal session restoration.

```powershell
& ./target/release/cat-plugin-player.exe --render-wav X:/measure/out.wav --plugin-format CLAP --plugin-id org.surge-synth-team.surge-xt --plugin-path 'C:/Program Files/Common Files/CLAP/Surge Synth Team/Surge XT.clap' --state-file X:/measure/state.bin --wait-ms 10
```

Format is `CLAP` or `VST3`; id and path are specified according to the plugin that saved the state. Create the parent folder for the output first, and use a new name that doesn't share a WAV filename with an existing `.json`. Input state, Favorites, History, and normal config/status/state are not overwritten.

Saves 9600 frames from note on as a 48kHz, 256 frames, stereo, 32-bit float WAV. `--wait-ms` is a non-negative integer for audio sample time. During this time, it processes empty events and renders without syncing to real-time, even after note onset. It does not add automatic waits from normal startup. The JSON records SHA-256 of state/PCM, plugin identification info, wait time, onset position/processed frames, silence judgment, and time taken for generation, state application, audio processing, and saving. Time spent waiting for generation callback is a separate item. Recording all-zero samples results in `status=silent`, retains WAV/JSON, and exits with non-zero code; loading/processing errors also result in non-zero exit. PCM may not match for the same input across different plugins.

### Surge XT CLAP Initial Note Wait Determination Table

All catalog patches are measured once each, under various conditions, with a new process and new instance, for fast offline measurement. Normal config/status/state, Favorites, History are not overwritten. WAV, state, and logs are kept in a measurement-specific `run` directory within the cache; the distributed JSON stores the start position, errors, and 0ms adoption judgment for all sounds.

```powershell
& ./target/release/cat-plugin-player.exe measure-surge-start-delay --output ../cat-music-patterns/surge-xt-start-delay.json
```

Default is 10ms vs 100ms, 200ms recording, and an onset difference of less than 1ms is allowed as 0ms. `--candidate-wait-ms 0` etc. can change the comparison wait; `--reference-wait-ms`, `--max-onset-delta-ms`, `--onset-ratio` can change determination conditions. 0ms allowance is an adoption policy and does not treat 10ms vs 100ms results as actual 0ms measurements. `--jobs` is parallel count (default 4), `--timeout-seconds` is max for each render (default 30 seconds), `--limit` is for operation check item limit, `--work-dir` is parent directory for saving measurement runs. Silent/errors are treated as separate categories and skipped.

If only thresholds are changed, re-rendering is not necessary. You can re-select, for example, with a tolerance of 2ms while retaining original measurement conditions and values.

```powershell
& ./target/release/cat-plugin-player.exe measure-surge-start-delay --reclassify ../cat-music-patterns/surge-xt-start-delay.json --max-onset-delta-ms 2 --output X:/measure/reclassified.json
```

The output table is replaced only upon successful completion. Committing and pushing to `cat-music-patterns` are separate, explicit operations. It does not wait for communication completion on startup, and table updates do not resume playback. Refer to [Key Points of Measurement and Adoption Judgment (ADR 0008)](docs/adr/0008-surge-xt-automatic-note-start-delay.md).

### Startup Time Measurement

Specifying an output destination for `CAT_STARTUP_TRACE` records each point in the startup process to CSV. If unspecified, it does not record, and does not change startup order or auto-playback conditions.
Example of running from the root of a release-built repository:

```powershell
$env:CAT_STARTUP_TRACE = Join-Path (Get-Location) 'target/startup.csv'
try {
    & ./target/release/cat-plugin-player.exe
} finally {
    Remove-Item Env:CAT_STARTUP_TRACE
}
Get-Content ./target/startup.csv
```

Create the parent directory for the output in advance. Files with the same name will be overwritten.
Each measurement point is recorded only once per process, so restart the application for each comparison.

- The baseline is the entry point of Rust's `main()`, not including process creation or OS DLL loading times before that.
- `scan_callback` is when the scan completion notification reaches the main thread. `load_call_returned` and `instance_callback` separate the generation API call and completion notification, and `gui_requested` to `app_creation` is the GUI initialization section.
- `first_audio_callback` is the start of the audio callback, `first_signal_rendered` is after processing the first block that generated samples with an absolute value exceeding 0.000001 (-120 dBFS). This is not the time sound is output from speakers.
- The audio thread only obtains time and records it atomically; CSV saving is done on the UI side. Typically, it saves after the first signal generation and catalog preparation are complete. If not completed, it saves partial results after 10 seconds of UI update, or on normal exit. Saving may not be possible during UI freeze or forced termination.
- Unreached measurement points appear under `# missing:`. For detailed failures, check the screen and standard error. For measurement point definitions, see [src/startup.rs](src/startup.rs); for startup speedup judgment and limitations, see [ADR 0034](docs/adr/0034-surge-xt-startup-minimal-data-home.md).

### Recording

When reproducing first-time installation for demo recordings, use `cargo build --release --features recording-mode`.
For each startup, it creates an empty save destination under `%LOCALAPPDATA%\cat-plugin-player-recordings\`,
does not read/write normal settings or history, and only detects Surge XT / Surge XT Effects CLAP.
It does not refer to the `cmrt` catalog and acquires a new Surge-specific catalog.
Absence of Surge XT is not faked; manual or automated uninstallation is expected before recording.
After recording, revert to the normal exe with `cargo build --release`.
Refer to [ADR 0026](docs/adr/0026-recording-mode.md) for scope and limitations.

### Surge XT Effects State Table

When updating Surge XT, etc., run the following in an environment with Surge XT Effects installed to regenerate the table:

```
cargo run --release --example export_surge_fx_states -- ..\cat-music-patterns\surge-xt-fx-states.json
```

Committing and pushing to `cat-music-patterns` is done manually. Refer to [ADR 0028](docs/adr/0028-surge-xt-fx-prepared-states.md) for format and reasons.

# Concept, What We Aim For
- Instrument
  - For example, a synthesizer with a MIDI keyboard makes sound when you power it on and press a key.
    - We aim for that level of ease of use.
      - Minimize the operations required to make a sound.
- Making Sound
  - We aim to maintain "it makes sound in the author's environment" as much as possible.
- Instant Sound
  - Perceptible 0.2 seconds from app launch to sound. We prioritize the fastest possible playback.
    - Processes like GUI display preparation are done after the sound.
      - Sound playing before the GUI appears might be considered a sound version of a splash screen.
- Educational Use
  - Rather than commercial use, it's oriented towards educational purposes.
- Experimentation, Exploration, Personal Use
  - We will frequently make breaking changes.
